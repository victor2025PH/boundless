# 智聊实例 备份 / 迁移 / 换机 SOP（WP-8，2026-08-17）

> 回答私有化客户的硬性采购问题：「数据怎么备份？换机器怎么办？」
> 工具：`scripts/instance_backup.ps1` / `scripts/instance_restore.ps1`（薄壳）
> → 核心 `scripts/instance_backup.py`（可单测，门禁 `tests/test_instance_backup.py`）。
> 适用**实例布局**数据根（`D:\chengjie-instances\<inst>\data` 或任意 AITR 数据根）；
> 桌面坐席机的「保登录态重装」另有既定链（`deploy/desktop/backup_chatx_data_node.ps1`
> + `restore_chatx_accounts_node.ps1`，见 `.cursor/rules/chatx-desktop-install.mdc`），不混用。

## 1. 备份

```powershell
powershell -ExecutionPolicy Bypass -File scripts\instance_backup.ps1 `
  -DataRoot D:\chengjie-instances\zhiliao\data [-OutDir E:\bak] [-Label pre-migration]
```

- **包含**：`config/`（全部 `*.db`、`config.local.yaml`、`license.key`、人设媒体、
  语音参考音）、`sessions/`（Telegram 登录态）、`domains/`、`events/`、
  `ledger_outbox/`、`plugins/`、`assets/`（预渲染语音）、根散文件。
- **排除**（denylist，见 `should_exclude`）：`logs/`、`temp/`、`tmp_*`、`src/`
  （历史 CWD 相对路径误落物）、`__pycache__`、`*.db-wal/-shm/-journal`（由快照合并）、
  既有备份 zip（防套娃）。
- **活库安全**：`*.db` 一律走 sqlite3 **online backup API** 出一致性快照——实例
  **不必停机**；WAL 里已提交未 checkpoint 的行也在快照里（有门禁钉住）。
- 产物：`instance-backup-<inst>[-label]-<时间戳>.zip`，内含 `backup_manifest.json`
  （逐文件 sha256 + 引擎版本戳 git/pkg_version + 总量）。默认落
  `<数据根>\..\backups\`。
- **周期备份**＝计划任务示例（脚本头注释里有 schtasks 模板）。自动云备份**刻意不做**
  ——客户自选存储，把 `-OutDir` 指到网盘同步目录即等效。

## 2. 恢复

```powershell
powershell -ExecutionPolicy Bypass -File scripts\instance_restore.ps1 `
  -Zip <backup.zip> -TargetRoot D:\chengjie-instances\zhiliao\data [-Force]
```

- 目标非空**拒绝**（`-Force` 才覆盖，绝不静默）。
- 自动校验：逐文件 sha256（坏一个点名一个）+ 每个 `.db` 跑 `PRAGMA integrity_check`
  ——「拷完了」≠「拷对了」。
- 版本兼容自检（warn-only）：备份由**更新版工具/更新版引擎**写出 → 打印警告
  （先升级引擎再恢复），不硬拦。

## 3. 换机全流程（7 步）

1. **旧机备份**：§1 命令 + `-Label pre-migration`；zip 拷到新机。
2. **新机装引擎**：版本 ≥ 备份 manifest 里的 `engine.pkg_version`（恢复端会警告）。
3. **恢复**：§2 命令，确认输出 `all files verified, all dbs integrity_check=ok`。
4. **授权**（两种情形，看 `license.key` 是否绑机）：
   - **付费码默认不绑机**（`machine` 声明缺省）→ 随备份恢复即生效，零操作；
   - **绑机码**（官网试用码 / 显式绑机签发）→ 新机上授权会报 invalid（machine
     mismatch）→ 走 §4 厂商重签，替换 `config/license.key`。
5. **停旧机实例**（关键！同一 Telegram 会话两处启动会互踢）：旧机
   `deploy\instances\stop_instance.ps1`；确认旧机不再自启（计划任务/看门狗一并停）。
6. **新机启动 + GO 验收**：起实例 → `deploy\instances\status_instances.ps1` 须 `GO`
   （或 `/login` 200）→ 工作台抽查 ≥3 个会话历史完整、人设/媒体/语音在位。
7. **观察 24h**：看板无授权/会话告警；旧机保留备份 zip ≥30 天再退役。

## 4. 厂商侧：绑机码重签（换绑）

```bash
# ① 客户在新机取机器指纹（两种途径任一）：
#    - 会员中心页面显示的机器码；
#    - 引擎根 CLI：
python -c "from src.licensing.machine_bridge import machine_fingerprint; print(machine_fingerprint())"

# ② 厂商用同 lic_id + 新指纹重签（license_tool 已支持 --machine，2026-08-17 加）：
python scripts/license_tool.py issue \
    --priv config/.vendor_license_private.pem \
    --sub "客户公司" --plan pro --days 365 --lic-id <原授权编号> \
    --machine <新机指纹> --out license.key
# `*` = 站点授权不限机器；省略 --machine = 不绑机。
# ③ 把新 license.key 发客户，替换 config/license.key；台账登记旧码作废。
```

校验语义（`license_manager` + `test_machine_binding.py` 钉死）：绑本机=active、
绑他机=invalid、`*`=站点通配、指纹判定不出来=**放行**（绑机是防滥用不是防破解，
真正闸门在签发侧台账）。

## 6. 备份产物是敏感物（保管要求）

zip 含 `sessions/`（Telegram 登录态）与 `license.key`（授权）——**拿到 zip ≈ 拿到
账号**。按敏感资料保管：不进共享网盘公共目录、传输走加密通道、旧备份按保留期销毁。
**刻意不做内建加密**：客户存储策略各异，内建口令管理反而成为丢数据的新单点；需要
加密时一行命令即可包一层：`7z a -p -mhe=on backup.7z instance-backup-*.zip`。
