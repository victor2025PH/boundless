# 安装包功能交付分级（三分法审计台账）— 2026-07-31

> **机器可读的单一事实源：`src/utils/feature_registry.py`**（P1 起）。同一张表
> 驱动三个消费面：种子门禁 `tests/test_desktop_seed_visibility.py`、桌面态基线
> 增量补齐 `ConfigManager._ensure_baseline`、功能总览 `/api/setup/features`
> （settings 页「功能总览」卡）。改分级只改注册表；本文档负责「为什么这么分」
> 与待拍板项。

## 背景与根因

现象：演示机上的功能（实锤标本＝工作目标）在客户安装包里"不存在"。

因果链（缺一环都不成立，四环全中）：

1. 功能代码 100% 随包（PyInstaller DATAS 带 templates + shared/copilot；routes 全注册）；
2. 开关走「新子系统默认 `enabled: false`」约定，桌面种子 `config.desktop.min.yaml`
   只带最小集，未列出的键=代码默认=关；
3. 演示机靠 `config.local.yaml` overlay 打开这些功能，而 overlay 在 `.gitignore`
   里、刻意不随包（含密钥与本机 LAN 拓扑，也不能随包）；
4. 「关闭 = API 403 = 前端整卡隐藏」（如 `cp-goal.js` `_hideCard`），且首启向导、
   能力面板均无开启入口——客户无任何自助途径发现或打开。

修法**不是**把开关都打开——那会撞上 `test_desktop_seed_deliverable.py` 记录过的
更糟形态（「开关开了但依赖没随包」：用户点了没反应，比灰着更困惑）。修法是补一层
**交付分级决策**，按下述三分法逐键归类。

## P1 落地记录（2026-07-31）

- **注册表升为生产构件**：分级表从 P0 的测试内字面量迁至
  `src/utils/feature_registry.py`（键路径逐字核实过才允许入表；`deep_persona` /
  `bio_retrieval` 因键名未核实**刻意不在 v1 表**，仍列 B 类候选）。
- **存量安装缺口已修**：桌面态（`AITR_DESKTOP_MODE`）启动时
  `ConfigManager._ensure_baseline` 按「合并视图键缺失」增量补齐 A 类进 overlay——
  只补缺失（用户从未表达意见），显式 true/false 都尊重；幂等零重写；
  **刻意挂在 `_validate_config` 之前**（桌面首启空凭据会 validation-fail 提前
  return，挂在成功路径末尾等于永不执行——`tests/test_baseline_reconcile.py`
  有时序回归钉）。服务器实例无此 env，零影响。
- **功能总览可发现性**：`/api/setup/features`（+`/toggle`）读注册表出四态
  （已开启/可开启/缺依赖/未开放），settings 页新卡渲染；A/B 类依赖齐备可一键开
  （写 overlay 即时生效），缺依赖拒绝硬开（防「开了但跑不动」），C 类只读展示
  原因；旧后端无此路由时整卡自动隐藏（模板热更新自洽）。C 类被部署 overlay
  打开时如实报「已开启」（总览必须与真实行为一致）。
- 门禁：`tests/test_feature_registry.py`（表不变量 + 纯函数语义 + **动态拼键
  i18n 两语完备**）/ `test_baseline_reconcile.py`（7 例，重点「不该动的绝不动」）/
  `test_feature_center_routes.py`（真 ConfigManager 端到端）；路由清单基线已登记
  两个新端点。

## 已知限制（如实记录）

- **`config.example.yaml` 不动**：自建部署的保守默认维持「新子系统默认关」纪律；
  产品基线概念先在桌面种子档落地，自建档是否跟进属运营决策。
- **基线补齐只在启动时执行**：运行中手删 overlay 里的基线键要到下次重启才会补回
  （合并视图判定，热重载路径刻意不掺和）。
- **功能总览的「缺依赖」是配置级判定**：只判「配没配」，不探端点活不活——在线
  探活属 readiness 体系，避免把网络抖动带进设置页。P1 曾计划的「测一下」探活
  按钮经评估**刻意不做**：端点健康已有 readiness/health watchdog 体系负责
  （黄灯 + 主动告警），设置页再造一套探针=双源口径 + 把网络抖动变成用户可见的
  闪烁状态，弊大于利。
- **needs_upgrade 仅在 `licensing.feature_gate.enabled=true` 时出现**：gate 默认
  关=全功能放行（与既有纪律一致），档位墙随 P2 拍板（四档矩阵）开启后生效。

**内测期不区分「生产机 / 内测包 / 标准包」：唯一打包形态 = 内测包（与生产机对齐）。**

1. **打包流程强制内测形态**：`desktop/package.json` 的 `predist`/`predist:win` 改为
   `copy-shared → stage_internal_assets → smoke_backend → smoke_internal` 全链——

   这条事故路径被结构性堵死。
2. **种子净差分收口（v1.002）**：用「zhiliao `config.yaml`⊕`config.local.yaml` 合并视图
   vs `config.desktop.min.yaml`⊕`config.desktop.internal.yaml` 合并视图」三方比对逐键核实，
   本机偏离出厂 269 键中安装包未覆盖 37 键——其中功能性缺口已补进内测种子：

3. **刻意不随包的净差分（原因固定进种子头注释④类）**：密钥/生产账号数据

## 相册/发图能力分级（2026-07-31，photo_capability 线）

对外可讲的三档（开关即商品化边界；能力判定单一事实源
`src/companion/photo_capability.py`）：

| 档 | 语义 | 开关组合 |
|---|---|---|
| 基础（默认） | 纯文字人设：绝不发图，对话中也**绝不承诺/暗示**发照片（提示层约束 + 出站守卫双保险） | `companion.selfie.enabled` 任意 + 人设 `capabilities.photos` 缺省/false |
| 相册档 | 运营上传真实素材，触发词/要图请求命中即自动发；关系等级门槛、冷却/防复读照常 | 全局 selfie 开 + 人设 `capabilities.photos: true` |
| 生成档 | 相册之上叠加 AI 现场出图（PuLID 锁脸/物体图），依赖 LAN ComfyUI（C 类基建） | 相册档 + 出图后端配置 |

交付要点：
