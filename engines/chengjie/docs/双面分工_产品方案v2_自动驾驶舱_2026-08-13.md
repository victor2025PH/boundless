# 双面分工产品方案 v2：原生页 = 手动挡，统一收件箱 = 自动驾驶舱

> 性质：**纯方案，不含代码改动**（2026-08-13，等确认后再排期动工）。
> 前置阅读：`双面板融合_能力对照与驾驶权方案_2026-08-13.md`（机制层，已上线）。
> 本文回答：构想深挖 → 方案优化 → 开发 / 市场 / 用户 / UI·UX 四视角逐页分析。

---

## 0. 构想还原与现状核对

**老板原话的构想**：原生官方聊天页 = 个人手动控制面；自建统一收件箱（「全部对话」视图）= 全自动模式。

一句话翻译成产品语言：**「原生页是方向盘，收件箱是自动驾驶系统的驾驶舱」**——人机不抢一个方向盘，AI 在驾驶舱里跑量，人只在需要时握方向盘。

核对现状（机制已在 ≠ 产品形态已到位）：

| 构想要素 | 机制现状 | 产品形态现状 |
|---|---|---|
| 两面并存不打架 | ✅ 驾驶权锁 + 双链让位（今日上线） | ✅ |
| 人工面 = 原生页 | ✅ 深链直达会话、注入翻译/草稿辅助 | ⚠ 接管动作零散（要自己切档位、自己跳页） |
| 全自动面 = 收件箱 | ✅ auto_ai 档 + AutosendWorker + 各类护栏 | ❌ **收件箱长得像「官方客户端克隆」而非「驾驶舱」**：满屏输入框诱惑坐席直接插话，监督信息淹没在聊天流里 |
| 人工聊完 AI 接得上 | ✅ TG/WA 协议层天然回流镜像 | ❌ **Messenger 断档**：sidecar 只回流入站（实测 server.js 全部 postIngest 均 direction:"in"），原生页人工出站收件箱看不见 → 交还后 AI「失忆」 |

**核心矛盾**：机制层已经完成「两面融合」，但产品层还是「两个聊天工具并排放」。本方案要做的是让收件箱完成身份转变——从聊天工具变成**自动化生产线的监控与例外处理台**。

## 1. 深挖：构想为什么成立（四个支柱）与两个隐患

**支柱 1 · 双登录态是平台原生能力，不是我们硬造的**：TG 多端同号原生共存、WA 多设备伴侣位（最多 4 台）、Messenger 双浏览器会话。「人一个登录态、AI 一个登录态」不违反任何平台机制，封号特征弱。

**支柱 2 · 回流让 AI 不失忆**：人在原生页说的每句话，TG 经 MTProto 更新、WA 经 Baileys fromMe 回显，自动镜像进收件箱线程 → 记忆/画像/上下文不断档。这是「接管—交还」循环能转起来的前提。（Messenger 是例外，见隐患 2。）

**支柱 3 · 仲裁机制已闭环**：账号级驾驶权锁 + 会话级 automation_mode + 消息级草稿审核，三层粒度都有，防双发有 DB 级原子闸门兜底。

**支柱 4 · 自动化光谱已存在**：系统里早就有 L1-L4 autopilot 分级和 manual/review/multi_choice/auto_ai 四档——构想不是从零造，是把散落的档位**升格为产品主叙事**。

**隐患 1 · 账号级二分太粗**：一个号下面 100 个会话，坐席只想亲自接 1 个大客户；把整号切「原生页托管」会让其余 99 个会话的 AI 全停。→ 方案修正：**日常接管以会话级为主**（切该会话 manual + 跳原生页），账号级锁只用于「整号交给人」的场景（如老板自己的号）。

**隐患 2 · Messenger 人工出站不回流**：坐席在原生 messenger.com 聊的话，服务器 sidecar 看得见（读线程 DOM 时 direction:"out" 已解析）却不上报 → 交还后 AI 不知道人说过什么，可能自相矛盾（「换人了」级穿帮）。→ 必须补：sidecar 出站镜像（成本低：解析已有，只差一个 post）。

## 2. 方案优化：从「两面二分」升级为「自动化光谱 + 显式接管」

### 2.1 自动化光谱（产品主叙事，四档统一话术）

| 档位 | 名字（对外话术） | 在哪操作 | 现有机制映射 |
|---|---|---|---|
| L0 | 纯手动 | 原生页 | 官方原生功能 |
| L1 | 辅助手动（翻译/草稿贴身） | 原生页 + 注入层 | inject 完整定制档 |
| L2 | 人审后发（AI 拟稿我把关） | 收件箱 review 档 | draft review + 人工投递链 |
| L3 | 全自动（例外才找我） | 收件箱 auto_ai 档 | AutosendWorker + 护栏族 |

### 2.2 「接管」从隐式状态变成显式动作（本方案最重要的产品概念）

现状：坐席想手动回，要么直接在收件箱打字（与 AI 抢方向盘，人格分裂 + 双发温床），要么自己去切档位、自己去原生页找会话——三四步散落操作。

方案：**一键接管 / 一键交还**，把已有机制串成一个坐席动作：

- **接管**（会话头一个按钮）：该会话切 manual → 深链跳原生页同一会话 → 会话行变黄「人工接管中 ⏱」→ 接管计时开始。
- **交还**（原生页顶条 / 收件箱会话头）：切回 auto_ai → AI 收到**交接摘要**（接管期间人工说了什么、达成了什么，注入下轮上下文）→ 会话行回蓝。
- **护栏**：接管超时提醒（默认 2h 无动作提示「还在人工吗？」）、接管期间该会话 AI 拟稿/投递全停（既有 manual 档语义）、交还后首条 AI 回复标记「刚交接」供抽查。

### 2.3 收件箱身份转变：聊天工具 → 驾驶舱

- 首屏从「会话列表 + 聊天窗」演进为「**驾驶舱**」：今日产能 KPI、**介入队列**（按优先级聚合：危机 > 风控 > 客户点名要真人 > AI 连败 > SLA 超时 > 待审积压）、账号健康。
- 聊天窗在 auto_ai 会话里降级为「**监督视图**」：消息流只读回放 + AI 决策依据 chips（人设/记忆/策略），composer 收起为干预区（主按钮 = 接管 / 纠正，直接打字需二次确认）。
- 「全部对话」保留但降为次级视图（流水账），坐席日常工作面是介入队列。

## 3. 四视角分析

### 3.1 开发工程师视角

**复用盘点（方案 90% 是串联，不是新造）**：

| 能力 | 现状 | 方案用途 |
|---|---|---|
| automation_mode 会话档位 + bootstrap | ✅ | 接管/交还的底层开关 |
| 驾驶权锁 + 双链让位 | ✅ 今日上线 | 账号级兜底 |
| 深链（msgr/t、tg #peer、wa send?phone） | ✅ 随桌面包发布 | 接管跳转 |
| 回流镜像 TG/WA | ✅ 协议层 | 交接不失忆 |
| 需人工 tag / SLA watcher / 草稿积压告警 / 危机检测 / kill-switch | ✅ 各自独立 | 介入队列的数据源（只差聚合） |
| 受控出站 AI 重写 / 纠正样本三元组 | ✅ 桌面链 | 接管期风格改写 + 人工示范反哺 |
| 行级 eff_persona / 效能徽章 | ✅ | 行级「谁在开车」三色的数据基础 |
| tk-token 主题体系 + i18n packs | ✅ | 全部 UI 改动的地基 |

**差距清单（真正要开发的）**：

| # | 差距 | 规模 | 风险 |
|---|---|---|---|
| 1 | 一键接管/交还（机制串联 + 会话头按钮 + 计时条） | 小 | 低（全是已有 API 编排） |
| 2 | 介入优先级统一队列（后端聚合端点 + 前端队列卡片流） | 中 | 低（数据源全在，注意查询用 TTL 缓存口径） |
| 3 | **msgr 人工出站回流**（sidecar tail 已解析 out，补 direction:"out" 的 postIngest + 服务端幂等去重） | 小 | 中（防「自己发的回声」重复入库，需与既有 recordSent 去重对齐） |
| 4 | 交还时 AI 交接摘要（接管窗口内消息 → 一段摘要注入 context） | 小 | 低（复用 list_recent_messages + 现有 hint 消费口） |
| 5 | 驾驶舱页（新路由 /workspace/cockpit） | 中 | 低（**新页增量，不动 17k 行 unified_inbox 热区**） |
| 6 | 接管观测（接管次数/时长/交还率/接管期客户回复率） | 小 | 低（ui-event + outreach 口径已有同类） |

**工程纪律**：新页新文件优先（共享树多线并发，unified_inbox.html 是最高危热区，只在会话头小区域动刀）；全部功能挂 feature flag 默认关；每步配门禁（接管往返状态机、msgr 出站回流幂等、队列聚合口径）。

### 3.2 市场经理视角

**卖点重构**：竞品（聚合聊天类）卖「聊得更快」，我们卖「**AI 员工替你聊，人只管例外**」。双面架构是打消客户最大顾虑（「AI 会不会乱说话搞砸我的客户」）的答案——**随时可以亲自下场，官方原版体验，一键接管**。

- 一句话：**「1 个坐席监管 50 个号：AI 聊天，人管例外，随时接管」**
- 三个数字化承诺（都有现成观测支撑）：例外才响（介入队列）、接管 10 秒内到位（深链）、AI 说过什么都可回溯（审计）。

**3 分钟 Demo 剧本**（驾驶舱即演示页）：
1. 开场驾驶舱：50 个账号在跑，今日 AI 已回 1,200 条，介入队列只有 3 个红点。
2. 点开红点：客户说「叫你们老板来」→ 一键接管 → 原生 Messenger/TG 页面直达该会话（官方界面，客户无感）。
3. 人聊两句搞定 → 点「交还 AI」→ 回驾驶舱，会话行由黄转蓝。
4. 收尾看周报：本周 AI 替你干了什么（价值周报已有）。

**定价分层随光谱**（license/SKU 基座已有）：辅助档（L0-L1，翻译+草稿）→ 人审档（L2）→ 全自动档（L3，按账号数阶梯）。接管功能放全自动档——它是「敢开全自动」的信心来源，正好锁定最高客单。

**风险话术预案**：客户问「AI 出事谁负责」→ 展示危机自动降档、kill-switch、审计三件套；问「和官方冲突吗」→ 双登录态是平台原生多端能力。

### 3.3 用户视角

**画像 A · 坐席**（一天动线，现状 vs 方案后）：

| 时段 | 现状 | 方案后 |
|---|---|---|
| 上班 | 打开收件箱，翻会话列表找红点，凭感觉判断哪些要管 | 驾驶舱首屏：介入队列排好序，逐个处理 |
| 要人工时 | 收件箱里直接打字（风格穿帮）或自己去原生页翻找会话 | 一键接管：档位、跳转、计时一次完成 |
| 人工聊完 | 忘了把会话调回自动，AI 停摆到被发现 | 一键交还 + 超时提醒兜底 |
| 空闲 | 无明确任务 | 抽查自动对话质量（👍👎 喂纠正样本） |

**痛点 → 方案映射**：「不知道看哪」→ 介入队列；「插一句话 AI 就乱了」→ 接管仪式 + 交接摘要；「Messenger 人工聊的 AI 不知道」→ 出站回流补齐；「接管后忘交还」→ 计时条 + 超时提醒。

**画像 B · 老板**：只看三张卡——产能（价值周报）、风险（风控/危机事件）、钱（成本卡），全部已有，方案只是把入口聚合进驾驶舱顶部，不新造报表。

### 3.4 UI / UX · 美术视角

**视觉语言：「谁在开车」一眼可辨**（贯穿所有页面的三色状态系统，沿用 tk-token）：

- 🔵 蓝 = AI 自动驾驶中（默认态，安静不打扰）
- 🟡 黄 = 人工接管中（带 ⏱ 计时，提醒「记得交还」）
- 🔴 红 = 需要介入（危机/风控/连败/点名真人）

落点统一：会话行左缘 3px 色条 + 会话头驾驶权徽章（已有蓝/黄，补红）+ 驾驶舱队列卡边框 + 原生页顶部接管计时条，四处同一套色。

**驾驶舱首屏（文字线框）**：

```
┌────────────────────────────────────────────────────────┐
│ 今日 AI 已回 1,208   回复率 92%   接管中 2   需介入 3   │ ← KPI 带（大数字）
├──────────────────────────────────┬─────────────────────┤
│ 介入队列（按优先级）              │ 账号健康 rail        │
│ ┌─ 🔴 危机 · 客户情绪异常 ──────┐ │ ● tg 主号   在线    │
│ │ 王先生 · tg · 3 分钟前        │ │ ● wa 8613…  在线    │
│ │ [查看上下文] [一键接管]       │ │ ⚠ msgr Nick 需重登  │
│ └──────────────────────────────┘ │                     │
│ ┌─ 🟡 接管中 1h24m · 李女士 ───┐ │ 产能迷你趋势图       │
│ │ [去原生页继续] [交还 AI]      │ │                     │
│ └──────────────────────────────┘ │                     │
└──────────────────────────────────┴─────────────────────┘
```

设计基调：暗色优先（坐席长时间盯屏）、大数字 KPI、卡片流而非表格、空态要讲话（「一切正常，AI 在岗 ✓」而不是空白）。

**聊天窗（auto_ai 会话）的监督视图改造**：消息流保留但 AI 出站气泡加微标（内部视图专用，客户不可见）；composer 折叠为干预条——主按钮「接管」次按钮「纠正这条」，展开打字需确认「你确定直接以 AI 身份插话？建议先接管」；右栏副驾保留（AI 决策依据 chips：人设/记忆/策略命中）。

**接管仪式（微交互）**：点接管 → 轻确认弹层（写清后果：AI 让位、去原生页）→ 跳转 → 原生页顶部常驻细条「🟡 人工接管中 12:34 ｜ [交还 AI]」。交还 → 短 toast「AI 已接手，交接摘要已注入」。仪式感的目的不是好看，是让「谁在开车」这个状态**有成本地切换、无成本地看见**。

**美化清单（存量小修，非重构）**：会话行密度分层（默认一行：状态点 + 客户名 + 情绪 emoji + 末句摘要）；统一空态插画与文案语气；驾驶权徽章/能力浮层的圆角阴影对齐 tk-token；平台品牌色只用于平台图标不用于语义状态（避免与三色系统打架）；日夜双主题过既有对比度门禁。

## 5. 分期路线图与验收

| 期 | 内容 | 验收标准 | 观测指标 |
|---|---|---|---|
| **P0**（1-2 天） | 一键接管/交还 + 三色行标 + 原生页计时条 + 接管超时提醒 | 接管往返 ≤10 秒 3 步内；接管期该会话 AI 零出站；交还后档位/锁状态正确 | 接管次数、平均时长、超时率、双发计数（恒 0） |
| **P1**（3-5 天） | 驾驶舱新页 + 介入统一队列（六信号聚合） | 坐席上班到首个介入动作 ≤30 秒；队列零漏报（对照各源头告警） | 队列吞吐、介入响应时长 |
| **P2**（2-3 天） | msgr 出站回流 + 交接摘要注入 + 接管期风格改写入口 | 交还后 AI 首条不与人工内容矛盾（抽查）；msgr 人工消息收件箱可见 | 交接后穿帮投诉数 |
| **P3**（观察后） | 原生页反向让位（锁全闭环）+ 接管效果对比看板 | 数据回答「人工接管真的更好吗」→ 反哺接管建议 | 接管期 vs AI 期客户回复率/转化差 |

## 6. 刻意不做

1. **不在收件箱重造官方全功能**（通话/贴纸/转发等）——那正是原生页存在的意义，桥接即可。
2. **不做「随手插一句」混聊默认放行**——人格分裂 + 双发温床；插话必须经接管仪式（或走 L2 人审的编辑发送）。
3. **不大改 17k 行存量聊天页**——驾驶舱走新页增量，存量只动会话头/行标小区域。
4. **不为 Messenger 原生页解禁全自动**——assistOnly 是刻意的（网页嵌入伪全自动=风控+双发风险），Messenger 全自动只认收件箱。

## 7. 待验证清单（动工前）

1. WA 多设备 fromMe 回显在坐席原生页发言场景下的延迟与覆盖率（协议层支持，需实测）。
2. msgr sidecar 出站镜像的回声去重（与 recordSent/synthMsgId 幂等对齐，防自发消息重复入库）。
3. 介入队列聚合查询成本（各信号源已有 TTL 缓存，聚合端点沿用 300s 口径即可，需压一下）。
4. 接管计时条在桌面壳的注入位置（原生页 DOM 外的壳层 overlay，不碰官方页面 DOM）。
