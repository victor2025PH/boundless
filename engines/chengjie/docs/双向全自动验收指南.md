# 双向全自动验收指南（两个自家账号互聊测试 SOP）

> 适用：.104/.198 内测机验收、销售 PoC 演示、任意「两个自家账号互发消息看 AI
> 自己聊」的场景。沉淀自 2026-08-07 排障（DEVLOG §98）：**双向全自动翻车几乎
> 从来不是链路坏了，而是安全闸门按设计把 AI↔AI 互聊单边掐停**——本指南教你
> 开测前把闸门摆对、翻车后一条命令定位。

## 一、开测前检查清单（5 项，缺一必翻车）

| # | 检查 | 怎么看 | 不满足的后果 |
|---|------|--------|-------------|
| 1 | 两侧会话档位都是 🚀 全自动 | 两台机各开对方会话，右上下拉框 | 单边 review/manual＝单边不回（守卫降过档会「切回去又被降」，看 #5） |
| 2 | 账号没挂 `translation` 业务线标签 | `why_no_reply` 的 account 行 | 该侧被内置封顶成人审（这是通译线账号的设计语义） |
| 3 | 账号接入 >72h，或开演练豁免 | `why_no_reply`（cap_warmup）| 新号预热窗内全部进人审，**界面不提示**（旧版）/胶囊提示（§98 后） |
| 4 | System-Z 架构（打包默认）要 `inbox.l2_autosend.deliver: true` | overlay | 出厂示例默认 false＝草稿只标记**不真发** |
| 5 | 测试号用户名/昵称别带 AI/客服/助手/bot | 账号资料 | 疑似分 +0.2，叠加索取话术易被判 suspected_bot 降档 |

## 二、测试行为红线（这些动作会触发对面的守卫）

- **别连发 3 条相同文本**（复读刹车 → 对面降 review 并持久写库）；
- **别做 <3 秒的机械同文互 ping**（秒回×同文熔断，2 次即降档）；
- 单会话每日自动回复 **40 轮预算**：触顶转人审，收件箱横幅「今日继续自动
  回复」可当日救济，跨日自动恢复；
- 两个 AI 互相索取照片/语音属正常人设行为，但会推高对面的疑似分——长测
  建议直接用演练模式（下一节）。

## 三、演练模式（推荐：受控放行，不改守卫全局配置）

`config.local.yaml` overlay（热重载 ~30s 生效，`inbox.duplex_drill` 模块需
实例已装载 2026-08-07 governance 批次）：

```yaml
inbox:
  duplex_drill:
    enabled: true
    pairs:
      - ["<账号A_id>", "<账号B_id>"]   # 白名单对（无序匹配）
    max_rounds: 20        # 单会话/日硬顶，到点自动停，跨日复位（绝对上限 200）
    exempt_guard: true    # 豁免复读/秒回/预算/Tier0 判定
    exempt_caps: true     # 豁免预热/业务线/平台封顶
```

语义边界：只对白名单对生效；**坐席手动切 manual 仍最高**（人的明示决定
不豁免）；硬顶不可关（防无限互聊烧 token）。

## 四、验收与排障工具（都是只读，零凭据）

```bash
# 对级验收：跑起来没有、几轮、延迟、风险（exit 0=通过）
python tools/duplex_report.py --a <账号A> --b <账号B> --hours 24

# 单侧排障：这个会话为什么没自动回（逐层闸门判词）
python tools/why_no_reply.py --platform telegram --account <不回的账号> --chat <对方>
# 异机：都支持 --data-root D:\chengjie-instances\<实例>\data 与 --json
```

判读 `duplex_report`：

- ✅ `duplex_alive` 且无 ⛔ → 验收通过（判词里带往返轮次与 p50 延迟，可截图交付）；
- ⛔ `<账号>_silent` → 单边哑火，按提示对该侧跑 `why_no_reply`；
- ⛔ `<账号>_cap_*` / `<账号>_mode` → 档位/封顶问题，对照第一节清单处理；
- ⚠️ `*_pending` → 半哑火（最后一段入站悬置超 15 分钟）：先想拟人延迟
  （30-60s 属正常）、班表、预算，再查降档；
- ⚠️ `*_repeat_risk` / `*_echo_risk` → 内容层风险：AI 回复雷同查
  `reply_variety`，人工测试改掉复读习惯。

## 五、常见误判速查

| 现象 | 真相 |
|------|------|
| 「切了全自动没反应」 | 下拉框是基础档位；实际档位可能被预热/业务线/平台封顶（§98 后档位旁有琥珀胶囊说明+剩余时间） |
| 「昨天还能聊今天不行」 | 日预算跨日复位、守卫降档持久化——看会话档位是否被写成 review/manual（`source` 列/胶囊能看到是谁降的） |
| 「等了半分钟没回=坏了」 | 投递前拟人延迟 30-60s 是刻意的（deliver_delay）；分条回复条间还有打字节奏 |
| 「AI 拟稿了但没发」 | 该会话有效档位是人审——去待审队列点发送，或解除封顶 |

—— 维护：本指南对应 DEVLOG §98/§99 批次；工具与配置键变更时同步更新。
