# 信用查 — 全部免费 · 功能与专业版面方案

> 产品定位：**全部免费**，不设任何收费或次数限制；重点做**更多功能**与**更专业版面**，提升可信度与使用体验。

---

## 一、全部免费说明

- **查询**：不设每日次数上限，用户可随时查询。
- **报告内容**：被查用户信息、风险等级、信用分、综合建议、标签、提示、详细信息、数据说明等，**全部免费展示**。
- **邀请链接、我的信用、举报、帮助、管理统计**：均免费使用。
- 不再设计或实现任何付费功能、额度、订单、支付相关逻辑。

---

## 二、更专业的版面（报告结构）

### 2.1 版面原则

- **分层清晰**：第一屏给结论，第二屏给关键指标与建议，第三屏给详情与数据说明。
- **区块有标题**：每个区块用统一图标+标题（如 👤 被查用户、📊 信用结论、📋 详细信息、📌 数据说明），便于扫读。
- **专业感**：报告头部增加「报告编号」「生成时间」，便于存证与引用；文末保留免责与数据说明。

### 2.2 报告结构（自上而下）

| 顺序 | 区块 | 内容 |
|------|------|------|
| 0 | **报告头** | 报告编号（短号）、生成时间（如 2026-02-16 18:30） |
| 1 | **👤 被查用户** | 用户ID、用户名、用户名称（有则显示）、是否 Premium |
| 2 | **📊 信用结论** | 风险等级、信用分、提示；若黑名单则醒目提示 |
| 3 | **📋 综合建议** | 综合建议文案 + 风险依据说明（一句） |
| 4 | **🏷 标签** | 新账号、有举报、黑名单、会员等标签 |
| 5 | **📋 详细信息** | 首次记录、举报明细、黑名单、被查询次数、数据更新于、最近活动（本系统） |
| 6 | **📌 数据说明** | 数据来源与免责（Telegram 不提供的内容、本系统范围） |
| 7 | **结尾** | 「仅供参考，交易需谨慎」 |

### 2.3 实现要点

- 报告编号：可用「日期 + 短随机」或「时间戳后几位」，保证单次报告唯一即可，如 `R202602161830-A1`。
- 生成时间：取当前 UTC 或本地时间，格式统一为 `YYYY-MM-DD HH:MM`。
- 区块标题统一用 i18n，中/英/塔加洛语一致。

## 三、更多功能（免费）

### 3.1 已具备功能（保持）

- 多种方式查询：数字 ID、@用户名、钱包地址、转发消息、邀请链接。
- 完整报告：身份、风险、分数、建议、标签、详情、数据说明。
- 邀请链接：对方点开发消息后，报告发回查询方。
- 我的信用：查看自己在系统中的信用报告。
- 举报与纠错：对某用户发起举报；误报反馈入口。
- 帮助与管理员统计。

### 3.2 可增强或新增（免费）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **报告头** | 报告编号 + 生成时间，提升专业感与可引用性 | 高（本次落实） |
| **版面分区与标题** | 明确「被查用户」「信用结论」「综合建议」「标签」「详细信息」「数据说明」分区标题 | 高（本次落实） |
| **本系统活动时间线** | 免费展示「该用户在本系统内活动」时间线（被查、邀请打开等），便于判断暴露度 | 中（需后端记录活动事件） |
| **我的信用 · 谁查过我** | 在「我的信用」中展示最近何人何时查过我（脱敏或匿名），增强透明与安全感 | 中（需后端记录查询人） |
| **报告一键复制/分享** | Bot 内提供「复制报告」或「分享链接」按钮，便于用户存证或转发 | 中 |
| **帮助/FAQ 结构化** | 帮助内容分条展示（查询方式、邀请流程、数据说明、举报与纠错），可带折叠或分页 | 低 |
| **多语言覆盖** | 确保所有新区块与文案有中/英/塔加洛语 | 持续 |

### 3.3 明确不做的内容

- 任何付费、次数限制、额度、订单、支付、订阅。
- 承诺「Telegram 注册时间」「实时在线」等 Bot API 无法提供的能力。

---

## 四、文案与合规（不变）

- 报告与建议处保留「仅供参考」「非官方征信」类表述。
- 数据说明区块明确：Telegram 不向机器人提供注册时间、最后在线、群/好友数；以上仅为本系统数据。
- 结尾保留「仅供参考，交易需谨慎」。

---

## 五、实施顺序建议

1. **立即**：报告头（报告编号 + 生成时间）+ 版面分区与标题（format_result 与 i18n）。
2. **后续**：本系统活动时间线（需 user_activity_events 表与接口）；我的信用·谁查过我（需记录查询人）；报告复制/分享、帮助结构化等按需排期。

本文档替代此前「收费功能」「计费接口」相关产品描述；功能与版面以本文档为准。
