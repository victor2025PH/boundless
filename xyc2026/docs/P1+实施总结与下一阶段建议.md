# P1+ 实施总结与下一阶段建议

## 一、实施范围

基于《管理后台实施总结与下一阶段建议》中 P1+ 全部 5 项任务，外加额外优化。

## 二、已完成功能清单

### 2.1 后端扩展（3 项 API 变更）

| 变更 | 文件 | 说明 |
|------|------|------|
| **stats 新增 feedback_pending** | `services.py` + `api/schemas.py` | `admin_stats` 函数新增 Feedback pending 计数；`AdminStatsResponse` 新增 `feedback_pending: int` 字段 |
| **reports 支持 reporter_tg_id 筛选** | `services.py` + `api/main.py` | `get_admin_reports` 新增 `reporter_tg_id` 参数；`GET /v1/admin/reports` 新增 `reporter_tg_id` Query |
| **批量审核接口** | `services.py` + `api/schemas.py` + `api/main.py` | 新增 `batch_update_report_status` 函数；新增 `POST /v1/admin/reports/batch` 端点，支持一次性最多 100 条批量核实/驳回 |

### 2.2 全局搜索 + 用户查找页

- **顶栏搜索框**：支持输入 TG ID 或用户名，回车跳转 `/lookup` 页面
- **快捷键 `/`**：全局按 `/` 聚焦搜索框
- **用户查找页面**（`/lookup`）：
  - 支持按数字 TG ID 或用户名查询
  - 展示完整用户画像：风险等级（色块）、信用分、判定、黑名单状态、举报数（待核实/已核实）、交易成功率、标签、风险提示
  - 双列卡片布局，信息密度高

### 2.3 批量审核

- 举报列表新增 **多选 checkbox 列**
- **全选按钮**：一键勾选当前页所有待处理举报
- 勾选后顶部显示 **批量操作栏**：「已选 N 条」+ 「批量核实」「批量驳回」「取消选择」
- 后端单次最多 100 条，逐条调用 `update_report_status` 保证每条的 ReporterStats 和 User.report_count 一致性

### 2.4 申诉管理徽标数

- 后端 `admin_stats` 新增 `feedback_pending` 计数
- 前端侧导航「申诉管理」旁显示待处理数量红色徽标
- 总览工作台新增「待处理申诉」待办卡片（橙色高亮 + 立即处理链接）

### 2.5 举报人穿透

- 举报人列表每行可 **点击展开**，展示该举报人的最近 20 条举报记录
- 子表格展示：ID、被举报人、分类、理由（截断）、状态、时间
- 调用 `GET /v1/admin/reports?reporter_tg_id=xxx` 获取数据
- 收起/展开带 ▼/▲ 图标指示

### 2.6 数据导出

- **举报管理**：顶部「📥 导出」按钮，导出当前页举报为 CSV
- **申诉管理**：顶部「📥 导出 CSV」按钮
- **交易列表**：顶部「📥 导出 CSV」按钮
- CSV 生成完全在前端（含 BOM 头，Excel 中文兼容），不依赖后端

### 2.7 额外优化

| 优化项 | 说明 |
|--------|------|
| **骨架屏加载** | 举报列表加载时展示 5 行骨架动画，替代纯文字「加载中」 |
| **CSS 骨架动画** | 新增 `.skeleton-row` `.skeleton-shimmer` 带渐变闪烁动画 |
| **快捷键扩展** | `G+S` 跳转用户查找页；`/` 聚焦搜索框 |
| **侧导航新增入口** | 用户查找（🔍）作为独立导航项 |
| **待办卡片增至 3 张** | 待处理举报 + 待处理申诉 + 待确认交易，三项待办一目了然 |

## 三、实施过程中的优化（超出原方案）

| 原方案 | 实际优化 |
|--------|----------|
| 搜索框在顶栏 | 搜索框 + 独立用户查找页面双模式；查找页展示完整画像（基本信息 + 举报 + 交易 + 标签 + 提示） |
| 批量操作需多选 | 增加全选 checkbox（仅选 pending 状态），清空选择按钮 |
| CSV 导出仅举报/交易 | **申诉管理也加了导出**，三个列表统一具备导出能力 |
| 举报人穿透需后端新接口 | **复用现有 reports 接口**，仅添加 `reporter_tg_id` Query 参数，零新接口 |
| 批量接口设计 | 限制单次最多 100 条防滥用；逐条调用 `update_report_status` 保证 ReporterStats 和 User.report_count 的事务一致性 |
| 待办卡片 2 张 | 增至 **3 张**（举报 + 申诉 + 交易），管理员首屏即覆盖全部待办 |
| 无骨架屏 | 举报列表加载时展示骨架动画，提升感知速度 |
