# TrustCheck V2.0 功能测试清单

> 开发已完成阶段：第 1～4 阶段（4.1、4.2 已完成；4.3、4.4 为可选未做）。  
> 用户端 UI = **Telegram Bot**（命令、主菜单、结果卡 Inline 按钮）；管理端 = **REST API**（需自行对接网页或 Postman 等验证）。

---

## 一、测试前准备

1. **环境**
   - 确保 `.env` 配置正确：`DATABASE_URL`、`BOT_TOKEN`、`API_BASE_URL`（Bot 调 API）、`API_INTERNAL_KEY`（管理接口 + Bot 拉取提醒）。
   - 已执行迁移：`python migrate_add_columns.py`（PG 或 SQLite）。
   - 启动 API：`python run_api.py`（或 uvicorn）；启动 Bot：`python -m bot.main`。

2. **账号**
   - 至少 2 个 Telegram 账号（A、B），用于：查人、被查、举报、交易确认、订阅、被查通知。
   - 若测群扫描：一个群组，且 Bot 在群内、你为管理员。

---

## 二、用户端 Bot UI 与功能验证

### 2.1 查询与报告展示（第 1 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 发送 `/check 对方ID` 或点「立即查询」后输入 ID | 主菜单 / 输入框 | 进入查询 |
| 2 | 查看返回的报告长文 | 消息正文 | 有「信用结论」「综合建议」「标签」「详细信息」；若有举报/风险数据，应出现「举报分类（已核实）」「近7天举报」「近30天举报」「风险来源占比」 |
| 3 | 查看结果卡下方按钮 | Inline 按钮 | 有「举报/纠错」「请求对方确认交易」「有变化时提醒我」「上下线提醒」「举报动态」「钱包变动」「上报在线/离线」等 |

**验证点**：报告正文中「举报分类」「风险来源占比」等区块在有数据时展示；无数据时不报错、可不展示或为 0。

---

### 2.2 举报流程与分类（第 1 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 在某人查询结果卡点击「举报/纠错」 | Inline：举报/纠错 | 进入举报流程 |
| 2 | 选择举报类型 | 4 个 Inline：诈骗 / 跑单/不发货 / 失联 / 其他 | 选一项后进入下一步 |
| 3 | 输入举报原因（可带截图链接等） | 文本消息 | 提交后提示「已收到举报，我们会核实」 |

**验证点**：必须先选类型再填原因；提交后 API 收到 `category`（scam/run_order/lost_contact/other）。

---

### 2.3 交易确认（第 2 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 在**非本人**查询结果卡点击「请求对方确认交易」 | Inline：请求对方确认交易 | 提示输入金额 |
| 2 | 输入金额（如 `100` 或 `100 USDT`），可选第二行备注 | 文本 | 提示「已发送确认请求…」；**对方**收到一条私信「对方请求你确认一笔交易」+ [同意] [拒绝] |
| 3 | 对方点击 [同意] 或 [拒绝] | 对方收到的消息下 Inline | 原消息变为「你已同意/拒绝这笔交易」 |
| 4 | 主菜单点击「待我确认」或发送 `/pending` | 主菜单 / 命令 | 列出待确认交易，每条有 [同意] [拒绝]；若无则「暂无待确认」 |
| 5 | 再次对**本人**点「请求对方确认交易」 | 同上 | 提示「不能向自己请求确认」 |

**验证点**：自刷被拒；同对多笔 pending 达上限后再发起会提示「待确认请求过多」；报告/我的信用中若有交易数据，应出现「交易确认」区块（成功笔数/成功率/累计金额）。

---

### 2.4 被查通知与开关（第 3 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 账号 A 查账号 B（B 已与 Bot 有过交互） | 查询流程 | 查完后 B 在约 30s 内收到一条「有人查了你的信用。使用「我的信用」查看报告」 |
| 2 | B 打开「我的信用」 | 主菜单「我的信用」 | 报告下方有「被查通知：开」+ [关闭] |
| 3 | B 点击 [关闭] | Inline | 提示「已关闭被查通知」；按钮变为「被查通知：关」+ [开启] |
| 4 | 再次用 A 查 B | 查询 | B **不再**收到被查通知（因已关） |
| 5 | B 再点 [开启] | Inline | 恢复开启，之后被查会再收通知 |

**验证点**：仅当 B 开启通知且 B 在 users 表存在时才会入队；Bot worker 轮询到后发私信并 mark_sent。

### 2.5 信用卡片（第 3 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 发送 `/sharecard` 或主菜单「分享卡片」 | 命令 / 我的信用内 Inline「分享卡片」 | 收到简短卡片：风险、信用分、可选「交易确认」一行、若黑名单则提示 |
| 2 | 在「我的信用」页点击「分享卡片」 | Inline | 同上 |

**验证点**：内容与当前用户 risk/score/tx 一致，无报错。

### 2.6 群扫描（第 3 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 在**群组**内发送 `/scan_group`（且你为管理员） | 群内命令 | 回复「群扫描已记录。（每群每日限 1 次。）」 |
| 2 | 同一群再次 `/scan_group` | 同上 | 回复「本群今日已扫描过，请明日再试。」 |
| 3 | 在私聊中发 `/scan_group` | 私聊 | 提示「请在群组内使用 /scan_group（需为管理员）。」 |
| 4 | 非管理员在群内发 `/scan_group` | 群内 | 提示「仅群管理员可使用 /scan_group。」 |

**验证点**：仅群组+管理员可成功；限频按群按日。

### 2.7 订阅类型（第 4 阶段）

| 步骤 | 操作 | UI 位置 | 预期 |
|------|------|---------|------|
| 1 | 在某人查询结果卡点击「举报动态」或「钱包变动」 | Inline | 提示已订阅举报动态/钱包变动 |

## 三、管理后台 API 验证（无内置 UI）

管理端为 **REST API**，需用 Postman/curl 或对接自建网页。请求头需带：`Authorization: Bearer <API_INTERNAL_KEY>`。

| 接口 | 方法 | 说明 | 验证要点 |
|------|------|------|----------|
| 运营统计 | GET `/v1/admin/stats` | 今日查询、总用户、黑名单、待处理举报、**待确认交易数** | 返回含 `transactions_pending` |
| 举报人列表 | GET `/v1/admin/reporters?limit=100` | 举报人信誉：举报数、已核实数、最后举报时间 | 按举报数降序 |
| 交易列表 | GET `/v1/admin/transactions?status=pending` | 交易列表，可筛 status | 与 Bot 发起的交易一致 |
| 风险趋势 | GET `/v1/admin/stats/risk_trend?days=7` | 按日风险分布（low/medium/high/extreme） | 有 query_log 时应有数据 |
| 申诉列表 | GET `/v1/admin/feedback` | 申诉列表 | 已有 |
| 黑名单 | POST `/v1/admin/blacklist` | 加黑 | 已有 |

## 五、快速自检顺序建议

1. **Bot 启动**：`/start` → 有欢迎语和主菜单。  
2. **查询**：`/check 自己ID` → 有报告且下方有举报、交易确认、订阅等按钮。  
3. **举报**：点举报 → 先选类型再填原因 → 收到「已收到举报」。  
4. **交易**：用 A 对 B 点「请求对方确认交易」→ 输入金额 → B 收到 [同意][拒绝] → B 点同意 → 再查 B 可见「交易确认」区块（有笔数/成功率）。  
5. **被查通知**：A 查 B → B 收到「有人查了你的信用」；B 在「我的信用」关掉开关后再用 A 查 B，B 不再收到。  
6. **信用卡片**：`/sharecard` 或「我的信用」→「分享卡片」→ 有简短卡片。  
7. **群扫描**：在群内以管理员身份 `/scan_group` → 成功一次，再发一次提示今日已扫。  
8. **订阅**：对某人点「举报动态」→「我的订阅」中有该条；他人举报该人后，你收到举报动态推送。  
9. **管理 API**：用 Postman 带 Admin Key 调 `GET /v1/admin/stats`、`GET /v1/admin/reporters`、`GET /v1/admin/transactions`、`GET /v1/admin/stats/risk_trend`，返回 200 且结构正确。

完成以上即覆盖当前已开发功能的 UI 展示与主流程，可按需再补边界与异常用例。
