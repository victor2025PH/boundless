# 管理后台 — 实施总结与下一阶段建议

## 一、实施范围

基于《网站管理后台-优化方案V2》的 P0 全部内容 + P1 部分能力，已完成并构建通过。

## 二、已完成功能清单

### 2.1 工程基础
| 项目 | 实现 |
|------|------|
| 框架 | Vite + React 19 + TypeScript |
| 路由 | react-router-dom v7（SPA 模式） |
| 图表 | recharts（堆叠面积图/折线图） |
| 构建 | chunk 分包（react / recharts / 业务），gzip 总计 ~190KB |
| 代理 | Vite dev proxy → 后端 8001 端口；生产可同域 Nginx 反代 |
| CORS | 后端已添加 CORSMiddleware（expose Retry-After） |

### 2.2 登录页
- 单输入框密钥登录，以 GET /v1/admin/stats 校验
- **失败延迟 2 秒**防暴力枚举
- **连续 5 次失败后锁定 60 秒**，前端倒计时展示
- 不展示产品名，仅「管理面板」
- 密钥仅存 sessionStorage

### 2.3 主布局
- **侧导航**：8 个页面入口，举报管理旁显示待处理徽标数（红色圆点）
- **顶栏**：数据刷新时间 + 手动刷新按钮 + 暗色模式切换
- **30 秒自动轮询** stats，导航徽标数自动更新
- **全局快捷键**：G+D/R/F/B/P/T/K/A 跳转各页面
- **Toast 系统**：成功绿/失败红/信息蓝，4 秒自动消失
- **暗色模式**：完整暗色变量，保存至 localStorage

### 2.4 总览工作台
- **待办摘要**：「待处理举报 N 条」「待确认交易 N 条」两张突出卡片，有待办时橙色高亮 + 「立即处理 →」按钮；已清完时绿色「全部处理完毕」
- **运营指标**：6 张卡片（今日查询、总用户、黑名单、绑定地址、开放流水用户、流水快照）
- **迷你风险趋势图**：嵌入 7 天堆叠面积图 + 「查看详细趋势 →」链接

### 2.5 举报管理（核心决策工作台）
- **主从布局**：左侧 60% 举报列表（状态 Tab 筛选 + 分页），右侧 40% 决策面板
- **决策面板内容**：
  - 举报详情全字段（ID、双方 tg_id、分类、理由全文、证据 JSON、状态、时间）
  - **被举报人画像**（调用 /v1/check，5 分钟内存缓存）：风险等级色块 + 信用分 + 判定 + 举报数 + 黑名单状态 + 交易成功率 + 标签
  - **举报人信誉**（从 reporters 缓存读取）：历史举报数、核实数、核实率 % + 进度条色块
  - **操作按钮**：「设为已核实」「设为驳回」+ 提示文案
- **5 秒可撤回安全网**：点击操作后进入倒计时，5 秒内可撤回；超时后自动发送请求
- 操作成功后自动刷新列表 + Toast 提示

### 2.6 申诉管理
- 同举报管理的主从布局模式
- 决策面板含：申诉详情 + 相关用户画像 + 操作按钮 + 5 秒撤回

### 2.7 黑名单管理
- **左侧表单**：tg_id（必填数字校验）+ reason + source 下拉
- **加黑前预览**：输入 tg_id 后先调 /v1/check 展示用户画像，确认无误再加黑
- **本地操作记录**：sessionStorage 维护本次会话加黑记录，防止重复操作并可追溯
- 重复加黑 tg_id 时弹出确认提示

### 2.8 举报人列表（P1 提前实现）
- 表格：举报人 tg_id、举报总数、已核实、核实率、最后举报时间
- **核实率进度条**：绿 ≥80% / 黄 50-80% / 红 <50%

### 2.9 交易列表（P1 提前实现）
- Tab 筛选（全部/待确认/已确认/已拒绝）
- **大额高亮**：金额 ≥1000 橙色加粗

### 2.10 风险趋势（P1 提前实现）
- 时间选择器：7/14/30/90 天
- **双图表模式**：堆叠面积图（默认）/ 折线图 可切换
- **汇总统计**：总查询数 + 高风险占比 %（占比高时红色）

### 2.11 待发提醒（P2 提前实现）
- 只读表格：ID、订阅者、目标、事件类型、语言、创建时间

### 2.12 会话安全
- **30 分钟无操作自动登出**（每次点击/键入重置活跃时间戳）
- 403 响应统一清除密钥并跳转登录
- 429 响应解析 Retry-After 展示在 Toast

### 2.13 视觉系统
- **统一颜色编码**：🟢低/🟡中/🟠高/🔴极高，贯穿所有风险等级和状态标签
- **分类图标**：🚨诈骗 / 📦跑单 / 📵失联 / 📝其他
- **暗色模式**：完整变量覆盖

## 三、实施过程中的优化（超出原方案）

| 优化点 | 原方案 | 实际实现 |
|--------|--------|----------|
| **P1/P2 功能前置** | P1（举报人/交易/风险趋势）和 P2（待发提醒）在后续迭代 | 全部在首版实现，8 个页面完整交付 |
| **后端 CORS** | 方案未涉及 | 添加了 CORSMiddleware + expose Retry-After，开发/生产环境均可用 |
| **Vite 开发代理** | 方案未涉及 | 配置 /v1 /v2 代理到 8001，开发无需 CORS 也能工作 |
| **Chunk 分包** | 方案要求 ≤500KB gzip | 三分包（react 17KB + recharts 105KB + 业务 67KB），业务代码仅 67KB |
| **举报人缓存策略** | 决策面板需调 reporters | 首次加载缓存 5 分钟，决策面板读缓存零延迟 |
| **用户画像缓存** | 方案提及 5 分钟 | 按 tg_id 独立缓存，同一用户在多条举报间切换时零重复请求 |
| **暗色模式保存** | 方案要求暗色 | 主题偏好存 localStorage，跨会话保留 |
| **防重复加黑** | 方案提及本地记录 | 不仅有记录，重复操作时弹出确认二次询问 |
| **风险趋势双图表** | 方案提及切换 | 堆叠面积/折线一键切换 + 汇总统计卡片 |

## 四、项目结构

```
admin/
├── src/
│   ├── api/          # 请求层：client + admin + check
│   ├── components/   # 通用组件：Badge/Toast/UndoAction/UserProfile/ReporterBrief
│   ├── hooks/        # useAuth / useToast
│   ├── layout/       # 主布局 + 侧导航
│   ├── pages/        # 8 个页面组件
│   ├── context.tsx   # App 全局 Context
│   ├── types.ts      # TypeScript 类型（对齐 API schema）
│   ├── styles.css    # 完整样式系统 + 暗色模式
│   └── main.tsx      # 路由入口
├── .env.example      # 环境变量示例
├── vite.config.ts    # Vite 配置（代理 + chunk 分包）
└── tsconfig.json     # TS 配置
```

## 五、使用方式

### 开发环境
```bash
cd admin
cp .env.example .env    # 配置 API 地址
npm install
npm run dev             # 访问 http://localhost:3000
```

### 生产部署
```bash
cd admin
npm run build           # 产物在 dist/
# 将 dist/ 部署到 Nginx 或与 API 同域
```

### Nginx 配置示例
```nginx
server {
    listen 80;
    location /admin/ {
        alias /path/to/admin/dist/;
        try_files $uri $uri/ /admin/index.html;
    }
    location /v1/ { proxy_pass http://127.0.0.1:8001; }
    location /v2/ { proxy_pass http://127.0.0.1:8001; }
}
```

## 六、下一阶段建议

| 项 | 说明 |
|----|------|
| **搜索功能** | 顶栏添加全局搜索框，支持按 tg_id 快速查找用户（调 /v1/check） |
