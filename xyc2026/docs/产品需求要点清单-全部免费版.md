# 信用查 — 产品需求要点清单（全部免费版）

> 产品定位：**全部免费**，无任何收费或次数限制。本清单仅包含功能与专业版面要求，供产品与开发对齐使用。

---

## 一、产品原则

- **全部免费**：查询、报告、邀请、我的信用、举报、帮助等均免费，不设次数上限与付费功能。
- **专业版面**：报告分层清晰、区块有标题、带报告编号与生成时间，便于阅读与存证。
- **更多功能**：在免费前提下逐步增加活动时间线、谁查过我、报告分享等，见下文清单。

---

## 二、功能范围

| 功能 | 说明 | 状态 |
|------|------|------|
| 查询 | 支持 数字ID / @用户名 / 钱包 / 转发消息 / 邀请链接；返回完整信用报告 | 已有 |
| 报告内容 | 被查用户、风险等级、信用分、综合建议、标签、提示、详细信息、数据说明 | 已有 |
| 报告头 | 报告编号、生成时间 | 本次落实 |
| 版面分区 | 👤 被查用户、📊 信用结论、📋 综合建议、🏷 标签、📋 详细信息、📌 数据说明 | 本次落实 |
| 邀请链接 | 生成链接，对方点开发消息后报告发回查询方 | 已有 |
| 我的信用 | 用户查看自己在系统中的信用报告 | 已有 |
| 举报与纠错 | 对某用户举报；误报反馈入口 | 已有 |
| 帮助 | 使用说明与入口 | 已有 |
| 管理员统计 | /stats 等 | 已有 |
| 本系统活动时间线 | 免费展示被查人在本系统内活动时间线 | 后续 |
| 我的信用·谁查过我 | 展示最近谁在何时查过我（脱敏） | 后续 |
| 报告复制/分享 | 一键复制或分享报告 | 后续 |

---

## 三、报告版面要求（专业版）

- **报告头**：报告编号（如 R202602161830-A1）、生成时间（YYYY-MM-DD HH:MM）。
- **分区标题**：每块有图标+标题，顺序为：被查用户 → 信用结论 → 综合建议 → 标签 → 详细信息 → 数据说明 → 结尾免责。
- **文案与合规**：数据说明与结尾保留「仅供参考」、Telegram 不提供项说明；不出现「官方征信」「实时在线」「注册时间」等无法实现的说法。

---

## 四、验收清单（可勾选）

- [ ] 所有功能免费，无次数限制、无付费入口
- [ ] 报告带报告编号与生成时间
- [ ] 报告分区清晰，每区有统一标题（含 i18n）
- [ ] 被查用户、信用结论、综合建议、标签、详细信息、数据说明、免责 顺序与内容正确
- [ ] 多语言（中/英/塔加洛语）覆盖新区块与文案
- [ ] 邀请、我的信用、举报、帮助、管理功能正常可用

---

## 五、明确不做的内容

- 任何收费、付费功能、次数包、月卡、订阅、订单、支付、额度相关设计与实现。
- 承诺 Telegram 注册时间、实时在线等 Bot API 无法提供的能力。
