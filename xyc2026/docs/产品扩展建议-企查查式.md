# 信用查 — 产品扩展建议（企查查 / 查询类产品参考）

## 一、已实现（本次新增）

| 维度 | 说明 |
|------|------|
| **综合建议** | 根据风险等级 + 黑名单给出结论：极高风险避免交易 / 较高建议谨慎 / 一定风险核实后决策 / 暂无重大风险 |
| **标签** | 新账号、有举报、黑名单、会员、商户等，一眼识别特征 |
| **举报明细** | 共 N 次（待核实 M，已核实 K），区分状态 |
| **被查询次数** | 本系统内该用户被查次数，反映“热度/被关注度” |
| **数据更新于** | 最后更新时间，增强可信感 |

---

## 二、可继续扩展（本系统数据即可）

1. **关联钱包 / 多号关联**  
   - 已有 `wallet_entity_graph`：同一钱包关联多个 TG 号。  
   - 展示：**关联钱包数**、**该钱包还关联以下账号**（脱敏或仅数量），便于识别“换号不换地址”。

2. **举报时间线（简化）**  
   - 按月份汇总：如「2024-01 被举报 1 次，2024-03 被举报 2 次」。  
   - 需在 reports 表按 `target_tg_id` + 月份统计。

3. **风险趋势**  
   - 若后续存历史评分（如每日/每周快照），可展示：**近 30 日信用分变化**、**风险等级是否上升**。

4. **“详细报告”入口**  
   - 结果页底部增加 **「查看完整报告」**，跳转 Mini App 或静态页：  
   - 包含上述所有维度 + 免责声明 + 可选导出 PDF（后期）。

5. **数据来源说明**  
   - 在结果中固定一行：**数据来源：用户举报 + 本系统统计，仅供参考。**  
   - 与隐私说明区分：一条强调来源，一条强调 Telegram 限制。

---

## 三、需外部数据或合规后才能做的

| 想法 | 说明 |
|------|------|
| Telegram 注册时间 / 最后在线 | Telegram 不向机器人提供，无法实现。 |
| 群数量 / 好友数 | 同上，接口无此数据。 |
| 链上履约记录 | 需对接链上索引（TRC20/TON 等），并做合规与隐私处理。 |
| 第三方黑名单库 | 可接行业/社区黑名单 API，需授权与数据合规。 |
| 实名/人脸 | 涉及 KYC，需单独合规与产品设计。 |

---

## 四、企查查式“报告感”可再加强的点

- **分块标题统一**：风险概览 / 举报与维权 / 关联信息 / 综合建议 / 数据说明。  
- **一句话摘要**：在结果最上方增加一句「该用户当前为高风险，建议避免交易」类结论。  
- **数字突出**：信用分、被举报次数、被查询次数用加粗或 emoji 强化。  
- **后续可做**：Mini App 内雷达图、趋势小图、一页式「信用报告」排版。
