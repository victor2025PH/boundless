# 信用查 — 更实用的用户需求优化方案

> 从**用户真实场景**出发，做「让人感觉有需求」的功能与体验优化；全部免费，不涉及收费。

---

## 一、用户是谁、在什么场景用？

| 角色 | 典型场景 | 最在乎什么 |
|------|----------|------------|
| **准备交易/合作的人** | 大额转账、OTC、陌生人合作前 | 这人能不能信？看完报告**下一步该怎么做**？能不能把报告发给对方对质？ |
| **被查的人** | 对方要我先证明信用 | 不想被「暗查」；希望**主动出示我的报告**建立信任；被误报时能**申诉/澄清**。 |
| **商户/中介** | 每天查很多人 | **少输入、快查**；能**再看上次查过谁**；某人风险变了能**提醒**。 |
| **加密货币用户** | 看钱包或 TG 靠不靠谱 | **同一钱包是否绑过多个 TG**（换号不换地址）；链上/钱包维度的风险提示。 |

---

## 二、按「感知有用」排行的功能优化

### 2.1 高感知 — 建议优先做

| 功能 | 用户需求（一句话） | 做法要点 | 实现难度 |
|------|--------------------|----------|----------|
| **下一步建议 + 一键操作** | 「看完报告我不知道该干嘛」 | 在综合建议下方增加 1～2 条**可执行建议**，并配按钮。例如：风险高 →「建议：暂不交易或要求对方出示报告」+ 按钮「请对方出示报告」；风险中 →「建议：小额可试，大额再核实」。按钮可跳转「获取邀请链接」或「如何让对方出示报告」说明。 | 低：文案 + 按钮逻辑 |
| **我主动出示我的报告** | 「对方不信我，我想主动给他看」 | 新增入口「出示我的报告」：生成**一次性链接**或**报告卡片**，用户把链接/卡片发给对方，对方点开即看到**当前用户本人的最新报告**（只读、带报告编号与生成时间）。对方无需查你，你主动透明，信任感强。 | 中：一次性链接或短链 + 展示页 |
| **钱包关联多账号提示** | 「这人换过号吗？同一钱包还绑了谁？」 | 查 TG 时：若该 TG 在 `wallet_entity_graph` 有关联钱包，报告里增加一块「**关联钱包**：xxx（曾绑定）」；查钱包时：若该钱包关联多个 TG，报告里增加「**该钱包还关联以下账号**：ID1、ID2…（换号不换地址，请留意）」。加密货币场景刚需。 | 中：API 返回关联钱包/多 TG，报告区块展示 |
| **谁查过我 + 最近被查次数** | 「我的报告被谁看过？最近被查了几次？」 | 在「我的信用」中增加：**最近 7 天被查询次数**、**最近一次被查时间**（可选：脱敏展示「某用户」或「匿名」）。不一定要展示具体谁查的，但「被查了多少次、最近一次何时」就能让用户感知透明。 | 中：记录查询人+被查人+时间；我的信用接口返回统计 |
| **误报/申诉进度** | 「我申诉了，有没有被处理？」 | 举报与纠错入口已有；增加「**我的申诉**」：用户可看到自己发起的纠错/误报反馈的**状态**（待处理/已处理/已驳回）。在「我的信用」或帮助里提供入口。 | 中：Feedback 表有 status；列表/状态查询接口 + Bot 展示 |

### 2.2 中感知 — 有资源再做

| 功能 | 用户需求（一句话） | 做法要点 | 实现难度 |
|------|--------------------|----------|----------|
| **报告转发/再次发送** | 「我想把报告发给对方或自己留底」 | 结果页按钮「**转发报告**」：把当前报告正文**再发一条**给用户，用户可转发到任意聊天或保存。无需复制粘贴，体验好。 | 低：Bot 按钮 + 重发同内容 |
| **最近查过的人（历史）** | 「我昨天查过那人，不想再输入一遍」 | 「**最近查询**」：展示用户最近查过的 N 个对象（如 5 个，仅 ID/用户名/钱包缩写），点击可**一键再查**。商户/高频用户刚需。 | 中：记录查询人+被查对象+时间；列表接口 + Bot 列表或按钮 |
| **本系统活动时间线** | 「这人最近在我们平台有没有动静？」 | 报告内或单独入口展示：该用户在本系统内**被查、邀请打开**等活动的**时间线**（按日聚合）。帮助判断「是否活跃、是否被多人关注」。 | 中：活动事件表 + 写入 + 时间线接口 |
| **风险变化提醒（订阅）** | 「我查过的人要是后来被举报/拉黑，想被提醒」 | 用户对某 ID 订阅「**有变化时提醒我**」；当该用户新增举报/被拉黑时，给订阅者发一条 Bot 消息。需订阅表 + 定时或事件触发。 | 高：订阅表、触发逻辑、推送 |

### 2.3 体验增强（不单独算功能，但很实用）

| 项 | 说明 |
|----|------|
| **综合建议更「可执行」** | 把「风险较高，建议谨慎」改成「建议：先小额试单，或要求对方出示报告后再大额」等，让用户知道**具体下一步**。 |
| **报告头写清「用途」** | 在报告编号下方加一句：「可用于对质、存证或要求对方出示」，强化「这份报告有用」的感知。 |
| **帮助里加「对方不信我怎么办」** | 引导到「出示我的报告」或「获取邀请链接让对方自己查」，减少用户迷茫。 |
| **查询方式再简化** | 已支持输入 ID/用户名/钱包；可再在帮助和欢迎语里强调「**转发对方一条消息即可查**」，降低门槛。 |

## 三、推荐实施顺序（兼顾价值与成本）

1. **第一步（低成本、高感知）**  
   - **下一步建议 + 可执行文案**：在综合建议下增加 1～2 条「建议：…」并配 1 个按钮（如「请对方出示报告」→ 跳转出示说明或邀请链接）。  
   - **综合建议文案优化**：让 verdict 更「可执行」（见上表）。  
   - **报告头加一句「用途」**：i18n 一句「本报告可用于对质、存证或要求对方出示」。

2. **第二步（中成本、高感知）**  
   - **钱包关联多账号提示**：API 查 TG 时返回关联钱包；查钱包时返回关联多 TG；报告里新增区块展示。  
   - **报告转发**：结果页「转发报告」按钮，重发报告全文给用户。

3. **第三步（中成本、强需求）**  
   - **我主动出示我的报告**：一次性链接或短链，对方点开看当前用户最新报告。  
   - **谁查过我 + 最近被查次数**：记录查询关系，我的信用页展示「最近 7 天被查次数」「最近一次被查时间」（可脱敏）。

4. **第四步（按需）**  
   - 最近查询历史、误报申诉进度、活动时间线、风险变化提醒。

---

## 四、与现有方案的关系

- **全部免费、专业版面**：保持不变；本方案只做**功能与文案**上的「更实用」补充。  
- **不新增收费**：以上功能全部免费。  
- **可替代/合并**：若原「活动时间线」「谁查过我」与本节一致，以本节描述为准；若原「报告复制/分享」与本节的「报告转发」一致，实现「转发报告」即可。

---

## 五、一句话小结

让用户觉得「有需求」的核心是：**看完报告知道下一步做什么**、**被查的人能主动出示报告建立信任**、**钱包/多账号关联可见**、**谁查过我/申诉进度可见**。优先做「下一步建议 + 可执行文案」「钱包多账号提示」「报告转发」和「出示我的报告」，再按顺序补「谁查过我」与「最近查询」「活动时间线」等。
