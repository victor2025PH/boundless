#### ⚠ 坑 1：Cloudflare 只转发「通过认证」的邮件（2026-08-28 实测拿到原文）

直连 `route3.mx.cloudflare.net` 投递会收到：

```
550 5.7.26 Cannot forward emails that are not authenticated.
https://developers.cloudflare.com/email-routing/postmaster/
```

即**发信方必须通过 SPF / DKIM 认证**，CF 才肯转发；否则当场 550 拒收。这是它的反垃圾策略。
影响两件事：

- **用「没有正确 SPF/DKIM」的邮箱测试会必然失败**——自建邮件服务器、某些小众/企业自建邮箱、
  以及任何脚本直连投递（本文这次探测就是被这条拦下的，属预期）。
  **用 Gmail / Outlook / QQ / 163 这类主流邮箱发**，它们的认证是齐的。
- **被 550 拒掉的信，发信方一定会收到一封退信**（bounce）。所以「信到底怎么了」最快的答案
  不在 Cloudflare，而在**你用来发信的那个邮箱的收件箱**——退信正文会直接写明原因。

#### ⚠ 坑 2：只有建了规则的地址才收，其余一律 550

RCPT 探测实证：`hello@bd2026.cc` → `250 Ok`，而任意未建地址 → `550 5.1.1 Address does not exist`。
所以**发给 `support@`、`info@` 等还没建规则的地址会被直接拒**（除非把 Catch-all 打开；
它默认是 Disabled、动作为 Drop）。测试时务必确认收件人拼写与已建规则**逐字一致**。

> **⚠ 我们本域第一次测试就栽在这里**（2026-08-28）：连发两封都「没收到」，
> 最后退信写的是「系统找不到网域 **bd2026.com**」——**后缀敲成了 `.com`，我们的域是 `.cc`**。
> 这种情况邮件**根本没离开发信服务商**，所以 Cloudflare 活动日志里查不到任何记录，
> 很容易误判成「路由没配好」而去反复重配。
> **判据**：活动日志空 + 发信箱有退信 = 收件地址写错或域不存在，跟 CF 配置无关。

#### ⚠ 坑 3：用同一个 Gmail 发给自己，Gmail 会把它折叠掉

如果用 `victor2018zzz@gmail.com` 发给 `hello@bd2026.cc`，转发后又回到同一个信箱，
Gmail 会识别成「自己发的」，通常**不在收件箱另外显示**（可能只出现在「已发送」或被会话折叠）。
测试请用**另一个不同服务商**的邮箱发，或在 Gmail 搜索框用 `in:anywhere to:hello@bd2026.cc`。
