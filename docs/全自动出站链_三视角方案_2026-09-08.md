## 0. 这次暴露的是同一个功能：全自动出站链

## 1. 三个角度分别看

### 1.1 开发工程师

1. **守卫挂错了层。** 去 AI 标点挂在发送门，等于「发出去的干净、看见的不干净」；工作台草稿、L1 审核稿、关怀预览都会继续露 em dash，用户复验必然再报。应在**起草完成处**（`drafts.auto_generate_draft` 返回前）做一次，发送门只做兜底并记 `punct_fix=0`。
2. **触发层没有「时间」概念。** 入站事件不分「刚到的」和「同步回来的」；起草不看入站年龄；`first_contact` 只是个计数。三件事叠加就是「登录即批量起草老客户」。需要三道闸：边车回填打 `backfill=True` 不进自动化；起草前 `inbound_age > 阈值` 不起草；切档 / 登录后有「沉寂会话待你决定」清单而不是静默起草。
3. **停联是会话态，不是人的属性。** 冻结记在档位上，重装、换机、换号都会丢。停联名单应是**账号级持久数据**（随人设 / 账号备份走），登录同步完先扫一遍历史（never write me again / stop / leave me alone / 别再发了）。
4. **文字和动作是两套脑子。** 「Just took this one for you」由 LLM 决定，发不发图由 `image_autosend` 决定，谁也不等谁；`outbound_promise_guard` 看见了「承诺」却没有动作权。正确结构是：模型只能输出结构化 `send_photo` 请求 → 管线真发成功才允许配文；没图就把「无图」回喂让模型自己拒；lie_caught 的固定动作是「重发上一张（id 已知）或说实话」，而不是给 hint 让模型再编。
5. **引用无锚点。** 「你之前提过 / 上次你说 / a while back」类短语没有事实校验；M-1 A 给关怀做了「档案注入与事实校验」，L-2 A 给问候做了「不编事实」，自动回复主链没有。要一个 `claim_guard`：引用短语必须在会话历史 + 记忆里找到锚点，否则改中性。
6. **首装态还是「客服公司」的。** 种子、示例、兜底话术、分类标签是四个来源，N-3 只把分类和 PAYMENT 种子按域切了；示例和兜底还在。应做成一个 `first_install_plan(business_domain)`：陪伴域 = 空 KB + 域内示例作为「新建条目」预填 + 零直发兜底。
7. **安全默认反了。** `lanServeHost` 把「有强令牌」当作「可以对外」，但 L-6 D 之后每台机器都有强令牌，于是全员 0.0.0.0。绑定地址应由**显式开关**决定（默认回环），扫码操控（#57）要用时再开。
8. **值守链两处「以为」。** 以为 `#N` 出现就是挂单意图；以为 send 返回 502 就没发出去（实际 12 条幻影行 + 1 条真发）。

### 1.2 市场经理

1. **「像真人」是唯一卖点，破折号是最贵的一个字符。** 80% 回复带 —，等于每个客户都拿到了识破证据。用户要求「热修、单独、最先」是对的——这条不该和拟人大包捆在一起等。
2. **「一切全自动就去骚扰三个月没联系的老客户」会让用户不敢开全自动。** 全自动是付费点；用户心里的画面必须是「我开了，它只回新来的」，而不是「它替我群发」。WhatsApp 对沉寂号批量发消息也是封号高危动作。
3. **编造回忆和谎称发图是信任事故，不是 bug。** 客户一句「我从没提过徒步」「哪有照片」，人设就死了，账号也可能被举报。宣传上我们说「有记忆」，实际是「会编」——这是反向卖点。
4. **首装第一眼决定留存。** 做情感陪伴的用户看到「退款政策 / 营业时间 / 投诉处理」示例，会觉得买错了产品。首装应该是干净、按行业给例子、三步上手。
5. **后台裸奔一旦被截图就是公关事故。** 「本地优先、数据在你手里」是我们对隐私敏感用户的承诺，公共 Wi-Fi 能打开后台直接打脸。
6. **口语简写是差异化，但要「像这个人」。** 一律 bro 比不用更露馅；应作为「拟人程度」下的可选强度，按人设性别 / 关系阶段 / 语言给词表，默认中档。
7. **版本叙事要拆开。** 1.0.78 = 「拟人止血」（零破折号 · 停联硬停 · 登录不群发 · 不编事实 · 后台回环）；1.0.79 = 「拟人升级」（口语层 · 引用回复 · 表情回应）。回访只说版本号不说日期（O-5 已定口径）。

### 1.3 用户（skuio 三个 WhatsApp 号 / 钧）

1. 我看到的草稿里还有 —，你说修了我不信。
2. 我一登录、一切全自动，它对我半年没联系的人写开场白，还包括昨晚让我永远别再写的那个人——这要是发出去我号就没了。
3. 它说「你之前提过徒步」，这人我根本没聊过；它说「照片发了，加载慢」，客户说没收到，它又说「再发一次」，还是没发。
4. 我自己的备忘录会话跑进客户列表，AI 会不会把我当客户回？
5. 知识库一装好就有「退款 / 营业时间」这种东西，我是做陪伴的。
6. 密钥自动生成了我很放心，但后台在咖啡店 Wi-Fi 上能被别人打开我不知道。
7. 「剩 None 小时」这种文案让我觉得软件没做完。
8. 你们的回执只要一条；我 Cursor 传的空备注包不用回。

## 2. 统一方案（按优先级；「落点」是给下一批指令用的，不改代码）

### P0（1.0.78 必须带上，比 O-1 D/E 优先）

**P0-1 破折号：起草即净化 + 全链可见。** `outbound_humanize` 前移到 `drafts.auto_generate_draft` 返回前（草稿 = 将发文本），发送门保留兜底；关怀润色 / 目标冲刺 / 问候 / 语音文案同一入口；生成侧 `persona_reply` 系统提示硬禁 + few-shot；质检页新卡「AI 指纹」：破折号率 / 客服腔率 / 引用无锚点次数（目标 0）。验收：200 样例门禁（已有）+ 工作台任意草稿肉眼无 —。
**P0-2 登录 / 切档不群发：三道闸 + 一张清单。** ① 边车 / 桥回填消息带 `backfill=True`，normalizer 落库但**不触发**任何自动化（起草 / 关怀 / 目标 / 问候）；② `auto_generate_draft` 入口加 `max_inbound_age_hours`（默认 72h，D-P1），超龄不起草，记 `[draft] skip=stale_inbound age=…`；③ 切全自动 / 登录完成后弹「N 个会话将进入全自动，其中 M 个有 3 天以上未回复的旧消息——默认不回」确认框，逐条勾选预览；④ 工作台新增「沉寂会话待你决定」清单（一键：忽略 / 人工回 / 让 AI 起草预览）。验收：重装 + 登录 → 零自动草稿；勾选 2 个 → 只生成 2 条且进 review。
**P0-3 停联名单账号级持久 + 登录扫描。** `stop_contact` 冻结同时写入账号级 `blocklist`（随账号 / 人设备份导出导入，随迁移脚本进 `account_scope_migration`）；登录同步完成后对历史跑一遍停联 / 负面词扫描（双语词表复用 O-1 A），命中即冻结 + 标签「客户要求停联」，永不 opener；人工解冻才恢复。验收：重装后 Sinue 会话登录即冻结。
**P0-4 「要么发，要么拒，不许说发了」。** ① 文字绑动作：模型输出结构化 `send_photo{query}` → `image_autosend` 真发成功才允许配文；无匹配图 → 回喂「无图」让模型自然拒绝；② `outbound_promise_guard` 升为**执行型**：承诺句（here it is / sent you / took this for you / let me send / check your phone / it went through / 发你了 / 看手机）在本轮无 `send_media` 时改写或拦下，落 `[media_promise] claims_send=1 attached=0 action=rewrite|hold`；③ `lie_caught` 固定动作：重发上一张（id 已知）或强制实话，禁「加载慢 / 再试」；复诉词补 no picture / where? / didn't get / nothing came；④ `capabilities.photos=false` 硬拒；⑤ 同会话 5 分钟内第二句照片文案必须真附图。验收：回放 6SRA2B 三轮 → 第一轮真发、第二轮重发同图、无第三轮谎话。
**P0-5 引用锚点守卫 `claim_guard`。** 引用类短语（you mentioned / you said / last time / a while back / as you told me / 你之前说 / 上次你说 / 你提过）→ 在会话历史 + 该客户记忆里找实体 / 关键词锚点；找不到 → 改写为中性问句（"how have you been?" 类），日志 `[claim-guard] anchored|rewritten phrase=… `；覆盖自动回复、opener、关怀润色、目标冲刺。验收：清库重装 + 老会话 → 零「你之前提过」。
**P0-6 后台默认回环。** `lanServeHost` 默认 `127.0.0.1`；新增设置「允许局域网设备连接（手机扫码操控需要）」默认关，开启时横幅提示当前网络与风险、显示访问地址与二维码；Windows 网络类别为 public 时开启需二次确认。验收：clean 装 → `netstat` 只见 127.0.0.1:18799；开开关 → 0.0.0.0 + 横幅。

### P1（1.0.78 能带就带，否则 1.0.79 第一批）

**P1-7 首装出厂态一张表 `first_install_plan(business_domain)`。** 陪伴域：KB 为空；「格式示例」改为「新建条目」预填模板（域内示例：称呼偏好 / 忌聊话题 / 常聊话题）；「系统话术」整类移出用户 KB 页，收进系统设置「兜底策略」（开发者模式可见）；陪伴域默认不启用任何直发兜底，AI 失败 = 静默 + 转人工提示；类型标签随域；`intent_tags.yaml` / 系统提示词随域（O-1 C 已做提示词）。销售域保留现有示例与兜底。
**P1-8 自聊会话过滤。** WhatsApp `peer == self`（Message yourself）/ Telegram Saved Messages：收件箱标「我自己 · 备忘」，排除全部自动化（起草 / 关怀 / 目标 / 问候 / 引用），默认折叠。
**P1-9 打包清单修正。** `handoff_scripts.yaml` / `handoff_compliance.yaml` 进 clean / lite 包（并把源文件从仓库根 `config/` 归到 `engines/chengjie/config/`）；`fatex.db` 移出用户包（命理产品库只随 FateX 产品线）；打包门禁加「必须在 / 必须不在」两张清单。
**P1-10 值守链三修。** ① `duty_auto_ticket` 挂单规则：`#N` 只在「行首 / 前后空白 / 工单·挂·关联 #N」上下文生效，紧贴词尾的引用（翻译器#106）不算；对 fixed / closed 单不升级、只 note；② 回执重试上限 3 次 + 幂等（先查收件箱是否已有同文本且带 mid 的 out 行）；空备注包不回执；③ `/api/unified-inbox/send` 失败不留幻影 out 行（或 `status=failed` 且工作台标红），502 必须带原因（M-3 D 四分类补这一支）。另：MTRCH2 从 #106 摘出，安全 / 打包 / 文案三件新立一单。

### P2（1.0.79）

**P2-11 口语简写层「口语化程度」三档（默认中）。** 与 O-1 B 同层的确定性词典：英文（u / ur / gonna / wanna / idk / tbh / rn / lol…按概率、会话内一致）、中文（哈哈哈 / 嗯嗯 / 咋 / 啥 / emm）、日文（w / 笑 / 〜）；称呼词（bro / babe / hun / dear）**只由人设词表决定**（性别 / 关系阶段），禁止全局一律；偶发拼写错每 8–15 条 1 处（可关）；URL / 人名 / 引号内 / verbatim 不处理；与「拟人程度」联动；门禁：200 样例 0 破折号 + 简写命中率达档；盲评。
**P2-12 小件。** `mb_trial_line` 加「未开始 / 不限时」分支；care interval 600s 与精确调度矛盾核实（FHSZTA⑤）；日志标签 `from domain 'conversion'` 改为 `business_domain` 名；帮助语料 292 条播种核实。

### 美化（随 P0/P1 一起落）

- 切档 / 登录确认框：标题「N 个会话将进入全自动」，两栏「会自动回（最近 3 天有来信）」/「不会碰（3 天以上旧消息 / 已停联 / 我自己）」，默认只勾第一栏，每行可预览草稿。
- 「沉寂会话待你决定」清单：收件箱顶部一条可折叠横幅 + 数字角标，三按钮（忽略 / 我来回 / 让 AI 起草预览）。
