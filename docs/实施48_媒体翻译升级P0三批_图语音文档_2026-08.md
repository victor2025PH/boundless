# 实施48：媒体翻译升级 P0 三批（图片 / 语音 / 文档）— 交接文档

> 日期：2026-08-19 · 实例：zhiliao（18799）· 状态：**三批全部装载生产并真机验证 PASS**
> 本文档 = 新会话接续开发的单一入口。方案缘起、四视角分析与 P1/P2 路线图见文末。

## 一、背景（老板原始痛点，附截图实录）

客户（马来语）发来纸巾包装图，坐席用「图片识别翻译」面板后反馈：
1. **译文图与原图不符**——大量文字区域没被翻译/覆盖；
2. **无目标语选择**——想把图译成日文/韩文，面板里没有任何入口；
3. 要求整体强化图片/语音/文档翻译的能力与体验（四视角分析 + 2026 技术调研后定了
   P0 快赢 → P1 质量根治 → P2 完全体的分期，本文档=P0 完成态）。

根因（代码实锤）：贴回链用通用 VLM（qwen2.5vl）顺带猜 bbox（漏块/丢弃/>60 块拒绝/
无擦字）；「识别翻译」与「译文图」是两次独立 OCR（面板与图对不上）；API 早支持
`target_lang` 但前端从未暴露；语音链只能念原文；文档要下载后去面板上传。

## 二、已交付（三批，均已在生产运行）

### 批次一：灯箱语言选择器 + 贴回管线统一（09:11 重启装载 → 真机验证 PASS）

- **前端** `unified_inbox.html` 灯箱：「译成」行=自动/中/EN/日/韩 chips + 12 语下拉
  （`_LBXL_MORE_LANGS`）；两级记忆 `localStorage aitr.lbxl.langs`（会话 pin + 全局）；
  换语言自动重跑；缓存键 **`mid|lang`**、在途键代际防串；覆盖率行「识别 N 处 · 已译 M」
  + 识别语言 + 引擎徽标；译文图按语言各自生成，切语言自动收回原图。
- **后端** `src/ai/image_patch_translate.py`：
  - **bbox sha1 缓存**（`MediaTextCache` 键 `bbox:{sha1}`；`text_cache` 注入参数，默认
    None 保单测密闭）→ 换语言/先识别后贴回**零二次 VLM**；只缓存解析成功的 raw；
  - **整图上下文批量翻译**（行号协议 `build_blocks_payload`/`parse_blocks_payload`；
    解析失真**整批回落逐块**——错位贴回比不贴更糟）；修「50 PULLS x 5 PLY→5层唱片」类
    孤立直译错误；构造参数 `context_translate` 默认 False（旧调用方零变化），生产由
    `resolve_patch_cfg` 默认 True；
  - **render=False 文本模式**：识别翻译与译文图**同源同块**；stats 分维
    `{blocks, patched, identity, failed}`（identity=同语保留，算正常）。
- **路由**（`unified_inbox_translate_routes.py` 图片分支）：patch 与识别翻译共用
  `_mk_patch_svc()`；`unified_ocr` 开启时识别翻译走文本模式，软失败（no_boxes 等）
  回落纯文本 OCR 旧路径；响应 additive：`unified:true + bbox_stats + source_lang`。
- **配置** `media.image_patch_translate`：`unified_ocr:true / context_translate:true /
  max_blocks:60`（`enabled` 仍默认 false；zhiliao overlay 已开 enabled）。
- **真机验证**（老板那张包装图所在会话实图）：识别 5 块/译 3/identity 2（品牌
  Cloudnest 与 100% 正确保留）/失败 0；贴回 `ocr_cached:true` + PNG magic；切 ko
  再验 `ocr_cached:true`（跨语言零 VLM）。

### 批次三：译声——打中文、发目标语克隆声（11:36 重启装载 → 真机验证 PASS）

- 新模块 `src/ai/voice_outbound_xlate.py::resolve_spoken_text`：**fail-open**——
  翻译异常/失败/空译/identity 一律念原文并如实 `meta.translated=False`（语音链绝不
  因翻译层故障断发）。
- `tts-test`（voice_routes）与 `send-voice`（unified_inbox_send_routes）都支持

  **先译后念**；`spoken_text` 决定：音色语言路由（`resolve_effective_voice_context` /
  `route_voice_cfg_for_text`）、合成、质量闸、**收件箱镜像 inbox_text**（写客户实际
  听到的话）、计费（tts 按译文长、translation 按源文长）。
- `tts_preview.py` 复用契约加 **target_lang 维度**（`lang_mismatch` 硬校验——试听
  日语后切韩语发送绝不复用日语音频；旧 sidecar 兼容=只匹配未翻译发送）；sidecar
  meta 带 `spoken_text` 供复用路径做镜像。
- **前端**：翻译弹层新增「语音消息：跟随翻译发声」行（默认开，`localStorage

- **设计决策**：不做独立语言选择器，语音**跟随出站文字翻译设置**——消除「文字发

- **真机验证**：tts-test zh→ja（fast 档）：`voice_translated:true` + 真日文译稿

## 三、关键契约（新会话动这些文件前必读）

1. 面板与译文图必须**同源同块**（unified 文本模式）；bbox 缓存只存解析成功的 raw。
2. 批量翻译行号协议：结构失真必须**整批回落逐块**。
3. 试听复用四维校验：文本 sha1 + persona_key + **target_lang** + TTL；均按**请求侧**
   入参（试听=发送同入参 ⇒ 同解析）。
4. 译声三铁律：fail-open 念原文 / 译文不进口语化改写 / 镜像写 spoken_text。
5. 前端灯箱缓存键 `mid|lang`；`.lbxl-patch-row` 已生成态**恒 2 按钮**（浏览器门禁
   `tools/verify_xlate_ctx_ui.py` 断言，改版式先看它）。
6. 全部新增响应字段 additive + 前端特性探测——新旧前后端任意组合自洽。
7. 本仓纪律：模板/i18n 热更即上生产（每步自洽 + bump ui-build）；.py 攒批走重启窗

## 六、方案缘起（简）

原始方案含四视角分析（用户：信任与入口统一；市场：私有化全媒体翻译差异化 +
克隆声跨语言演示；开发：抽取层换专业件、引擎栈不动；UIUX：决策就近/对照优先/
过程可见/诚实标注）与技术调研（PP-OCRv5/v6、LaMa、manga-image-translator 管线形态、
BabelDOC、SeamlessM4T 因 CC-BY-NC 弃用改级联）。实施中的主要再优化：bbox 指纹缓存、
整图批译从 P1 提前、复用契约语言维度、译声跟随出站翻译设置而非独立选择器、
文档链完全复用上传口基建（零新路由）。
