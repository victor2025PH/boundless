## 3. D1 —— 地区语气自适应（#40 的真诉求）

### 报障人（钧）的原话

> 「设定的 AI 是台湾人，之前反馈的句尾常带『呀』『啦』『耶』『嘛』不常见，
> 做不到聊天起来像是台湾女生的语气」
> 「不然所有的聊天看起来都像是大陆的语气」

### 现状（先只读确认）

`src/ai/spoken_style_bridge.py`（240 行，可以整读，不大）的 L1 / L2 层是
**单一套中文口语指令**（`zh_only` 默认开），**没有地区维度** —— 所以不管人设设成
哪里人，出来都是同一种大陆口语腔。

```
Select-String -Path engines/chengjie/src/ai/spoken_style_bridge.py -Pattern "l1_inject|l2_inject|zh_only|role|_resolved_persona_name" -Context 2,2
```

### 修

给口语层加**地区档**，`zh-CN` / `zh-TW` / `zh-HK` 起步（架构上留扩展位，后面可能加
新马华语、粤语区细分）。

**来源优先级**（三级，缺一级就往下走）：
1. 人设显式地区字段（最高优先，坐席明确设了就听它）
2. 会话「发→」语言变体：`zh-tw` → TW 档，`yue` → HK 档
3. 全局默认（`zh-CN`）

**每档给各自三样东西：**
- 语气词表（例：TW 档「啦 / 耶 / 喔 / 欸 / 齁」）
- 句式偏好（例：TW 档偏「有没有…」「会不会…」的软化问句）
- **禁用词**（例：TW 档禁「咋 / 整 / 牛逼 / 老铁」；HK 档要求**繁体字形** + 粤语口语虚词）

**禁用词那一半比语气词那一半更重要** —— 加几个「啦」容易，但一句话里蹦出一个「咋整」
就当场破功，用户一眼看出是大陆人在演台湾人。

**地区档放在本线的桥接层**，按人设口称名分流时**叠加**在现有指纹之上。
指纹文件 `speech_prints.json` 是 avatarhub 字节拷贝件，**不要改它**。

### 验收

1. 同一份人设文本 + TW 档 → 出站**含 TW 语气词**且**零大陆特征词**
2. CN 档输出与今天**逐字一致**（回归钉，这条最重要——新功能不能改动存量行为）
3. 非中文主体消息仍走 `zh_only` 不注入，`l2_skip_lang` 计数**不变**
4. 人设没设地区、会话也没设「发→」时 → 走 `zh-CN`，行为等于今天

## 4. D2 —— AI 自动链的引用回复（#37）

### 基建已在，缺的只是「决策」

- `src/web/routes/unified_inbox_send_routes.py` L832「P4-5B 引用回复」已支持原生 `reply_to`
- `src/client/telegram_client.py` L3990 / L4030 已在用 `reply_to_message_id`

缺的是**AI 自动链的引用决策** —— AI 自动回复**从不带引用**。客户连发 3 条、AI 回一条，
对方不知道在回哪句。

### 修：新建一个保守的纯函数决策模块

新建 `src/inbox/reply_quote_policy.py`，纯函数（好测、好回归、不碰别人的文件）：

**只在明确有歧义时才引用：**
- 未回复的入站 ≥ 2 条 → 引用最相关那条
- 或者被回内容与最后一条相隔 ≥ N 条 / ≥ M 分钟 → 引用

**单条入站一律不引用。** 真人不会对着唯一一条消息按引用，那样很机械 ——
这条比「什么时候引用」更重要，宁可少引用也不要每条都引用。

决策结果透传到发送层填 `reply_to`。

**平台能力差异先查 `docs/平台能力矩阵.md`**（那份是 `scripts/platform_matrix.py`
**从代码生成**的，勿手改；**别信散落在 worker 里的能力注释**，2026-07-31 实测有三处
是错的或已过期）。不支持引用的平台**静默降级为不引用**，不报错不阻塞发送。

### 验收

1. 单条入站 → **不引用**
2. 连发 3 条后 AI 回复 → **引用最相关那条**（给金标句对，断言选中的是哪一条）
3. 不支持引用的平台 → **不报错、不阻塞发送**，降级为普通发送
4. `reply_to` 的目标消息已被删除 / 找不到 → 降级为不引用，不抛异常
