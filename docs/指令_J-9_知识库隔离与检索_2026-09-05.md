## 2. A —— #184 厂商产品知识随首装进用户知识库

### 原话（B3PT5D）
> 知识库预置 110 条厂商自家产品销售知识（AI 视频翻译配音/AvatarHub 客户端/幻声/幻影/实时换脸部署/场景推荐…，分类均为产品介绍，已停用、用 0 次、未翻译）随首次安装导入。受众是买智聊的人而非用户的客户，污染用户业务知识空间；仅靠「已停用」软开关，误启用/向量化未排除即会让 AI 对用户客户推销厂商产品（叠加 #175 出戏风险）；首页显示 184 反馈 0.0% 满意；厂商产品说明已由悬浮球与 AI 助手承担，职责重叠。

### 先核（便宜）
- 这 110 条从哪来：`src/utils/kb_starter.py::_STARTER_PACKS`（键 `ecommerce/payment/outreach/bazi/general`）+ `POST /api/kb/seed-pack`（`kb_routes.py` L490）；桌面首装是否自动调 seed-pack、调的是哪个 domain，`rg -n "seed-pack|seed_pack" src desktop`。若 110 条不在 starter packs 里，看 `kb_importer.py` / 安装包内置 KB 文件（`rg -n "AvatarHub|幻声|VoiceX" src/utils config desktop --glob !*.pyc`）。
- 「184 反馈 0.0% 满意」口径：`rg -n "满意|satisf" src/web/templates/knowledge*.html src/web/routes/kb*.py`。

### 修
1. **首装不导入厂商条目**：种子只留 2–3 条示例（教用户格式）；厂商产品说明迁到悬浮球/AI 助手内置帮助（`howto_pack.py` 已承载产品说明，确认覆盖后删 KB 侧）。
2. **存量隔离**：条目加 `source` 字段（`vendor` / `user` / `import`），存量 110 条按标题/分类标 `vendor`；知识库页给「系统预置·厂商产品」筛选 + 「一键清除」；升级时提示清理。
3. **检索层硬隔离**：`kb_gate` / `kb_store.search` 对**客户会话召回**排除 `source=vendor`（不依赖「已停用」开关）；管理员在 KB 页仍可查看。
4. **接通性自检**：`GET /api/kb/health`（或并入 `/api/workspace/metrics.kb`）返 `{entries_total, entries_user, entries_vendor, embedded, last_hit_ts, hits_7d}`；ops 卡一行「知识库：用户条目 N / 近 7 天命中 M」——「知识库对拟稿零贡献」从猜测变读数。**注意**：命中计数要在 `kb_gate` 真正把 `kb_context` 注入的地方计（skill_manager L2322 附近你不能改——在 `kb_gate` 返回非空时计数即可）。
5. 「反馈 0.0% 满意」：核口径，若分母是「被展示次数」而分子恒 0 是因为反馈按钮无人点，改成「暂无反馈」而不是 0.0%。

### 验收
- 新装（空 KB）→ 只有示例条目；存量库迁移后 110 条标 vendor 且客户会话检索零命中它们（单测用假库）；管理员页可见可清除。
- `tests/test_kb_starter.py tests/test_faq_resolution_gate.py` 绿（后者可能 skip：缺库属正常）；新单测覆盖 source 过滤与 health 计数。
