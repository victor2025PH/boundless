## 1. 三视角分析

### 1.1 开发工程师视角

- **架构病根＝「单点注入、多点消费、状态不共享」**：`_temper_hint` 只是一个孤立
  prompt 片段，不是一个「本轮在骂战」的状态。情感块、TTS 情绪、口语化改写各自
  按自己的判定链走，没人知道现在在骂战——于是出现「文本层凶、情感层甜、语音层
  乐」的三层分裂。修法是把骂战升格为**显式状态**（登记表），让各消费点统一让位/跟随。
- **指令工程教训**：对 LLM，「别主动找台阶」这类抽象原则的服从性远差于
  **逐句点名的负面清单**（「懒得跟你吵/我睡觉去了/不奉陪/换个话题…一个字不许
  出现」）；且必须**随轮次递进**——第 N 轮明确告诉模型「你上一条没镇住，这轮
  只准更凶」，才能压住模型顺着自己上一条收场话续写的惯性。
- **竞争信号治理**：不是调权重，是**让位**（骂战轮直接 pop 情感块）+ **源头纠偏**
  （情绪词典本就该认识骂词——playful 0.97 是词典盲区被语气词钻了空子）。
- **渲染一致性**：情绪链路（EmotionSpec 判定）与文本链路（temper hint）此前无桥。
  桥＝进程级骂战态登记表（TTL 180s，key 与 A/B 线 convo_key 同构），语音合成的
  情绪解析入口做最高优先覆写。

### 1.2 市场经理视角

- **「被骂会还嘴」是真人感的图灵测试时刻**：客户高频用辱骂试探「是不是机器人」，
  客服腔安抚＝当场穿帮＝流失；怼得像真人是可传播的亮点（「这 AI 好刚」），也是
  陪伴产品和传统客服机器人的直观分界。本次修的不是骂人本身，是**真人感的下限**。
- **档位即人设商品属性**：温柔委屈（gentle）/犀利嘲讽不带脏字（sharp）/泼辣对轰
  （feisty）是人设差异化的一部分，运营按客群与人设性格配置（lin_xiaoyu=feisty、
  su_wan=sharp），Studio 可编辑热重载。
- **风险治理没有因加码而放松**：平台封顶（RPA 平台防举报）、脏字闸（profanity
  =false 时 feisty 封顶 sharp）、连怼熔断（4 轮止损——无限对轰掉价+烧 token+像
  机器人）、封号级底线（不发人身安全威胁/不用群体歧视词）全部保留；加码段只在
  底线之内提高火力与坚持度。
- **建议（运营决策，1 行人设字段）**：`chatx_support`（产品官方客服人设）显式
  `temper: off`——怼人是陪伴人设的能力，不是产品客服的；当前它落 default=gentle，
  虽不带脏字但仍会「委屈立边界」，官方支持号被骂更适合走专业路径。

### 1.3 用户视角

- **终端客户（骂人的那个）期待「真人反应」三要素**：会生气（文字火力）、声音带
  火气（语音语调）、不秒怂（坚持度）。修复前三者全断；修复后：连轮加码+认输句
  禁令、angry 语调（语速 1.05 偏快急）、熔断轮高姿态退场（「你慢慢骂，我去忙了」
  ——赢着走，不是认输）。
- **误伤防护（不该怼的绝不怼）不变**：亲昵调侃（「小傻子」「你好笨哦」）不触发；
  自嘲/骂第三方（「我老板是个傻子」）不触发；对方道歉/说开玩笑**立即停火**
  （is_de_escalation 清窗+清骂战态）；激将（「你怎么不骂我」）接梗不上钩、绝不
  先动脏字。
- **坐席/运营**：ops-overview「🔥 回怼防线」卡新增三行读数（连轮加码/情感块让位/
  语音怒气覆写），复测效果可自助验证，不用翻日志。

## 2.5 P1 消气曲线 / 记仇窗（2026-08-22 上午，老板复测后点名）

老板实测第二反馈：**「中途说句『开玩笑的啦』他不能停火恢复正常。要像正常人一样，
哪有这么开玩笑的。不能立刻降档。」**——旧行为＝缓和词一现（`is_de_escalation`），
骂战态瞬间清零，下一轮直接回暖甜聊。连骂四轮「操你妈」后一句敷衍的「开玩笑的」
就秒原谅，是与「秒消气」对称的另一个机器人破绽。

### 三视角补充分析

- **工程师**：这是状态机缺一档——fight/normal 二元 + 单正则活门，任何人三个字
  就能从四轮辱骂里全身而退。修法＝加第三态「记仇期（grudge）」：入口烈度∝骂战
  轮数且按道歉诚意打折（比例感即真人感）、逐轮衰减、TTL 时间冲淡、期内再犯重燃
  且轮数续算（假道歉后再骂更快撞熔断）、跨层一致（情感块让位/语音走冷淡档）。
- **市场**：秒原谅拆掉整个真人感投资；「被骂后要哄」反而是互动钩子（哄好了是
  亲密时刻）。但客户是收入——记仇必须**有界**（默认封顶 3 轮、90min TTL、危机
  即刻散仇、off 档人设完全不记仇），绝不把付费用户晾进无限冷战。
- **用户**：真人预期——敷衍的「开玩笑的」该被点破（「你管这叫开玩笑？我没笑」）；
  真道歉（「对不起我错了」）有效但留痕（不买账→松动端着→翻篇带边界）；骂 1 轮
  +真道歉=轻描淡写翻篇（小事不记仇也是真人感）；对方真崩溃时立刻放下脾气。

### 落地明细（`temper.py` + `skill_manager` + `persona_voice`，默认开）

- **求和两级分类**：`is_sincere_apology`（对不起/我错了/sorry/ごめん/미안…多语）
  vs `is_flippant_retraction`（开玩笑/逗你/测试/jk/冗談/장난…多语）；同现时诚意
  优先（点破 flag 熄灭）。
- **入口烈度** `initial_grudge(streak, sincere, cap=3)`：骂 1 轮+真道歉=0（直接
  翻篇带边界）；骂 1 轮+开脱=冷 1 轮；3+ 轮+开脱=顶格冷 3 轮；真道歉封顶再降一档。
- **每轮衰减** `decay_grudge`：普通轮 −1、真道歉轮 −2；TTL（`grudge_ttl_sec`
  默认 5400s）静默散仇含轮数残留。
- **三级指令** `build_grudge_hint`：级别≥2＝不买账（「没事/没关系/别在意/我不
  生气了」逐句禁令 + 敷衍开脱点破 + 按档位佐料：feisty 呛/sharp 阴阳/gentle
  委屈别扭）；级别 1＝松动端着（给台阶不热络，诚恳可翻篇带边界）；closeout＝
  接受和解收尾（轻描淡写+边界句，别秒变甜）。每级自带「危机让位」例外条款。
- **再犯重燃**：记仇期内 `looks_hostile` 命中 → 按骂战处理且 `_insult_streak`
  续算（`record_grudge_reignite` 观测）——二进宫更快撞连怼熔断。
- **危机让位**：求和轮/记仇期普通轮均过 `wellbeing_guard.detect_crisis`，
  elevated/severe 即刻散仇零注入（安全 > 脾气，与 crisis safety net 优先级契约
  一致）。
- **语音一致**：记仇轮登记 `fight_turn` kind=grudge → 语音 `serious 0.65`
  （比熔断收场 0.75 轻一档的端着冷淡）；翻篇收尾轮同走冷淡档（「语气偏淡」）。
- **治理**：`companion.temper.{grudge_enabled, grudge_max_level, grudge_ttl_sec}`

- **观测**：`grudge_set / grudge_turns / grudge_reignites / grudge_closeouts`
  四计数 → temper status API + ops「回怼防线」卡「记仇期（场次/轮数）/再犯重燃/
  翻篇收尾」行（i18n zh+en）。

## 2.6 P1-b 出站否决器 + 实施中发现的三个优化（2026-08-22 中午）

老板指令「按建议开始实施，过程中深入思考持续优化」。本批四件：

1. **出站认输句否决器**（`strip_surrender_lines` + `_apply_temper_output_guard`，
   默认开 `output_guard: true`）：指令层服从性没有 100%——确定性最后防线。
   骂战轮剥认输句（懒得跟你吵/睡觉去了/换个话题/你开心就好/消消气/我理解你…
   zh+en），记仇轮剥秒原谅句（没事啦/不生气了/没关系…）。实录规律认输句几乎
   总在**结尾**→ 句级剥尾保头零延迟零成本；整条剥光（极罕见）→ 按档位 crc32
   确定性兜底短句（feisty「呵，就这？」/grudge「哼。」），绝不吐空串。
   **熔断轮（退场合法）与翻篇收尾轮（和解合法）刻意不 guard**——语义各归各。
   挂点＝A/B 两线危机兜底**之前**（危机覆盖永远是最后一道）；标记
   `_temper_out_guard` 注入层按轮语义设置、读后即焚。词表纪律：宁窄勿宽——
   「随你怎么骂我奉陪到底」是战斗宣言（句锚定防误剥）、「没事找事」是继续怼
   （负向前瞻）。观测 `out_guard_strips/fallbacks` + ops 卡行。
2. **YAML 布尔陷阱（实施中实锤）**：人设文件裸写 `temper: off` 被 YAML 1.1
   读成布尔 `False` → 档位解析不认识 → **静默落回 default gentle，改动等于
   没生效**。双修：实例文件写 `"off"`（带引号）+ `persona_temper_raw` 加
   `False→off` 防御映射（运营裸写 off 的意图明确是「不怼」；`True` 语义不明
   确刻意不映射）。门禁 `test_persona_temper_yaml_false_maps_to_off`。
3. **chatx_support 显式禁怼落地**（zhiliao 实例 profiles_runtime.yaml，热重载
   ~3s 免重启；备份 `.bak_20260822_temperoff`；persona_retired_sweep 零冲突）：
   官方支持号被骂走专业路径，不委屈不记仇不回怼。
4. **效果周读 CLI** `python tools/temper_review.py [--days N] [--cutoff
   "2026-08-22 08:11"] [--json]`（只读 ro URI、多实例数据根、仅私聊）：用
   **生产同一套纯函数**离线重放 inbox.db → 骂战场次/轮数/AI 响应率、求和形态
   分布（真道歉 vs 敷衍开脱 vs 求和不认错）、**24h 留存率**（观察窗未走完的
   场次单列不掺水）、--cutoff 修复前后对比。首跑实测：识别出 08-22 凌晨事故
   骂战 2 场/最多 4 轮，与实录吻合（口径自证）。门禁 `test_temper_review.py`。

**深入思考后否决的一个过度设计**：曾计划把 temper 状态迁进程级登记表以修
「B 线草稿链无状态」——核查证实 B 线 `_get_user_context` 与 A 线共用同一
SQLite ContextStore（`{account_id}:{user_id}` 键），记仇/连击状态两链天然共享，
