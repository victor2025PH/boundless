## 〇 根因（代码只读核对，与指令「事实」段一致）

1. **一次 adult explicit 命中留下 24h 会话持有**：`adult_grader.regrade_inbound` 对 `explicit × (human|soft_reply)` 与 `pressure` 同路——`risk=high` + `risk_hold.set(adult, ttl=24h)` + `tag_needs_human(adult:<level>:<hit>)`。之后每条入站：`autosend_policy._resolve_risk_hold` 见持有活跃 → `forced=L1 review_required=True` → drafts 再调 `tag_needs_human` → 命中「保持」路径（标在场 + 持有活跃）→ `[risk_hold] touch n=26`。
2. **保持行 `level=low category=- hits=-`**：drafts 传给 `tag_needs_human` 的 `level/category/hits` 来自本条入站的 `risk_grader` 结论（benign 入站 = low / 空类别），而不是持有本身的类别；保持路径照抄打印。低级入站不但没有释放 hold，还把它「保持」了下来。
3. **释放条件只有两条**：`clear_needs_human(actor=agent_ack|agent_send)`（Q-17 摘标 / 手发）。切档路由 `mode=auto_ai` 只接回 Q-18 让位（`_resume_agent_yield_q18`），不碰 risk_hold；TTL 到期在 `active()` 内写 `cleared_by=ttl` 但日志口径是 `expired` 不是 `clear by=`。
4. **keyword-only 可单独 high**：`risk_grader.TRUE_HIGH_REASONS` 含 `money` / `adult`（quick_analyze 一个词即 high），`_downgradable` 对 `drafts._SENSITIVE_PATTERNS[0]`（refund / password / OTP 支付词表）命中一律不降；`payment_keyword` 类别本身 `level=high`。
