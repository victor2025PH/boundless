## 1. 三轮才修对，前两轮错在哪

老板与其他用户在 1.0.92 上仍复现同一个弹窗，所以这一轮不再按症状猜，先把「那句话是谁打印的」查清。关键事实：`appCannotBeClosed`（＝`智聊 无法关闭。请手动关闭它，然后单击重试以继续。`）在 app-builder-lib 里由**三处**打印，截图分辨不出来：

| 出处 | 触发 | 我们的处置 |
|---|---|---|
| `allowOnlyOneInstallerInstance.nsh`（库存 `_CHECK_APP_RUNNING`） | 杀不掉应用 | 1.0.93 起**不再插这段**，整段自己接管 |
| `installUtil.nsh` UninstallLoop | 旧卸载器连失败 5 次 | `customRemoveFiles` 让卸载器不再失败 |
| `extractAppPackage.nsh` | CopyFiles 撞占用文件，重试 5×1s | 覆盖安装兜底（点「重试」能装完就是这条） |

- **轮 1（1.0.92）**：把进程收割从 `Get-Process().Path` 改成 WMI `ExecutablePath`。修的是真 bug（`Path` 需要 `PROCESS_VM_READ`，高完整性进程读不到），但**不是现场那个弹窗的主因**。
- **轮 2**：探针 `probe_stockcheck2.ps1` 实测库存 `_CHECK_APP_RUNNING` 总预算只有 **~6.3s**，决定性复查紧贴 `taskkill /f` 之后、零沉降；而 `main.js` 的 `before-quit` 按设计 `preventDefault` + `stopAndWait(8000)` + `sidecars.stopAll`（B57 要求后端干净退出，否则半死后端抢会话＝全账号重登）。**按设计正常退出的应用必输这场没人写下来的竞速**。第一版探针没复现，是因为测试应用复用了宿主后端、秒退——工具骗了自己一次。
- **轮 3（真因，C9）**：`probe_uninst_rc.ps1` 实测「无任何本方进程存活、探测的文件均未被锁」时旧卸载器**仍返回 2**。读源码定位：`uninstallOldVersion` 以 `/S --updated _?=<dir>` 跑旧卸载器 → `uninstaller.nsh` 走 `un.atomicRMDir`：把 `$INSTDIR` 全部文件逐个改名进 `$PLUGINSDIR`，**任一改名失败即整树回滚 + `Abort`（退出码 2）**；模板再重试 5 次才弹窗。我们随包 **9429** 个文件，杀软扫描时以不带 `FILE_SHARE_DELETE` 的方式打开任意一个就够了。

## 2. 本版改了什么（`desktop/build/installer.nsh`）

| 宏 | 作用 |
|---|---|
| `cxCloseAppNicely 15` | `CloseMainWindow()`＝WM_CLOSE（才会触发 `before-quit` 的后端清退），随后**轮询**到家族真清空为止，清空即刻返回（关着的应用零额外耗时） |
| `cxReapFamily 20` | 强杀 + 持续复验；幸存者带 pid/name/path 写日志。家族判据单一事实源 `CX_FAM_FILTER`：`$INSTDIR\*`（**真实安装目录**，自选目录以前漏掉）∪ 默认包目录 ∪ 本会话同名进程，减去 `*Uninstall*`、`*-updater*` |
| `cxLogState` | 每次安装写一行「阶段 + 进程家族 + 哪些文件真被锁」，**不只失败时写**——「家族空且无锁」正是证明下个弹窗来自解包阶段的那行 |
| `customRemoveFiles`（C9） | 保留 `un.atomicRMDir` 快路径；失败则**点名占用文件**、重试一次，仍占用就降级 `RMDir /r $INSTDIR`（忽略错误）→ 卸载器返回 0 → 没有 5 次重试、没有弹窗。刻意**不**排进重启后删除队列（新版本马上装进这个目录） |
| 静默卸载自收割 | `uninstaller.nsh` 只在非静默时调 `un.checkAppRunning`，而升级链与运维推机全是静默——正是最需要的场合没人关应用 |

绝对路径 `$SYSDIR\WindowsPowerShell\v1.0\powershell.exe` 是刻意的（PATH 被裁就会静默解除这整套武装）；弹窗一律带 `/SD`（无 `/SD` 会挂死静默安装，库存那条还是 `/SD IDCANCEL`＝直接中止升级）。契约钉在 `test/uninstall-nsh-invariants.test.js`（新增 C9 段）。

## 4. 边界（已如实写进官网说明与频道帖）

升级时执行「移除旧版」的是**旧版本自带的**卸载程序。所以 1.0.92 → 1.0.93 这一跳本身仍可能提示一次（点「重试」即可装完）；**装上 1.0.93 之后**这类提示不再出现。先说清，免得再来一轮「还是有问题」。

老板决定：**保留安装向导，本版不改静默安装**（`quitAndInstall(true)` 之类的形态变更不在本号范围）。
