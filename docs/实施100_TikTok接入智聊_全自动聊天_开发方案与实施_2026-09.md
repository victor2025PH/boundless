# 实施100 · TikTok 接入智聊：全自动聊天（Business Messaging）开发方案与实施

> 决策（2026-09-08，老板）：**抖音官方通道冻结**（三道资质门：能力获批 / 私信正文可读 / 日均 100 OpenID 活跃门槛；任一不过即停），**TikTok 正式开发**。
> 目标：TikTok Business Account 的私信在智聊里**全自动接待**——客户开口 → 收件箱 → SkillManager 出稿 → 策略层放行 → 48 小时窗内自动回复 → 转人工/接管随时可用；接入体验做到「点一下授权、点一下注册 webhook、发一条私信验收」。
> 前置：TikTok for Business 开发者应用 + Business Messaging 访问申请（约 10 个工作日，区域不勾美国）；客户 Business Account 注册地在可用区（APAC / 拉美 / 中东 / 加拿大），且已挂 Business Center 取得 Advanced Access。

## 1. 接口契约（2026-09-08 按官方 SDK 类型定义、官方 webhook 验签文档与 chatwoot 生产实现核实）

| 项 | 契约 |
|---|---|
| 基地址 | `https://business-api.tiktok.com/open_api/v1.3`；请求头 `Access-Token`；响应壳 `{code, message, request_id, data}`，`code=0` 成功 |
| 授权页 | `https://www.tiktok.com/v2/auth/authorize/?client_key&response_type=code&scope&redirect_uri&state`；scope 逗号分隔：`user.info.basic,user.info.username,user.info.profile,message.list.read,message.list.send,message.list.manage`；用户可部分授权 → 回调后校验 `data.scope` 是否齐全 |
| 换令牌 | `POST /tt_user/oauth2/token/` JSON `{client_id, client_secret, grant_type:"authorization_code", auth_code, redirect_uri}` → `data.{access_token, expires_in, refresh_token, refresh_token_expires_in, open_id, scope}`；**`business_id` ＝ `open_id`**；auth_code 10 分钟一次性 |
| 刷新 | `POST /tt_user/oauth2/refresh_token/` `{client_id, client_secret, grant_type:"refresh_token", refresh_token}` → 同上（access 短期、refresh 约 1 年） |
| 账号资料 | `GET /business/get/?business_id=&fields=["username","display_name","profile_image"]` |
| 发送 | `POST /business/message/send/` `{business_id, message_type: TEXT/IMAGE/SHARE_POST/TEMPLATE, recipient_type:"CONVERSATION", recipient:<conversation_id>, text:{body} / image:{media_id} / share_post:{item_id}, referenced_message_info:{referenced_message_id}?}` → `data.message.message_id` |
| 图片上传 | `POST /business/message/media/upload/` multipart `business_id / file / media_type=IMAGE` → `data.media_id`（30 天有效，JPG/PNG ≤ 3MB） |
| 图片下载 | `POST /business/message/media/download/` `{business_id, conversation_id, message_id, media_id, media_type}` |
| 会话/内容 | `GET /business/message/conversation/list/`（近 90 天）、`GET /business/message/content/list/`（最近 20 条） |
| 能力探测 | `GET /business/message/capabilities/get/?business_id&capability_types=[…]&conversation_id?` → `data.capability_infos[{capability_type, capability_result}]` |
| 自动消息 | `/business/message/auto_message/create|update|get/`：`auto_message_type` + `welcome_message` / `suggested_question` / `chat_prompt` |
| Webhook 注册 | `POST /business/webhook/update/` `{app_id, secret, event_type:"DIRECT_MESSAGE", callback_url}`；`GET /business/webhook/list/?app_id&secret&event_type=DIRECT_MESSAGE`——**可编程注册，不必进控制台** |
| Webhook 验签 | 头 `Tiktok-Signature: t=<unix>,s=<hex>`；`s = HMAC-SHA256(client_secret, f"{t}.{raw_body}")`；校验时间差（官方建议自定容忍，chatwoot 用 5 秒，本实现默认 300 秒可配） |
| Webhook 载荷 | 外壳 `{event: im_receive_msg / im_send_msg / im_mark_read_msg, user_openid:<business_id>, content:"<JSON 字符串>"}`；`content` 二次解析后：`conversation_id, message_id, timestamp(ms), message_type(text/image/sticker/share_post/…), text.body, image.media_id, share_post.embed_url, referenced_message_info.referenced_message_id, from, from_user.id, to, to_user.id`；**方向判定：`to_user.id == business_id` ⇒ 客户进线，否则为我方回显** |
| 规则 | 只能回复先开口的用户；客户最后一条后 48h 内 ≤ 10 条（我们封顶 3 气泡）；文本 ≤ 6000；无按钮/主动私信/群发/视频语音；图片按注册地表；10 QPS |
| 地区 | Business Account 注册地在 EEA / 瑞士 / 英国 / 美国不可用（美国为 USDS 隔离）；已编码于 `tiktok_regions.py` |

## 2. 现状（已提交）与本次范围

已就位：`tiktok_regions.py`（地区模型）、`tiktok_official.py` 骨架（客户端 / webhook / worker）、`channel_policy` 的 tiktok 规则（6000 字、48h/10、首条禁链、3 气泡、仅图片）、`window_guard` 执行器、注册表条目、能力矩阵、教程页 TikTok 面板（手填令牌）、8+1 例测试。

本次范围（按批）：

| 批 | 内容 | 验收 |
|---|---|---|
| **T1 契约对齐** | 验签改官方 `Tiktok-Signature` 方案；webhook 外壳 `user_openid + content 字符串` 解析；方向按 `to_user.id`；`im_mark_read_msg` 记录；回显去重（我方发送成功的 message_id 入 seen 表，回显事件不再二次落库） | 假载荷全分支测试 |
| **T2 OAuth 与令牌** | `authorize_url / exchange_code / refresh / business_profile`；`token_state`（access 到期前刷新、refresh 过期→needs_reauth）；worker `start()` 与发送前自动刷新；鉴权错误码先刷一次再判失效；scope 不齐 → 明确错误 | 令牌矩阵测试 |
| **T3 一键接入** | 面板：选注册地 → 「用 TikTok 授权」→ 回调登记 `tiktok/<open_id>`（资料名、头像）→ 自动 `POST /business/webhook/update/` 注册回调 → 能力探测显示「可发文本 / 可发图」→ 成功态「去 TikTok 发一条私信」 | 全应用端到端测试 |
| **T4 入口经营** | 面板生成 TikTok.me 引流链接 / 二维码（`ref=`）；`referral.short_link.ref`、`referral.ad` 落会话来源；欢迎语 / 推荐问题写到平台 auto_message（可选） | 会话来源含 ref |
| **T5 值守** | 令牌 7 天预警（复用抖音 `reauth_days_left` 思路）；webhook 静默检测（>24h 无事件且账号活跃→黄条）；地区不可用红灯 | 会话健康记录 |

不做：TikTok Shop 客服 API（门槛 1000 卖家/日 100 万调用）、评论转私信（仅 VN/TH/ID 灰度，等契约公开）、视频/语音、群发。

## 3. 与智聊的对接点（不改禁改文件）

- 进线：`handle_webhook` → `protocol_bridge.make_message/emit_incoming` → `maybe_auto_reply`（既有 3 条回复引擎与 SkillManager 不动）。
- 出站：`account_orchestrator.send/send_media` → `channel_policy.text_block_reason`（6000 / 首条禁链）→ `window_guard.send_block_reason`（48h/10）→ `TikTokOfficialWorker.send`（需 `conversation_id`，无则 `policy_window_no_inbound`）。
- 拆分：`reply_split.cap_max_parts_for_platform` → 3 气泡。
- 风险策略：`autosend_policy.decide(platform="tiktok")` → enforce。
- 账号：`account_registry` `tiktok/<open_id>` mode=official，meta：`access_token / access_expires_at / refresh_token / refresh_expires_at / scope / region / username / display_name`。
- 健康：`platform_session_health.record(tiktok, open_id, authorized|expired|blocked)`。

## 4. 配置

```yaml
tiktok:
  enabled: true
  app_id: ""          # 开发者应用 App ID（client_key）
  secret: ""          # 应用 Secret（验签与换令牌同一把）
  webhook_path: /webhook/tiktok
  signature_tolerance_sec: 300
  verify_signature: true
```
对外基地址：优先 `web_admin.public_base_url` / `official_media.public_base_url`，否则按请求 Host 推断（面板可见）。

## 5. 风险与停止条件

- 访问申请两次被拒 → 停止 TikTok 官方通道。
- Open Beta 条款变更（窗口 / 条数 / 地区）→ 只改 `channel_policy` 与 `tiktok_regions` 两处常量。
- 目标客户主要在美国/欧洲 → 转 WhatsApp / Instagram 官方通道 + Messaging Ads，不再投入。
