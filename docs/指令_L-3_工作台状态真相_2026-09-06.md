## 2. A —— 「需人工」闭环（#207，P2）

**现象与根因**：Loki（whatsapp:17345893506:13308422244）的红标是 09-05 02:57:30 `AutosendWorker guard=near_duplicate 拦截后未救回且客户有新入站在等 → 已打「需人工」(reason=dup_guard_blocked)`；11:24 AI 自动回复「Then sleep easy」成功，但 `clear_needs_human` 只在**坐席人工发消息**时调用 → 标一直挂到 09-06 仍在（BJZFSX），点进会话无原因、无入口，且与「全自动 + AI 已回」同亮。

**修法**：
1. **自动摘标**：`autosend_worker` 在自动回复成功投递后、`protocol_autoreply` 在 AI 回复成功后，调用 `clear_needs_human`（reason 为 `dup_guard_blocked` / 漏回类才自动摘；`crisis` / `L3 人审` 类不自动摘）。会话被归档 / 客户消息已被消化（无待回入站）也摘。
2. **会话内可见**：打开带标会话 → 顶部原因条「需人工：AI 回复被近重复拦截，客户 02:57 在等（系统打标）」+ 两个按钮「去回复台处理」/「我知道了（摘标）」；数据来自已有 `store.get_handoff_meta`。
3. **互斥**：列表项「需人工」与「AI 已回/全自动」徽标不得同时亮——有标时 AI 徽标降为灰。
4. 打标/摘标都落 INFO（谁/何时/为何），ops 看板「需人工」计数按 reason 分列。

**验收**：`tests/test_needs_human_autoclear_207.py`：dup 打标 → AI 成功回复 → 标消失；crisis 打标不自动消失；会话头部原因条渲染。Loki 会话装载后红标消失。

## 3. B —— 幽灵未读闭环（#170 复报，P2）

**现象**：1.0.74 上 steven 角标 1 / 另一账号 2，会话列表无未读；看门狗 00:28:21 `被埋会话 8 个（昨 7）最老 86h 人工归档 8`；`HealthWatchdog alert_on_warn=False` → 告警只写日志不上屏；3h 内无 mark_read / 浮回 / 取消归档事件（U3YUH3）。skuio 用了一夜没找到 J-4 A 的入口。

**修法**（不重做入口）：
1. **上屏**：被埋会话告警从「只写日志」改为工作台内横幅（复用 `_renderBuriedHint`）常驻直到归零，文案「有 N 条未读在已归档会话里（最久 86 小时）→ 一键取消归档 / 逐条查看」；`alert_on_warn` 语义拆成 `alert_on_warn`（外部 webhook）与 `surface_in_ui`（工作台横幅，默认 True）。
2. **核实浮回**：`store._unarchive_on_inbound` 是否真在协议入站路径上跑——被埋数 7→8 是反证；写一个探针测试（归档会话收新入站 → archived=0）；若确实不生效，修接线（协议路径 `unified_inbox_account_routes` 入站落库处）。
3. **入口引导**：角标浮层第一次出现时（本机 localStorage 标记）显一行「这些是归档会话里的未读，点开或『全部标已读』即可清零」。
4. 孤儿未读（会话已删仍有 unread 计数）启动时清理一次并落日志。

**验收**：skuio 机装载后：被埋横幅可见 → 一键取消归档 → 角标归零；`tests/test_unarchive_on_inbound.py` 绿；看门狗被埋数归 0。

## 4. C —— 断线弹窗出口 + 告警归拢（#196，P2）

**现象**：右下角「whatsapp 通道 (Alixia) 已断线 3 天 9 小时，客户消息可能积压」只有「1 小时内别再提醒」，每小时重弹，两天 50+ 次；同期看门狗被埋会话 / 媒体质疑超龄 / LAN GPU 不可达 / 草稿质量黄灯 / AI 对聊 全部逐条 toast，无归拢无分级。

**根因落点**：`src/web/static/workspace/notify-bus.js` + `workspace_base.html`（`ws.chandown.*` 文案）只实现了 snooze 1h；`health_watchdog.py` 各 check 各自发 toast。

**修法**：
1. chandown 弹窗出口：**1 小时 / 24 小时 / 不再提醒此账号** + **「去重连」**（跳登录页对应账号）+ **「标为已停用」**（账号进 `disabled/maintenance` 态，看门狗跳过，账号栏灰显）。静默状态按账号存本机 + 服务端（换机不丢）。
2. 归拢：同一告警 key（账号 + 类型）合并计数，只更新持续时长不重弹；右下角同时最多 1 条汇总 toast「有 3 项需要注意 ›」，点开进通知中心列表。
3. 分级：客户在等（漏回/需人工）> 通道断线 > 基础设施（GPU/Embedding）> 质量黄灯；低两级默认只进通知中心不弹。**基础设施类在 desktop_mode 下随 L-6 B 剥离后应几乎不再出现**，落点表注明依赖。

**验收**：Alixia 弹窗选「不再提醒此账号」后 24h 无重弹；`tests/test_notify_coalesce_196.py`：同 key 3 次告警只 1 条 toast。
