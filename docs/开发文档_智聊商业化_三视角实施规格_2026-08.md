## 1. 视角一：开发工程师 → 工程工作包

> 每个 WP 的结构：目标 / 已有资产 / 范围（做·不做）/ 技术要点 / 验收 / 涉及面。
> 优先级：P0 = 90 天内必须（决定能不能卖）；P1 = 强烈建议；P2 = 只立项不动工。

### WP-1（P0）纯云起步档：零 GPU 一键可跑

**目标**：陌生客户在一台普通 Windows 机器上（无局域网 GPU 拓扑），30 分钟内跑通
「安装 → 绑账号 → 首条 AI 回复」。这是整个销售漏斗的第一块砖。

**已有资产**：
- `ai.primary=cloud` 模式已存在（`unified_inbox_setup_routes.py::_AI_PRIMARY_MODES`）；
- 全链路降级本来就是软失败设计：语音失败回落 edge_tts、视觉多端点回落云端、
  嵌入缺失记忆退化为关键词召回、本地 MT 缺失走 DeepL/Google/AI 引擎；
- 桌面包自带后端 sidecar（`desktop/build/check_backend_freshness.py` 指纹机制）。

**范围（做）**：
1. 定义**能力预设档** `deploy.profile: cloud_light`（配置层预设，非新代码路径）：
   - 语音：`avatar_voice` 关、TTS 后端仅 `edge_tts`（或整体关语音）；
   - 视觉：`vision.base_urls` 空 → 仅云 key（或关）；嵌入：不配 → 关键词召回；
   - 本地 LLM 容灾：关（`ai.fallback.enabled=false`）；翻译：云引擎序；
   - 176/140/117 等内网地址在该档**一律不出现**（预设文件不含任何 LAN IP）。
2. **就绪自检**：新增只读端点或复用 readiness，输出「当前档位 + 各能力
   开/关/降级」一屏（供向导与支持排障用）；ops-overview 在 cloud_light 档下
   不得出现常驻红灯（探针对未启用组件应静默，现有探针决策函数大多已按
   「未启用不探」设计，逐个核对即可）。
3. 桌面包在干净 Win10/11 虚拟机上按 cloud_light 档全量冒烟一次，记录时长。

**范围（不做）**：不改任何降级逻辑本身（都已存在）；不做 Linux/Docker（P2）。

**技术要点**：
- 预设落点建议 `config/profiles/cloud_light.yaml`（随包分发）+ 桌面首启播种逻辑
  选择档位写入 overlay（`config.local.yaml`，走 ruamel 保注释写入器）；
- 生产两实例**不受影响**：预设只在新装机器生效，严禁改 `config.yaml` 基线默认值；
- 例外注意：`voice_prerender.DEFAULT_BASE_DIR` 的相对路径例外有成对门禁守护，
  cloud_light 档语音关闭时不触碰它。

**验收**（2026-08-16 实施：`docs/实施32_WP1纯云起步档cloud_light_2026-08.md`）：
- [ ] 干净 VM（无 LAN GPU）安装 → 首条 AI 回复中位 < 30 分钟（实测 2 次取中位）
  ——⏳ 待实测：需干净 Win10/11 VM（生产机不适合装测），程序见实施32 §4；
- [ ] cloud_light 档下 ops-overview 零常驻红灯、告警 webhook 零误报（观察 24h）
  ——⏳ 24h 实机观察待做；「探针对未启用组件静默」已机制化进门禁
  （`test_cloud_light_silences_lan_probes`，健康组件逐个核对结论见实施32 §2.4）；
- [x] 预设文件零内网 IP（加一条静态门禁扫描 `config/profiles/`）
  ——`tests/test_deploy_profiles.py::test_profiles_dir_has_no_private_ip`，CI 常驻；
- [x] 现有全量回归不红（预设不改默认行为）——本线涉及面全绿（新门禁 12/12 +
  邻居定向 237 过 + 桌面 npm 全绿）；「不改默认行为」有专项门禁（无 env / 既有配置
  一律不应用）。树上既有红（他线 in-flight）归属清单见实施32 §3，报告未默改。

**涉及面**：`config/profiles/`（新）、desktop 首启播种、`unified_inbox_setup_routes.py`
（就绪快照扩展）、一条新门禁测试。

### WP-2（P0）首启向导：四步跑通

**目标**：把「激活授权 → 绑渠道 → 挑人设 → 选自动化档位 → 发测试消息」串成一条
不需要读文档的向导流。现在每一步都存在，但散落在会员中心 / setup 路由 / personas /
capability 面板四处，陌生人找不到路。

**已有资产**：渠道向导 `/api/setup/*`（含凭证校验、overlay 写入、扫码交棒）、
授权激活（membership 页粘贴授权码）、人设创建向导 JS、陪伴能力一键预设档
（`companion_capability_presets`，带护栏 toggle/快照回滚）、L1–L4 自动化分级。

**范围（做）**：
1. 新页面 `/welcome`（或桌面壳首启直达）：五步向导壳，每步嵌既有能力：
   ① 授权/试用状态（读 license state，缺授权给官网试用深链）→
   ② 渠道接入（复用 `/api/setup/*` 全套，不重写）→
   ③ 人设：从**模板列表**选一个（内置 3–5 个开箱人设模板：客服型/陪伴型/销售型；
   模板=persona 档案 + 默认全局规则组合，暂不含语音相册——那是 WP-6）→
   ④ 自动化档位：三选一卡片（全人工 L1 / AI 拟稿人审 L2-review / 全自动 auto_ai），
   写对应配置（复用 capability presets 的护栏写入路径）→
   ⑤ 发测试消息（给自己的 Saved Messages，复用现有 send 链）+ 完成页（指向工作台）。
2. 完成度持久化：`onboarding_state`（实例数据根 JSON），中断可续；完成后不再弹。
3. i18n：全部词条进 `src/web/i18n_packs/`（新 pack `onboarding.py`），zh+en 齐备。

**范围（不做）**：不改各步骤的底层实现；不做人设语音/相册备货（WP-6）；
不动生产两实例的默认行为（feature flag 控制，见下）。

**技术要点**：
- Feature flag：`onboarding.enabled` 基线 `false`（仓库规则：新子系统默认关）；
  桌面包播种 overlay 置 `true`——生产老实例不受打扰，新装客户默认见到向导；
- 步骤 ③ 的人设模板注意**人设数据纪律**（`.cursor/rules/chengjie-persona-discipline.mdc`）：
  模板落库走 Studio 同一保存路径（含 retired_facts 冲突检测），勿直写 YAML；
- 新增常驻人设必须同步 `platform/spoken_style/data/speech_prints.json` 指纹条目
  （规则明示：漏了=该人设没有口语指纹）——模板安装时自动补占位条目并提示；
- 内联 onclick 必须挂 window（哑按钮门禁会扫，但热更新先于门禁上生产，写时就带）。

**验收**（2026-08-16 实施：`docs/实施33_WP2首启向导_2026-08.md`）：
- [ ] 干净实例走完五步 ≤ 10 分钟（不含扫码等待）；每步可跳过、可回退、中断续走
  ——跳过/回退/断点续走三链已机制化（浏览器门禁 S3/S9/S10 断言）；⏳ 计时走查
  待干净 VM（与 WP-1 的 30 分钟冒烟同一台，程序见实施33 §4）；
- [x] `tools/` 下补真浏览器只读门禁 `verify_onboarding_ui.py`（对齐 verify_goal_form_ui

### WP-3（P0）老板日报：让买单的人每周看到「钱」

**目标**：ops-overview 是工程师视角（几十张卡）。给运营主管/老板一屏「AI 今天/本周
替你干了什么」：回复了 X 条 / 养熟 Y 人 / 促成 Z 单 / 折算省了 N 小时人工。
这是续费率的决定性界面。

**已有资产**：`src/ops/value_report.py::build_weekly_value`（周窗聚合，四路消费已接：
`/api/report/weekly`、周报推送循环、ops 卡、watchdog `ops_report` 事件）；
`reply_latency`（p50/p95/零回复）；proactive 周报 CLI；告警 webhook 渠道面板。

**范围（做）**：
1. `value_report` 增**日窗口径**（`build_daily_value`，复用同一套 SQL 窗口参数化，
   口径注释对齐周版：剔 bot、触达回复判定同源——首跑口径分裂的教训已写在模块里）；
2. 新页面 `/boss`（或工作台内「经营」tab）：大数字 + 7 天趋势小图 + 一句话解读；
   词汇用钱和时间（「省了约 N 小时人工」= 回复条数 × 每条人工均时的可配置系数），
   **不出现**工程黑话（草稿/L2/autosend 等词不进这页）；
3. 推送：接现有 watchdog `ops_report` 通道加 `daily` 档（`health_watchdog.
   daily_report_enabled`，基线 false），走 notify_webhooks 既有渠道，不造新出口；
4. 导出：页面加「导出本周报告（Markdown）」——WS-3 案例采写直接用。

**范围（不做）**：不动 ops-overview 现有卡（另一批线在维护）；不做多租户口径。

**技术要点**：
- 数据全部走持久库口径（重启不清零），沿 value_report 现有查询习惯（LEFT JOIN
  conversations / 剔 bot SQL 与主计数同源）；
- 人工均时系数放 `ops.value_report.manual_minutes_per_reply`（默认 3，可配）——
  这是销售话术数字，必须让客户能按自己团队实情调；
- 新键全走 i18n pack；页面权限对齐 workspace 坐席鉴权（老板也是坐席角色即可读）。

**验收**（2026-08-17 实施：`docs/实施35_WP3老板日报_2026-08.md`；页面落
`/workspace/boss`——「老板也是坐席角色可读」要求 agent 可达，/workspace 前缀是
agent 角色唯一放行面）：
- [x] `/boss` 页在零流量实例显示诚实空态（不摆零假数据）；有流量实例数字与

### WP-4（P0）合规模式：把法规风险做成开关和卖点

**目标**：应对已生效的三部法规——EU AI Act 第 50 条（2026-08-02 生效：首次交互披露，
罚 €15M/3%）、加州 SB 243（2026-01-01：披露 + 危机协议公示 + 未成年人提醒 + 2027 年报 +
私诉权）、纽约 GBL §1700。做成产品开关 + 导出物，让「合规」成为对 B 端客户的溢价点。

**已有资产（这是卖点的底气）**：危机识别→安全回复覆盖→热线资源保障的完整闭环
（`_apply_crisis_safety_net` + `crisis_resource_assurance` + 三套 eval 门禁）——
恰好是 SB 243 的核心强制项。缺的只是「披露」与「对外可展示的协议文档」。

**范围（做）**：
1. 配置组 `compliance.*`（基线全 false，运营方 opt-in）：
   - `compliance.disclosure.notice`：**系统级披露**——新会话首条出站前置披露语
     （按会话语言取 i18n 文案，形如「您正在与 AI 助理对话，人工团队随时可接入」），
     每会话只发一次，落 `conversation_meta` 防重；
   - `compliance.disclosure.honest_identity`：**对话内如实承认**——开启时，
     (a) 全局规则注入层跳过「不要自称 AI」类硬约束（该约束现存于 global_rules，
     属实例覆盖层数据），(b) `persona_guard` 的「AI 自曝剥离」按开关放行直答
     （客户直接问「你是 AI 吗」时如实回答的话术模板进 prompt）。
     **设计决策**：披露走系统通知层、诚实身份走守卫放行层，两者独立开关——
     多数 B 端客户会开 ① 不开 ②（法规只要求「不误导」，不要求每句自认）；
   - `compliance.crisis_protocol_url`：运营方公示页 URL（进披露语可选占位）。
2. **危机协议导出物**：官网新增《危机干预协议》模板页（WS-1 一并做），引擎侧
   加只读端点导出「危机转介计数」（SB 243 2027-07 年报要求的核心数字——

## 5. 实施纪律（违反 = 生产事故，逐条有前科）

本仓是**生产机共享工作树**，所有 WP 实施必须遵守（详见各 rules 文件，此处是索引）：

1. **动工前探活 + 意向登记**：`engines\chengjie\scripts\agent_probe.ps1 -Intent "WP-N 主题 (涉及文件)"`；
   目标文件 ACTIVE（≤10min）或热区（`unified_inbox.html`/`ops_overview.html`/
   `skill_manager.py`/`personas.html`/i18n packs）先避让。收工 `-Done` 清除。
2. **重启纪律**：`.py` 改动攒批，唯一入口
   `deploy\instances\restart_instance.ps1 -Instance zhiliao`（先 `-Advise`，
   重启前跑 `scripts\restart_preflight.ps1`）；模板/i18n/多数 overlay 免重启。
   非紧急批次收敛到每日三窗 04:00/12:30/22:30(±45min)。
3. **热更新即生产**：模板/i18n pack 保存即生效——分步保存每一步必须自洽；
   内联 onclick 的函数写完立刻挂 window。
4. **前端双戳**：每批前端落地同时 bump `src/web/static/workspace/ui-build.txt` +
   相关 CSS `?v=`。
5. **i18n 单源**：新词条只进 `src/web/i18n_packs/<域>.py`（zh/en 键一一对应），
   禁往 `web_i18n.py` 单体加键；`window.T` 不留中文兜底。
6. **Feature flag**：新子系统 `config.example.yaml` 默认 `enabled: false`；
   桌面包/客户档经播种 overlay 开启。
7. **Overlay 写入保注释**：走 ruamel round-trip 写入器
   （`set_yaml_key_preserving`/`merge_yaml_patch_preserving`），禁裸 yaml.dump 整写。
8. **测试隔离**：测试绝不写仓库 `config/`（conftest 四层隔离已在），新测试写配置一律
   `tmp_path`；生产机跑回归用 `engines\chengjie\scripts\regression.ps1`（禁裸 `-n auto`）。
9. **收口跑广域门禁**：`powershell -ExecutionPolicy Bypass -File scripts\gate_sweep.ps1`
   （改前端/共享组件后跑 `-Full`）；别人门禁红了先报告别默改。
10. **媒体产物验证**（涉及语音/图片产物的 WP-6 等）：HTTP 拉媒体先看 Content-Type、
    落盘验 magic bytes、首样本验证通过前禁批量（`.cursor/rules/media-artifact-validation.mdc`）。
11. **完工记录**：每个 WP 合入后在 `docs/` 落 `实施NN_<WP主题>_2026-08.md`
    （沿用现有编号惯例），并回填本文档的验收框。
