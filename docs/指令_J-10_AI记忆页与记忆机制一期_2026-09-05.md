## 1. 背景：三视角问题清单（值守 2026-09-05 15:1x 分析，B 组按此做）

**开发工程师看到的**
1. 「待确认」＝`ai_inferred` 未 confirm；但所有条目都已参与召回，confirm 只提权——队列没有闸门语义，「采纳率」量的是坐席点击率不是记忆质量。
2. **跨语言接地 bug**：`memory_grounding.fact_grounded_in_user_msg` 按中文双字/英文单词重叠判锚定，抽取器把英文客户的话抽成中文事实 → 零重叠 → 全丢。88MP86 实锤：`接地护栏丢弃 2 条未锚定用户原话的事实: 客户一生只交过三个女朋友…; 客户结过一次婚`（BABY BEAR 英文语音亲口说的）；skuio 机整晚 `llm_count=0`。**外语客户基本零记忆**，页面上完全看不出来（只在日志 WARNING）。
3. 抽取漏斗不可见：入站 → 候选 → 接地通过 → 去重 → 入库 → 晋升，没有任何一层的计数进页面。
4. 晋升只认「重复 ≥2 次」（`stable_min_hits=2`）；没有「N 天无冲突且被召回过」信号；stable 永不裁剪 → 陈旧稳定事实。
5. 使用侧零埋点：哪条记忆被注入过哪轮回复没有记录 → 算不出价值（被用次数/贡献），也做不了「草稿旁可见」。
6. 运维工具（补全向量 / 键健康 / 键迁移 / 清理未识别 / 演示打码）与业务操作混在同一页同一层。
7. 「向量：已索引/无向量」是基础设施状态，暴露给用户。
8. 删除是硬删；编辑＝隐式转正；没有「不再使用」软状态。
9. 默认 limit 80，无分页/虚拟滚动；真实用户几千条。
10. 缺「AI 自身经历」层（说过的话/承诺/发过的东西）与实体关系（第三方人物）——#177/#171/#182 的共同根（业界：Hindsight 四网、Zep 时间图）。
11. 敏感类（健康/财务/身份/见面）无标记无门控（Claude 2026：敏感话题默认不存）。
12. 评测门禁 `memory_extract_eval` 没有跨语言用例。

**市场经理看到的**
1. 页名与词汇（情景记忆/向量/原始/稳定/过期/接地/未识别）是研发词，页面像数据库管理台；卖点应是「AI 记得你的每一个客户」。
2. 核心价值没被展示：记忆→关怀→目标推进这条价值链在页面上断的；没有「这条记忆帮 AI 说对了什么」。
3. 「38 条待确认」对用户是负面信号（AI 不靠谱还要我审）；应变成「AI 已记住 N 件事，有 M 件请你看一眼」。
4. 多语言市场（菲律宾/台湾/东南亚）——外语客户零记忆是致命卖点缺口（同上 bug）。
5. 隐私即卖点没写出来：数据在本机、可删可导、敏感类默认需确认。
6. 演示需求真实存在（有「演示打码」），但页面结构不适合讲故事——缺「一个客户的记忆时间线」。
7. 「采纳率（近似）」这类自我保护措辞不利传播；改「AI 记忆准确率（坐席抽检）」。

**用户（坐席/运营）看到的**
1. 想问的是「这个客户 AI 记住了什么、对不对、下次会不会用」；现在要先配筛选再点「加载」，空态是「点击加载」。
2. 38 条待确认没有优先级、没有「为什么要我看」；「全部确认属实」是唯一高效出口 → 审核形同虚设。
3. 记忆错了不知道来自哪句话（早期条目无来源原话），「在收件箱打开会话」不定位到消息。
4. 删除不可逆、编辑即转正，心理负担；想要「AI 别再提这件事」而不是删。
5. 术语看不懂（原始/稳定/过期/未识别/已索引/补全向量）。
6. 找不到「AI 自己说过什么、承诺过什么」；看不到「这条记忆上次用在哪句回复」。
7. 外语客户记忆几乎为空——他以为 AI 不记东西。
8. 6 列表格在桌面壳窄栏挤；清理/批量删除这类危险操作与日常操作同层。
9. 没有「今日需处理」入口，全靠自己翻。

## 2. 决策 D8（老板 2026-09-05 15:1x 已定方向：采纳 #183 提案 + 先修跨语言 bug；不引入 Mem0/Zep 第三方记忆层）

## 4. A 组 —— 机制（先做，4 件）

### A1 跨语言接地（P0 bug）
- `extract_memory_bullets` 的 prompt 改为**每条事实附客户原话引文** `evidence`（原语言、逐字、≤80 字），输出结构化 JSON；接地判据改为**引文级**：`evidence` 必须是 `user_msg` 的子串（归一化空白/大小写/标点后）或 token 重叠 ≥60%，事实文本本身不再参与匹配 → 语言无关。引文存进 `source_quote`（现有列，早期条目为空）。
- 无 `evidence` 的事实 → 丢（沿用「宁可漏记」）；`evidence` 与 `user_msg` 不符 → 丢并计数（防 LLM 编引文）。
- `human_outbound_memory.filter_grounded_facts` 同款切换（人工出站也可能是英文）。
- **观测**：丢弃计数按原因（`no_evidence` / `evidence_mismatch`）进 `admin_summary` → 页面「有 N 条因无法核对原话未记录」；日志保留 WARNING。
- 评测：`src/eval/memory_extract_eval.py` + 语料加英文/混语用例（「I have a daughter and she is my greatest treasure」→ 期望「客户有一个女儿」被保留；AI 臆测句仍必丢——Phase8 事故语料一条不能过）。
- 验收：`tests/test_memory_grounding.py` 旧 9 例全绿 + 新跨语言例；`python -m scripts.run_eval --memory-extract` 召回不降、误抽不升。

### A2 「待确认」改例外队列 + 自动转正
- store 新字段：`review_reason`（`conflict` / `high_impact` / `low_confidence` / `self_fact` / `commitment` / 空）、`impact`（`high`/`normal`）、`status`（`active` / `ignored` / `stale`，替代硬删默认）；幂等 ALTER。
- 入库时打标：高影响词表（金钱/转账/见面/地址/健康/身份证件/家庭成员）→ `high_impact`；与同槽 stable 冲突 → `conflict`（**不再自动覆盖**，两条并列 `conflict_group`）；LLM 置信 <阈 → `low_confidence`；`author=human`/AI 自我事实 → `self_fact`；承诺类（`outbound_promise_guard` 已有词表）→ `commitment`。
- `consolidate()` 加第二条晋升路径：`age ≥ promote_days(7)` 且 `recall_count ≥ 1` 且无 `conflict` → stable；配置 `memory.consolidation.auto_promote.{days, min_recalls}`。
- 「待确认」列表只显示 `review_reason` 非空的条目；其余不进队列。`confirm` 语义不变（转正 + 清 review_reason）；新增 `ignore`（软删）、`resolve_conflict(keep_id)`。
- 验收：单测覆盖五类打标、自动转正、冲突并列不覆盖、软删不召回可恢复。

### A3 召回记账（使用侧地基）
- 新表 `episodic_recall_log(ts, memory_key, row_id, conversation_id, chain, draft_or_reply_id)`，skill_manager 记忆注入点（`get_bullets_for_prompt` 返回后）**一行**写入，best-effort 零阻断；`episodic_memory` 加 `recall_count` / `last_recalled_ts`（A2 的自动转正依赖它）。
- 新接口 `GET /api/episodic-memory/used?conversation_id=&limit=`（最近一轮/最近 N 轮用了哪些条目）→ 供 J-4 在草稿旁渲染「本轮用了这几条记忆 · 一键不再使用」（前端落点交 J-4；本条只出接口 + 在 `episodic_memory.html` 的会话抽屉里先做一个「最近被用」分区自证接口）。
- 验收：注入一次 → log 一行；`recall_count` 递增；接口按会话返回。

### A4 「AI 自身经历」入口（一期只做入口，不做完整层）
- 同一客户档案抽屉加分区「人设说过 / 承诺过」：读 `_human_said_log`（J-1 #177）+ `_media_sent_log`（发过的媒体）+ `outbound_promise_guard` 的承诺记录（若有持久面；没有则只显示前两者并在落点表写明「承诺持久化归二期」）。只读展示 + 「删除这条记录」。
- 验收：人工发过「我有个女儿」后抽屉里能看到；不影响任何注入逻辑。

## 5. B 组 —— 「AI 记忆」页重构 + 人话化 + 美化（A 组落点表读完再开）

### B1 信息架构：按客户为主视图
- 页面三层：**顶部**「今日需处理 M 件」（例外队列入口，按 review_reason 分类计数）+ 「AI 已记住 N 件事 · 覆盖 U 位客户 · 近 7 天新增 X」+ 「有 D 条因无法核对原话未记录」；**左栏**客户列表（昵称/头像/记忆数/待看红点/最近更新，搜索昵称·内容·手机号）；**右栏**该客户的**记忆时间线**（分组：基本信息 / 关系与家人 / 偏好与习惯 / 近期事件与约定 / 人设说过·承诺过；每条：内容 · 客户说的/AI 推断 · 来源原话可点 → `open-conv` 定位到那条消息 · 上次被用 · 被用次数）。
- 现有「列表」视图降为「全部记忆（表格）」次级 tab，保留搜索/排序；「按人分组」抽屉升格为主视图。
- 空态：「AI 会在聊天里自动记住客户说过的事。先打开一位客户 →」（不再是「点击加载」）；首次进入自动加载最近活跃客户。

### B2 例外队列体验
- 每条例外卡片说明「为什么需要你看」（冲突：两条并列 + 「保留哪条」；高影响：红标 + 「确认/忽略」；低置信：「像是这样吗？」；自我事实：「这是人设的设定吗」；承诺：「已兑现/未兑现」）。
- 批量动作只对同类型：「本客户的低置信全部确认」；去掉全局「全部确认属实」。
- 处理完自动跳下一条；目标日均 <5 的口径写在页头（「今天 3 件」）。

### B3 人话化（i18n 双语，`episodic_page.py`）
