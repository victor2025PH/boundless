## §〇 先答一问：为什么 09-04「L3/L4 全放行只记录」没有豁免项，客户说了「别再写了」还连发两条？

**答：09-04 的 #160 v2 把「风险扣稿」整体理解成了「敏感词误伤」问题，于是把整张 L3/L4 表**无差别**改成 shadow；`stop_contact` / `self_harm` 只被当成「要人看的两个 reason」进了即时告警，没有进发送行为。** 三层：

1. `src/inbox/autosend_policy.py`（09-04 v2）：`decide()` 在 `auto_ai` 下对任何 `would_hold_level ∈ {L3, L4}` 一律 `level=L2 + 空 hold_reason + ShadowRecord`——**hold_reason 是什么不影响 level**。`_REASON_PRIORITY` 把 stop_contact / self_harm 排最前，只用来给台账分桶与 `autosend_shadow_log.maybe_alert` 推值守群（文案「已放行，如需止损请人工介入」）。事故当晚这条告警**发了**（台账 hold 行 21:00:26 / 21:02:18 都在），只是没人能在 13 秒内介入——「不拦只报」对秒级自动发送等于零。
2. 放行的初衷是 09-04 事故「Yes you did because I was happy chatting with you i didn't want to stop」被 `"stop" in t` 子串命中 → L4 静默不发、用户只看到「全自动不工作」。当天同时做了整词化 + 否定式排除，分类器修好之后**扣稿本身已经不会再误伤那句**，但决策仍按「一个月后再定规则」把所有 reason 全放行，没有给「客户明确要求停联」留一条硬底线。
3. 词表缺口：`_STOP_CONTACT_EN` 里 `(don't|never) (contact|message|text|call|write to) me` 要求 **write to**，「Never write me again, please」（21:03:38）漏判 → `shadow=-` → 连告警都没有，第三条照发。中文缺「拉黑」「别烦我」。

**修法 = 在单一入口 `decide()` 加两条豁免（D-O1），其余结构不动**：① stop_contact / self_harm → `hard_stop` 一律带出（不看 policy_mode / 档位），shadow × auto_ai × 未冻结 → L2「最多一条」（停联 = 告别模板，不发 AI 稿；自伤 = AI 那一句陪伴照发，与 R8 危机穿透同向）→ 调用方冻结会话；② risk=high 非停联 → L1 转人工审。medium 仍按 09-04 放行进台账。09-04 的台账 / 告警 / enforce 反向验证基线全部保留（enforce 旧表逐字 L4，测试钉住）。
