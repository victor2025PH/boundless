### 1.1 ⚠ 两个数据可信度缺口（必须先修，否则后续裁决无效）

**缺口 A：没有分母。** `assistant-ball.js` 的 `orbBeacon` 只发 5 个 `asb_orb_*`

没有「点球打开面板」、没有「提问」、没有「点了大家常问 chip」、没有「切 tab」、
没有「提交报障」。因此 101 是「页面加载了球」，**真实打开率至今未知**，
本方案的任何改动都无法量化验收。

**缺口 B：口径自相矛盾。** `asb_teach_click` = 8，但 `asb_teach_term_hit` 与
`asb_teach_term_miss` **都是 0**。按 `assistant-teach.js:384-386`，每次 `showBubble`
必发其中之一，两者之和应等于 click 数。已排除落库封顶（`ui_event_trend.py`
`_DAY_ACTION_CAP=150`，实际 distinct action 仅约 25）。剩余可能：坐席机跑的
teach.js 版本早于 term_miss 上线（实施62 §1.1 新增），或 beacon 链路在该路径断了。
**校准前，上述数字只作方向性证据，不作精确裁决依据。**

**P0-2 结论（2026-08-27）**：按日拆解 + 代码复核后判定为**同日版本错位**，
不是链路断。依据：① 全部 8 次 click 与 term_miss 的上线**同在 08-23**，
而当天该文件正被热更多次改写（VER 20260823g 是当日第 7 版），点击发生在
beacon 落地之前完全成立；② 现网实测三模块均为最新版且 `showBubble` 的
hit/miss 分支健在；③ 无法用 git 复核（见 §9.2 —— `shared/assistant/` 从未进过
git）。**处置：不改代码**，等 P0-1 的新埋点跑出第一周真实数据后自然验证
（届时 `term_hit + term_miss` 应等于 `teach_click`；若仍不等，才是真断链）。

## 2. 五视角问题清单

### 2.1 开发工程师视角

1. **三大功能是「外挂」进面板的，不是面板的一部分。**
   `assistant-ball.js` 只渲染骨架（`renderPanel()` @1263）；教学与替我做由
   `assistant-teach.js` / `assistant-agent.js` 各自 `MutationObserver` 监听
   `.asb-panel`，再 `panel.insertBefore(row, tools)` 插入 `.xzt-row` / `.xza-row`
   （teach @185、agent @426）。**升格为一级模式 = 推翻这个注入模型**，而
   `tests/test_orb_sibling_dom_contract.py` 正是钉住该 DOM 契约的——必须先改协议
   与门禁，再动渲染。

2. **版本戳有 7 个手工同步点**（实施时才发现是 7 不是 6）：三个文件各一个 `VER`
   + 两壳 loader 各一份 `?v=`（`base.html` ~1702、`workspace_base.html` ~4266）
   + **`src/web/routes/assistant_pair_routes.py::_AGENT_JS_VER`**（手机页 `/xz`
   服务端注入 agent 组件时自带的戳）。第 7 个是 P0 实施时被
   `test_assistant_pairing.py` 抓出来的——方案阶段漏数了。
   漏改一处，不是门禁红就是线上跑旧版。

3. **样式三套并行**：`--as-*`（ball）/ `--xzt-*`（teach）/ `--xza-*`（agent），
   三份 `injectCss()` 各自映射同一批宿主 token。**不先合并就做不出视觉统一的模式条。**

4. **埋点缺分母 + 口径存疑**（见 §1.1）。

5. **热更与打包双轨 → 分叉期**。`shared/assistant` 在 zhiliao 走 HTTP 热更即时生效，
   坐席机桌面包走 PyInstaller `_MEIPASS` 拷贝、需新安装包。整屏重构会出现
   「总部新版 / 坐席旧版」窗口，且两版 DOM 契约不兼容。

6. **规模已到临界**：ball 2445 + teach 737 + agent 1763 = **4945 行**，全 ES5、
   字符串拼 HTML、无构建。继续往 `renderPanel` 里堆模式路由会加速腐化。

7. **i18n 双轨无定论**：`i18n_packs/assistant_ball.py` 的 55 键（`asb.*` + `ov2_as_*`）
   服务于路由 `tr()` 与 ops 卡；**面板 DOM 文案在各 JS 内的 `I18N` 对象**。新面板词条
   进哪边没有定论 → 容易写死中文，伤白标与出海。

8. **常问数据源存在但不够用**：`assistant_routes.py:231` 的
   `qa_log.top_questions(days=14, limit=5, page=...)` 是页级真实高频，
   但**无全站口径、无分类、无搜索**——完整面板必须扩端点。

### 2.2 市场经理视角

1. **最强差异化被做成脚注**：三大功能是相对「又一个客服系统」的全部差异，现在是
   面板最底部两行**虚线小按钮**，视觉权重低于上方「问功能 / 报障 / 学操作」三张实心卡。
2. **手机操控零成功配对 = 白做**：这是天然的销售「哇」时刻（扫码 → 手机说句话 →
   电脑设置改了），至今一次完整演示都没有。
3. **「替我做」没说清边界**：后端 20 个动作（4 个 L0 查询 + 1 导航 + 15 个 L2 写入），
   用户只看到「一句话交给小智」——不知道能做什么就不敢用，也不敢卖。
4. **「手机操控」是技术词不是收益词**：听起来像远程桌面，实际价值是「不用坐在
   电脑前也能指挥」。名字本身在劝退。
5. **新手心智没被接住**：线上「大家常问」真实条目里有 **「我是新手，不会用。」**
   ——产品自己采集到的最强信号，面板里却没有任何新手路径。
6. **没有价值回收**：`src/ops/value_report.py` 的 AI 价值周报里，小智替坐席做了多少次
   操作、省了多少步，一条都没有。老板看不到就不会推。
7. **白标风险**：面板名已走 `dispName()`/brand，但模式名若写死中文会露馅。

### 2.3 用户视角（坐席 / 老板）

1. 打开先读 **4 行欢迎文字**才知道能干嘛。
2. **同一件事两个入口两个名字**：大卡「学操作 · 点哪教哪」与底栏「教学模式 ·
   点哪学哪」点下去是同一个 `XZTeach.start()`。
3. **最该看到的承诺被截断**：「进入后点击页面任意位置看讲解，不会真…」——
   「不会真的执行操作」被吃掉，这正是没人敢点教学模式的直接原因之一。
4. **虚线框 = 未完成**：`border:1px dashed`（teach.js:146、agent.js:255）在所有设计
   系统里都表示占位/拖放区。主功能长成这样，第一反应是「还没做好」。
5. **点「替我做」会发生什么不知道**：会不会直接改我的设置？后端其实有确认卡和撤销，
   但点之前看不到任何「会先给你看计划」的承诺。
6. **扫完码手机上能干嘛，零字说明。**
7. **「做过什么」是第四个按钮**：真要撤销误操作时根本找不到。
8. **「动效：饱满」看不懂**：画质档偏好常驻功能区。
9. **大家常问一半是别人的问题**（如「怎么给客户退款打八折并兑现」）→ 觉得小智不懂我。
10. **窄屏很痛**：桌面壳 405px 下要滚很久才到底部功能按钮。
11. **两个 AI 入口挨着**：面板下方紧贴右栏 copilot 的「AI 生成图片」卡，不知该用哪个。

### 2.4 美术设计视角

1. **一屏四套形态语言**：tab 下划线 / h3 实心圆角卡 / chips 实线胶囊 / 三大功能虚线胶囊。
2. **虚线是语义错配**（同 2.3-4，既是 UX 也是视觉问题）。
3. **强调色被稀释**：全屏只有一个蓝紫 `#4f6ef7`，在四个虚线按钮上平均分配——
   四个都强调等于一个都不强调。
4. **emoji 当图标**：💬🐞🎓⚡📱📜 跨平台三套渲染，无法统一描边/尺寸/色彩，
   且 🎓 出现两次（大卡 + 底栏）。
5. **垂直节奏接近等距**：各区块间距都在 `.4rem–.8rem`，无呼吸感、眼睛找不到落点。
6. **打开面板 = 品牌消失**：实施59 给球做了活体能量核（极光层 + 粒子 + 声波涟漪 +
   bloom），**面板里一点都没有**，是普通灰底卡片。
7. **深色无自持基线**：靠宿主 `--tk-*` / `--card` 继承，虚线在深底上几乎不可见。
8. **空态全是「…」或纯文字**：报障 / 我的 / 常问 三面板零插画。

### 2.5 UI/UX 设计专家视角

1. **信息架构错层——五类东西平铺同层**：模式（怎么帮）、通道（手机）、内容（常问）、
   记录（工单/历史）、设置（动效）。**这才是「不清爽」的根因**：不是元素太多，是类别太杂。
2. **重复入口普查**：报障 2 个（tab + 大卡）、教学 2 个（大卡 + 虚线按钮）、
   问答 3 个（大卡 + chips + 输入框）。删重复即可砍掉近三分之一可点目标。
3. **首屏可点目标约 17 个**，且层级差异极小 → Hick's law 直接税。
4. **没有自治档位（autonomy）显示**。2026 年 agent UX 的核心共识（Smashing Magazine
   *Designing For Agentic AI* 的 Autonomy Dial、aiuxdesign.guide 的 Autonomy Spectrum、
   Cursor 的 Ask/Edit/Agent）是**在动作发生的地方显示当前权限档**。后端已有 L0/L1/L2
   分级与确认卡，**UI 上完全没暴露**，用户只能靠猜。
5. **没有独立活动面板**。多份 2026 研究（Zylos、Fuselab、Hatchworks、Brainy）结论一致：
   agent 必须有**与对话流分离的 activity panel**（计划 / 进度 / 收据 / 撤销）。
   我们把它压成了一个叫「做过什么」的小按钮。
6. **输入框无模式感知**：placeholder 恒为「输入问题，回车发送…」。
7. **空态被浪费**：空态是最好的教学位，现被 4 行文案 + 通用 chips 占满，
   而非「本页你可以问什么 / 学什么 / 让我做什么」。
8. **可访问性欠账**：tab 用 `<button>` 无 `role="tablist"` / `aria-selected`；
   模式条做 segmented 需 `role="radiogroup"` + `aria-checked` + 方向键 +
   `prefers-reduced-motion` 时禁滑块动画。
9. **窄屏只拉宽未重排**：`@media` 仅 `left:8px;right:8px`，密度一点没变。
10. **反馈闭环未闭**：有 👍👎，但「这条没解决 → 转报障」的 `to-report` 不显眼。

## 3. 目标信息架构

**设计主张**：把「小智怎么帮我」升格为一级导航，把「我的东西」降格为次级页签，
让每个面板只装一类内容。

```
┌──────────────────────────────────────┐
│  ✦ 小智 · 替我做          [📱•] [✕]  │  手机=通道，标题栏图标 + 连接状态点
├──────────────────────────────────────┤
│  ┌─────────┬─────────┬─────────┐     │  ← 模式条（主视觉，滑块指示）
│  │ 💬 问答 │ 🎓 教学 │ ⚡ 替我做│     │
│  └─────────┴─────────┴─────────┘     │
│                                      │
│        （只放当前模式的内容）          │
│                                      │
├──────────────────────────────────────┤
│  [说一件要我做的事…]        [🎤] [→] │  ← placeholder 随模式变
│  报障 · 我的 · 常问 · ⚙              │  ← 次级页签（弱视觉）
└──────────────────────────────────────┘
```

### 3.1 为什么手机操控不占模式条第四格（已拍板）

它**不是第四种能力**，它是「替我做」的**远程输入端**——同一个
`/api/assistant/agent/plan` + `/act`，只是嘴巴换到手机上。做成第四个平级模式，
用户会以为是另一种能力，反而更看不出它与「替我做」的关系（这大概正是
`pair_open` 只有 1 次的原因之一）。

**落法**：标题栏图标 + 连接状态点（未配对灰 / 已配对绿 +「手机已连」），
**同时**在「替我做」模式内给一张大卡「换个说法：用手机指挥」。两处曝光，语义诚实。

### 3.2 各面板承载物（清爽 = 每个面板只装一类）

| 面板 | 只装 | 从别处搬走 / 删除 |
|---|---|---|
| **问答** | 一句话欢迎 + 本页相关 3 条建议问题 + 对话流 | 删 3 张 h3 卡（全是重复入口）；5 条 chips 减为 3 条并移走「全站高频」到常问 |
| **教学** | 状态卡 + 「开始点哪学哪」大按钮 + 副按钮（带我走一遍 / 教我这个页）+ 本页可讲解 N 处 + 安全承诺全文 | 从底栏虚线行升格 |
| **替我做** | 任务态优先（在跑=进度时间线）；空闲=说一句 + 本页能力 chips + 「最近做过」3 条 + 自治档说明 + 手机指挥卡 | 「做过什么」按钮并入；从底栏虚线行升格 |
| **报障** | 描述 + 截图 + 环境 + 提交 | 去掉与问答重复的引导 |
| **我的** | 工单列表 + 刷新 | 不变 |
| **常问**（新） | 本页高频 / 全站高频分组 + 搜索 + 点击直接切问答并发问 + 空态 seed | 承接原 chips 的「全站」部分 |
| **⚙**（新） | 动效档 + 语音开关 + 术语提示 +（admin）快捷键 / 命令面板 / 引导 / 诊断上传 | 「动效：饱满」从功能区移入 |

**量化收益**：首屏可点目标 ~17 → ~12，**主视觉层级只剩 3 个大目标**。

## 8. 外部参照（2026 年做法，用于佐证而非照抄）

- **Autonomy Dial / Autonomy Spectrum**（Smashing Magazine 2026-02；aiuxdesign.guide）：
  四档 Observe&Suggest → Propose&Confirm → Act&Notify → Full Autonomy，
  **按任务类型存档位而非全局**，且档位必须显示在动作发生处。→ 对应 P2-3。
- **Activity panel 与对话流分离**（Zylos / Fuselab / Hatchworks / Brainy 四家结论一致）：
  chat 负责意图输入与澄清，activity panel 负责计划 / 进度 / 收据 / 撤销的可审计日志。
  → 对应 P1-7、P2-4。
- **Agent UX 成熟度三级**（Hatchworks）：L1 chat-first（只能做 demo）→
  **L2 guided agent（taskboard + 时间线 + 收据 + 人工检查点，v1 应瞄准这里）**→
  L3 trusted autonomy。→ 小智当前在 L1.5，本方案目标是 L2。
- **空态 3-4 条建议提示**是 chatbot UX 单项收益最高的模式；一旦有历史即让位。
  → 对应 P1-3（chips 5 减 3）与「常问」独立成面板。
- **Progressive disclosure**（Nielsen 1995 → 2026 agentic 版）：新手看到干净表层，
  深度一键可达、可折叠、记住用户偏好。→ 对应 §3.2 的面板分工与 ⚙ 收纳。
- **Segmented control 可访问性规范**：`role="radiogroup"` + `aria-checked` +
  方向键 + 标签不截断 + `prefers-reduced-motion` 禁滑块动画。→ 对应 P1-1。
- **2026 视觉走向**：material realism（层叠卡 + 柔和高度 + 模糊而非硬描边）、
  purposeful motion（<200ms 反馈动画，reduced-motion 为默认考量）、
  玻璃拟态回归但须守对比度并提供降透明选项。→ 对应 P3。

### 11.2 五个设计决定

1. **计数与导览必须同源**。「本页 12 处可讲解」而导览只走 5 站，用户不会理解成
   两个口径，只会认为导览坏了。故只留**一处** `querySelectorAll(PICK_SEL)`
   扫描，计数与导览都从它取数，门禁数着这个数字（`== 1`）。
2. **三态各说各话，绝不把「还没加载」洗成「0 处」**。词典在 workspace 壳是
   `GET /api/assistant/terms` 异步下发的：`-1`＝在路上、`-2`＝取不到、`0`＝本页
   真的没有。混成一个 0 不只是文案问题——**P2-2 的补货清单正是照
   `asb_teach_cov_0` 去补的**，谎报没备货会直接把补货补错页。
3. **覆盖率落成三桶埋点**（`asb_teach_cov_0` / `_lo` <5 / `_ok` ≥5）：beacon 只能带
   action 带不了数字。按页看 `cov_0` 的分布，就是 P2-2「该给哪页铺 `data-anchor`
   / 补词条」的采购清单。每页每桶只发一次，否则反复开合面板会把分母灌水。
4. **状态行样式写进 `assistant-ball.js`**，不写进 teach 自己的 `xzt-style`。
   `.asb-md-*` 是球提供的模式卡样式族（P0-4「三套变量合流」的成果），teach 自带
   一份就是当场再分叉一次。代价是 ball 也要 bump 一版，值得。
5. **只 bump ball 与 teach 的 `?v=`，agent 保持 `20260828a`**。版本戳门禁是**逐文件**
   比对（组件内 `VER` ↔ 该文件的 `?v=`），三者不必同版；`_AGENT_JS_VER`
   （第 7 个同步点）只属 agent.js，本批未动。§10.6 说的「三者版本恒一致」是
   描述那一批的事实，不是约束。
