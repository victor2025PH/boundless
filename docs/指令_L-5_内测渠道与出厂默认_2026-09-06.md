## 2. A —— 出厂默认进基础配置（D-L1 半边）

**修法**：`config/config.yaml` 三键默认改 `true`（与 `cloud_light.yaml` / `config.desktop.internal.yaml` 一致，后两者保留但不再是唯一来源）；`config.example.yaml` 文档段同步；`background_tasks.py` 启动日志现有 WARNING 逻辑不改（默认开后自然变 ✅）。**用户显式写过 false 的机器不动**（`_ensure_baseline` 三态语义）。

## 3. B —— 内测渠道（D-L1 另半边）

**目标**：两台内测机以后能拿到 seed-data 的包，而不靠人手推。

**修法**（选其一，落点表写明）：
- **B1 独立渠道**：`publish_chatx.ps1` 加 `-Channel internal`：把 smart 包也上传到 R2/VPS 的 `internal/` 路径并生成 `latest-internal.yml`；桌面壳 `autoUpdater` feed URL 按 `ui_visibility.flavor=internal`（或安装时写入的 channel 文件）选 `latest-internal.yml`。内测机一次性切渠道后自动更新拿 smart 包。
- **B2 推装**：沿用 `push_chatx.ps1 -TargetSsh …`，把两台内测机加进目标清单（需要 SSH 可达——内测机不在我们 LAN，大概率不可达 → 优先 B1）。
- 无论哪种：`chatx_fleet_status.ps1` 输出加「edition: smart/clean（有无 seed-data）」列，以后一眼看出谁装的什么包。

**验收**：坐席机 yunsheng 切 internal 渠道 → 自动更新拿到 smart 包 → boot 日志出现「已播种功能 overlay」或「功能 overlay 已按种子补齐 N 个缺失键」。

## 4. C —— 种子缺席可见
