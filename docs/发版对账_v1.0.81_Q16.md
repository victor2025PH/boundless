## 2. E — `err=ai:target_lang_mismatch` 排查（只读）

**样本**：skuio（fp DC8F，1.0.79）四份报告 `tmp_diag\{Z4NFJ7,G229PJ,SFFR2H,VUDAJP}` 去重后 **52 条**（01:20:36–05:51:16）。zhiliao 近 24h：`engines/chengjie/logs/app.log` 停在 08-11、进程 15756/17728 无落盘日志、IDE 无相关终端 → **zhiliao 侧本轮无样本**（不臆造）。

**#275 裁剪是否波及翻译 system 提示**：**否**。翻译走 `AIEngine.bare_chat` → `generate_reply(context={_bare_system: 英文机翻 system ≈80 token})`，`_build_system_instruction` 在 `_bare` 处直接 return（`ai_client.py` L3070），不装人设/记忆/注入；一次翻译 prompt 总量数百 token，远低于旧预算 6000。52 条事件前后无一条 `[ai] prompt_tokens=… trimmed=` 与之相邻（报告里唯一一条 01:21:06 是 WA 会话的起草）。`4fdd238f` 的裁剪器改动对翻译路径是空操作。

**判定**：`target_lang_mismatch` = `_output_lang_sane(out, target)` 判「输出脚本与目标语不符」（CJK 目标输出零 CJK / 拉丁目标 CJK 占比 > 0.2）。同一文本在 45 分钟内每次真打引擎都稳定失败 → **不是限流/余额抖动**（那会是 `provider_unavailable` / `license`，且充值后应恢复），是模型对该 prompt **可复现地输出了错误脚本**。「充值后仍现」与此吻合。

**卡点（修不了的原因）**：`[xlate]` 出口行 **不带 `tgt=` / `src=` / 引擎序列**，52 条无一能判定目标是 ja / zh / en——三个候选根因都需要它：① 1.0.79 主链模型名仍是退役别名 `deepseek-chat` → 官方路由到 V4.1 但「关思维链」按模型名 `deepseek-v4*` 判 **漏发**（`4fdd238f` 改为按主机下发）→ 混合推理模型内容/推理串扰；② 备用池硅基条目套用主链 `thinking` extra_body → 422 或 `</think>` 混正文（同 commit 修）；③ 「收→中」入站显示翻译对拉丁文短句模型原样回显。①② 都已随 `4fdd238f`/1.0.80 上架，**skuio 升 1.0.80 后若不再复现即可闭环**。

**建议（立单，不在本线改）**：
1. `translation_service._log_xlate` 加 `tgt=%s src=%s`（1 行；文件是成本对账线在途，本线不碰）；`AIEngine.translate` 判 mismatch 时再落一行 `out_len= out_cjk=`（不落正文）。
