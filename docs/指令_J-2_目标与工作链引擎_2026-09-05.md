## 2. A —— #166 工作目标「自动推进」不推进

### 原话
> 「分析我这里的工作目标为什么没有执行，调取我这边的操作日志，重点分析是否我的工作目标引擎又关闭了」（图 1166：BABY BEAR/Loki 会话，右栏「自定义目标 · 进行中 · 自动推进 · 当前：收口 · 第 1/1 天 · 89%」）

### 证据（全部已核，直接用）
- 会话键：BABY BEAR = Loki = `whatsapp:17345893506:13308422244`（图 1166 电话 133****44）。该会话在 88MP86 窗口内有**几十条** `auto_generate_draft`。

- 88MP86 backend.log **9.5 小时零 `[goal-inject]` 行**。按 `src/companion/goals/service.py` L921-940 `_note_meta`：`injected` 与所有 `NOT injected reason=…` 都是 INFO，**只有 `no_goal` / `disabled` 是 DEBUG**。`disabled` 被 config 排除 ⇒ 每一轮拟稿都走了 **`no_goal`**，或 `store.find_active_goal`（`store.py` L262-307）内部异常被 `except → debug → None` 吞掉后表现成 no_goal。
- 而右栏卡片（`goal_routes.py` L365 `/api/goals/for-conversation` → 同一个 `find_active_goal(conversation_id, platform, chat_key, account_id)`）**能查到**这条目标。同一函数、同一库，一边有一边无 ⇒ 拟稿链传入的键与卡片传入的键不同（`conversation_id` 空/形态不同、`account_id` 不同导致 L289「账号锁」精确匹配落空、或 `status` 非 active 但卡片仍显示进行中），或读库异常。
- 「第 1/1 天 · 89%」是**时间进度**（#152② 原话「显示第 3/3 天却零推进」同病）。

### 修（四步，前两步是确定性缺陷，后两步是决策 D1 落地）
1. **可见性**（`service.py::_note_meta`）：`no_goal` 在 `conversation_id` 非空时升 INFO 并带**全部查找键**（`conv=… plat=… chat_key=… acct=…`），按会话 10 分钟节流防刷屏；`store.find_active_goal` 的 `except` 升 WARNING 带异常类名。`_inject_goal_context`（skill_manager L6559 `debug("goal inject skipped")`）那层的吞异常你不能改——在 `build_block_for_chat` 入口自己 try/except 记 WARNING 后再 re-raise 即可。

## 4. C —— #167 首次登录不该直接全自动（skuio 提案；同族钧 #63 / skuio #156）

### 原话
> 「默认人设新用户启动应该处于关闭状态……首次登录直接进入全自动，所以首次登录之后，默认都是非全自动，全自动由用户开启，因为首次登录还没来得及绑定人设，全自动就全发消息出去，就容易出错误」

### 证据 / 现状
- 88MP86 config：`inbox.auto_draft.bootstrap_automation_mode: true`（L35）与 `onboarding.enabled: true`（L918）并存；`automation_mode.py` L126 `_account_mode_layer` L144-145 会读 `bootstrap_automation_mode`。
- #63 的 fix_note：「新登录的账号在设置页确认 全自动/拟稿人审/关闭 之前，一律按拟稿人审运行」（`account_mode_onboarding`）。#156（1.0.72 `933da0f8`）：新登录账号不再自动套默认人设。
- B44 事故（钧客户端在报障群自动代答）就是「新号 + bootstrap 全自动 + 默认人设」这个组合。

### 修（先核再改）
1. 读 `automation_mode.py` L126-200 + `account_mode_onboarding.py`：确认「账号未在设置页确认档位」时 `_account_mode_layer` 的返回是否**优先于** `bootstrap_automation_mode=true`。若 bootstrap 仍能把未确认账号推成 `auto_ai` → 改成 onboarding 未确认恒 `review`，bootstrap 只对已确认账号生效。
2. 首条入站真发前的最后一道：`persona` 为账号默认/全局默认（非用户显式绑定）且账号 onboarding 未确认 → 不真发只拟稿（与 #156 精神一致）。
3. 单测覆盖矩阵：{onboarding 未确认/已确认} × {bootstrap true/false} × {人设显式/默认} → 期望档位。

### 验收
- 新登录账号（无确认记录）首条入站：草稿生成、**不投递**；确认全自动后才投递。
- #63 / #156 / #167 三单在落点表里写同一结论，值守一并回访。
