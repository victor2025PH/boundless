## 1. 开发工程师视角

### 1.1 架构：一厂一队一闸（全部复用既有底座）

**歌房工厂（supply factory）**＝`scripts/song_factory.py`（song_prerender 改造升级）：
- 三条生产线：`casting`（新嗓选角：提示词×N seed 抽签）/ `cover_direct`（认可成品
  直存——今晚手工干的活收编进 CLI）/ `remix`（换词保嗓：ref=锚定 take，
  strength 0.45~0.55，女 24~28s / **慢板男 34s**（8-23 实测常数））；
- **统一收尾闸产品化**（今晚 tmp 版收编）：verbose ASR 末句词尾 → 3s 内最深能量
  谷 +0.4s 收刀+淡出——「画布填充污染」（词尽后 ACE 自填怪音/男声，8-23 实锤）
  在闸内根治；
- **五道质检全自动**：RIFF magic → 四句 ASR 逐句 ≥0.5（缺一句即弃，重抽 ≤5 seed）
  → 自然收尾 → campplus vs 锚定样本 ≥0.75（同嗓不变量）→ 时长带 12~35s。
  单次合格率实测 3~5 成，5 抽累积 >90%；
- **176 显存编排舞步进 CLI**（今晚实锤三坑机制化）：任务前 ollama keep_alive=0
  卸载 + park singing/sbv2/ace；ACE 任务后必 park（torch 缓存 ~10.9G 不回落自阻
  塞）；全程尊重 /api/song/yield 直播让路；失败重试带 VRAM 原因分类计数。

## 2. 市场经理视角

- **差异化主张**：竞品没有「人设开口唱+把你的名字唱进歌里」；传播钩子=晒图/
  晒音（「AI 女友给我写了首歌」），分享面天然带获客。
- **变现阶梯**（与命理同模）：曲库免费（留存/惊喜）→ 专属歌=付费 SKU
  （catalog `custom_song` 建议 $6.99~9.99，锚 bazi_reading $4.99 之上——有实际
  GPU 成本+稀缺感）→ 会员权益含 N 首/月。免费专属歌灰度期先跑通质量，再开闸
  收费（monetization gate 既有链，零新基建）。
- **软引导不硬卖**：免费唱完后低频 offer（「想不想要一首只属于你的？」），
  被拒即静默；绝不在情绪低谷推销。
- **放量四阶段**（数据闸推进，都能回滚）：
  ① 点名+场景灰度（本周）→ 读 requests/sent/complaints；
  ② 曲库 ≥3 首/嗓后开主动献唱低概率 → 读回复率反哺（media_feedback 加 song 臂）；
  ③ 专属歌 review 档免费灰度 20 单 → 读审核通过率/送达时长/客户反应；
  ④ 付费开闸 + 会员权益。
- **风险与对策**：新鲜感衰减→repertoire 工厂常态补货（周 2 首节奏）；质量投诉
  →投诉词表+每联系人静音+ops 卡可见；版权→供给台账 source 字段强制
  origin/pd，营销话术禁「点歌任意唱」。

## 3. 用户视角

- **惊喜时刻排序**（触发时机>曲目数量，实施57 结论延续）：点名要=必回应；
  生日=高光时刻（尽量带称呼版专属）；晚安=陪伴感；主动献唱=稀有彩蛋（宁缺
  勿滥）。
- **诚实与可爱**：点名唱《七里香》→「那首我不会唱诶～不过我自己写过一首，
  唱给你听？」——拒绝转供给，绝不装会；录废了→「今天嗓子不给力，改天补你」
  ——失败也是人味。
- **拟真节奏**：专属歌不秒回——「等我哦，去给你录一首」+ 几分钟后语音到达，
  比瞬间生成更像真人；深夜下单次日晨送（安静时段护栏顺带成全拟真）。
- **听感规格**：15~30s 清唱段（语音消息的自然长度，不是 3 分钟成品歌）；同一
  人设唱歌嗓恒定（锚定 take 契约）；说话嗓≠唱歌嗓对真人也成立，不解释不道歉。
- **控制权**：「别唱了」立即静音且不再主动；负反馈进投诉观测；英文客户在英文
  模板批落地前一律不唱（语言闸）。

### 10.1 声音不符——根因与修复路线（核心问题）

**根因不是 bug 是路线遗留**：8-22 人耳裁决把 SVC 转换路（音色像 0.82 但唱法
机械「太假」）判死，改走声选角路（唱法自然但音色只贴到 campplus 0.15~0.35
——机器口径「不是同一个人」）。当时的赌注是「真人唱歌嗓≠说话嗓」能被接受；
老板 06:10 裁决＝**赌输了，音色必须修**。这与 impl60「克隆音色身份可信链」
同一律：声音就是身份，唱歌不能例外。

**修复路线（三层递进，读数闸门推进）**：

| 层 | 内容 | 成本 | 预期 | 归属 |
|---|---|---|---|---|
| A0 实验（当天） | ① 按人设说话声「声学画像」重写选角提示词（音高/亮度/年龄感 → prompt 工程化）多 seed 重抽；② ACE remix 以**说话参考音**当 ref 低 strength 拉音色 | 纯 GPU 几十分钟 | 0.33→0.45~0.5（不达标但摸天花板） | 本线 |
| **A1 主修（数天）** | **hub 侧 per-persona RVC 训练 + 离线批量转换端点**：用人设 TTS 说话声合成 10~20min 语料训 RVC → 把**已认可的选角 take**（唱法自然）过 RVC 换成人设音色。RVC 是 AI 翻唱场景的标准件（hub 已有 67 个名人 RVC 模型+实时口，缺的只是训练管线和批量口），换声保旋律保唱法，与 Seed-VC 的「说话风格嵌入硬套唱歌」结构性缺陷不同路 | hub 侧开发 + 每人设一次性 ~30-60min GPU 训练 | 音色 0.7+ 且唱法保留（两全） | **AvatarHub 线**（需交接） |
| A2 备选（周级） | SoulX-Singer 零样本 SVS/SVC（Apache-2.0，人设参考音零训练直出；~12G VRAM 可落 173/176 低峰） | 部署+评测 | 若成＝免训练、按语料升级 | AvatarHub 线 |

**验收闸（新增硬指标）**：`voice_match = campplus(人设说话参考音, 唱段)`——
当前质检只量「vs 选角锚」（同嗓一致性），**从未量「vs 本人说话声」**，这就是
问题没被仪表盘看见的原因。补进五闸做 WARN 位 + 点唱台/备货矩阵人话展示
（「音色贴合度」三档灯）。放行标准：voice_match ≥0.70 + 老板耳终审。

**修复落地前的止损（立即生效项）**：唱歌保持「点名才唱」灰度不扩（主动献唱/
场景触发/付费 SKU 全部押后到音色闸过）；送达话术加一句人味铺垫（「我唱歌嗓
跟说话不太一样哈～」——真人也成立的柔性框定，降穿帮锐度但不解决问题，
诚实标注为止血不是修复）。
