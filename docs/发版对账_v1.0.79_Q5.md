## §〇 先答一问：为什么画像永远空？

三段，缺一都是空：

1. **键不在基线**：`companion.goals.profile_llm.enabled` 在 1.0.78 及以前不在 `feature_registry` 基线里，clean 装 / 升级机都是缺键 → `profile_llm` 从不启用；而 `memory.extract.use_llm` 虽默认开，走的却是另一条链（见 2）。两键各自守着自己的门，任何一把没开都等于画像那条链关着。Q-4 E（`c860436e`）把 `profile_llm.enabled=True` 进了 A 类基线，本线再把两键做**语义合并**（任一开即走 LLM）——`profile_fill.llm_extract_enabled()` 同时看两键，返回 `(on, "profile_llm"|"memory_use_llm")`。
2. **两链各自为政**：`skill_manager._episodic_memory_extract_async` 一条链只产「记忆事实」（`extract_memory_facts`），画像槽位另有 `profile_llm.extract_slots_llm` 一条链，靠 `goals/service.py` 里的探针触发——**没人在入站抽取时顺手写画像**。结果：记忆页有事实（「客户是纽约的木工」），画像卡却全空。本线把两条链并成**一次 LLM 调用**（`profile_fill.run_extraction`）：同一 prompt 同时出 `facts[]` 与 `slots{}`，两路分发——事实走既有 `add_fact` 路径不变，槽位走 `profile_fill.apply(source="ai_inferred", status="mentioned")`。日志一行 `[extract] conv=… facts=n slots=n llm=1|0` 直接可读。
3. **昵称没人读**：客户昵称「Michael/46/New york/union carpenter/5.28」把年龄 / 城市 / 职业都写脸上了，联系人同步只把它当 `display_name` 存起来，画像链从没读过。本线新 `src/contacts/nickname_parse.py` 做分隔格式解析（名 / 年龄 18–80 / 城市词典 / 职业词典 / 日期片段忽略），`profile_fill.nickname_prefill()` 在**抽取链**与**画像卡读取**两处触发一次、昵称变了再触发（进程内 memo），写 `source=nickname status=mentioned`「来自昵称 · 待确认」。

**修法 = 一个模块 `src/companion/goals/profile_fill.py` 收口三件事**（合并抽取 / 槽位写入规则 / 昵称预填），加 schema v2 的格形态 `{value, source, status}`（读时兼容、写时升级），前端画像卡给「AI 推断 · 待确认」「来自昵称 · 待确认」徽标 + ✓/✎/✕ 一键确认。

## 一、接口约定①（与 Q-1 读侧的契约）

| 项 | 约定 |
|---|---|
| 格形态 | `{value, source: user\|nickname\|ai_inferred\|confirmed, status: unknown\|mentioned\|confirmed}`；**双形**——同格保留 legacy `v/src/ts` 供旧读者（`profile_slots.slot_value/slot_src/facts_line`、`_profile_view._row`），legacy src 映射 `ai_inferred/nickname→llm_pending`、`user/confirmed→agent` |
| 读侧 | Q-1 经 `profile_slots.cell_view(cell) -> (value, source, status)`；旧 src `agent/auto→confirmed`、`llm/llm_pending→mentioned`；裸字符串→`confirmed` |
| 写入规则 | 自动来源（ai_inferred / nickname）**永不**覆盖 confirmed（冲突 → 通知中心一条，不打断对话）；mentioned 只被同级或更强来源替换（同值更强来源升来源带 evidence，仍 mentioned）；人工来源（user / confirmed）覆盖并强制 confirmed；AI / 昵称 status 强制 mentioned |
| 导出 | `export_profile(fields) -> {"schema_version": 2, "fields": …}`；`import_profile` 兼容无版本号的旧形态 |
| 日志 | 每次槽位写入 `[profile] conv=… slot=… value=… source=… status=…`；每次抽取 `[extract] conv=… facts=n slots=n llm=1\|0`（**一行**，slot 丢弃明细另起 `[profile] slot candidates dropped:`）；`heuristic_count / llm_count` 行不变 |
| 停滞 | 连续 50 次 `facts=0 slots=0` → `stall_status().stalled=True`，记忆页 `#cs-stall` 第二行 + 目标页 `#gr-extract-stall` 告警「抽取可能未生效：检查 AI 抽取开关与模型」 |
