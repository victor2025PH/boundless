## §2 先答一问：为什么 skuio 机装的是 conversion 域包？

**答：是代码级缺省 + 配置基线不写 `domain`，不是首装让用户选了、也不是内测 seed 指定。** 三层证据：

1. ZNW5CN 启动日志 13:14:41：`配置不存在，已从内置种子播种到可写目录: …\config.yaml ← config.desktop.min.yaml`，紧跟 `随包种子缺席（clean 包，无 resources/seed-data）：内测 overlay 种子不会应用`。skuio 13:14 卸载重装的是 **clean 包**，config.yaml 全部来自 `config/config.desktop.min.yaml`。
2. `config.desktop.min.yaml` 里**没有** `domain` 键；`src/utils/domain_policy.py::effective_domain_name` 是 `raw = cfg.get("domain") or "conversion"`——缺省硬编码 conversion。内测 overlay `config.desktop.internal.yaml` L63 与 CLI 预设 `config/presets/companion.yaml` L16 倒是写了 `domain: conversion`（因为 `domains/` 下没有 companion 包，陪伴预设只能指向它）。首装向导（`--init` 预设脚手架 / 桌面首启）没有任何一步问「做什么生意」。
3. **但「装 conversion 包」本身不是错**：`domains/conversion/manifest.yaml` 自述「多语言情感陪伴与日常闲聊」、`persona.yaml` 就是「线上陪伴」、`system_prompt.txt` 是 companion prompt；而 `skill_manager.py`（8 处）/ `ai_client.py`（5 处）/ `client/sender.py`（3 处）全以 `effective_domain_name(cfg) == "conversion"` 当「是陪伴部署」判定——换包名会让记忆 / 亲密度 / 陪伴注入整套熄灭，且 skill_manager 是红线文件。**真正错配的是挂在这个包上、以及散落在代码里的销售物料**：包内 `kb/categories.yaml`（产品价值 / 常见问题 / 转化话术 / 异议处理 / 命理）、hook 类名 `ConversionDomainHook`；代码里 `profile_slots.py` 的 BANT 六槽、`templates.py` 四张 `kind=conversion` 模板、「标成交」产品 / 金额、「营销目标」字样、`kb_store.SYSTEM_REPLY_SEEDS` 23 条系统话术（13 条 GXP）。它们在 zhiliao 生产（厂商自家售卖机器人，同一个 conversion 包 + vendor KB + su_wan 获客人设）是对的，在陪伴运营的客户机上全是噪音。

**所以 A 的入口 = 配置基线 + 后台设置，不是首装向导也不是换域包**：新增顶层键 `business_domain`（companion / sales）作为「这台机器做什么生意」的单一真值，与 `domain`（装哪个包）正交；桌面基线 `config.desktop.min.yaml` 出厂 `business_domain: companion`；已装机器缺键时按部署形态推导（桌面客户机 → companion；服务器 / 内部 → sales，zhiliao 零变化）**并在启动期写进 overlay 一次**，从此显式；开发者页（后台）可改。Domain hook / KB 分类 / 目标模板库 / 摸底槽位 / 客户画像 schema / KB 种子全部读它。首装向导本批不建（预算），落点见 §四。

- **#241**：「摸底标签换成陪伴用的（称呼 / 坐标 / 职业 / 年龄 / 兴趣 + 家庭 / 婚恋 / 收入 / 居住 / 资产），收入 / 资产默认不勾、勾了 AI 也只会顺着话头慢慢带出不直接问；可以加自己的标签；客户画像和摸底标签是同一套，你之前填的商机字段还在『其他已记录』里没丢；『标成交』改成『标记达成』，填达成结果和备注就行；界面和日志里没有『营销目标』字样了，都叫『工作目标』。」
