| # | 原话 | 能力定义 | 本方案落点 |
|---|------|----------|-----------|
| 1 | 「把小智做为一个新手指导，所有问题解析」 | 全知答疑：任何页面任何功能问得出、答得准 | §4 P0：语料补全 + 上下文感知；已有 RAG 底座 |

| 6 | 「真智能操作…我要登陆飞机，直接弹出 telegram 二维码，小智进行语音交互，完成后还可以继续下一步的操作引导和使用。并且是真实操作和工作的」 | **业务流程级真操作（Flow）**：多步有状态流程（等待态/事件续跑/断点续传），全走真实 API、成功判据客观可验证、完成即引导下一步 | §3.4 流程层 + §4 P5：Flow 引擎 + 旗舰流「登陆飞机」 |

一句话结论：**不需要「像素级 AI 看屏点鼠标」那套重炮**——我们自家掌控整个 DOM 和后端 API，
正解是「应用内工具调用」（intent → 白名单动作 → 既有 API），快、稳、可审计、零 GPU 截图开销；
像素级 computer-use 只留作跨应用场景的远期研究（§7）。

### 1.3 缺口（本方案要补的）

1. **无教学模式**：「带我去」只能亮一个锚点，没有「点哪教哪」的 inspect 态、没有逐页锚点注册表。
2. **无动作执行力**：小智只会说不会做——没有 function-calling 循环、没有动作注册表、没有确认/撤销 UI。
3. **语音半成品**：mic→ASR 代码就绪但默认关；小智不会说话（无 TTS 接线）；LAN http 无 secure context 时 mic 按钮隐藏（Electron 内正常）。
4. **无手机遥控**：webhook 只出不进；没有可对话的遥控 bot。
5. **面板体验粗糙**（对照截图，详见 §3.3）：文字墙欢迎语、chips 无分类无图标、无模式分流、空间浪费。
6. **杂项债**：`asb.err.q_too_long` 文案说 ≤500 字而代码已放宽 20000；悬浮球零 ui-event 漏斗（点击/使用无法裁决）。

### 2.2 路线对比与选型

| 路线 | 原理 | 优点 | 缺点 | 判定 |
|------|------|------|------|------|
| A. 像素级 computer-use | VLM 看截图→点坐标 | 通用、跨应用 | 慢（每步一次 VLM）、贵、非确定、误点风险、需常驻截屏 | ❌ 应用内不用；§7 远期研究 |
| B. 浏览器混合（DOM+视觉） | agent 读 DOM 结构+视觉兜底 | 比 A 稳 | 仍是外挂视角，权限粗粒度 | ❌ 我们不是别人家的网页 |
| **C. 应用内工具调用（选定）** | LLM function-calling → **白名单动作注册表** → 既有 API/前端动作总线 | 毫秒级、确定性、逐动作权限+审计+撤销、零新模型 | 需维护注册表（本来就该有） | ✅ **主路线** |
| D. 语音层 | 自有 ASR（176 Whisper，mic 代码已就绪）+ 自有 TTS（avatar 栈） | 零采购、隐私本地 | LAN http 无 mic（Electron 不受限） | ✅ 直接开闸+接 TTS |
| E. 手机操控 | **扫码配对的手机操控版**：桌面小智出二维码 → 手机浏览器直开（PWA 可装主屏）→ 发令 → 同一智能体后端 → 桌面小智流星执行 + 双端进度镜像 | 零安装零配置 10 秒上手；教学/操作/进度一屏；流量不出内网 | 手机需与电脑同网段（LAN）；页内麦克风需 HTTPS（零成本绕法=输入法语音听写） | ✅ P4 落地（对齐 Claude Dispatch「手机派单→桌面执行」范式，但免 bot 免配置） |
| F. 业务流程编排 | 自研轻量 **Flow 引擎**（声明式步骤 + 等待态 + 事件续跑 + 断点续传），步骤复用动作注册表与既有状态 API | 「真操作」而非演示；等待态主动检测（扫码/超时/换码）；可取消可续跑 | 需维护流程目录（用覆盖率爬坡机制管，见 §3.4） | ✅ P5 落地（旗舰流＝登陆飞机） |

**架构一句话**：小智大脑 = 现有 `ai_client`（DeepSeek 主链+qwen3 本地兜底）加 function-calling 循环；
手 = 「动作注册表」（服务端白名单 API 调用 + 前端动作总线 goto/spotlight/确认卡）；
眼 = 页面上下文（`context_builder` 已有 page/role/lang）+ 因素注册表诊断；
嘴/耳 = 自有 TTS/ASR；遥控器 = 扫码即用的手机操控版（同一后端、双端 SSE 镜像）。**全部零外购。**

## 3. 四视角分析

### 3.1 用户视角（新手坐席 / 老板 / 运营）

**画像与痛点**（内测实录佐证：常问 chips 里赫然有「我是新手，不会用。」）：

| 画像 | 典型场景 | 现在的体验 | 期望 |
|------|----------|-----------|------|
| 新手坐席 | 第一天上岗，找不到「怎么发语音」 | 问小智→得到文字步骤→自己找按钮，找不到就报障 | 「带我去点一遍」或「你直接帮我弄好」 |
| 老板 | 「为什么不自动回复了？」 | 打开 reply-settings 看因素卡（实施56），看不懂术语 | 对小智说一句话，它诊断+修好+汇报改了什么 |
| 老板（不在电脑前） | 想关某能力/看状态/调节奏 | 打电话让坐席操作 | 手机扫码一次→说句话，电脑上小智化流星执行，手机看进度收回执 |
| 运营 | 批量调回复节奏、开关能力档 | 逐页找开关，怕点错 | 说目标（「回复再快一点但别太机器」），小智给方案预览→确认应用 |

**信任三要素**（没有这三条，「替我做」没人敢用）：
1. **先看后做**：每个写动作先出「变更预览卡」（现值→新值），确认才应用；
2. **一键撤销**：应用后卡片常驻「撤销」（capabilities 已有 snapshot rollback，推广为通用模式）；
3. **留痕**：改了什么、谁让改的、何时——审计可查（复用 audit jsonl 模式）。

**用户旅程（目标态）**：问 →（答+带我去）→ 跟着学（点哪教哪/任务清单）→ 让它做（确认卡）→ 撤销兜底 → 越用越省。

### 3.2 市场经理视角

- **卖点定位**：从「客服软件+帮助中心」升级为「**自带 AI 员工的客服软件**」。对话式 onboarding 正在取代静态 tour（Gartner/2026 买方趋势），竞品多是「旧 tour 引擎+聊天壳」（AI-enabled），我们是全栈自有的 AI-native——这句话能直接写进官网合规能力页（实施45）和频道日更（实施52）。
- **演示即成交**：最强 demo 三连——① 新手点哪教哪（10 秒懂）；② 「为什么不自动回复」语音一句话修好（因素注册表加持）；③ 老板手机扫码→说一句话→电脑上小智化作流星把设置改完（Dispatch 同款范式、观感更炸）。每条 ≤30 秒，适合录屏投渠道；**流星执行画面本身就是自传播素材**。
- **商业化分层**（对齐既有 monetization/membership 体系）：
  - 免费档：答疑 + 点哪教哪 + 带我去（降支持成本，本来就该送）；
  - 付费档/高级版：「帮我设」「替我做」智能体 + 语音 + 手机扫码操控（按席位或按会员档）；
  - 成本侧：全用自有 LLM/ASR/TTS，边际成本≈0，毛利干净。
- **降本账**：报障 deflection——小智答掉/修掉的问题不再进人工支持（实施51 的报障台账正好当分母）；新手培训成本从「老坐席带三天」压到「小智带半天」。
- **风险话术**：「AI 会不会乱改我的设置」——回答就是 §5 的三板斧（白名单/确认/撤销+审计），把安全设计当卖点讲。

### 3.3 UI/UX 设计师视角

**对照当前截图的问题清单**：

| # | 问题 | 证据 |
|---|------|------|
| 1 | 欢迎语是文字墙，无行动引导 | 「你好，我是产品助手。功能怎么用、哪里出问题…」三行纯文本 |
| 2 | 无模式分流：学/设/做混在一个输入框里 | 面板只有 chips+输入框 |
| 3 | chips 无分类无图标、粒度混乱、标点不统一 | 「怎么发语音」vs「我是新手，不会用。」（带句号） |
| 4 | chips 全局同一份，不随页面变 | 代码实况：`top_questions` 全局 14 天榜 |
| 5 | 面板中部大片空白，信息密度低 | 截图中间 ~40% 空白 |
| 6 | 麦克风按钮图标含义不明、无状态反馈 | 输入框旁魔棒样图标 |
| 7 | 悬浮球单一状态：无未读/思考/警示区分 | 球只有静态渐变 |
| 8 | 「报障」负向词占一级 tab；「我的」语义模糊 | tabs：对话/报障/我的 |
| 9 | 无教学/操作可视化语言（聚光灯只有单点脉冲） | `asb_goto` 仅 CSS pulse |
| 10 | i18n 文案债：字数上限提示 500 vs 实际 20000 | `asb.err.q_too_long` |

**重设计规范（目标态）**：

1. **悬浮球状态系统**：待机（呼吸微动）/ 有提示（角标点）/ 思考中（转圈）/ 播报中（声波）/ 警示（琥珀脉冲，接因素注册表红灯）。球即状态灯。
2. **首屏改「三卡分流」**：问候一行 +
   `🎓 带我学`（教学模式/新手任务）｜`🛠️ 帮我设`（设置向导）｜`🤖 替我做`（智能体任务）；
   下方「本页常见问题」（按 `context_builder.page` 过滤）+ 全局常问。
3. **教学模式视觉**：进入后顶部驻留细条「教学模式：点任意位置看讲解 ｜ Esc 退出」；悬停元素描边高亮；点击弹讲解气泡（名称/一句话/详细讲解/带我操作/帮我设置四按钮）；复用 `#blTourHole` 聚光洞语言，pointer-events 只拦一层不卡死页面。
4. **消息类型扩展**（对话流里出现结构化卡片，而非纯文本）：
   - 步骤卡：1-2-3 步，每步带「带我去」；
   - **变更预览卡**：设置项 现值→新值 diff + [应用][取消]；应用后变 [已应用][撤销]；
   - **任务执行卡**：步骤清单实时打勾 + 醒目 `⏹ 停止`；执行画面＝下述流星粒子；完成出「本次改动汇总 + 全部撤销」；
   - 错误卡：一键转报障（已有链路）。
5. **流星粒子执行秀（v2 核心新增：演出即教学）**——发出命令后，悬浮球化作一道流星替用户操作：
   - **五拍演出脚本**：①起飞（球压缩成光点、拖出彗尾）→ ②飞行（贝塞尔曲线 400-600ms/跳，飞向目标控件中心）→ ③到达（目标涟漪+描边高亮，字幕气泡「第 2/5 步：打开回复设置」）→ ④操作（开关真实翻转/填值/跳页；跨页时粒子经 sessionStorage 队列在新页**续飞**——复用现成 `asb_goto` 跨页机制）→ ⑤收尾（飞回球位还原成球，弹「改动汇总 + 全部撤销」）。
   - **三档节奏 × 三种深度（教学与实操合一的落点）**：教学速（每步驻留 ≥1.5s、带字幕、可暂停）/ 正常速 / 极速（连跳免字幕）；「🔁 再看一遍」＝纯视觉重放不重复应用；「✋ 我自己试试」＝粒子只飞到位不出手，聚光灯等用户亲手点——同一个功能：看一遍 → 跟一遍 → 自己来。
   - **失败演出**：某步失败粒子闪红折返，已完成步骤保留，出「进行到第 N 步失败：原因 + 撤销已做部分」卡。
   - **工程与体面**：纯 CSS/canvas 零依赖（requestAnimationFrame 路径动画 + 拖尾粒子）；粒子层 `pointer-events:none` 永不挡真实点击；`prefers-reduced-motion` 或「简洁模式」自动退化为聚光灯顺序高亮（低配机/晕动敏感兜底）；执行期悬浮状态条与停止键在最顶层。
6. **语音 UX（桌面端）**：按住说话（波形反馈）→ 实时转写预览 → 松开发送；「小智播报」开关（TTS 短句，用系统音色不用人设克隆声——身份边界）；Electron 端全功能，LAN http 自动隐 mic（现有行为保持）。
7. **手机操控版 UI（扫码即用，教学+操作+进度一屏）**：
   - **配对流**：桌面小智面板「📱 手机操控」→ 全屏二维码（一次性 token URL）+ 三步图示 → 手机相机扫开即用；页顶常驻「添加到主屏幕」安装引导（iOS 分享→添加 / Android 安装提示）——即「手机版操作安装引导」。
   - **主界面**（拇指优先竖屏单列）：顶栏＝连接状态+电脑当前在哪页；中部＝任务卡流（与电脑端流星逐步同步打勾的实时镜像）；底部＝超大「按住说话」+ 文字输入（占位提示「也可点键盘上的麦克风说话」）。
   - **教学合一**：每张完成的任务卡带「📖 学一遍」＝电脑端教学速重放；本页常问 chips 手机端同步。
   - **确认双端等效**：L2/L3 确认卡同推手机与电脑，先确认者生效，另一端自动收起。
8. **主题与窄屏**：全部走 `--tk-*` token（暗色 `data-cp-theme` 自动跟随，映射层 `--as-*` 已有）；405px 窄壳内面板改全高抽屉；手机操控页同一套 token。
9. **发布纪律**：新词条全进 `i18n_packs/assistant_ball.py`（zh+en 齐备）；每批 bump `ui-build.txt` + `?v=`；补 `asb_*` ui-event 漏斗（ball_open / mode_select / teach_click / action_confirm / action_undo / voice_use / agent_task_done / **meteor_replay / self_try / pair_scan / mobile_cmd**）——没有埋点就没有裁决权（iflt_ 前例）。

### 3.4 开发工程师视角

**四层架构**（自下而上，每层独立可验收；④ 的编号与权限分级 L0-L3 无关）：

```
┌─ ④ 智能体层（P2）: function-calling 规划循环
│    ai_client(主链/本地兜底) + 工具schema + 多步计划 + dry-run
├─ ③ 流程层（P5，v3 新增）: 业务流程引擎 assistant_flows.py
│    声明式流程（步骤/等待态/分支/断点续传）+ 事件续跑 + 客观成功判据
├─ ② 动作层（P1）: 动作注册表 assistant_actions.py
│    白名单动作 → 既有API执行器 + 权限分级 + 确认token + 快照撤销 + 审计
└─ ① 教学层（P0）: 锚点注册表 + inspect覆盖层 + blTour复用
     data-anchor扩面 + help_entries/help_terms 讲解底料 + LLM兜底讲解
```

**双端拓扑（v2）**：手机（扫码 PWA）←HTTP/SSE→ 后端（同一实例）←SSE→ 桌面小智执行器（流星演出）。
**动作的真身在服务端 API，流星只是桌面可视化**——桌面页面不在线时，API 级动作（设置/开关/预设）照常执行并回执手机；纯前端动作（带看某页/教学演示）才要求桌面在线。

**动作注册表 schema（设计草案，范本=实施56 fix 描述符）**：

```yaml
# src/assistant/actions.py（新）——每条动作：
- id: set_reply_speed            # 唯一键
  level: L2                      # 权限级（见下）
  kind: settings                 # settings|preset|feature|toggle|nav|query|draft
  executor:                      # 映射既有端点，绝不造新写口
    route: POST /api/reply-settings
    fields: [min_reply_delay_sec, max_reply_delay_sec]
  preview: true                  # 必出 diff 卡
  undo: snapshot                 # snapshot|inverse|none(仅L0/L1)
  i18n: asb.act.set_reply_speed  # zh+en
```

**权限分级（结构性防线，不靠 prompt 自觉）**：

| 级 | 含义 | 确认要求 | 例 |
|----|------|----------|-----|
| L0 | 只读查询 | 无 | 状态/健康/因素注册表/在哪儿 |
| L1 | 教学导航 | 无 | goto（nav_schema 校验）/聚光灯/tour |
| L2 | 可逆设置 | 面板内确认卡 | reply-settings 白名单键/capability toggle/preset |
| L3 | 敏感操作 | 显式二次确认+审计强留痕；手机端需 typed confirm | 给客户发消息（走既有人审投递链）、budget relief、关守卫类开关 |
| ⛔ | 永久禁区 | 小智永远不可执行 | 实例重启、凭证/telegram 密钥、绕过 autosend 人审、任意 shell/HTTP、跨实例操作 |

**智能体循环（P2）**：`POST /api/assistant/agent`（SSE）——RAG 上下文 + 页面上下文 + 动作 schema →
LLM 出 tool_calls → L0/L1 直接执行回填 → L2/L3 停下出确认卡（human-in-the-loop，AG-UI 思想）→
用户确认带 token 续跑 → 执行事件流驱动前端「任务执行卡」。首周全量 **dry-run 档**（只出计划不应用，
对齐 care 引擎 enable_dry→go_live 灰度范式）。**主链断网时本地 qwen3:30b 兜底**——tool-calling 走
Ollama 原生口（已有 keep_alive 经验），断云期教学/查询档不降级，写动作档保守禁用。

**业务流程引擎（P5，v3 新增——「真实操作和工作」的载体）**：

流程定义＝声明式结构（一条 flow 一个 dict）：`trigger`（说法族）/ `preconditions`（查询动作）/
`steps`（原子动作 ｜ `wait_for(状态API, 判据, 超时, 播报词)` ｜ `user_input(secret=仅键盘)` ｜ 分支）/
`success_check`（**客观判据**）/ `next`（下一步建议，可链下一条 flow）/ `cleanup`（取消/超时收尾）。

**旗舰流「🛫 登陆飞机」全分解（每步映射既有 API，登录内核零改动）**：

| 步 | 动作 | 落点 |
|----|------|------|
| 1 | 意图识别：「登陆飞机/登录 telegram/加个号」说法族 → L3 确认卡「要登录一个新 Telegram 账号，对吗」 | 智能体层 |
| 2 | 前置体检（通道/凭据），不过→教学卡指路 | `GET /api/platforms/telegram/login/preflight` |
| 3 | 起登录 → 拿 login_id + qr_url → **小智面板/手机操控页内直接渲染二维码**；TTS「二维码出来了，手机 Telegram：设置→设备→连接桌面设备，扫一下」 | `POST /api/platforms/telegram/login/start` |
| 4 | 等待态轮询：`pending→scanned` **主动播报**「看到扫码了，正在确认」；`password_needed` → TTS 提示两步验证 + 弹**键盘输入框**（密码前端直投，绝不经小智）；`qr_expired` → 自动换新码播报重扫 | `GET …/login/{id}/status`（状态机已有全部语义） |
| 5 | 两步验证（如需）：错密可重试（既有 SRP 语义） | `POST …/login/{id}/password` |
| 6 | 成功判据（双证据）：status=`authorized` **且** 账号出现在账号注册表 | 状态 API + 注册表 |
| 7 | **续跑下一步（教学合一）**：「要不要现在给这个号绑人设→设回复模式→发条测试消息？」语音「好」即链下一条 flow | flow.next 链 |
| 任意时刻 | 语音「取消/等一下」→ 取消并清理半登录态 | `POST …/login/{id}/cancel` |

**语音陪跑三原则**：① 等待态靠轮询**主动检测**（绝不逼问「扫好了吗」——scanned 信号自己会来）；
② **敏感输入零接触**：密码/验证码只走键盘输入框直投既有 API，**不进 LLM 上下文、不语音朗读、不落日志**；
③ 随时可打断（取消/等一下/换个号）。

**真实性三保证**（「并且是真实操作和工作的」的工程化定义）：
① 每步＝真实生产 API（与人手点同一条链，无 mock 无演示态）；
② 成功判据客观化（状态机+注册表双证据，**不以 LLM 自述为准**）；
③ 完成后可选自验（如登录后真发一条收藏消息 smoke——复用既有冒烟范式）。

**断点续传**：flow 实例状态挂服务端会话——面板关了重开、手机↔电脑换端，都能续跑或体面收尾；超时自动 cleanup。

**「软件内所有功能都能操作」的路径**＝覆盖率爬坡机制：不是一次写完所有 flow，而是每月按

页面上下文只进消毒后的摘要；RAG 语料是自家策展；LLM 输出永不 eval；每会话动作预算+现有 rate_limit。

## 5. 安全与治理红线（一票否决项）

1. **小智永久禁区**：实例重启、凭证/密钥读写、绕过 autosend 人审直发客户消息、任意 shell/HTTP、跨实例写、关闭审计。
2. **写动作三板斧缺一不可**：白名单注册表（结构性）、确认卡（human-in-the-loop）、快照撤销+审计（事后可救）。
3. **给客户发消息 = L3**：必须走既有人工投递链（`deliver_human_approved`），受既有 stale/budget/dedup 护栏管辖——小智不是第二条发送通道，只是入口。
4. **手机操控最小面**：一次性配对 token（TTL 2 分钟、单次核销、绑定当前登录用户与实例）；桌面面板「已连接的手机」可随时踢下线；仅同网段（LAN）可达、不暴露公网；L2 起步（L3 需 typed confirm）+ 全量审计标 `source=mobile`。
5. **灰度纪律**：P2 首周 dry-run（只出计划）；`assistant.agent.enabled` 独立开关默认关，example 基线关、zhiliao overlay 先行——与全仓 feature flag 约定一致。
6. **敏感输入零接触（v3）**：密码/验证码/密钥类字段**永不**经小智——不语音朗读、不进 LLM 上下文、不落日志，前端输入框直投既有登录 API（`…/password` SRP 链路已有）；登录/账号资产类 flow 一律 L3 显式确认；每条 flow 必须有「取消→清理」出路（登录半途取消走既有 cancel API），杜绝半登录残留。

## 7. 刻意不做（本期）与理由

| 不做 | 理由 |
|------|------|
| 应用内像素级 computer-use | 自家 DOM 全权掌控，确定性动作快 100 倍且可审计；连 Anthropic 都为 web 场景出了「带页面结构」的 browser use tool——像素是没有结构时的下策 |
| 常听唤醒词（「小智小智」） | LAN http 无 secure context + 隐私观感 + 功耗；按住说话已覆盖场景 |
| 无确认全自动 L2/L3 | 信任要靠确认卡攒出来；等动作成功率数据（§6）稳定后再议「免确认白名单」 |
| 引入 CopilotKit/React 栈 | 前端是 vanilla+Jinja；抄 AG-UI 协议思想（事件流+确认+共享状态）零依赖自实现 |
| 独立手机 App | 扫码 PWA 已覆盖（可装主屏）；原生 App 等出现公网远程刚需再议 |
| TG 遥控 bot（v1 设想） | 已被「扫码即用操控版」取代——免建 bot、免 token 配置、教学/操作/进度一屏，且流量不出内网 |
| 接管外部应用（TG Desktop 等） | 那是 RPA worker 的既有领地（messenger_rpa 等），不重复建设 |
| 引入第三方工作流引擎（temporal/prefect 类） | 首批 8 条声明式 flow 用轻量 dict+状态机足够；重引擎＝运维负担，与「零外购」方针冲突 |
