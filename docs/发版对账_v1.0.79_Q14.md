## 〇 为什么 2.4% 的 AI 调用是沉默（三段）

1. **30 < 55**：客户端 `ai.timeout=30`，官网网关 chat 路由预算 55s（`ROUTE_BUDGET_MS.chat`），nginx read 180s。DeepSeek 峰时 + 1.0.78 把系统提示词 1868 → 3940 字，生成常超 30s → 客户端先断 → 网关还在等上游 → nginx 记 499（09-08 两天 78/3300 ≈ 2.4%，23h 后升到 4.4%）。
2. **无重试**：`max_retries=0` + 调用方两枪都在同一 30s 口径下；连接类错误（网关重启窗 502/503、连接被重置）本可再试一次救回，读超时则重试只会双倍成本双倍延迟。
3. **不可见**：全链失败 → `_fallback_reply` 返回 None = 本轮不回（罐头兜底 08-15 已移除，口径不变），日志只有「AI 两次调用均失败」不带会话 / 原因 / 耗时，工作台无任何标记，坐席以为「AI 没理」。
