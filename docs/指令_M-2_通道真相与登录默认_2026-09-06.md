## 2. A —— 发送 ✓ 以回执为准 + 通道状态上屏（#232，P1）

**事实**（CW6RP4 / GSYXQ8 / ZGKVQB）：智聊界面「已登录」与边车网页会话脱节；发送状态为乐观显示非边车回执；`msg-sidecar` 500/502 原样透传且不落日志。

**修法**：
1. 手动发送 ✓ 只在 `channel_adapters` 拿到边车 `delivered=True` 回执后落；无回执 → 「发送中」；边车明确失败 → ✗ + 原因人话（复用 L-1 D 的四分类口径）。
2. 账号级通道状态上屏：账号栏 / 会话头部显示「已连接 / 未连接（需重新登录）/ 重连中」，数据源 `platform_session_health.py`（L-3 C 已为断线卡片建好）；**未连接时禁止自动投递并阻止手动发送**，给出「该账号 Messenger 会话未建立，请重新登录」提示。
3. 登录流程以边车健康探测通过为「登录完成」；`msg-sidecar` 500/502 落边车日志（今日仍为零）。

## 3. B —— 登录默认半自动 + 冷静期 + 账号级批量 + 连续失败降级（D-M1，P1）

**修法**（UE7VM3 ①②③④⑤⑦⑧）：
1. `config.yaml`：全局 `automation_mode` 默认 `auto_ai` → `semi`；`bootstrap_automation_mode` 默认 `false`（`_ensure_baseline` 三态：用户显式写过的不动）。
2. 任何账号**登录 / 重登 / 清数据重登** → 该账号全部会话进半自动（只起草），进入 **10 分钟冷静期**：只起草并在账号栏列出「积压未读 N 条待你过目」；冷静期内所有草稿 `level=L1 reason=cooldown`。
3. 全自动开启只能按账号显式操作：账号头像菜单「此账号全部会话 → 手动 / 半自动 / 全自动」+ 确认「将对 N 个会话开启，覆盖 N 个个别设置」。
4. 通道门禁：同账号连续 3 次发送失败 → 自动降半自动 + 账号红标「通道异常，已暂停自动发送」，恢复后需用户确认再开。
5. 手动发送与自动投递分开配额，手动优先。

**验收**：`tests/test_login_default_semi_m2.py`：重登 → 全会话 semi + 冷静期 L1；连续 3 失败 → 降级 + 红标；账号级批量切换写入 N 个会话。

## 4. C —— 退避锁手动优先 + 登录重置 backoff（#233，P1）

**事实**（K9CY6R / SAD7Q2）：`send_backoff` 熔断后自动重试 13s/23s 改期重投使熔断续命；手动发送与自动共用同一退避锁 → 手动被 429。

**修法**：退避期内自动投递不重试（或重试不计连续失败）；手动发送独立于自动退避锁、优先放行（至多一次探测性发送，成功即解锁）；登录成功 / 通道健康探测通过 → 重置 backoff。
