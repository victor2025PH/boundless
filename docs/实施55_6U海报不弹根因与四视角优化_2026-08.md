# 实施 55：6U 海报「开机不弹」根因 + 四视角优化落地（2026-08-22）

老板实测：装了新版本（1.0.47）开机没有海报弹出。本批 = 根因定性（**不是坏了，是设计
如此且不可自查**）+ 四视角（开发/市场/用户/UI-UX）优化全部落地。两条线合流交付：
桌面批（poster/campaign/main，10:07–10:16 落盘）+ 合流批（归因断链修复 + funnel 拆分 +
本文档，11:00–11:30）。**桌面改动随下一个安装包（1.0.48）生效；官网改动待部署。**

## 一、为什么 1.0.47 开机不弹（根因，按可能性排序）

海报要连过 8 道闸门（campaign-model.cmEligible + 渲染层前置），全过才弹：

| # | 闸门 | 内部机器的实况 |
|---|---|---|
| 1 | 包内含海报代码 | 1.0.47 已含（03:40 构建）✓ |
| 2 | 非 --first-run 会话 | 演示向导时整会话压制（旧版连完成 reload 后都压）|
| 3 | 托管版（managed） | npm start 开发态永不弹 |
| 4 | feed 拉到有效活动 | 首启无缓存 + 拉取未收尾 = 本次静默（旧版有竞态窗）|
| 5 | 活动在期内 | 2026-08-21 ～ 2027-08-21 ✓ |
| 6 | onboarding.completed_at 存在 | **坐席机还原旧 config.json，可能根本无此键** |
| 7 | 距完成首启向导 ≤72h | **主犯：所有老安装/升级/重装机器全部超窗** |
| 8 | 频控（<3 次 · 距上次 ≥12h · 未点不再提醒） | 昨天弹过的机器撞 12h 冷却 |

**主结论**：海报 audience=new_user，锚定「首启向导完成时刻 +72h」。而我们自己的机器
全是「老用户」——升级不动 %APPDATA%、坐席机 restore 流程连 config.json + Partitions
（向导 localStorage 标记）一起还原、卸载脚本刻意保留用户数据 ⇒ 时间戳永远是老的 ⇒
`window_passed` 永不弹。**真新用户（全新安装完成向导 72h 内）一直能看到。**

**比不弹更大的问题**：cmEligible 明明算出精确原因（window_passed/no_onboarding/
interval/…），主进程 IPC 却丢弃返回 null——无日志、无诊断面、无预览开关，每次
「为什么没弹」都要翻代码 + 翻 %APPDATA%。本批的核心就是把这个黑洞闭掉。

**受影响机器 1 分钟自查**（改动装上前的老包也适用）：
`%APPDATA%\telegram-ai-desktop\` 下看三个文件——`config.json` 的
`onboarding.completed_at`（超 72h 即 window_passed）、`campaign-state.json`
（shows 次数 / never 标记）、`campaigns-cache.json`（不存在 = feed 从没拉到过）。

## 二、四视角结论（浓缩版，全文分析见 plan）

- **开发**：纯函数模型+单测+安全边界（文本-only feed / https 白名单 / 具名版式）扎实；
  但判定原因黑洞、无验收通道、--first-run 会话语义冲突、首启 feed 竞态、skip 无埋点
  （poster6u_view=0 时分不清「没人合格」还是「链路断了」）。
- **市场**：真倒计时红线/改 JSON 零发版/频控克制都对；但受众只打 72h 新用户（存量
  未付费用户零触达，且团队永远看不到自己的广告——本次疑问会每次发版重演）、跨系统
  漏斗断面、文案卖点是产品口径（价值藏小字）、付款后无奖励时刻。
- **用户**：退出成本低/延迟 3.5s/到点自动收都对；但开机全屏蒙层打断要干活的人、
  第 2/3 次曝光与第一次完全相同（无增量信息）、纯文字排版像系统通知不像礼包。
- **UI-UX**：官网版是真「互动海报」（3D 倾斜/光泽/流光/CountUp），桌面版却是静态卡
  ——同一 campaign 两种档次；无入场动画、数字无仪式感、倒计时权重过低不随剩余时间
  递进、emoji 当主视觉。

## 三、落地清单

### 桌面批（engines/chengjie/desktop，随 1.0.48 发包生效）

**P0 可诊断化 + 验收通道**：
- skip 原因三路透出（`campaign-model.cmSkipSummary` 单一口径）：IPC 回
  `{campaign:null, skip:{id, reason}}` + 主进程日志一行（`[campaign] skip: … onboarding=… feed=… managed=…`）
  + `desktop:campaign-diag` IPC → 🩺 健康看板「活动海报」行（最近判定/feed 数/频控概览）。
- **`--poster-preview` 验收开关**（argv → env → preload 旗标）：跳资格/频控强制弹出、
  埋点走独立 `poster6u_preview`、shown/never 不落频控账本、feed 不可达用内置双语样例
  （CM_PREVIEW_SAMPLE）、deadline 已过时合成满窗让倒计时可视、卡片带 PREVIEW 角标、
  延迟缩到 0.8s。市场/设计验收一条命令：`智聊.exe --poster-preview`。
- --first-run 会话语义修复：向导完成（sessionStorage `aitr_firstrun_v1`，与 first-run.js
  同键契约）后海报放行——修「演示完成 reload 后 env 仍在 → 整会话压制」。
- 暗面漏斗埋点：没弹时发一条 `poster6u_skip_{reason}`（每会话至多一条，预览态不发）
  → 引擎 `/api/admin/ui-event-trend?prefix=poster6u_` 直接读「多少台被哪道闸门拦住」。
- 首启 feed 竞态兜底：`_campRefreshInflight` 首拉在途 promise，海报查询等它收尾
  （refreshCampaigns 自带 10s abort，绝不挂死）。

**P1 美化（全部尊重 prefers-reduced-motion，降级为静态）**：
- 入场动画（蒙层 fade 200ms + 卡片 scale .96→1 约 280ms）；金色流光描边（conic-gradient
  1px 环缝，零依赖）；光泽跟随鼠标（ShineCard 简化版）；CTA hover 微动效。
- headline 数字仪式感：`cmHeadlineParts` 拆出 ≥1000 的最大数字 → 金色渐变 + CountUp
  滚动 800ms（找不到大数字原样静态，宁缺勿滥）。
- 倒计时紧迫递进：`cmCountdownUrgent`（剩余 <24h）→ pill 金色转橙红 + 文案换
  「即将截止 · 仅剩」；与 12h 冷却错开 = 第二次曝光多数已带紧迫增量，不是复读机。
- CTA 价值分层：feed 新增 `cta.sub`（按钮放价值「立即领取 18,000 Token」，价格
  「仅需 6U · 双倍到账」落按钮下方小字；老客户端不读该字段自动忽略）。
- 打扰递进降级：第 2/3 次曝光（payload.showCount≥1）不再全屏蒙层，改右下角 340px
  非模态角卡（频控/曝光口径不变）。
- `poster-hero` 版式进白名单：内置礼盒 SVG 随安装包走（feed 仍只下发文本，安全红线
  不变）；老客户端遇未知版式整条丢弃 = 天然向后兼容。

**P2 奖励时刻**：海报 CTA 点击后主进程盯 `/api/workspace/quota` 每 60s × 30min，
余量较基线增加 → 原生系统通知「充值已到账 🎉 +N」（SS 双语键 camp.credited_*）；
fail-soft 绝不打扰、预览态不布防。闭合「弹窗→下单→付款→到账→确认」最后一环。

## 四、验收与读数 runbook

1. **视觉/文案验收**（发包后任一台，或开发机）：`智聊.exe --poster-preview`
   （开发态 `npx electron . --poster-preview`）——强制弹出，不落频控不污染埋点。
2. **真新用户链路**（全新 VM 装 1.0.48）：向导完成 → reload → 3.5s 弹大卡（CountUp/
   流光/倒计时）→ 稍后再说 → 12h 后第二次为右下角角卡 → 剩余 <24h 倒计时转橙红 →
   72h 到点自动收 → 3 次后不再弹；「不再提醒」永久静默。
3. **为什么没弹**：壳内 🩺 健康看板「活动海报」行直读最近判定（show/skip/preview +
   原因）；机群口径读引擎 `/api/admin/ui-event-trend?prefix=poster6u_`（skip_* 分桶）。
4. **端到端漏斗**（官网部署后）：/console/funnel 新人卡——官网曝光/点击 + 全渠道
   下单/已付 + **桌面弹窗引流拆分**；桌面曝光侧在引擎 ui-event-trend，两边周报合读。
5. **到账奖励时刻**：测试单付款履约后 30min 内，桌面应出系统通知「充值已到账 🎉」。

## 六、经验沉淀

- **「营销组件对内不可见」是结构性盲区**：受众定向（新用户 72h）+ 数据保留（重装不清）
  叠加 = 团队机器永远不合格 ⇒ 每次发版都会有人问「怎么没弹」。凡此类组件，验收通道
  （--poster-preview）与判定透出（diag 行/skip 埋点）必须与功能同批出生，不能等疑问来了再补。
- **归因链要按「值的旅程」验收**：捕获（URL→localStorage）、落库（API→store）、消费
  （funnel）三段各自都对，但「提交体带不带」这一米断了整条链就是零——排查归因类需求
  时逐跳追值，别按模块清单打勾。
- 两线同主题撞车的合流实操：探活看 mtime 判断对方产出 → 重读全部现状 → 只补缺口
  （验证/断链/文档），绝不重写对方文件。
