## 二、现行带感情语音链（配置写的是 176 主力，实际跑的是 104 平声）

1. 情绪判定：词表；认不出且句子够长 → 173 chatx 补判一次（`voice_reply.emotion.llm`）。
2. 173 chatx 口语化改写（`avatar_voice.colloquial`，vivid / disfluency / think / laugh）。
3. 合成先打 hub `176:9000` → IndexTTS-2，`hub_fish.emotion_threshold: 0.35`，带情绪标签 + emo_text + emo_alpha。
4. 176 显存被 qwen3:30b 挤满 → 合成超时 → `timeout_breaker` 开路跳过 hub → 回落 `104:7865`。
5. 104 路径 `emotion_channel_threshold: 2` → 情感永不打开；4070 比 5090 慢一倍。

结果：客户多数时候听到的是 104 上慢一倍、没有感情的版本。

## 五、新模式下带感情的语音怎么走

**输入侧（听客户）**
- 客户语音 → 176:8765 whisper 转写 + emotion2vec 识别语气（5090 上约 44ms）。转写与情绪识别同一进程同一张卡，情绪信号不再跨到 198。
- 客户文字 → 词表判情绪；认不出且句子够长 → 173 chatx 补判一次。

**输出侧（说出来）**
- 173 chatx 把稿子改口语（停顿、口头禅、笑、人设方言味）。
- 176 IndexTTS-2：情绪强度 ≥ 0.35 就带情绪标签 + 不念出的情感描述（emo_text）+ 强度系数（emo_alpha），语速按情绪曲线。
- 参考音直传（reference_audio_b64），逐字稿 sidecar 保音色；IndexTTS-2 情感与音色解耦，不吃音色税。
