## 修复说明（给后续 PR 的依据）

### CI 依赖

工作流只装 `engines/chengjie/requirements-ci.txt`，故意不装 torch/whisper。下面这些包已经在完整 `requirements.txt` 里，CI 精简清单漏了，测试是 `import` 失败或功能静默退化，不是产品逻辑坏了：

| 包 | 表现 |
|---|---|
| `pyrogram` | Telegram 出站守卫 14 个：`filters` 导入失败被置 `None`，装饰器 `@filters.private` 抛 `AttributeError`。另有协议登录、群列表、删历史共 7 个 `ModuleNotFoundError` |
| `okline` | LINE 登录 PIN、同步、媒体、协议登录共 15 个。其中 2 个不是 import 错误：没装 okline 时 `_build_okline` 直接走无参回落，`LineConfig` 超时注入断言失败。装上之后这两条在本地通过 |
| `brotli` | 压缩中间件协商落到 gzip |
| `emoji` | `demojize` 原样返回 emoji，`😂 != 😂` 为假 |
| `opencc-python-reimplemented` | 繁简归一没发生。ASR CER `0.3333 == 0.0`（2/6）；synth_verify 两条繁体转写同样 |
| `ruamel.yaml` | 产品保注释写入在用（注释写明本机 0.18.x），但两份 requirements 都没列。overlay / realloc / duty / 危机审计 / 租户预设注入共 13 个 |

不把 `tgcrypto` 加进 CI（可选原生加速，不是这些失败的原因）。

### 跨平台（改产品）

- `SKELETON_SUBDIRS` 与 `scripts/provision_instance.py` 写了 `"events\\spool"`。Windows 上 `Path` 把反斜杠当分隔符；Linux 上这是一个带反斜杠的目录名，`events/spool` 不是目录。改成 `"events/spool"`（Windows 的 `Path` 接受正斜杠）。
- `tenant_card_path` 用 `Path(data_dir).parent`。Linux 不拆 `D:\chengjie-instances\zhiliao_acme\data`，父路径变成 `.`，结果是 `tenant_card.json`。改为先把两种分隔符归一再取父目录。测试期望值同样用 `Path(r"D:\...")` 拼接，在 Linux 上自己就是错的，断言改成同一套归一规则。Windows 上 `Path("D:/...") / "tenant_card.json"` 与原来的反斜杠路径相等。
- `audio_cable.py` 顶层 `from ctypes import HRESULT`。Linux 的 ctypes 没有 `HRESULT`，整模块导入失败，静音裁剪和响度归一两条纯函数测不到。`HRESULT` 只在 `comtypes` 分支的 COM 类里用，导入失败时置空。
- `resolve_exe_from_registry_value`：目录值在 Linux 上 `os.path.join` 会在尾随 `\` 后再插一个 `/`，得到 `Weixin//Weixin.exe`。注册表路径按自身的分隔符拼接。

### 过期测试（断言保留）

- `test_local_prompt_trace_n4.py`：类体里写 `prompt_tokens = prompt_tokens`。类体不看外层函数局部变量，Python 3.12 直接 `NameError`。这是假客户端写法错了，不是 `_trace_prompt` 坏了。改为类定义之后再赋属性。
- `test_preview_speech_verdict.py`：`tree.replace("/", "\\")` 在 Linux 上把 `desktop/renderer/shared` 收成一个路径分量。改为 `Path` 分段拼接。前端文件是在的。
- `test_schedule_reaction_followup_enqueues`：`now=1000` 是 1970-01-01 00:16。默认安静窗 23:00–08:00，`shift_out_of_quiet_hours` 把到期推到 08:00（约 ts 28800）。`row_id > 0` 已经成功，`drain_due(now=2000)` 看不见。同文件的冷却测试只看 `row_id`，所以是绿的。改为本地正午的时钟，并在 `defer_sec` 之后再 drain。安静窗逻辑不动。
- `test_too_long_rejected`：服务在看时长之前先查 ffmpeg。CI 镜像没有 ffmpeg，返回 `ffmpeg_unavailable`。同文件的并发测试已经把 `shutil.which` 打成假 ffmpeg。这条补上 `ffmpeg_available → True`，继续断言超限必须在抽轨之前拒绝。
