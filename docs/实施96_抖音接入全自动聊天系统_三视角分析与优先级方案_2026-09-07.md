## 0. 一页结论

**三个必须先知道的事实**（每条都改变路线选择）：

| # | 事实 | 依据 | 对方案的影响 |
|---|------|------|------------|
| 1 | **第三方「移动/网站应用」的抖音私信 API 已被官方彻底回收。** 2025-04-14 起停止新申请，存量分批回收，最后一批延期应用也在 2025-12-26 收回。今天新开发者**拿不到** `im.direct_message`。 | 抖音开放平台公告 #300《移动/网站应用的私信群聊能力下线/回收公告》及后续通知 | 「注册一个网站应用、配 webhook 收私信」这条最直觉的路**不存在**。所有宣称能给第三方系统直连企业号私信的，要么是存量老授权，要么是非官方手段。 |
| 2 | **官方仅剩的合规通道全部绑定「企业主体 + 抖音小程序」或「抖店服务商」身份。** 小程序侧「私信/群管理」「主动授权私信」仍可经能力实验室申请（条件：企业主体小程序已上线、信用分 ≥ 90、场景合规）；抖店侧飞鸽客服有 ISV 机器人接口；巨量引擎飞鱼 CRM 有线索推送 webhook。 | 抖音开放平台小程序能力中心、`/im/send/msg/` 文档（更新 2025-05-08）、抖店开放平台飞鸽 API、飞鱼 CRM 线索推送规则 | 智聊「合规主站」的抖音企业版 = **一个上线的企业主体小程序（我们自建或客户自有）+ 企业号绑定**。这是一条 4–8 周的资质路径，必须**今天就启动**，不能等代码写完再申请。 |
| 3 | **引擎侧接一个新渠道的公共层已经很薄，但「平台枚举」散落在约 20 处。** 入站按 `make_message` 形状进、出站 worker 实现 `send` 即可复用收件箱落库 / SSE / 三条回复引擎 / 翻译 / 风控闸门 / 出站镜像（`protocol_bridge.py:993–1018`、`account_orchestrator.py:125–140`）。但展示名 / 颜色 / 图标 / 向导 / 事实卡 / 能力矩阵 / i18n 各自维护一份平台表（`normalizer.PLATFORM_DISPLAY` 只有 4 项、`unified_inbox.html:2018–2020` 的 PC/PI/PN、`workspace_base.html:1111`、`platform_icons.js:30–36`（桌面壳 `desktop/renderer/` 还有一份手工同步的逐字节副本）、`setup_wizard.html:344`、`product_facts.py:39–42`…）；品牌色表在约 25 处重复且互不一致（Telegram 同时存在 `#229ED9 / #2AABEE / #2BA5E0` 三个值）。以 X 为例新增一个渠道 UI 侧要改约 30 处，其中只有 5 条链是数据驱动的。 | 代码勘察（见 §1） | 抖音接入的工程主体不在「传输层」而在「平台注册表收口 + 抖音特有的出站策略」。同时 `product_facts.UNSUPPORTED_CHANNELS` 与小智金标把「抖音不支持」钉死了，上线前必须**一起翻**，否则销售 AI 继续答「不支持」。 |

**方案主轴一句话**：抖音按智聊既有的**合规分层**接入——**主站走「小程序 IM 官方通道 + 抖店飞鸽 + 巨量线索」的企业版**，**准入区走「真机托管（huoke）/ 网页托管（Playwright 边车）」的个人号版**；引擎侧一次性补齐「平台注册表单一事实源」和「按渠道出站策略层」，让抖音成为**最后一个为散落枚举付税的渠道**；AI 侧坚持「**chengjie 是脑、huoke 是手**」，不允许出现两套回复大脑。

**优先级总览**（详见 §5）：

|------|------|------|------|

## 1. 现状梳理：智聊今天是什么、缺什么

### 1.1 渠道接入现状（7 个平台、三种接法并存）

| 平台 | 个人号协议 / 边车 | 官方 API | 真机 RPA | 关键文件 |
|---|---|---|---|---|
| Telegram | MTProto（pyrogram）A 线主客户端 + B 线薄 worker | — | device 模式 | `src/client/telegram_client.py`、`account_orchestrator.py:1115` |
| WhatsApp | Baileys Node 边车 | Cloud API | `whatsapp_rpa/` | `account_orchestrator.py:1529`、`whatsapp_cloud.py` |
| LINE | okline 协议 | Messaging API | `line_rpa/` | `account_orchestrator.py:2148`、`line_webhook.py` |
| Messenger | Playwright 网页托管边车 | Graph Send API | `messenger_rpa/`（12k 行，含 VLM 视觉兜底） | `account_orchestrator.py:1725`、`facebook_webhook.py` |
| Instagram | Playwright 网页托管边车 | Graph API | — | `account_orchestrator.py:2048`、`instagram_webhook.py` |
| Zalo | zca-js 边车 | OA OpenAPI | — | `account_orchestrator.py:1932`、`zalo_webhook.py` |
| 网页 Widget | 服务端原生 | — | — | `web_chat/` |
| **抖音 / TikTok / 微信** | **无** | **无** | **无**（TikTok 国际版真机自动化在兄弟仓 `engines/huoke`） | `product_facts.py:39–42` 明确声明「不支持」 |

四层鸭子类型契约决定了「接一个渠道要写什么」：

- **编排器 worker**（出站 + 生命周期）：`async start/stop/healthy`、`status()`、`send(chat_key, text, *, reply_to=None)`，可选 `send_media / mark_read / send_chat_action / delete_messages`；能力由 `hasattr` 判定并被 `platform_capabilities.py:38–43` + `tests/test_platform_matrix.py` 钉住。
- **入站桥**：`protocol_bridge.make_message(...)` → `emit_incoming` → `ingest_incoming`（`protocol_bridge.py:839–990`）；Node 边车走 `POST /api/internal/protocol/ingest`。
- **登录 provider**：`platform_login.register_login_provider("<platform>", "<mode>", fn)`，`login_kind ∈ {qr, hosted, phone_code}`，非官方模式统一带 `notice_key="inbox.connect.notice_unofficial"`（`platform_login.py:139–206`）。
- **收件箱 ChannelAdapter**（`inbox/channel_adapters.py:42–68`）：协议/边车渠道只要落库即被 `ProtocolInboxAdapter` 读出，**不必新写**。

### 1.2 回复链现状（抖音可以直接复用的资产）

三条回复引擎（A 线 Telegram、B 线 `protocol_autoreply.run_autoreply`、System Z `AutosendWorker` 拟稿→自动发）共用 `SkillManager.process_message`，并共用一整套闸门：Kill-Switch / canary / 反封号 `send_guard`、`outbound_text_guard` 语言闸、`work_hours_gate`、`reply_pacing_settings` + `humanize`（先已读、再「正在输入」、再分段发）、`takeover` 人工接管、`journey_stage / relationship_stage`、`goals` 成交目标引擎、`care` 主动关怀与 `reactivation` 唤回（注意 `src/nurture/` 是**养号**——标已读、给自己发消息，不触客，与客户培育无关）、`media_enrich` 识图/语音转写、`outbound_translate` 出站翻译、`cta_links` 短链追踪（实施93）。**这些对抖音都是零改动可用的**——差异只在「收发管道能力」和「平台规则」。

### 1.3 兄弟仓 huoke 的可复用资产与边界

- `engines/huoke/src/app_automation/tiktok.py`（约 5000 行）：TikTok **国际版**（`com.ss.android.ugc.trill` / `musically`）安卓真机自动化——养号、筛选关注、回关聊天、`check_inbox` 收件箱处理，基于 `uiautomator dump` XML + 视觉兜底；配套 `ComplianceGuard`、`human_pacing`、`LeadsStore`、A/B 话术胜者、地域策略。**抖音（`com.ss.android.ugc.aweme`）没有对应实现**，UI 树完全不同，但 `BaseAutomation` / 目标筛选 / 节奏 / 合规护栏约四成可复用。
- huoke 有自己的 `ChatBrain`（`src/ai/chat_brain.py`、`chat_bridge.py`）——**第二个回复大脑**。抖音接入若沿用它，会出现「同一客户在抖音被 ChatBrain 接、转到 WhatsApp 后被 SkillManager 接」的人格分裂。
- 两仓已有桥：`leadbus` 线索总线（huoke → chengjie，`src/integrations/leadbus_account.py`，`personal_rpa` mode = 收件箱可见、可治理、**本机编排器不接管**），以及 `huoke/docs/INTEGRATION_CONTRACT.md` 的 task_type 命名空间。实施46 提出过「chengjie 向 huoke 投 task、只读回收结果」的桥接思路，**未落地**。

### 1.4 明显短板（与抖音直接相关）

1. **无「按渠道的出站策略」**：字数上限、是否允许外链、回复时间窗、每轮消息条数上限，目前散在 `reply_split` / `cta_links` / `media_limits` 里且按全局或按人设配置。抖音的规则（文本 ≤ 1000 字、**禁止外部 URL**、24 小时窗内 ≤ 6 条、进私场景 30 秒内 ≤ 3 条）如果不落成策略层，System Z 的多气泡分段会直接把配额打光，`cta_links` 的短链会触发 `28001038 text 不允许传入 HTTP 超链接`。
2. **平台枚举 20 处散落**（见 §0 事实 3）：Zalo/IG 接入时的历史欠账，抖音再付一次税就是第三次。
3. **无「回复窗口」概念的 UI**：WhatsApp Cloud / Messenger 也有 24 小时窗（`fb_send_with_window_fallback` 只在后端兜底），坐席看不到倒计时——抖音窗口更严苛，必须可见。
4. **无「线索捕获 → 结构化留资」的统一模型**：`leadbus` 落库是 `[线索捕获]` 占位文本（`leadbus_account.py:32`），客户面板没有「留资卡回填的手机号/微信」字段；而抖音的核心变现动作就是留资卡。
5. **事实卡与金标把「抖音不支持」钉死**：`product_facts.UNSUPPORTED_CHANNELS`、`howto_pack.py:1013–1028`、`config.desktop.internal.yaml:385` 的对客 system_prompt、`tests/test_product_facts.py`——上线时必须一并翻转，且要区分「企业版支持 / 个人号版准入区」两种口径。
6. **「转人工」触发是三处独立实现、后果各异**：`case_center.py` 的人工请求词只开案例、AI 照常回复；`messenger_rpa/escalation.py` 的关键词真正拦截进审批队列但只服务 Messenger 真机；`human_escalation.py` 只在 Telegram 群追加 @；人设的 `boundaries.escalation_phrases` 声明了却没有任何消费代码。抖音客户说「找人工 / 转客服」时应有渠道无关的统一处置，而不是取决于消息从哪个平台进来。
7. **风险策略默认 `shadow`**（`autosend_policy.policy_mode`，2026-09-04 拍板）：风险扣稿全部放行只记台账。这对宽松平台可以接受，对抖音这种以行为指纹和内容合规为主判据的平台不行——策略档位需要能**按渠道覆盖**。

### 2.2 竞品与市场信号（用于定优先级，不用于抄）

- 抖音私信咨询量同比 +145%，人工客服覆盖率只涨 12%（艾瑞 2025 白皮书，竞品文章转引）——需求侧真实。
- 2026 年头部方案（快商通、美洽、来鼓、米多客、智齿）的**标配清单**：7×24 秒回、**评论追粉**（评论区意向词 → 自动私信）、**自动发留资卡/名片卡**、自动打标签、**定时回捞**、多账号聚合（≥ 50 号）、行业违禁词库、留资**秒推企微/飞书**、**3 分钟内回访**（转化是 30 分钟后的 5 倍）、按流量来源（测评视频 vs 秒杀直播）切换接待策略。快商通的差异化是「AI 客服 + 工作手机 + SCRM」三合一——**工作手机 = 真机 RPA**，说明头部玩家也在用非官方通道补官方缺口。
- 风控口径（字节营销观察 2026 Q1，竞品文章转引）：超过 50% 的私信违规与「非正常用户行为」有关；平台按回复速度、频次、句式同质化形成「行为指纹」，1 毫秒内千篇一律的回复比 1–3 秒波动、句式多样的账号更容易被标记。**智聊现成的 `humanize` / `reply_pacing` / 人设多样化正是对症的资产。**
- 具备官方授权的系统「账号安全性高 10 倍、转化高 40%」（美洽引用中国信通院 2025 报告）——**企业版必须是官方通道**，这是销售话术，也是合规底线。

### 2.3 抖音 × TikTok：同源不同规——一个渠道族、两套传输层

老板追问「抖音和 TikTok 规则是否一致、能否一起开发、全球规则是否一样」。结论：**产品逻辑相似，但账号体系、开放平台、接口协议、平台规则、法律环境全部不同；公共层一起做，传输层各做各的；TikTok 的官方接口还按账号注册地分区。**

| 维度 | 抖音 | TikTok |
|---|---|---|
| 产品与后端 | 独立 App（`com.ss.android.ugc.aweme`），仅中国大陆 | 独立 App（`trill` / `musically`）；美国业务自 2026-01-22 归 TikTok USDS 合资公司（Oracle 托管数据与算法，独立 ToS） |
| 开放平台 | `open.douyin.com` / 抖店 / 巨量引擎 | `developers.tiktok.com`、`business-api.tiktok.com`（Business Messaging）、`partner.tiktokshop.com` |
| 第三方私信 API | 移动/网站应用能力已回收，只剩企业主体小程序 IM | **Business Messaging API 存在，Open Beta**（APAC / 拉美 / 中东非 / 北美），需 Business Account + Business Center 授权 |
| 地区可用性 | 仅中国大陆 | 按**注册地**：EEA / 瑞士 / 英国不可用，美国多数伙伴标不可用，印度无 TikTok |
| 谁能开口 | 用户先发 / 进私事件 / 已授权用户主动私信（每日 1 次） | **仅用户先发**，无主动私信与群发；付费入口 Messaging Ads |
| 回复窗口 | 24h ≤ 6 条；进私 30 秒 ≤ 3 条 | 48h ≤ 10 条 |
| 内容形态 | 文本 ≤ 1000 字、禁外链；留资卡 / 问题引导卡 / 小程序卡 / 券 | 文本 ≤ 6000 字、图片 ≤ 3MB（美、欧盟、英、日、韩、菲、澳、印等多地禁媒体）、share post；无按钮 / 语音 / 视频；welcome message / suggested questions / chat prompt |
| 评论 → 私信 | 无官方；`item.comment` 可公开回复（待核实） | 公开回复有 API；评论触发私信仅越南 / 泰国 / 印尼经 Marketing Partner 灰度 |
| 电商客服 | 抖店飞鸽 ISV（`/pigeon/*`） | TikTok Shop Customer Service API（`seller.customer_service`，`/customer_service/…/conversations/…`，`NEW_MESSAGE` webhook，HMAC-SHA256，3 秒内回 200）；按国家站点授权 |
| 端内私信规则 | 未互关 1 条；企业号更宽；实名制 | 16 岁以下禁用、16–17 仅好友、18+ 可开所有人；非互关 1 条 message request；实测日限 10–100 随信誉浮动 |
| 风控 | 行为指纹（速度 / 频次 / 句式 / 外链） | 同风格；新号 72h 冷账号、首条带链即拦、24–48h 分级禁发 |
| 法律 | PIPL / 网络安全法 / 未成年人保护 | GDPR / DSA、美国 USDS 数据托管、各国年龄法 |
| 直播弹幕 | 直播小玩法 / 互动工具官方推送 | 无公开第三方接口，市面走非官方 websocket |
| 语言 | 简体中文 | 多语言（翻译栈价值点） |

**一起开发（公共层，约六成工作量）**：`platform_registry` 两条目同属 `family=bytedance` 共用图标族；`channel_policy` 同机制不同参数（24h/6/1000/禁链 vs 48h/10/6000/按地区禁媒体）；大脑、人设、翻译、出站闸门、收件箱、回复窗倒计时组件、结构化留资模型、卡片气泡框架、huoke RPA 基座、Playwright 边车模板。

**分开开发（传输层，零共享）**：官方 worker（小程序 IM vs Business Messaging API；飞鸽 vs TikTok Shop CS API）；授权与令牌（抖音扫码 15/30 天续 5 次 vs Business Center 授权）；卡片类型集；RPA 选择器（`tiktok.py` 复用、`douyin.py` 新写）；网页 DOM 脚本；合规词表（中文行业词 vs 多语言 + 地区法规）。**TikTok 账号必须多一个 `region` 维度**——注册地决定私信 API 与媒体是否可用、店铺按站点授权，这是抖音没有的复杂度。

**对优先级的含义**：TikTok 官方通道的资质门槛（Business Account + 开发者权限）**低于**抖音（企业主体小程序上线 + 信用分 90）。若海外市场优先，TikTok 官方接入可从 P3 提前到与抖音 P1 并行，由老板按市场优先级拍板。

## 3. 三视角分析

### 3.1 开发工程师视角 —— 「传输层不难，难的是策略层和 20 处枚举」

**做对的地方（可直接复用）**
- 入站/出站契约稀薄且稳定；三条回复引擎、闸门、翻译、镜像全部平台无关；`platform_capabilities` 从代码推能力矩阵并有门禁，新 worker 一注册就自动进表。
- 非官方模式已有成熟的产品化表达：`login_kind`、`notice_unofficial` 正向提示（「小号 + 独立代理」）、`platform_readiness` 三态原因码——抖音个人号版直接沿用。
- 官方 webhook 有统一骨架 `shared/official_inbound.process_official_inbound` + `official_api_worker.OfficialApiWorker`，`line_token_refresh.py` 是令牌续期的现成范式。
- `leadbus` + `personal_rpa` mode 给「外部进程驱动的账号」定义了正确的安全不变量（可见、可治理、不接管），抖音真机托管就该挂这个 mode。

**真正的工程难点**
1. **抖音特有出站规则 → 必须新建「渠道出站策略层」**（`channel_policy`）：`max_text_len=1000`、`links=deny`（命中即改为留资卡/问题引导卡或删链）、`reply_window=24h`、`per_window_cap=6`、`enter_scene_cap=3/30s`、`bubbles_per_turn≤2`、`risk_policy_mode=enforce`（覆盖全局的 `shadow` 档）。由 `reply_split`、`cta_links`、`outbound_gate`、`autosend_policy` **查询**该层，而不是各自再长一份 if platform == "douyin"。WhatsApp Cloud 24h 窗、LINE 5000 字上限也顺手归位。
2. **进私 30 秒硬时限**：`im_enter_direct_msg` 到达后 30 秒内必须发出问候，否则 `28003080`。System Z 的拟稿 → 人审链路来不及；需要「**进私即发预置问候（模板/问题引导卡），随后 AI 接管**」的快路径——这正是 `greeting.py` + `holding_reply.py` 的用武之地，只需支持「按事件类型触发」。
3. **令牌生命周期**：15/30 天 + 最多续 5 次 = 195 天后**必须人重新扫码**。要有定时续期 + 到期前 7 天在工作台和小智里提醒（`platform_session_health` 已有 `reason_class` 机制可扩）。
4. **官方 webhook 需要公网 HTTPS**：桌面版（Electron + PyInstaller，`cloud_light` 档）没有公网入口。企业版天然是服务器/云实例交付，或经云端中继转发到桌面——沿用现有官方渠道（LINE/Meta/Zalo）的部署口径，方案里明说而不是假装桌面版能直连。
5. **真机路径的脑手分离桥**：huoke 新增 `douyin.py`（UI 树 + 视觉兜底），暴露 task_type `douyin_read_inbox` / `douyin_send_dm` / `douyin_reply_comment`；chengjie 侧 `DouyinDeviceWorker` 出站 = 向 huoke host 投 task 并等回执；入站 = huoke 把会话按 `make_message` 形状 POST 到 `/api/internal/protocol/ingest`（携 `source.account_id` 归属真实设备号）。**huoke 的 ChatBrain 对抖音关闭**。这条比协议级调用重一个数量级（异步、重试、状态回传），实施46 已经指出。
6. **网页托管边车**：仿 `services/instagram-web` 新建 `services/douyin-web`（Playwright），登录形态是**扫码**（抖音网页版本身就出二维码，用户体验与 TG/WA 一致），`storage_state` 持久化，Draft.js 编辑器注入，stealth 指纹；边车常驻即满足「页面常开」。
7. **抖音 chat_key / 消息 id 口径**：官方 = `douyin:user:<open_id>`，`conversation_short_id` 长期有效、`server_message_id` 24 小时有效——两者都要落 `source`；`normalizer._PLATFORM_MSG_ID_FIELDS` 加 `douyin: ("server_message_id","msg_id")`。真机/网页托管拿不到 open_id，用「昵称 + 头像指纹」当 chat_key，与 Messenger web 的 `synthMsgId` 同策略。
8. **测试门禁清单**：`test_platform_matrix`（WORKERS/INBOUND_SITES 登记）、`test_official_channel_onboarding`（向导字段 ↔ webhook 键 ↔ account_id 口径）、`test_product_facts`（事实卡翻转）、`test_platform_login_defaults`、`test_seed_modes_are_implemented`，外加新的 `test_channel_policy_douyin`（外链拦截 / 6 条配额 / 30 秒快路径）。

### 3.2 市场经理视角 —— 「抖音是国内第一流量入口，但智聊今天卖的是美元」

**为什么值得做**
- 智聊的差异化不是「又一个抖音客服」，而是**唯一一个把抖音和 Telegram / WhatsApp / LINE / Messenger / Instagram / Zalo 放进同一个收件箱、同一个人设、同一条成交目标链的产品**——跨境卖家（抖音 + TikTok Shop + WhatsApp）与出海品牌是天然客群；「客户从抖音进线、加了 WhatsApp 后 ChatX 还认识他」（`contacts` 跨渠道身份归并）是竞品没有的故事。
- 免费标准翻译（0 Token）对「抖音进线的海外华人 / 东南亚客户」是独特卖点。
- Token 按量计费对中小商家比 SaaS 年费友好；企业年框 / 私有化部署承接医美连锁、教培这类头部行业（快商通在消费医疗 80% 市占，说明该行业付费意愿最高）。

**必须诚实面对的缺口**
1. **支付与主体**：国内抖音商家用微信/支付宝付人民币，智聊定价是 USD/USDT（`products/zhiliao/product.yaml`）。合规分层里已写「支付主体 / 域名分离」，抖音企业版上线前要有**人民币收款主体与开票**，否则线索来了收不了钱。
2. **准入区不能出现在主站**：个人号版（真机/网页托管）按 `compliance.guard` 只能进准入区，销售口径要与 Zalo/IG 个人号一致——「稳定运行建议」而非「绝对安全」，绝不承诺「不封号」。
3. **功能对标表**（上线即要能回答「你们有没有」）：秒回 ✅（现成）、评论追粉 ⚠（需 `item.comment` 或真机）、留资卡 ⚠（需实现）、自动标签 ✅（`intent_tags`）、定时回捞 ⚠（抖音官方仅对已授权用户每日 1 次；真机可做但受节奏约束）、多账号聚合 ✅（注册表；真机受设备数限制）、行业违禁词库 ⚠（`src/compliance` 需补抖音医美/教培词表）、留资秒推 ✅（`webhook_notifier` 可推企微/飞书/TG）、3 分钟回访 ⚠（`sla_watcher` + 手机推送需接线）、按来源切策略 ⚠（官方 webhook 无来源字段；真机可读「来自视频/直播」）。
4. **GTM 节奏**：先用**自家抖音蓝 V**（实施77 已在抖音投放）当第一个客户吃自己的狗粮，跑通留资到成交；再找 3–5 家医美 / 教培 / 房产客户做企业版试点（他们有企业号、愿付年框、痛点在夜间进线）。
5. **KPI 定义要从第一天埋点**（实施02B 的 KPI 看板可扩）：首响时长、夜间留资率、评论追粉开口率、留资率、3 分钟回访率、账号健康 / 封禁率、人工接管率、每条线索 Token 成本。

### 3.3 用户视角（两层用户）

**老板 / 运营（买单的人）**
- 想要：「把抖音号连上就自动接待，别封号，线索一个都别丢，夜里也有人（AI）接」。
- 怕：封号、违规被处罚、漏掉进私 30 秒窗口、AI 乱承诺（实施69「夜市摊照片谎称已发」的教训在抖音会被放大，因为图片要走 `tool.image.upload`）、24 小时窗过了发不出去、抖音客户加微信被平台拦。
- 需要看到：接入向导里三张卡（企业版官方 / 手机托管 / 网页托管）各自的门槛与风险写清楚；抖音账号卡上有**今日发送 / 上限、令牌剩余天数、风控状态**；日报里有抖音进线与留资；转人工时手机（企微/飞书/TG）秒收提醒。

**坐席（用的人）**
- 统一收件箱里抖音会话要一眼可辨（图标、来源标签「视频 / 直播 / 主页 / 评论追粉」）、**24 小时回复窗倒计时**、「本轮剩余可发 N 条」提示；粘贴链接时被拦并建议改发留资卡；一键发问题引导卡 / 留资卡 / 小程序卡；评论追粉任务列表（哪条评论、已私信否）。
- 人工接管后 AI 让位（`takeover` 现成），并提示「抖音规则：24h 内最多 6 条」。

**终端客户（抖音用户）**
- 想要：秒回、像真人、说抖音的话（口语、短句、少量表情、不发长段落）、留资一键（卡片）而不是被问「电话多少」、不被生硬导流到微信、转人工不用重复说。
- 智聊对症资产：`humanize` 已读→输入→分段、人设多样化、`reply_split`（在抖音要收紧到 ≤ 2 段）、`holding_reply` 稳住话头、`goals` 引导留资的节奏感。

## 4. 目标架构：一个渠道族、两条合规轨、一颗大脑

```
                      ┌──────────────── 合规主站（企业版，官方通道） ────────────────┐
  抖音开放平台 ─webhook─▶ douyin_webhook.py（验签/幂等/30s 快路径）─┐                 │
  （小程序 IM）  ◀─/im/send/msg/─ OfficialApiWorker(douyin) ◀──────┤                 │
  抖店飞鸽      ─事件/消息─▶ doudian_pigeon_webhook.py ────────────┤                 │
  巨量飞鱼 CRM  ─线索 POST─▶ leadbus（clue_source=5 抖音私信留资）─┤                 │
                      └──────────────────────────────────────────────┼─────────────────┘
                      ┌──────────────── 准入区（个人号版，非官方） ───┼─────────────────┐
  抖音 App(真机/云手机) ◀─task/回执─▶ huoke douyin.py（手）◀─桥─▶ DouyinDeviceWorker ┤
  抖音网页版           ◀─Playwright─▶ services/douyin-web 边车 ◀────▶ DouyinWebWorker   ┤
                      └──────────────────────────────────────────────┼─────────────────┘
                                                                     ▼
                 make_message → emit_incoming → InboxStore（douyin:<acct>:<chat_key>）
                                                                     ▼
            channel_policy(douyin) ─┐   SkillManager（唯一大脑：人设 / KB / 目标 / 关怀）
     reply_split / cta_links / gate ◀┘            ▼
                           send_via_adapters → AccountOrchestrator → 对应 worker → 出站镜像
                                                                     ▼
                     platform_registry（单一事实源：名称 / 颜色 / 图标 / 模式 / 事实卡 / i18n 键）
```

**四条设计纪律**
1. **一颗大脑**：抖音所有模式的回复生成都走 `SkillManager`，huoke 只做设备 I/O；`personal_rpa` mode 不进 `ORCHESTRATED_MODES`（门禁已钉）。
2. **策略层先于传输层**：`channel_policy` 是 P0，任何抖音 worker 上线前必须先过它，否则第一天就会撞 `28001038` / `28003070`。
3. **合规分层可机检**：`compliance.visibility`（主站 / 准入）在渠道注册表里是字段，官网与向导按字段渲染，不靠人记。
4. **不接管就不假装接管**：网页/真机托管在工作台的状态、能力矩阵、日报里都如实标「托管（非官方）」，与 Zalo 个人号口径一致。

## 5. 按优先级排序的统一实施方案

### P0 —— 路线拍板 + 资质启动 + 引擎公共层 + 网页托管 MVP（本周起 1–2 周）

**P0-1 决策（老板拍板，不写代码）**
- 确认双轨：企业版 = 小程序 IM 官方通道（主站）；个人号版 = 真机 / 网页托管（准入区）。
- 确认「企业主体小程序」由谁持有：**自建「无界智聊」小程序**（合规主站主体，一次申请服务所有企业版客户；客户企业号授权绑定到该小程序）vs **要求客户自有小程序**（门槛高、周期长）。建议自建，客户自有作为私有化部署选项。
- 确认人民币收款主体与开票路径（市场侧前置条件）。

**P0-2 资质申请立即启动（长周期，并行于开发）**
- 抖音开放平台：注册企业主体小程序 → 上线 → 信用分维持 ≥ 90 → 能力实验室申请「小程序私信/群管理」「主动授权私信组件」「留资卡（`im.message_card`）」「图片上传（`tool.image.upload`）」；同时申请移动/网站应用的「管理视频评论（`item.comment`）」并确认是否仍开放。
- 抖店开放平台：服务商入驻 + 「客服消息 / 飞鸽 ISV」权限申请。
- 巨量引擎：以自家蓝 V 在飞鱼 CRM 配一条线索推送规则到测试 URL，拿到真实样本载荷。
- 自家抖音企业号：绑定小程序、授权 IM；**关闭「互动经营工作台」自动回复策略**（否则 API 发信 `28003095`）。

**P0-3 引擎公共层（结构改动，抖音之外全渠道受益）**
- 新建 `src/integrations/platform_registry.py`：单一事实源（`id / display_zh / display_en / brand_color / icon_key / modes / default_mode / login_kind / compliance_visibility / msg_id_fields / console_url / i18n_keys / facts_supported`），由它**派生**：`normalizer.PLATFORM_DISPLAY`、`platform_login.DEFAULT_PLATFORM_MODES`、`product_facts.SUPPORTED/UNSUPPORTED_CHANNELS`、`channel_setup.CHANNELS` 的平台段、前端 `platform_icons.js` 与各模板 PC/PI/PN/PLAT_COLOR 表（构建期生成一份 `platform_registry.json` 供 JS 读取）。加门禁：任何模板/脚本里再出现手写平台色表即红。
- 新建 `src/inbox/channel_policy.py`：按平台的出站策略（字数、外链、回复窗、配额、每轮气泡数、媒体白名单），`reply_split / cta_links / outbound_gate / autosend_policy / media_limits` 改为查询该层；先登记 douyin 与 whatsapp(official) 两套值，其余平台默认「无限制」保证零行为变化。

## 6. 刻意不做（与做什么同等重要）

1. **不做协议逆向**（创作者平台 protobuf / websocket 抓包直发）——违反用户协议与网络安全法规，封的是客户的号，砸的是我们的牌子。
2. **不在私信里发微信号 / 外链 / 导流卡片**——官方接口本身不支持，非官方通道发了就是高危行为指纹；留资只走留资卡与小程序卡。
3. **不做群发骚扰式「主动私信」**——官方主动私信只对已授权用户每日 1 次；真机模式的主动触达受 `care` 打扰账本（实施84）统一预算约束。
4. **不让 huoke ChatBrain 接抖音**——两颗大脑必然人格分裂，也让人设、知识库、目标引擎的投入白费。
5. **不在主站宣传个人号托管版**——合规分层是硬约束（`product.yaml compliance.guard`）。
6. **不承诺「不封号」**——所有非官方模式沿用 Zalo/IG 的「稳定运行建议」口径。
7. **不为抖音单独造一套收件箱 / 拟稿 / 发送链**——契约已在，任何「抖音特殊所以另写一条」的提议先证明策略层放不下。
