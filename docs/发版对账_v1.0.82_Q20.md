## §〇 根因两句话

1. **爱称层级漏水**（VDUJX6 / PQE9ZF）：#155 把双向称呼挪到联系人级后保留了「逐字段回落人设级」，客户面板占位还写「未填则沿用人设称呼」——运营不填，一百个客户就共用人设档的 `babe`。
2. **客户侧名字被人设名压过**（Q9GDEH / 2PKKM6，15:56 实录）：账号在客户那里叫 Alicia、人设名 Mizuki，联系人级「对方怎么叫我 = Alicia」只进了 #24 钉子的「绝不拿它称呼对方」，没有「那就是你的名字，绝不纠正」——AI 出站「It's Mizuki, not Alicia」，客户「Mizuki who are u? I know only Alicia」。

## 一、层级规则（本线之后的单一事实源：`contact_names.resolve_address_context`）

| 场景 | `call_peer`（我怎么叫对方） | `peer_calls_you`（对方怎么叫我） |
|---|---|---|
| 有会话 id，联系人级已填 | 联系人级值（`source=contact`） | 联系人级值（`source=contact`）；≠ 人设名 → 追加「对方一直叫你 X，绝不纠正、自我介绍用 X」硬约束 |
| 有会话 id，联系人级空 | 会话显示名（`conversations.display_name` 过 `usable_display_name`：非裸号码 / ≠ chat_key / 含字母 / ≤40 字，`source=display`），措辞「用名字或不称呼、**不用任何爱称**」；显示名不合格 → 空＝不称呼 | 空＝对方叫你就是叫人设名（不出附加行） |
| 无会话 id（纯人设预览 / 工具型调用） | 人设级 `names.call_peer`（`source=persona`，旧行为） | 人设级 `names.peer_calls_you`（旧行为） |
| inbox store 不可用 | 空（宁可不称呼，不串味） | 空 |

出站呼格守卫（`sendpoint_guard` ← `contact_names.overlay_sendpoint_names`）改为**替换语义**同上表，与 prompt 注入同源；人设级 `babe/baba` 不再经守卫漏进有会话的出站。
