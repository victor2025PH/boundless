> 背景：老板明确「我们不做报价系统——转化行为是把用户引导到网站/落地页/其他 APP」。
> 实施92 建成的成交引擎脊柱（阶段推导/自动挂链/回复让路/漏斗归因）全部保留，
> 本方案只换**转化语义层**：报价→成交 换成 引导→转化。
> 状态：方案待拍板；实施92e 已上线部分不受影响（报价关键词推导在 guide 风味下停用）。

## 一、业务模型转译

| 销售风味（92 现状） | 引导风味（本方案） | 触发源 |
|---|---|---|
| quoting（报价：出现价格词） | **guided（已引导：发出过追踪链接）** | 出站消息带本会话专属短链（事件驱动，不再扫关键词） |
| deal（成交：人工标记/变现入账） | **converted（已转化：客户完成了目标动作）** | ① 短链被点击（轻转化，自动）② 落地页/APP 回传 webhook（深转化）③ 人工标记 |
| repeat（复购） | **re-converted（复访/再转化）** | 第二次转化事件 |

核心决策：**阶段内部 id 不改**（quoting/deal/repeat 在库里、触发器里、漏斗里原样），
改的是（a）展示标签（i18n 换文案：报价→已引导、成交→已转化），（b）进入阶段的
**推导来源**（关键词 → 追踪链接事件）。这样 92 全部机器零重写：stage_enter 触发、
自动挂链、回复让路、NBA 建议、漏斗归因、批量挂链全部自动适配新语义。

配置开关 `inbox.workflows.journey.flavor: sales | guide`（默认 sales=现状零变化；
本部署 overlay 置 guide）。flavor 决定：标签集、推导器、种子链包、预设接线表。

## 二、核心新机制：每会话追踪短链（转化的事实源）

转化发生在站外（网站/落地页/APP），IM 侧看不见——必须给每次「引导」发一个
**可归因的凭证**。业界标准做法就是带参跳转链：

```
运营配置转化目标（CTA 目标库）
   └─ {target_id, 名称, 目标URL, 类型: site|landing|app|group, utm 追加}
坐席/链步骤要发链接时
   └─ 引擎按 (conversation_id × target_id) 铸造 token → 短链 {public_base}/r/{token}
客户点击
   └─ GET /r/{token}（公开路由，无鉴权）
        ├─ 302 → 目标URL（自动追加 utm_source=chat&utm_content={token}）
        ├─ cta_links 落账（clicks+1, first_click_ts）
        ├─ 旅程阶段 guided → converted（首点）+ EventBus 事件（坐席 toast「客户点了链接」）
        └─ 漏斗计数
落地页/APP 后端（可选，深转化）
   └─ POST /api/cta/convert {token 或 contact_key, kind: signup|install|order, amount?}
        （复用 monetize webhook 的密钥校验模式；有 amount 走 deal_events 记营收）
```

### 数据结构

- `cta_targets`（DB 表，运营在 /workflows 页维护）：target_id / name / url / kind /
  enabled / utm(bool)。
- `cta_links`：token(PK) / conversation_id / target_id / created_ts / sent(bool) /
  clicks / first_click_ts / last_click_ts。token = 8 位随机 urlsafe（不可枚举），
  同会话同目标 24h 内复用同 token（防重复铸造刷库）。
- 深转化沿用 `deal_events`（source='cta_webhook'，带金额进营收归因；点击不进
  deal_events——**点击不是钱**，漏斗分开数）。

### 公网可达前提（部署配置，非代码问题）

短链必须客户可点：`cta.public_base` 配置（如 https://<你的网站域>/r 反代到引擎，
或托管实例的 public_url）。未配置 → 功能面板显示「需配置公网基址」，铸链入口
禁用——诚实降级，绝不发内网地址给客户。

## 三、阶段推导改造（guide 风味）

- **guided**：铸链且消息真实发出（事件驱动写 stage，`src=cta`）——不扫文本、
  零误判；`quote_keywords` 推导在 guide 风味下整体停用。
- **converted**：首次点击（`/r/{token}` 命中）自动推进 + 事件；深转化 webhook /
  人工「标记转化」同样推进（人工入口沿用 92c 右栏旅程条，按钮文案随 flavor 换）。
- 前进棘轮 / manual 优先 / 让路 / 挂链判重全部不变。

## 四、自动化接线：`{{cta:target_id}}` 占位符

链话术步骤 / 坐席草稿里写占位符，**出站管线统一解析**为该会话的追踪短链：

- 解析点与披露注入（disclosure）同款三接线（A 线 sender / deferred / autosend
  deliver），同样有静态门禁钉「三点全接、绝不绕行」；
- AI 自动拟稿的指令追加「如需引导用户访问，原样保留 {{cta:xxx}} 占位符」——
  LLM 不碰 token，铸造在发送时刻（保证 conversation 绑定正确）；
- 解析失败（目标停用/未配公网基址）→ **整条消息不发并降级提醒坐席**（发出去
  一个死链接比不发伤害大得多——fail-closed）。

## 九、93b 增量（2026-08-31 深夜：URL 保护 + 深转化 webhook + 一键发链）

### ① 出站翻译 URL 保护（正确性修复，优先级提到最前）

自动发送 + 出站自动翻译都已开闸，链步追加的追踪短链会进翻译引擎——LLM 系引擎
改写/转写/吞 URL 是常态风险，短链错一个字符=死链整条引导白发。修法（`outbound_translate.py`）：

- 译前 `_protect_urls`：URL → `[[[Ln]]]` 占位（纯 ASCII 三重方括号，NMT/LLM 引擎
  几乎必然原样保留）；译后 `_restore_urls` 还原。
- **质量判定全在掩码域比较**（same-text/CJK 残留 vs `text_masked`）——无 URL 时
  逐字节旧行为，2026-08-17 无兜底纪律零松动（echo 未真译照样 HOLD）。
- 纯链接消息（掩码后无可译内容）不调引擎原样放行；占位被引擎吞掉 → 对应 URL
  追加文末（链接必达；比 HOLD 整条或发丢链版本都诚实）。
- 门禁：`test_outbound_translate.py` +5 例（掩码/还原/丢失追加/纯链接跳过/掩码域 HOLD），55 绿。
