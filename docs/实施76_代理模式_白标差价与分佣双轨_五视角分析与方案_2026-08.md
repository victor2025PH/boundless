# 实施76 · 代理模式：白标差价 vs 分佣 —— 五视角分析与三级双轨方案（2026-08-27）

> 命题（老板原话）：分析官网，怎么把我们的产品做出一个代理模式——
> ① 让代理换 LOGO 和名字、自己定价、赚差价？还是 ② 让代理沿用我们的 LOGO
> 和产品系列、只给分佣？深度思考、多角度给方案。
>
> 本文以**官网（website/，bd2026.cc）与引擎（engines/chengjie）现有代码实况**为地基，
> 不是空对空的商业模式讨论——先盘家底，再对比，再给分阶段落地方案。

---

## 零、三句话结论

1. **不是二选一，是三级双轨**：分佣（推广员）和白标差价（合伙人）服务的是两种完全
   不同的代理人群，中间还漏了一档最容易成交的「经销商」（用我们的牌子、批发价进货、
   按牌价卖赚差价）。正确结构 = **L1 分佣 → L2 经销 → L3 白标**，代理按出货量逐级
   升，两头都要，先上最快的。
2. **家底比想象厚，两条路都已建成约 80%**：白标侧——引擎 `C1-1 白标/贴牌`
   （`/api/admin/branding` 改名/换色/换 logo + 旗舰档去署名）、桌面壳品牌热替换
   （`brand-util.js`，连任务栏图标都能热换）、托管租户一键开通（`tenant_ops`，
   订单→40 秒全自动开实例+子域+证书）**全部已在生产**；分佣侧——邀请裂变台账
   （`referral-store.ts`：归因、五层防刷、7 天退款观察窗、首充 10% 返利、人审）
   **也已在生产**。真正要新建的是「代理」这个身份层：现金佣金台账、批发进货面、
   代理工作台三块。
3. **一条铁律贯穿所有档位：Token 是持续烧钱的云成本，代理只能预付、绝不赊账**。
   分佣是「后结佣金」（我们先收到钱才分），经销/白标是「预付进货」（代理钱包先充值
   再消耗）——两个方向的现金流都必须朝我们，坏账结构性为零。

## 一、官网与引擎现状盘点（方案的地基，均为已验证的代码实况）

### 1.1 官网（website/，Next.js，bd2026.cc）

## 二、两种模式的本质对比（先想清楚再动手）

| 维度 | A. 白标贴牌 · 代理定价赚差价 | B. 我们品牌 · 分佣 |
|---|---|---|
| 商业本质 | **批发-零售**：代理是我们的客户，终端客户是代理的客户 | **联盟营销**：客户始终是我们的，代理只管引流 |
| 客户关系归属 | 代理（我们看不到、也不该看到他的客户） | 我们（LTV、复充、数据全归我们） |
| 定价权 | 代理完全自主（不同牌子不构成比价，无窜价问题） | 必须统一官网价（否则自毁价格体系） |
| 代理毛利 | 批发折扣决定，可到 40-70%（信息差市场甚至卖 2 倍价） | 佣金比例决定，通常 10-30% |
| 代理动力 | 最强——「这是我自己的产品」 | 中等——顺手推荐的零花钱 |
| 我们的品牌积累 | 无（但对灰度市场反而是**隔离层**：出事是代理的牌子） | 全积累 |
| 支持负担 | 代理必须自担 L1（终端客户根本不知道我们是谁）；我们只对代理 L2 | 全在我们 |
| 现金流 | **预付进货**，现金流前置、坏账为零 | 我们先收全款、后结佣金，无坏账 |
| 财务复杂度 | 低（卖货给代理，一次性收入） | 中（佣金台账、观察窗、退款回收、提现打款） |
| 风险 | 代理拿我们的产品做违规业务、代理跑路后其终端客户断供善后 | 刷单套佣（已有五层防刷可复用） |
| 工程量（基于现状） | 中：批发进货面 + 白标开通参数化 + 代理钱包 | 小：现金佣金台账 + 代理码 + 工作台 |
| 上线速度 | 4-6 周 | **1-2 周** |
| 适合的代理 | 有客户资源、想做「自己的生意」的工作室/团队长 | 个人用户、KOL、社群主 |

**为什么不能只做 A**：白标门槛高（要预充、要自己做支持、要自己收款），95% 的潜在
推广者跨不过去——他们只想发个链接赚钱。只做 A 等于放弃长尾流量。

**为什么不能只做 B**：分佣对「手里有 20 个跨境团队客户」的团队长没有吸引力——
10-30% 的佣金 vs 自己贴牌卖 2 倍价赚 60%+，他会去找可以贴牌的竞品。只做 B 等于
放弃最有出货能力的渠道。

**为什么中间必须有 L2 经销**：很多代理想赚差价但不想（也不配）做白标——给他们
批发折扣、用我们的牌子按官网价卖，差价=折扣空间。这一档**转化门槛最低、对价格
体系伤害最小**（限价协议钉死官网价），而且是白标代理的天然筛选器：L2 出货量
达标才升 L3，避免「白标开出去三个月卖零单」的沉没服务成本。

## 三、五视角分析

### 视角一 · 财务/定价（钱怎么算才不亏）

**成本结构认知先行**：我们卖的不是一次性软件，是「授权 + 持续的云端 Token 消耗」
（GPU/云模型是真金白银的边际成本）。这决定了：

1. **批发折扣的底线由 Token 边际成本决定**。假设牌价 1U=1,500 Token 的综合毛利为
   G（老板掌握真实数），批发折扣率 d 必须满足 `d > (1-G)`，并留出运营余量。
   建议锚点（可按真实成本调）：

   | 档位 | 进货价 | 代理毛利（按牌价卖） | 门槛 |
   |---|---|---|---|
   | L2 经销 | 牌价 **7 折**（首批）→ 6.5 折（月出货 ≥2,000U） | 30-35% | 首批进货 ≥500U |
   | L3 白标 | 牌价 **6 折** → 5.5 折（月低消 ≥5,000U） | 自主定价，典型 50-70% | 首批预充 ≥2,000U + 签白标协议 |

2. **分佣比例**：现有 C 端首充返利是 10%（Token）。代理档要拉开差距才有动员力：
   - **首充佣 25%**（现金 USDT）+ **复充佣 10%**（12 个月内）——复充佣是让代理
     持续维护客户的关键设计，比一锤子 40% 更健康；
   - 沿用 **7 天退款观察窗**（`REFERRAL_REBATE_DELAY_DAYS` 同款）后才可结算，
     `refunded` 订单佣金自动回收；
   - 月结、USDT 打款、单笔起结 50U（凑不够滚入下月，省打款手续费与碎单核对）。

3. **三档收入模拟**（以 200U 客单、年复充 600U 估）：

   | 角色 | 动作 | 年收入 |
   |---|---|---|
   | L1 推广员带 10 客 | 首充佣 10×50U + 复充佣 10×60U | ~1,100U |
   | L2 经销月出 2,000U | 差价 30-35% | ~7,000-8,400U/年 |
   | L3 白标月出 5,000U、卖 1.5 倍价 | 差价+溢价 | ~40,000U+/年 |

   逐级收入落差就是升级动力，体系自带「向上爬」的势能。

4. **绝不做的两件事**：
   - ❌ 后付/赊销 Token（云成本先烧我们的钱，代理跑路=双重损失）；
   - ❌ 给白标代理「按他的售价分成」（他的售价我们不可见也不可审计，
     只按我们的批发价结算，他卖多贵是他的本事）。

### 视角二 · 产品/工程（复用什么、新建什么）

**复用映射表**（这是本方案最值钱的部分——绝大多数轮子已造好）：

| 需求 | 复用 | 新建 |
|---|---|---|
| 代理归因 | `order-store` 的 `ref`/`utm_source` 字段模式 | `agent_code` 字段 + 下单链接 `?agent=AG-XXXX` |
| 防刷 | referral 五层防刷 + `refunded` 回收 + 观察窗 + console 人审，**全部原样复用** | 无 |
| 佣金计算 | `rebateCharsForOrder` 的算式骨架（比例+封顶+观察窗） | 现金口径台账（`agent-store.ts`，仿 referral-store 的原子写+审计流水模式） |
| 批发签码 | 厂商机 `issue_license`/`topup_voucher` 离线签发 | 批量签码守护分支（一单 N 码，回填码清单） |
| 白标换皮 | 引擎 branding API + 桌面壳热换标 + PWA，**零新代码** | 无 |
| 白标开通 | `tenant_ops provision` + `tenant_ai_preset.yaml` 白名单注入 | preset 扩 `brand:` 段；`provision --brand-preset` 参数 |
| 白标域名 | `expose --slug` 子域 + LE 证书自动签 | 自有域名 CNAME 接入（P2，nginx server_name 加一行的量级） |
| 白标计量 | hosted gateway `IID:` 计量 + `gw-budget` | 代理父账户聚合（多个 IID 挂一个 agent，钱包扣代理） |
| 违规熄火 | license CRL 吊销 + `tenant_ops suspend` | 无 |
| 代理后台 | `/console` 宿主 + referral-approve 先例 | console「代理」tab（审核/佣金率/结算记录）+ 代理自助工作台 `/agent` |
| 招募 | `lead-store` 表单管道 | `/partners` 落地页（双语） |

**工程量评估**：P0（分佣）约 1-2 周；P1（经销批发）约 1-2 周；P2（白标）约 2-4 周
——三段可流水线推进，P0 上线当天起就在验证渠道需求，为 P1/P2 提供真实数据。

### 视角三 · 市场/渠道（招谁、怎么讲故事）

1. **代理画像分层**：
   - L1：现有用户（用得爽的人是最好的推销员）、TG 群主/KOL、跨境社群运营者——
     **官网会员中心已有邀请卡 UI**（`/app` 会员中心 invite-info/referral-stats 路由），
     升级文案即可触达存量；
   - L2：卖号商、TG 生态服务商、跨境电商培训机构——他们已有付费客群，缺一个
     「能赚差价的货」；
   - L3：想做「自己的 SaaS」的工作室、GoHighLevel 式白标玩家、区域市场代理
     （东南亚/中东语言区——产品的多语能力是白标卖点）。
2. **讲故事的顺序**：招募页主推 L1（零门槛，人人可进），L2/L3 作为「晋升路径」
   展示——「从分享链接到拥有自己的 AI 客服品牌」，让代理看到天花板。
3. **渠道冲突治理**：
   - L2 用我们的牌子 → **限价协议**（不得低于官网挂牌价销售；差价来自批发折扣
     而非降价倾销），违者扣保证金/降级/清退；官网价就是市场最低价，直营渠道
     永远不被自己的代理打穿；
   - 大客户**报备制**：代理报备的企业客户 90 天保护期，直营不抢单（抢单一次，
     渠道口碑归零）；
   - L3 白标品牌不得与「智聊/ChatX/无界」构成混淆性近似（协议条款）。
4. **借力现有归因**：订单 `ref` 字段本就支持「AI 会话促成的下单」归因——代理
   自己就是 ChatX 用户时，**他用 ChatX 卖 ChatX**，效果即案例，这是最有说服力的
   招募素材。

### 视角四 · 风控/合规（哪里会翻车）

| 风险 | 场景 | 防线（大多已建成） |
|---|---|---|
| 刷单套佣 | 代理自买/机器批注册 | 指纹去重、self_invite 拒绝、IP 聚集人审、日/累上限、观察窗——referral 全套复用；代理档另加**佣金按月人审后打款**（打款是手动动作，天然最后闸门） |
| 退款套佣 | 首充→拿佣→退款 | `refunded` 状态 + 7 天观察窗 + 已结佣金从下月佣金抵扣（负余额） |
| 窜价 | L2 低于官网价倾销 | 限价协议 + 定期测试购买（mystery shopping）+ 保证金制度 |
| 白标违规业务 | 代理拿贴牌产品做黑产 | 白标协议（用途承诺、责任转移、违约金）+ **熄火开关双保险**（license CRL 吊销 + tenant suspend，一分钟内可断供）+ gated 产品线（智控 MatrixX 等 `visibility=gated` 高风险 SKU）**首期不入白标目录** |
| 代理跑路 | 白标代理失联，其终端客户断供 | 协议写明：数据导出义务 + 我们保留「转直营接管」选项（托管实例在我们机器上，技术上随时可接管；`tenant_ops export` 已有）——这反而是托管白标相对装机白标的巨大优势 |
| 品牌反噬 | 白标客户体验差，骂声传回主品牌 | 白标形态下终端客户不知道我们（隔离层生效）；但**质量下限仍是我们的算力与引擎**——SLA 对代理承诺即可 |
| 佣金纠纷 | 归因争议（谁的客户） | 归因规则白纸黑字：下单时 `agent_code` 唯一有效、首触归因（第一个归因码锁定 12 个月）、争议以订单台账 jsonl 审计流水为准 |
| 收款合规 | 代理收款方式我们不背书 | 白标模式代理**自主收款**（我们只对代理收批发款 USDT/Stripe）——终端支付合规责任在代理，协议明示 |

### 视角五 · 运营/支持（谁伺候谁）

1. **支持分层铁律**：
   - L1/L2 的终端客户 = 我们的客户，支持照旧（客服控制台、报障入口不变）；
   - L3 白标的终端客户 = **代理的客户**：我们的工单系统只认代理身份，终端客户
     摸到我们的支持入口一律回「请联系你的服务商」。托管实例的 `/api/support`
     一类入口要能按租户配置隐藏/改写指向（品牌 overlay 顺带配 support 联系方式，
     branding 已有 `website_url` 字段先例）。
2. **升级/发版**：白标托管实例跟随我们的发版节奏（tenant 体系天然如此）；装机
   白标用通用安装包 + 后端热换标（见 §1.2），**不为单个代理维护安装包分支**——
   这条红线不守，发版矩阵会指数爆炸（打包 SOP 现在就有 173 机型的坑，别再乘 N）。
3. **代理生命周期**：申请 → 人审（console）→ 签协议（L2/L3）→ 激活码位/进货 →
   月度对账单（自动生成，仿 weekly-report 机制）→ 分层升降级（按季出货量）。
4. **额度看板**：白标代理需要看到「我的钱包余额、我的子客户用量」——复用
   `gw_usage_trend` 采集 + 代理工作台读数（不给他看单客户聊天内容，只给用量汇总，
   数据边界清晰）。

## 四、推荐方案：三级双轨代理体系

```
 L1 推广员（Affiliate）        L2 经销商（Reseller）        L3 白标合伙人（White-label）
 ─────────────────           ─────────────────           ─────────────────
 我们的品牌                    我们的品牌                    代理的品牌（LOGO/名字/域名）
 分佣：首充25% + 复充10%       批发进货 6.5-7折              批发进货 5.5-6折
 现金 USDT 月结               按官网价卖，赚差价 30-35%      自主定价，赚差价 50-70%
 零门槛，人人可申请            首批进货 ≥500U + 限价协议      首批预充 ≥2000U + 月低消 + 白标协议
 客户是我们的                  客户是我们的                   客户是代理的（L1支持归代理）
 上线：P0（1-2周）             上线：P1（+1-2周）             上线：P2（+2-4周）
```

**升级路径**：L1 累计带单 ≥1,000U 可申请 L2；L2 连续两月出货 ≥2,000U 可申请 L3。
每一级都是下一级的漏斗与筛选器——白标只开给已证明出货能力的人，服务成本不空转。

### P0 · 分佣推广员（1-2 周，先上先验证）

1. `website/lib/agent-store.ts`（仿 referral-store 骨架）：代理档案（申请/人审/
   状态机 pending→active→suspended）、`AG-` 归因码、佣金台账（订单号/比例/金额/
   观察窗到期日/结算状态/打款 tx）、月度聚合；
2. 下单链归因：`/order?agent=AG-XXXX` → `OrderEntry.agent_code`（宁缺毋错，与
   `ref`/`utm_source` 同款纪律）；首触归因 cookie 12 个月；
3. `/partners` 招募落地页（双语，lead-store 收表单）+ `/agent` 代理工作台（我的
   链接/带单列表/佣金余额/申请提现）；
4. console 新增「代理」tab：审核申请、看台账、标记打款（打款本身手动 USDT，
   月结，起结 50U）；
5. 防刷全复用 referral 模块既有五层 + 观察窗 + refunded 回收。

### P1 · 经销商批发（+1-2 周）

1. 批发 SKU（`agent-pack-*`：授权码包/充值码包，7 折档）进 `sku_registry` +
   下单流（仅 active 代理可购，走既有 USDT/Stripe 通道）；
2. 厂商机守护批量签码分支：一单 N 码，码清单回填订单，代理工作台可查可导出；
3. 限价协议模板 + 保证金条款；console 代理 tab 加进货/出码记录；
4. 码激活时回写归因（哪个代理的码激活了）→ 复充佣金仍按 L1 规则叠加（经销客户
   的后续官网直充，代理拿复充佣——鼓励代理把客户引到正规通道）。

### P2 · 白标合伙人（+2-4 周）

1. **托管白标（主推形态）**：`tenant_ai_preset.yaml` 扩 `brand:` 白名单段
   （company_name/product_name/logo_url/primary_color/hide_powered_by/website_url/
   support 联系方式）→ `tenant_ops provision --brand-preset <agent>` 开通即贴牌；
   子域用代理指定 slug（或 P2.5 支持自有域名 CNAME）；桌面壳用通用安装包，登录
   即换皮换图标（brand-util 现有能力，零新代码）；
2. **代理钱包**：代理预充（批发价）→ 子客户实例的 `gw-budget` 从代理钱包划拨；
   代理工作台看余额与子客户用量汇总；余额告警（复用 watchdog 告警管道）；
3. **白标协议 + 熄火开关**：协议模板（用途承诺/责任转移/数据导出义务/违约条款）；
   违规处置 SOP = license 吊销（CRL）+ `tenant_ops suspend`，一条命令断供；
4. 白标目录**首期只放 ChatX 主线**（含内建翻译），gated 高风险 SKU 不入；
   `white_label` 功能位随白标授权签发（去 Powered by 的既有 gating 直接生效）。

### 刻意不做（防跑偏）

- ❌ 为每个白标代理**重打安装包**（后端热换标已覆盖 95% 需求；桌面安装器本身的
  图标/文件名保持中性即可，P2.5 再议「中性无品牌安装器」）；
- ❌ 给白标代理建「他定价的官网商店」（他的定价他自己收款，我们不碰他的零售价，
  也就不用建 N 个变价商店——这是白标模式能保持轻的关键）；
- ❌ 分佣与经销差价对同一笔订单叠加（一单只走一种归因，先码后链）；
- ❌ 后付账期（任何档位）。

## 六、风险与止血预案（上线后盯的三张表）

1. **佣金台账健康表**：观察窗内退款率 >10% 的代理自动 flag 人审（复用 referral
   flagged 语义）；
2. **窜价巡检**：L2 出码激活价与官网价比对异常（码大量流向低价二手渠道的信号=
   激活地域/指纹分布异常），console 出报表；
3. **白标代理余额/低消表**：连续两月未达低消 → 折扣回落；余额告警 → 断供前 72h
   通知代理（不通知终端客户——那是代理的客户）。

极端止血：任何代理一分钟内可全链断供（吊销 + suspend + 归因码停用），已有机制，
无需新建。
