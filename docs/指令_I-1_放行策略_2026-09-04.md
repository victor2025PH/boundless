## 2. 这个 bug 是什么（工单 #160，P1）

报障人 skuio 花无缺，1.0.71，证据包 `GRECHC` / `JTU34M`，原始会话
`D:\chengjie-instances\zhiliao\data\protocol_media\telegram\6834964252_1148.md`。

客户说了一句**完全正面**的话：

> `"Yes you did because I was happy chatting with you i didn't want to stop"`

系统的处理链：

1. `src/ai/chat_assistant_service.py` L246-249 `_detect_intent` 用
   `any(k in t for k in ("stop", ...))` **子串匹配** → 在 `i didn't want to stop` 里命中了 `stop`
2. 判为「停止联系」意图
3. L278 `_detect_risk` → `reasons=[stop_contact]` → risk=**high**
4. `src/inbox/drafts.py` L1192 `risk_to_autopilot` high → **L4**（最高审批档）
5. AI 生成的稿子是干净的（`"Aww, that's really sweet…"`），但被扣留到 21:04 才被人发现

**用户看到的现象**：全自动模式下，AI 明明写好了得体的回复，却什么都不发；聊天页零提示；审批卡片只显示一个英文类别名，不显示到底命中了什么词。用户不知道发生了什么，只知道「全自动不工作」。

> ⚠ 「聊天页没提示 / 卡片说不清原因」这两条**不要去修**。§3 的决策是让风险挂起整体消失，
> 挂起没了，提示就没有存在意义——修它属于给死路径加装饰。前端零改动。

**根本问题不止是正则写错**。真正的设计错误是：**把「客户提到了敏感话题」当成「AI 不能回复」的理由**。客户提到银行、提到分手、提到身体，这些都是正常聊天内容；该管的是**AI 自己要说什么**，不是客户说了什么。

## 3. 老板已拍的决策（2026-09-04 更新，**这是最终版，覆盖任何更早的说法**）

> **风险扣稿全部放行，一条硬底线都不留。触发只写台账，不改变发送行为。**
> 攒满一个月真实流量数据后再做深度分析、定新拦截规则。

拍这个决定的理由：拦截的**代价对用户是不可见的**。用户只看到"全自动不工作了"，
不知道为什么、也不知道要去哪看。在没有真实分布数据之前收紧规则，是拿用户体验换
一个没被验证过的假设。所以先全放、先量出来。

### 3.1 影子档（shadow）——本条要实现的形态

配置键 `inbox.l2_autosend.policy_mode`，取值 `shadow` | `enforce`，**默认 `shadow`**。

`shadow` 档语义：

| 输入 | 行为 |
|---|---|
| 客户入站风险 low / medium / high（含 `stop_contact`、`self_harm`、索要凭证） | **一律放行**，`decide()` 返回 L2 |
| AI 稿 `reply_risk` low / medium / high（含要说付款、账号、密码） | **一律放行**，`decide()` 返回 L2 |
| 上述任一条按旧规则**本会**降档 | 写一条台账记录，**不改变发送行为** |

**唯一不受影响的是会话自己的档位设置**：会话 `automation_mode=review` 是用户显式选的
人审档，与风险无关，照旧挂起。本条只取消**风险驱动的降档**。

`enforce` 档在本条里**只留代码骨架、不接线、不给默认值**——一个月后读完台账再定它的
规则表。不要现在猜着写 enforce 的内容。

### 3.2 坐席侧完全无感（已拍：ops_only）

- 审批卡片、聊天页横幅、待处理清单**一个字都不加**。全自动就该是无感的。
- 台账只进两个地方：JSONL 落盘（持久，一个月数据的权威口径）+ ops 看板（值守读数）。
- 例外只有一个：`stop_contact` / `self_harm` 命中时**即时推值守群**（见 3.3）。这是 ops
  侧通道，坐席界面不受影响。

### 3.3 `stop_contact` 的即时通知（不拦，只报）

放行 `self_harm` 有下游兜底——`_apply_crisis_safety_net` 挂在草稿生成链上
（`skill_manager.py` L2723 = A 线、L3582 = B 线 `generate_inbox_draft` 内），
severe/elevated 会注入安全指令、触自伤红线的回复被 `safe_fallback_reply` 整段覆盖、
热线资源补一次。所以放行发出的是**已被安全网处理过的稿**。

`stop_contact` 没有任何下游守卫。客户说"别再联系我"之后 AI 继续发 = 骚扰 = 举报 = 封号，
而这个仓库有 `ban_signal` / kill-switch / 账号冻结机制，说明封号是真实发生过的。

所以：**不拦，但命中即时发 EventBus 事件**（新事件 `autosend_shadow_alert`，webhook 订阅
别名 `autosend_shadow`，`rate_key` 按 `account:conv` 防同会话刷屏），文案带会话 id +
命中词 + "已放行，如需止损请人工介入"。值守能在封号前几分钟看到，代价是零。

### 3.4 入站风险仍要转成守卫提示（这条不变）

风险不再扣稿，但仍**转成守卫提示**喂给人设产线：「对方提到 xx，不得报价 / 不得给账号或
付款信息 / 不得越界」。这是**在生成侧**约束 AI 说什么，不是在发送侧拦——正是老板要的方向。

风险信息照样写进 draft 行的 `peer_risk` / `peer_reasons`（供台账和一个月后的分析用），
但**前端不显示**（ops_only）。

### A. 放行决策收口到单一入口（纯函数）

新建 `src/inbox/autosend_policy.py`：

```python
def decide(
    peer_risk, peer_reasons, reply_risk, reply_reasons,
    risk_hits,                 # 命中词，来自 quick_analyze 新增返回值
    automation_mode,           # 会话档位：auto_ai / review / off
    policy_mode="shadow",      # shadow | enforce
) -> Decision:
    """Decision = (level, hold_reason, shadow: ShadowRecord | None)"""
```

`shadow` 档的实现就是一句话：**先按旧规则算出 `would_hold_level` / `hold_reason`，
然后无条件把 `level` 覆写成 L2、`hold_reason` 覆写成空，把算出来的东西放进 `shadow`
字段返回。** 旧规则的计算逻辑要**保留**（那是 enforce 档一个月后的起点，也是台账的判据），
只是不再作用于发送。

`automation_mode=review` 走在这一层**之前**——那是用户显式选的人审档，与 `policy_mode`
无关，直接返回挂起且 `shadow=None`（不是风险触发的，不该进台账）。

然后 `drafts.py` 的 `auto_generate_draft` / `enrich_draft` / `risk_to_autopilot` /
`is_autosend_allowed` 与 worker 的捞稿逻辑**全部只认它**——不许任何一处再自己算一遍档位。
这是本条最重要的结构不变量：两处各算一套，就会出现「台账说放行了、实际还是被拦」这种
一个月后无法归因的状态。

账号级覆写**本条不做**（shadow 档下全放行，覆写没有作用面）。留到 enforce 档再设计。
