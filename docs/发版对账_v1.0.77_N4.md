**问 2：钧机 Mizuki 的 `voice_profile` 是否是 L-2 A「配置需修正」组合？引擎实际用了什么声？**

**问 3：「试听已过期」是谁触发的？**

- 两层：① 橙条本身也是上面那条 CSS 病——`stale-note` 同样恒常可见；② 但截图里「发送」按钮确实是灰的（`send.disabled = stale || silent || busy`），而 `_silent` 在服务端 voiced 时不可能为真 → **stale 真为 true**。复现（Playwright 夹具，`_effConvLang='zh'`、服务端回 `voice_translated=false / target_lang=''`）：生成一结束 `_isStale()=true`、`sendDisabled=true`。
- 机制：「跟随翻译发声」默认开 → 请求 `target_lang='auto'`；服务端把 auto 解析成会话客户语言 `zh`，与原文同语种 → `resolve_spoken_text` 走 `identity` 不译 → 回包 `voice_translated=false, target_lang=''`；前端把「未译」记成 `_previewXlEff=''`，过期比对时基准回落成 `'auto'`，当前有效值却是 `_effConvLang='zh'` → `'zh' !== 'auto'` → 过期。**用户没改任何东西，是面板自己的翻译维度比对把「没译」和「目标语 auto」当成了两个不同的设置。** 中文客户 + 中文文本 = 钧的全部场景，所以他两天两次都撞上；skuio 0831 原图 924 是同一比对的另一形态（#121 时只补了 `'auto'→'en'` 那一侧的豁免）。
- 顺带核实 mid 1319「零 TTS 行」：他的关键词 `tts` 本可命中 `[tts] 合成生效` / `[voice/tts-test] 有声终审`（zl_collect 是子串匹配），真因是 **时间窗**——报告 21:46:17 抓「最近 40 分钟」（21:06–21:46），而他的生成在 18:29 与 21:49，窗内本就没有合成。E 项统一 `[tts]` 前缀仍做（一词抓全），但回访要告诉他「Since 要覆盖到出问题那一刻」。
