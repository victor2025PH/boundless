## §〇 先答一问：`織り機の前に座って…` 是怎么进画像的？

工单 7FN84P 日志（`tmp_diag/7FN84P/…report.md`）：16:42:40 `[episodic] schedule run … msg_len=125` → 16:42:41 `[profile] conv=telegram:7331682688:7340576921 slot=occupation value=織り機の前に座って、新しい帯の色合わせ source=ai_inferred status=mentioned`，`grounding_dropped=0`。同一分钟我方拟稿 `lang=ja … 金曜の午後はやっぱりいいよね、こっちのカフェも静かで`。三处缺口叠在一起：

1. **形态没人管**：`ground_slots` 只验「出处」（值 / 引文在 `user_msg` 里）、`slot_value_suspect` 只拦语言名——一段带 `、` 的日语整句只要在 `user_msg` 里出现过（客户消息里夹了引用 / 转发的我方日文稿）就能过闸。年龄槽同理：`age` 没有「必须是 16–99 数字或年龄段」的约束。
2. **出站进了 prompt**：`build_merged_prompt` 把 `ASSISTANT:` 我方回复一并送给 LLM 作「语境」——粤语客户 + 日语咖啡馆稿 = 串台幻觉的原料。
3. **没有语种守卫**：客户 30 条入站全是粤语（汉字），值却是假名整句，没人比对。

另 16:48 `[episodic] residence captured … 我住在去嵐山散步`（后续 `我住在河邊行`、`我住在得慣呀`）不是画像槽，是 `skill_manager._capture_residence_fact → user_clock_resolver.stated_place_from_inbound_text → memory_slots._RESIDENCE_PATTERNS` 的裸「住」正则把「住得慣呀」「去嵐山散步」当地名写成 `user_stated` 事实——同一个「形态没人管」的病。

**修法**：在 `profile_slots` 立**一把尺子** `slot_validate(key, value) -> (归一值, 原因)`，画像三条写口（合并抽取 `profile_fill.apply`、旧 LLM 轨 `profile_llm.run_llm_capture`、居住地启发式 `user_clock_resolver`）同吃；`profile_fill.apply` 对 `ai_inferred` 再加原话锚定（evidence 必填 + 最近 30 条入站逐字）与语种守卫；`run_extraction` 不再把 `reply` 送进 prompt；前端 N/10 只数 confirmed、待确认另显、年龄控件数字化、任何值 ≤24 字省略；`tools/profile_purge_unanchored.py` 清存量。
