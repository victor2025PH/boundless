## 2. 三视角分析

### 2.1 开发工程师视角：这个项目的病根与体质

**病根＝配置源的「四头马车」**。同一个功能的开关状态散在四处：`config.example.yaml`
（4400+ 行，服务器语义）、`config.desktop.min.yaml`（clean 档）、
`config.desktop.internal.yaml`（内测档）、zhiliao overlay（生产灰度真值，1160 行，
不进 git）。已有机制覆盖了「注册表 ↔ min.yaml ↔ 存量升级」三角（种子门禁 + 基线补齐 +
升级可达性门禁，本次全部实测有效），**但 zhiliao overlay → 内测种子这条边没有任何
机制**——v1.004 到 v1.005 之间 19 天的漂移（小智、唱歌、话题源、图文一致性 P2/P3……）
全靠这次人工净差分才追平。灰度毕业没有「毕业典礼」：一个功能在生产 overlay 里开了
两周表现良好，不会有任何东西提醒「该进种子了」。

**体质好的部分要说清楚**（这次修得快正是因为它们在）：探针式前端激活（关=零痕迹，
开=自动出现，模板热更新与后端重启解耦）；`_ensure_seeded_extras` 的「只补缺失键」
让存量坐席机升级即拿到新开关、用户显式改过的值永不被覆盖；升级可达性门禁
`test_seed_switch_upgrade_coverage` 在本次实施中当场抓住两个孤儿子键——这张网是活的。

**软降级的诚实度参差**是第二个工程债。全功能开箱后，LAN 依赖功能出了内网的表现：
翻译回落 ai 引擎（无感 ✓）、唱歌 hub 不可达如实拒绝（✓）、识图/克隆语音/转写走托管
网关（✓）、**小智语音提问按钮却会在外网机上「按钮在、点了报错」**（transcribe 读
`audio_pipeline`=LAN 端点，托管 ASR 网关只接管 `voice_recognition` 段）——「开了但
必然失败的入口比没有更糟」这条产品纪律（min.yaml 灰选项教训）在这个子键上破了例。

### 2.2 市场经理视角：卖的到底是什么

**1.0.50 clean 包是「毛坯房」，客户以为买的是「拎包入住」**。官网发的是零数据种子档：
无人设、无相册、无克隆语音、无 KB，而产品的全部宣传卖点（12 个真人感人设、语音、
相册、唱歌、全自动成交推进）都长在数据资产上。用户下载后的第一分钟决定口碑——
毛坯房+找不到开关+发布说明还在宣传住进来多舒服，这是**负口碑放大器**（「假宣传」
比「没功能」伤得深）。1.0.51 用内测形态直接交付，把第一分钟从「空壳」变成
「满配演示间」，这是本次最大的转化率改进。

**发布说明必须是「包内实况的镜子」**：1.0.50 notes 写了「小智助教升级」但包里开关
是关的——写 notes 的人看的是代码仓（功能确实做完了），没人核对交付形态。发版
SOP 需要一步「notes 宣传的每个功能名，在这个包的种子里状态是什么」。

**商业口径要显式拍板（本次按老板指令执行，但要点名后果）**：内测形态自带
`licensing.feature_gate.plan_override: flagship` + `trial.enabled: false`——
**1.0.51 是「旗舰全功能、不计量、无试用墙」的包**。对内测/演示是对的；若把它
直接放官网当正式发行档，等于把全部售卖档位白送。正式售卖前必须出「计量发行档」
（全功能可见 + 试用额度 enforce + 到期引导付费——功能可见性和付费墙是两层，
不要再用「关功能」当付费墙，那就回到这次事故的起点了）。

**卖点排序建议**（按差异化强度）：① 真人感全家桶（节奏/分条/克隆语音/唱歌/相册/
图文一致性——竞品最难抄，因为是几十个细节的叠加）；② 小智（把「上手成本」变成
卖点：装完 5 分钟内小智手把手教会接入第一个账号——这直接降激活流失）；③ 多平台
聚合收件箱；④ 全自动成交推进（目标/工作流/主动触达）。

### 2.3 用户视角：第一天的体验旅程

**开箱 10 分钟**（1.0.51 后）：装完 → 满配演示间（12 人设/相册/语音全在）→ 右下角
小智球会呼吸 → 问「怎么接 WhatsApp」得到带路径的答案 → 扫码接入 → 客户来消息，
AI 自动回了，节奏像真人。这条路今天是通的，是本次改动的直接收益。

**但「全功能」对新用户同时是认知过载与掌控感风险**：
- 装完第一天 AI 就在**替我给客户发消息**（全自动开箱）+ **主动给沉默联系人打招呼**
  （proactive_topic 开、72h 冷启动预热闸在）。对「陪聊运营」用户是卖点，对「正经
  客服」用户第一反应可能是害怕。安全带都在（AI 接管三档一键退、出站安全闸、
  额度守卫、kill-switch），但**用户不知道安全带在哪**——需要首启时一句人话：
  「现在是全自动模式，AI 会直接回复客户；点这里随时改成『AI 拟稿、你审核后发』」。
- 演示资产的身份问题：12 个人设/相册照片是厂商演示内容，用户会问「这些照片是谁、
  我能商用吗、怎么换成我自己的」。设置页已有演示数据清空按钮，但没人告诉用户它在哪。
- 报错要说人话：外网机点小智麦克风报「语音识别不可用」——用户不知道这是「你不在
  办公室内网」。凡是环境依赖型失败，文案要带「为什么+怎么办」。

## 3. 优化方案（分级，可直接排期）

### P0（本批已交付）
全功能种子 v1.005、小智 A 类基线化（含存量升级自动点亮）、帮助语料首启自动播种、
1.0.51 打包发坐席/待发渠道。

### P1（下一批，工程可直接做，无需拍板）
1. **种子漂移审计工具**（治本）：`tools/seed_drift_report.py`——zhiliao overlay ⊕
   合并视图 vs 内测种子的**功能开关类键**净差分（密钥/生产数据类自动归入白名单桶），
   输出「生产开了、种子没带」清单；挂 `gate_sweep -Full` 当提示灯（不拦发版），
   `push_chatx/dist` 前人工过目一眼。灰度毕业从「靠人想起来」变成「有账可对」。
2. **小智语音按钮可达性探测**：bootstrap 响应带 `voice_ready`（服务端探
   `audio_pipeline`/托管 ASR 可达性，60s TTL），前端按它亮/隐按钮——把「点了才知道
   不行」变成「不行就不出现」，对齐灰选项纪律。
3. **首启向导补「自动化模式确认页」**：一句人话说明全自动已开 + 一键切拟稿人审 +
   演示资产说明（含清空入口指路）。零新后端，向导页面加一屏。
4. **发版 SOP 补核对步**：notes 宣传功能 ↔ `feature_matrix` / 种子开关状态逐条过目
   （把本次事故的教训固化进 `chatx-desktop-install` 规则）。
5. **dist:win:smart 链式 bug 修复**（意向板 04:10 已点名：refresh 成功分支不接
   dist:win）——分步跑是当前 workaround，修掉少踩一次。

### P2（需要拍板再动）
1. **正式发行档的计量策略**：旗舰全开不计量（现内测形态）只适合内测/演示期；
   正式售卖需「全功能可见 + trial enforce + 档位墙在权益层不在可见层」的发行种子
   （licensing 段独立成第三档种子或经官网签发授权文件驱动）。
2. **clean 档的定位**：保留（隐私敏感客户/OEM 白标需要零演示数据形态；本次已让
   clean 档也带小智），但官网默认下载位应指向全功能档，clean 档转为按需提供。
3. **用途分流预设档**：首启按「客服型 / 运营陪聊型」二选一，差异只在
   proactive_topic/daily_ritual 等主动行为的默认档（安全闸两档都在）。
4. **instagram/zalo 边车随包**：zhiliao 生产已在用（8792/8793），桌面壳 SPECS 尚无
   ——要不要把这两个登录方式带给客户属产品决策（涉及包体积 + 平台风控面）。
