# 实施65 · 语音真人感：有逻辑的停顿、口误与重复（三视角分析与优化）

> 日期：2026-08-23 深夜。触发：老板试听实施63 B.1 的云端真链路对比稿后拍板方向可行，
> 但点出核心缺陷——**「停顿感要在分句后；故意读错字、说错话、重复感要有逻辑，
> 不是乱停乱错」**。本文＝根因解剖 + 最新技术对标 + 三视角优化方案。
> 姊妹篇：实施63（算力迁移，含 B.1 语音上云审计）、实施57/58（唱歌能力）。

---

## 0. 结论速览

1. 「乱」的根因不是模型不行，是**架构里管「停哪/错哪/重复哪」的三个机制全是瞎子**
   （几何切分 + crc32 掷骰子），而链上唯一懂语义的组件（口语化 LLM）的理解力
   没有传递下去——它输出的省略号停顿标记被 pacing 无视，pacing 自己重新瞎切。
2. 2026 业界共识与我们的差距恰好互补：**「语音剧本」模式**（LLM 一次产出带
   停顿/呼吸/口误标记的说话剧本，TTS 层纯执行）——OpenAI GPT-Live 用端到端模型
   把韵律决策交给懂语义的模型；ElevenLabs v3 干脆放弃 SSML 改用内联音频标签 +
   LLM「Enhance」自动打标；学界（FillerSpeech、SSML 级联 Qwen）用 LLM 预测
   填充词位置/类型/时长，MOS 3.20→3.87。我们的所有零件都在，只差把决策权
   从 crc32 移交给 LLM。
3. 唱歌算力：作曲上云（Mureka）后，**推荐先做 176 减负（下 ACE-Step，释放 ~11G，
   零跨机风险），再评估 173 音乐专机化**（vLLM chatx 转冷备可再释放 20G+，
   但涉及断云容灾档与中枢线契约，需老板拍板+跨线会签）。

## 1. 现状解剖：五个「瞎插」点（代码级根因）

对照实测产物（实施63 B.1 七人设对比稿）与源码，「乱停乱错」的每一处都能指到行：

| # | 机制 | 现行逻辑 | 为什么乱 |
|---|---|---|---|
| 1 | 长句切分 `voice_pacing.split_chunks` | >44 字的句子在「**几何中点附近**的逗号」切开（`abs(i-len/2)` 取最近） | 中点逗号 ≠ 语义边界——「非要拉着我，喝两杯」从主谓宾中间劈开，停顿落在**分句内部**而不是分句后。这正是老板听到的「停顿不在分句后」 |
| 2 | 思考词 `ensure_think` | 整段无思考词 → 按 `crc32(文本)` 在第 2/3 段**随机**段首硬贴「嗯……」 | 真人「嗯…」出现在**要想的地方**：回答问题前、报数字前、换话题前。贴在随机段首＝为停而停 |
| 3 | 段间停顿 `gap_ms_after` | 按标点类型给固定档（逗号 0.3s/句号 0.56s/问号 0.62s）±15% crc 抖动 | 只认标点不认语义：列举项之间该短、话题转折该长、**反问抛给对方后是句尾不该有长停**；固定档全一视同仁 |
| 4 | 口误/自纠 `disfluency` | 提示词一句「允许一处很轻的口误自纠，随意不刻意」交给 14B 模型自由发挥；出现频率由 crc（每 5 条一次）控制 | 没有位置与对象规则：模型可能在**数字/人名上**打磕巴（锚点守卫只兜「丢失」不兜「选址差」）；「随意不刻意」对小模型等于没说 |
| 5 | 呼吸注入 `inject_paralinguistic` | `[breath]` 插在「crc 选中的**任意一个逗号**后」 | 真人换气在**语调群边界**（一口气说完一个意群，边界处吸气准备下一段长话）；随机逗号可能在意群中间——听感就是「说半句突然吸气」 |

**根因一句话**：唯一懂这段话在说什么的组件（口语化 LLM，跑在 173 qwen2.5:14b）
已经在链上、甚至已经会输出「……」停顿标记，但下游 pacing **不消费它的语义判断**，
用几何+骰子重新决策——三个瞎子踩着一个明眼人的产出各干各的。

## 2. 对标研究（2026-08 联网核实）

| 对标 | 核心做法 | 对我们的启示 |
|---|---|---|
| **OpenAI GPT-Live**（2026-07 上线，替代 Advanced Voice Mode） | 端到端全双工语音模型：去掉轮次检测器，模型每秒多次决策「听/说/停/应和」；停顿、呼吸、嗯哼全部由模型从语义现场生成；深推理异步委派 GPT-5.5 不断流 | 天花板路线（我们没有端到端语音模型），但原理可平移：**韵律决策必须由懂语义的模型做**，规则层只做执行与兜底。用户偏好 75.7% vs 旧版——语义驱动的自然度差距是决定性的 |
| **ElevenLabs v3 audio tags**（2026-03 公开） | 放弃 SSML，改内联自然语言标签 `[pause]/[hesitates]/[stammers]/[sighs]/[inhales deeply]/[short pause]/[long pause]`＋标点（省略号=自然停顿）；UI 的「Enhance」按钮＝**LLM 自动给文本打标** | 工业界已把「打标交给 LLM」产品化；标签词表就是现成的协议模板；「标点即停顿」与我们省略号语义一致 |
| **FillerSpeech**（EMNLP 2025） | LoRA 微调 LLM 从上下文预测填充词的**位置+类型+时长+音高**，交叉注意力控制风格 | 「嗯/啊」的位置是可学习的语义问题，不是随机撒；即便不微调，用强提示词+规则校验也能拿到大部分收益 |
| **SSML 级联 Qwen2.5-7B**（arXiv 2508.17494） | 两个 QLoRA Qwen 级联：模型 A 只预测**韵律边界位置**（F1 99.2%），模型 B 只回归数值（音高/语速/停顿时长）；MOS 3.20→3.87，25-40% 误差下降 | **边界预测与数值预测分离**的级联架构；我们 173 上就是同家族 qwen2.5:14b——同样的活我们的卡白跑得动 |
| **Disfluency Insertion**（arXiv 2412.12710） | LoRA 微调 LLM 插入口误（重复/假开头/自纠），配合支持口误发音的 TTS，感知自然度显著提升 | 口误类型学（repetition / false start / repair）是有限集合，可以规则化为提示词协议；TTS 得会念（CosyVoice 系对「啊不对」类自纠友好） |
| **CosyVoice3 原生标记** | `[breath]/[laughter]` 等副语言标记 tokenizer 层消费 | 我们本地 140 与云端 SF 同家族，标记协议向下兼容——执行层无需换 |

## 3. 差距清单（我们缺什么）

1. **没有「语音剧本」中间产物**：口语化 LLM 输出纯文本，停顿/呼吸/思考/口误四类
   决策散落在三个下游瞎子机制里各自为政。
2. **切分不认语义边界**：几何中点切逗号；LLM 已写的「……」不被当作切分依据。
3. **口误没有类型学与选址规则**：提示词一句话带过，没有「重复只重复句首词/人称、
   自纠只错非事实词、错完立刻纠」的硬规则。
4. **停顿时长没有语义分级**：列举/接续/转折/答问前/句尾问句五种边界一个价。
5. **没有质量回路**：全靠老板耳朵；`prosody_scorer`（韵律 F0/能量 vs 参考音）只进
   夜间探针，没接「新版本 vs 旧版本」的 A/B 判分。

## 4. 优化方案：「语音剧本」架构（Speech Script v1）

### 4.1 架构变更（一句话）

口语化 LLM 的职责从「改写文字」升级为「**产出说话剧本**」——一次输出带标记的
逐段脚本；`voice_pacing` 从「自作主张的切分器」降级为「**剧本执行器**」（解析
标记→逐段合成→按标记停顿/呼吸）；crc32 三兄弟降级为**剧本缺失时的兜底**。

### 4.2 剧本标记协议 v1（借 ElevenLabs 语义，落 CosyVoice 原生）

LLM 输出格式（每行一个语段＝一个合成 chunk，行尾标记控制其后间隙）：

```
今天可把我忙坏了 ‖短
中间还闹了个大笑话，哈哈[laughter] ‖长
嗯……回头讲给你听 ‖中
[breath]你那边一切都顺利吧？ ‖尾
```

- `‖短/中/长/尾`＝段后停顿档（280-380ms / 480-650ms / 750-950ms / 0，执行层加
  ±10% 抖动）；**位置永远在语段（意群）末尾**——「停顿在分句后」由格式天然保证。
- `[breath]`＝段首吸气（执行层替换成参考音真呼吸或 CosyVoice 标记）；只许出现在
  **段首**且下一段 ≥12 字——「换长气说长话」的生理逻辑。
- `[laughter]`＝只跟在笑点后（继承现规则）。
- `嗯……/我想想`＝思考词，只许出现在：答问段首/报数字或选择前/话题转折段首。
- **口误协议**（有逻辑的错，全部进提示词硬规则）：
  · 类型 R（重复）：段首第一个词或人称代词重复一次（「我、我跟你说」）；
  · 类型 C（自纠）：仅限**非事实词**（形容词/普通名词/方位）说错→「啊不对」立刻纠正
    （「上周…啊不对，上上周」这种**日期金额人名品牌一律禁止**——锚点守卫之外再加
    选址禁区）；
  · 频率：R+C 合计每条 ≤1 处，且仅 vivid 档、仅 disfluency 开、仅长度 ≥20 字；
  · 位置：只许前 2/3 段（结尾出错像失智，开头出错像紧张——真人分布）。

### 4.3 执行层与守卫

- 解析器在 `voice_pacing` 前置：有剧本标记→逐行成段、按档取 gap、段首 [breath]
  消费；**无标记（LLM 回落/旧缓存）→ 完整走现行 crc 兜底**——灰度零风险。
- 守卫三条：① 锚点守卫照旧（数字/金额/人名丢失即拒）；② 标记预算（停顿 ≤5、
  呼吸 ≤2、笑 ≤1、口误 ≤1，超额剥标记降级为纯文本）；③ 剧本行数与原文句数
  偏差 >2x 拒收回落。
- 缓存键并入剧本版本号（`script_v1`），与现缓存机制兼容。

### 4.4 质量回路（不再只靠老板耳朵）

- A/B 产物对：每次调参出「旧链 vs 剧本链」同稿对，老板盲听裁决（沿用实施63
  对比稿命名法）；
- 机器初筛：`prosody_scorer`（F0/能量 vs 参考音）+ ASR 回验 CER + 停顿分布统计
  （段长方差、gap 分布应呈现「短多长少」的自然分布而非均匀分布）；
- 埋点：剧本命中率 / 回落率 / 标记预算剥除率进 avatar-status。

### 4.6 P0 实施记录（2026-08-23 深夜，当晚完成）

**落地面**（全部落盘，未激活——`avatar_voice.colloquial.script` 默认关，激活走
overlay + 下个重启窗）：
- `voice_colloquial_llm.py`：`build_speech_script_prompt`（协议提示词，独立版本号
  `_SCRIPT_PROMPT_VERSION` 进缓存键——bump 全局 `_PROMPT_VERSION` 会作废普通口语化
  的全量落盘缓存，刻意分开）+ `sanitize_speech_script`（预算/口误选址/复用既有
  锚点守卫）+ `strip_speech_script`；`llm_colloquialize(script=True)` 分支。
- `voice_pacing.py`：`parse_speech_script`（剧本→chunks；2..10 段出界回落）+
  `gap_ms_for_class`（短300/中560/长850 ±10%）+ `paced_synthesize` 自动识别
  （剧本模式跳过 ensure_think 乱插；[breath] 段前停顿强制 ≥620ms 并成为呼吸插槽）；
  `merge_to_max` 透传 gap_class。
- `tts_pipeline.py`：`_hub_fish_paced` 增 `spec` 参数 + script 前置调用
  （经 `prepass_colloquial_llm(script=True)`）；剧本只活在 pacing 分支内，
  PacingSkip 回落整段单发用的是调用方原 text——**标记零泄漏**到其他合成路径。
- 门禁 `tests/test_speech_script.py`（16 例）全绿；受影响模块既有回归 330 绿
  （test_avatar_voice 3 红＝当日另一线「哑音守卫」与旧夹具冲突，非本改动，已知会）。

**实施中的四次现场优化**（对原 4.2 设计的偏离，均已验证）：
1. 剧本格式从多行改**单行**（‖ 分隔）——多行会被既有消毒的元话语截断规则误伤，
   且缓存/日志更干净；
2. [breath] 从「文本标记直送 TTS」改为「执行层插槽」——剥出标记转真呼吸插入，
   避免「模型合成的吸气 + 参考音真吸气」双重呼吸；参考音呼吸不可用时该段只是
   多一点停顿（软降级，绝不合成噪声凑数）；
3. 口语化与剧本标记**合并为一次 LLM 调用**（原设计隐含两段式）——省一次 LLM
   往返（实测 1.2-3.6s/条），且改写与分段天然一致；
4. 提示词 v2：[breath] 从纯可选改「≥40 字通常应有恰好 1 处」（v1 实测 7/7 全部
   弃用=过度保守）；补「不新加感叹词开场」对齐 vivid 档既有纪律。

**七人设真机 A/B 实测**（173 出剧本 + 云端克隆执行，产物
`tmp_sf_test/克隆_<人设>_剧本链v1.wav`，三版本可盲听对比：干稿直读/真链路v3(crc)/剧本链v1）：
- 剧本成功率 **7/7 零回落**；LLM 1.2-3.6s/条（173 暖态）；
- **停顿位置 100% 落在意群边界**；7/7 把 ‖长 放在「自己的事说完→转问对方」的
  话题转折处——本主线要修的核心缺陷在首批产物上即达标；
- 尾段问句/嘱咐全部零标记（结尾不留怪停顿）；[laughter] 紧跟笑点；
- R 型口误（段首词重复「哎呀哎呀」）出现 4/7，全部在预算内（≤1/条）且在前段；
- 已知余项：[breath] 实测 0/7——测试句的段全部 <12 字，与「带呼吸段要 ≥12 字」
  规则自洽（长回复场景才触发，P1 用长稿复测）；bed QC 在云端干净音频上 4/7
  回落（实施63 B.1 适配器已列「底床改参考音取噪」，同一工单）。

**下一阶段（P1）**：① 长稿复测 [breath] 触发率 + few-shot 补口误/呼吸示例；
② 停顿分布自动体检（段长方差/gap 直方图）进 avatar-status；③ 剧本命中率/回落率
埋点；④ 与 TTS 云适配器合流（同一剧本驱动 140 本地与 SF 云端）；⑤ 生产灰度：
overlay `colloquial.script: true`（重启窗装载）→ 盯 ops 卡回落率 <15% → 老板抽听。

### 4.7 迭代 2（同晚，老板反馈「仍有 AI 感：咬字重音 + 话术不够口语」）

归因拆两层：**咬字重音**＝合成引擎层（首批演示用云端 CosyVoice2-0.5B 小模型；
生产质量轨是 176 IndexTTS-2，不该拿小模型的咬字定全案生死）；**话术**＝改写
模型层（qwen2.5:14b 保守，「笑死我了」被改成书面的「真是把我逗乐了」）。三改：

1. **提示词 v3**（`_SCRIPT_PROMPT_VERSION=3`）：书面词→口头词替换表（非常→特别、
   但是→不过、如果→要是、之后→回头…）、句长上限十二三字、语气助词纪律、
   few-shot 加长稿示例（教会 [breath] 用法）；script 档 max_tokens 240→400（防长剧本截断）。
2. **改写模型升级**：173:8001 vLLM `chatx`（Qwen3.6-27B 无审查，主链锁云后闲置）
   ——`_rewrite_via_endpoint` 本就支持 /v1 + enable_thinking=false，纯配置换血。
   实测冷 13.3s / 暖 1.9s，产出明显更「嘴上说的」；qwen14b 降为备点。
3. **合成引擎三路 A/B**（同一剧本喂三个引擎，产物齐听）：hub IndexTTS-2 质量轨
   （生产同款，22.9-26.3s/长稿 best_of=1，**bed QC 全过 + 赵明德版真呼吸插入**——
   hub 音频有 residues 可取噪，云端「过净」问题不存在）；SF CosyVoice2（对照）；
   **SF MOSS-TTSD-v0.5 克隆实测可用**（对话式 TTS，2.9s 整段，拟人向备胎）。

实测剧本样例（chatx 27B，v3）：赵明德版在 24 字长段前自主放了 [breath]、
「哈哈，笑死我了[laughter]」原样保留——v2 的两个遗留问题（呼吸不触发/笑点丢失）
在长稿+强模型组合下自然消解。产物 `tmp_sf_test/剧本链v3_*`（hub质量轨/云CosyVoice

## 5. 三视角分析

### 5.1 开发工程师视角

- **对的**：分层清晰（文本加工/标记注入/编排/合成解耦），换云端后端零改文本层——
  实施63 已实证；锚点/预算/回落的守卫哲学成熟。
- **错的**：语义决策下放给了非语义机制。crc32 确定性是**缓存友好**的优点，但被
  用在了「需要理解」的决策上——确定性应该保留（同文本同剧本＝缓存安全），改由
  「LLM 一次产出剧本」承担，即**把随机性上移到有智力的层，把确定性留在执行层**。
- **优化即 4.5 表**；另立一条工程红线：**pacing 不得再新增任何「自作主张」的文本
  修改逻辑**（ensure_think 是最后一个），新智能一律走剧本协议进。

### 5.2 市场经理视角

- 「真人感」是本产品在陪聊赛道的**第一卖点**，且是竞品最难抄的（竞品多用裸 TTS）；
  GPT-Live 75.7% 偏好率证明市场对自然度的支付意愿真实存在。
- 剧本协议是**可演示的差异化**：销售可以放「干稿直读 vs 剧本链」A/B 音频——
  实施63 的对比稿已经是现成的销售素材工厂。
- 风险：过度拟人（口误太频/太假）会反噬信任——「有逻辑的错」比「多错」重要，
  频率预算（≤1/条）是产品底线不是技术参数。
- 定价联动：剧本链多一次 LLM 调用（~¥0.001/条），对 token_ledger 定价无感。

### 5.3 用户视角（坐席+终端客户）

- 终端客户的「破绽点」排序（按实录事故）：换声 > 复读机 > 乱停乱错 > 平淡——
  剧本链修的是第 3 项，且绝不能引入第 1/2 项（voice strict 与变体守卫不动）。
- 坐席可感知面：试听即所发照旧；剧本失败回落旧链**不能静默降级到明显更差**
  （回落率进看板，超阈值告警）。
- 验收即用户验收：老板盲听 = 终端客户耳朵的代理；每批改动必须带同稿 A/B 对。
