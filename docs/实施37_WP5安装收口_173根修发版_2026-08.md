## 2. 根因与修法（为什么旧流程会产生「exe only」）

旧杀进程步是 fire-and-forget：`Stop-Process -ErrorAction SilentlyContinue` 吞掉
访问拒绝/慢退出，**从不验证真死、从不看 18799**。旧后端幸存 → 新壳的后端绑
端口失败即退 → 旧后端随后寿终 → 坐席变「exe only (backend not serving)」。
沙箱 smoke（随机端口）结构上看不见这个病——所以修法是两把锁：
**装前**（收割必须验证 + 端口必须空闲，否则拒装）与**装后**（坐席真后端的
`started_at` 必须晚于本次安装，旧后端顶包一秒现形）。

## 4. 瘦身调研结论（WP-5 §3，只出结论不动工——本批实测数据）

安装包 488MB，unpacked 构成实测：

| 块 | 大小 | 备注 |
|---|---|---|
| `services/messenger-web/node_modules/playwright-core` | **448.5MB** | 自带整套 Chromium 浏览器——**单个依赖占整包近一半** |
| `backend/`（PyInstaller） | 304MB | 大头：backend.exe 78M / ntgcalls 27M / openblas 20M / jieba 词典 22M |
| `seed-data/` | 123MB | 人设媒体/语音预渲染种子 |
| `services/whatsapp-baileys` | 86MB | 纯 JS 依赖，无浏览器 |

三条路线判定：
- **A（首选）Chromium 按需下载**：打包剔除 playwright 浏览器本体（保留 ~5MB JS），
  首次启用 Messenger 渠道时下载到数据区（`PLAYWRIGHT_BROWSERS_PATH` 指
  `AITR_DATA_DIR`）+ 进度 UI + 重试/镜像。预估安装包 **488 → ~300MB**
  （Chromium 压缩比 ~2.5:1）。风险：首用需网络——对 cloud_light 新装客户
  本就在线，可接受；不用 Messenger 的客户永远不下载（纯赚）。
- **B electron-updater 差分升级**：blockmap 已在产（1.0.38.exe.blockmap），
  接 electron-updater 后 OTA 升级只传差块。**只优化升级不优化首装**；LAN 舰队
  走 scp 全量不受益。低风险，需要更新服务器（latest.yml 已生成）。
- **C Web 安装器 / 后端按需下载**：复杂度最高（安装器管线+签名+离线安装破坏），
  **不建议**现阶段做。
- 顺带发现登记：打包产物里有 `services/messenger-web/_authed_shot.png`
  （登录截图残留，0.1MB）——不是体积问题是**卫生问题**，下批打包前应加
  extraResources 排除（本批不动打包配置，避免与发版混批）。
