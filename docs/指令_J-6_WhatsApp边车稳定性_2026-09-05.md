## 2. A —— 403 forbidden 账号被无限重连（日志被刷满、真问题被淹）

### 证据（J-3 已核）
- skuio 88MP86 wa-sidecar：`closed unexpectedly → scheduling reconnect` **205 条，185 条来自同一 login `wa_6mvl0luy`（accountId 12132684190）**，掉线码 `403 pending "Connection Failure"` ×186；5 次快退避 3→6→12→24→48s → `reconnect loop exhausted → giving up` → 15min 慢重试再来一轮，**08:26Z–18:27Z 十小时 38 轮**。
- `close-policy.js::decideCloseAction`（L32–）只把 `401 loggedOut` 当终态；`403`（风控封/禁）与 `428` 一样落进「曾配对账号 → reconnect」分支（L44–46）。
```
Select-String -Path D:\boundless\tmp_diag\88MP86\logs\wa-sidecar.log -Pattern '"statusCode":403|status.?403|forbidden' | Measure-Object
Select-String -Path D:\boundless\tmp_diag\88MP86\logs\wa-sidecar.log -Pattern 'giving up' | Measure-Object
```

### 修
1. `CLOSE_CODES` 加 `forbidden: 403`；`decideCloseAction` 对 403 返回新动作 `{action: "forbidden"}`（**终态**，与 `logged_out` 平级）；`server.js` 消费：`postStatus("forbidden")` 给 Python（`/api/internal/protocol/session-status`），停止快/慢重连，会话条目标 `forbidden` + 原因文案「账号被 WhatsApp 限制（403），需换号或申诉后手动重新配对」。
2. 保守起见给一个「连续 N 轮 403 才判终态」的阀（默认 N=2 轮 giving up；首轮 403 仍按 reconnect 走完一轮退避——防瞬时 403 误判），N 可配。
3. Python `platform_session_health`：认 `forbidden` 状态 → ops 卡「🔌 平台会话健康」该账号行红 + 文案 + 「重新配对」按钮语义；不健康行不再被 428 闪断刷掉。
4. 单测：403 首轮 reconnect、第二轮 giving up 后 → forbidden 终态；401 语义不变；428 语义不变（2026-07-22 事故回归钉）。

## 3. B —— `ENOTFOUND web.whatsapp.com`（DNS）与「connection closed」分不清

### 证据
钧 3PZ95W：`408 pending "WebSocket Error (getaddrinfo ENOTFOUND web.whatsapp.com)"` ×29 / `428 authorized` ×17 / `515` ×1。#181「扫码 4–5 分钟才上线」最像：扫码窗口内 DNS 反复 ENOTFOUND → 每次 408 进退避 → 凑够 4–5 分钟。

### 修
1. close 日志与 `postStatus` 带 `reason_class`：`dns`（ENOTFOUND/EAI_AGAIN）/ `net`（ECONNRESET/ETIMEDOUT）/ `server`（428/503）/ `forbidden`（403）/ `logged_out`（401）；`/health` 与 session-status 事件暴露最近 10 分钟各类计数。
2. 配对流程（扫码后到 authorized）单独计时：`pairing_ms`，超过 60s 在会话状态里给坐席可见提示「网络解析 WhatsApp 服务器失败 N 次，正在重试（DNS 问题，检查本机网络/代理）」——把「等 5 分钟不知道在等什么」变成能看懂的等待。
3. ENOTFOUND 的退避不要按 403/428 的曲线：DNS 失败用更短的固定间隔（3s ×10）再回退到常规曲线（DNS 抖动通常几秒就恢复）。

## 4. C —— Bad MAC（libsignal 解密对方消息失败）自愈复核

### 证据
skuio 09-05 Cursor 报告尾每份 5–6 条 `Session error:Error: Bad MAC`（`session_cipher.js:250 doDecryptWhisperMessage`，会话 `259146280653037_1.0`），跨 3 小时都在；紧跟 `WA app-state resync requested`（既有自愈已触发但似乎没修好该对端）。

### 修
1. 按 `(loginId, 对端 jid)` 计 Bad MAC 连续次数；同一对端 resync 后仍连续 ≥3 次 → 删该对端 session 文件让 libsignal 重建（Baileys 常规处置），记 WARNING 带对端 jid（打码）。
2. 计数暴露到 `/health`（`bad_mac_total` / `bad_mac_peers`），Python 侧进平台会话健康卡。
3. **不要**对全部会话做 resync（会打断在线号）。
