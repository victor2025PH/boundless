## 3. 事故与沉淀

- **`git commit -- <paths>` 会绕过 index**（21:15）：E 段 `config.example.yaml` 按 Q-14 同法手工造 index blob（HEAD CRLF 字节 + 本块 27 行）后，用 `git commit -m … -- <显式路径>` 提交——pathspec 提交**取工作树内容而非 index**，把整文件 LF 版 + 他线 3 处在途行（Q-6 `album_ai apply` / 运维降噪 `min_fail_min`·`daily_digest` / 实施95 voice `rate_per_*`）一并写进 `6654f46d`（stat 10413 行）。发现于 `git show --stat`；HEAD 仍是本线 commit 且无人在后 → `update-index --cacheinfo` 换回正确 blob + `commit --amend --no-edit` → `3a6b485f`（config 段 +27 行，CRLF，YAML 可解析，他线行未带入）。**规则**：凡 index 里有手工 blob 或 `stage_hunks` 部分 hunk，提交只用裸 `git commit`（提交 index），`git add` 显式路径 + `git diff --cached --name-only` 核对即可，**不要**给 `git commit` 传路径。已写进 TK-2 指令 §4 红线。
- `stage_hunks.py` 把本线自己上一步暂存的文件也当「他线暂存」拒绝 → 多文件一次传多个 `--file`，或对确认为本线的暂存用 `--allow-foreign-staged`。
- 「起草」不另起大脑：huoke 桥进线后直接 `maybe_auto_reply` 走既有 reply hook（System Z / 人设产线），桥只做 I/O 与闸门（D-TK-6）；评论原文是真实发言故允许起草，与 leadbus `[线索捕获]` 占位符（禁起草）区分——两条规则同源于 `leadbus_account.is_lead_capture_text`。
