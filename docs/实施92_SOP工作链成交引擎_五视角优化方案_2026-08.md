# 实施92：SOP 工作链「成交引擎」——五视角分析与优化方案（2026-08-31）

> 目标：让坐席/运营能快速完成客户「打招呼 → 建联 → 培育 → 报价 → 成交 → 复购」整条链。
> 范围：`engines/chengjie` 工作链域（workflows.html / cp-chain-exec.js / workflow_runner.py /
> workflow_starter.py / unified_inbox_workflow_routes.py / chain-funnel）。
> 结论先行：机器已造好，缺的是「客户阶段」脊柱 + 「回复即停」神经 + 一键激活总闸。

## 一、现状链路逻辑

1. **配置**：`/workflows` 建链（步骤 = template 话术提醒 / task 建任务 / tag 打标 / note 备注），
   `delay_hours` 定节奏；执行档位 `remind`（默认）或 `auto`（话术步自动拟稿投 L2 autosend，四重闸）。
2. **启动**：坐席右栏 `cp-chain-exec` 手动启动；`silence_days` 自动扫描开链（种子链全没配）；
   建目标自动挂链（`goal_auto_attach`，默认关）。
3. **推进**：`WorkflowRunner` 随 ScheduledReporter tick 推进；template 步发 `workflow_step` 事件
   → 工作台 toast + 右栏「采用并拟稿」。
4. **度量**：`chain-funnel` 出启动/完成/失败 + 72h 回复率 + 目标归因 + 推荐跟随率。

## 二、生产实况（2026-08-31 只读探针，zhiliao）

| 指标 | 值 |
|---|---|
| 种子链 | 4 条已导入、全启用、全 remind、全无自动触发 |
| 工作链执行 | **0 次（上线以来）** |
| 分流路由规则 | 0 条 |
| 同期流量（14 天） | 39 活跃会话，872 进站 + 657 出站 |

流量真实存在、功能彻底零使用——2026-08-12「零使用」复盘后两轮改进仍未解决**激活模型问题**。
另一关键事实：**客户回复不影响运行中的链**（cancel/pause 只有手动 API 调用点，入站路径零触碰）。

## 三、业界对照要点（2026）

- **信号驱动取代时间驱动**：回复/点击/意向决定推进、升级或退出；**停止规则是标配**。
- **会话式成交链**：停滞成交单自动轻推（报价后 7 天等）；**聊天→成交金额归因是黄金指标**；
  会话式跟进回复率 30–50% vs 群发 5%。
- **NBA（下一步最佳动作）UX**：有界建议卡 = 动作 + 触发原因 + 证据 + 后果 + 接受/推迟/驳回；
  上下文出现比常驻面板采纳率高 3–4 倍。
- **管道 UI**：卡片只展示「是什么/多大/什么状态信号」；活动时间线 + 持续下一步提示。

## 四、五视角问题清单

### 开发工程师
1. 纯时间驱动、零信号分支——无「客户回复→退出/暂停」，链与真实对话脱节。
2. 「成交」没有事件源：monetization 与链/漏斗互不联通，漏斗只能数回复率。
3. 安全默认叠加成「永不自转」：种子无触发 + auto_advance 关 + goal_auto_attach 关。
4. 没有统一客户阶段状态：contacts intimacy / proactive pacing / goals 模板 / 链推荐互不消费。
5. 与 proactive_topic 功能重叠且各自为政（仅 B41 单向互斥）。
6. 采纳读数进程内计数、重启清零。
7. 双入口双主题 + 分流路由混页。

### 市场经理
1. 讲不出成交故事（竞品：AI 自动跑完 greeting→close；我们：提醒坐席别忘了跟进）。
2. 没有营收归因（chat-to-revenue 是品类黄金指标）。
3. 只有 4 条通用种子链，无行业 playbook 包（KB starter pack 先例可复用）。
4. 零使用的功能锁 pro 档 = 零转化诱因，顺序反了。
5. 零执行 → 价值条永远空白 → 演示是空页。
6. proactive 战绩（35%+ 回复率）没打包进同一故事。

### 用户（坐席/运营）
1. 启动成本与收益倒挂：39 会话逐个手动挑链启动，而链只会「提醒」。
2. 提醒疲劳（草稿积压 214h 事故已证明注意力稀缺）。
3. 唤回：proactive / care / SOP 三个名词分不清、怕双发干脆不碰。
4. 缺「这个客户现在该干嘛」的答案，而不是「你配的第 3 步到点了」。
5. 采用并拟稿前看不到 AI 会写什么，信任成本高。
6. 成交没有顺手「记一笔」的入口。

### 美术设计
1. 工程表格风，没有「旅程」视觉隐喻；步骤是列表不是时间线。
2. 空态只有链环 SVG，缺讲价值的示意插画。
3. 链卡徽章堆叠无主次。
4. 右栏卡与相邻卡同质化。
5. 成交时刻零情绪设计（应庆祝 + 引导复购）。

### UI/UX 设计专家
1. 零状态设计失败（数据证明）：引导止步于「导入示例链」，aha moment 是「第一条链跑出第一个回复」。
2. 启动流摩擦：无基于会话状态的默认推荐。
3. NBA 模式缺失：actionable_note 只有动作没有 why/证据/后果。
4. 无批量挂链（筛选体系已有，差批量动作）。
5. 信息架构混乱：路由与链同页；管理在 admin、使用在工作台。
6. delay_hours 裸小时输入 vs 运营「第 N 天」心智。
7. 监控执行卡无点击直达会话。
8. wf-table 无窄屏适配。

## 五、统一方案（按优先级）

### P0 — 让链「自己跑起来、跑得对」
1. **客户回复即让路（停止规则）**：会话有 running 链时客户回复 → 自动暂停/完成，
   链级 `on_reply: pause | complete | continue`（默认 pause；唤回类语义=回复即成功 → complete）。
2. **客户阶段脊柱（journey stage）**：`new → contacted → nurturing → quoting → deal → repeat`
   规则推导 + 手动覆写 + 阶段事件；全部推荐/触发/漏斗挂此脊柱。
3. **成交事件一等公民**：标记成交（金额）+ monetize grant 联动 → 漏斗出「链→成交数/金额」。
4. **按阶段自动挂链**：trigger_conditions 增 `stage_enter`（进报价挂跟单、成交挂关怀）。
5. **「成交引擎」一键预设档**：一个开关收口整组配置（按阶段挂链+回复即停+安静时段+预算）。

### P1 — 坐席端升级为「下一步最佳动作」
6. 右栏 NBA 卡：阶段 + 触发原因/证据 + 建议动作 + 预览话术 → 采用并拟稿 + 推迟/跳过。
7. 收件箱批量挂链（筛选结果 → 批量启动，带预算确认与首步预览）。
8. 与 proactive_topic 划界合流：链步消费同一冷却/频控账本，机制上消灭双发。
9. 管理页重构：时间线编辑器（按「第 N 天」输入）、路由迁出、空态旅程示意图。

### P2 — 增长与打磨
10. 行业 playbook 包 + demo_seeder 覆盖链。
11. 阶段漏斗可视化（打招呼→成交图形漏斗 + 营收）进 boss 页/价值周报。
12. 成交高光时刻（动效 + 顺势挂复购链）。
13. 每步回复率反哺（弱步就地标黄 + 建议改写）。
14. 细节：监控卡直达会话、窄屏适配、adoption 落持久趋势、付费墙顺序调整。
