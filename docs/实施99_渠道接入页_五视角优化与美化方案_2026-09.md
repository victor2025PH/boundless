# 实施99 · 渠道接入页（抖音 / TikTok / 付款）五视角优化与美化方案

> 对象页面：`/help/onboarding/{douyin|tiktok|payment-cny}`（模板 `help_onboarding.html`，数据 `src/assistant/onboarding_guides.py`，路由 `onboarding_guide_routes.py`，含抖音接入面板 ⑪⑫ 与 TikTok 面板 ⑬）。
> 依据：DY 线 ⑨–⑬ 五个 commit 的现状 + 2026-09-08 竞品分析（respond.io / SleekFlow / Infobip / ManyChat / Sprinklr / 尘锋 / 美洽 / AI 即用 / 浏览器插件系）。
> 性质：**只给方案，不改代码**；落地时按 §4 优先级分批，每批独立可提交。

---

## 0. 现状一屏

| 维度 | 现状 | 一句话判断 |
|---|---|---|
| 壳与令牌 | 继承旧管理壳 `base.html`（`--t/--bd/--p`），而接入向导 `/workspace/setup`、渠道页、收件箱等 23 张主产品页都在 `workspace_base.html`（`--tk-*`） | **用户从工作台点进来会换一张脸**：侧栏、字号、卡片阴影、按钮圆角都不同 |
| 入口 | 产品内**零入口**：只有小智问答条目和直达 URL；`channel_setup.py`（向导卡）被实施97 线占用 | 页面做得再好，没人找得到 |
| 信息结构 | 三个 tab 并列：抖音企业版 / TikTok / 付款方式；每页＝元信息 → 导语 → 前置 → 7 步文本卡 → 规则 → 错误码表 → 链接 → 页脚 | 「付款」与两条「渠道接入」不是同类；7 步是**文档**不是**流程**，没有状态、没有「我卡在哪」 |
| 面板 | 抖音第 6 步：凭证表单 + 回调地址 + 扫码授权 + 已授权账号（令牌徽标、7 天预警）；TikTok 第 4 步：business_id + 令牌 + 注册地 + 应用凭证 + 地区能力徽标 | 功能齐，但靠 `loop.index == 6 / 4` 硬编码挂在文本步骤里，位置不是「流程终点」而是「第 6 段落」 |
| 反馈 | PRG 跳回 `?saved=1 / ?connected= / ?error=` 顶部横幅；错误直出原因码（`exchange_failed:10008`、`missing_secret`） | 成功态没有「下一步做什么」，失败态是给工程师看的 |
| 运维耦合 | 保存凭证后**必须重启**才挂 webhook 与官方 worker；TikTok 令牌手填、无刷新 | 非技术用户在这里断掉 |
| 视觉 | 无图标、无插图、无平台品牌色（抖音 `#FE2C55` / TikTok `#25F4EE+#FE2C55` 只在注册表里）；`<style>` 内硬编码 `#16a34a / #dc2626 / #d97706 / #1e8cf2`；序号圆一律品牌蓝 | 一眼看不出「这是抖音页」；语义色绕开了主题令牌 |
| 文案 | 混入内部术语（实施96、TK-1、config.local.yaml、`douyin.enabled`、client_key）；抖音页第 6 步单段 200+ 字 | 老板读不下去，运营不敢点 |
| 工程门禁 | 内联颜色棘轮 0 违规（内联 style 只有布局值）；路由基线已登记；测试 12 例 | 底子干净，可以放心重构 |

竞品对照给出的**胜负手**：一键授权（respond.io「Connect with TikTok」/ 美洽扫码授权）、前置自检与「Refresh Permissions」、第一屏声明地区与能力边界、限制清单诚实且可执行、入口经营（ref 链接 / 二维码 / 广告→私信）、AI 留资闭环、合规作为卖点。我们已有后半段（策略层、地区门控、卡片），缺的是**前半段的体验层**。

## 1. 可用方案：把「教程页」升级为「渠道接入中心」

### 1.1 目标形态（一句话）

**一张状态板 + 一条有状态的步骤流 + 一个参考区**，同一份数据同时喂页面和小智。用户打开就知道「能不能接、到哪一步、谁来做、下一步点哪」。

```
┌ 状态灯卡 ──────────────────────────────────────────────────────┐
│ ● 抖音企业版    状态：待授权（第 6 / 7 步）   预计剩余：1 天       │
│   [继续：扫码授权]  [让智聊团队代办 →]         核实日期 2026-09-08 │
└────────────────────────────────────────────────────────────────┘
┌ 步骤流（可折叠，每步带状态/责任人/耗时/动作） ─────────────────────┐
│ ✓ 1 注册开放平台并上线企业小程序      老板/技术 · 1–3 周 · 已完成   │
│ ✓ 2 能力实验室申请四项能力            技术 · 5 工作日 · 已完成      │
│ ● 3 绑定企业号并授权私信能力          老板 · 10 分钟 · 进行中 [去做] │
│ ○ 4 关闭互动经营工作台策略            运营 · 5 分钟                  │
│ ○ 5 配置 Webhook                     技术 · 5 分钟  [复制地址]      │
│ ○ 6 填凭证 + 扫码授权                 老板 · 3 分钟  ← 面板在这里    │
│ ○ 7 验收：发一条私信                  任何人 · 1 分钟 [去收件箱]     │
└────────────────────────────────────────────────────────────────┘
┌ 参考区（默认折叠）：平台规则 · 错误码 · 官方链接 · 常见问题 ─────────┘
```

### 1.2 数据与接口

1. **步骤状态模型** `onboarding_progress`（SQLite，`config_dir()/onboarding_progress.db`）：`(slug, step_id, state, source, updated_at, note)`，`state ∈ todo|doing|done|blocked`，`source ∈ auto|manual`。用户可手动勾「已完成」（审核类步骤只能手动），系统能探测到的步骤自动置状态并**覆盖**手动值。
2. **自检接口** `GET /api/onboarding/{slug}/status`（session auth）返回：
   - 抖音：`credentials_configured`、`webhook_mounted`（app 路由表里有 `douyin.webhook_path`）、`worker_registered`（`(douyin, official)` 工厂存在）、`public_https`（对外基地址是 https 且非 localhost/内网）、`accounts_authorized[]`（注册表 + `token_state` + `reauth_days_left`）、`first_inbound_seen`（收件箱有 `platform=douyin` 会话）、`workbench_conflict_recent`（最近 24h 出现 28003095）、`restart_required`（`enabled` 为真但未挂载/未注册）。
   - TikTok：`app_configured`、`webhook_mounted`、`accounts[]`（含 `tiktok_regions.capabilities`）、`first_inbound_seen`、`restart_required`。
   - 由自检推导 `current_step` 与状态灯颜色：灰（未开始）/ 蓝（进行中）/ 琥珀（等审核 / 需重启）/ 红（阻塞：地区不可用、令牌失效、工作台冲突）/ 绿（已连通并收到首条私信）。
3. **步骤数据驱动面板**：`onboarding_guides.py` 的步骤由 7 元组改为 dataclass `Step(id, title, detail, owner, eta, url, link_label, panel=None, auto_key=None)`；`panel="douyin_connect" | "tiktok_account" | "webhook_copy"`、`auto_key="credentials_configured"` 等。模板按 `step.panel` 渲染，删掉 `loop.index == 6/4`。
4. **热挂载**：保存凭证后调用 `register_douyin_routes(app, …)` / `register_douyin_official_worker(config)` 立即生效（两函数已幂等：路由表查重、工厂查重），并由 `account_orchestrator` 重新拉起账号；做不到的场景（沙盒/多进程）退回「需要重启」状态灯 + 一键跳 `restart_preflight`。
5. **错误人话表** `onboarding_errors.py`：`bad_state / missing_* / exchange_failed:<code> / denied:* / registry_failed / save_failed` → 标题 + 原因 + 下一步按钮（重试 / 去控制台 / 联系我们），中英双语；抖音 `10008`（code 无效或已用）、`10010`（redirect 不匹配）等常见换令牌错误码进表。
6. **入口经营（TikTok）**：面板生成 `https://www.tiktok.com/@<handle>?…` 的 TikTok.me 私信链接与二维码（带 `ref=` 渠道标记），webhook 里 `referral.short_link.ref` 落到会话来源，收件箱可按 ref 归因。
7. **迁壳**：页面改为 `/workspace/channels/onboarding/{slug}`，`extends "workspace_base.html"`，旧 `/help/onboarding/{slug}` 301 保留（小智条目、外部书签不失效）。入口三处：渠道页 `workspace_channels.html` 每张未接入平台卡「如何接入 →」；接入向导 `setup_wizard.html` 抖音 / TikTok 卡（实施97 收工后一张卡即可）；收件箱空态「还没有抖音会话？去接入」。
8. **付款页拆出**：`payment-cny` 不再作为渠道 tab，改为「账单与付款」独立页（或用量页 `workspace_usage.html` 的侧栏卡），保留 slug 与小智条目。

### 1.3 交付批次（与 §4 优先级对应）

| 批 | 内容 | 依赖 | 估时 |
|---|---|---|---|
| A | 迁壳 + 令牌化 + 步骤数据驱动 + 状态灯卡 + 自检接口 + 错误人话 | 无（全在本线文件） | 1.5 天 |
| B | 热挂载 + 进度落库 + 手动勾选 + 成功态「下一步」 | 无 | 1 天 |
| C | 三处入口（渠道页 / 收件箱空态先做；向导卡等实施97） | 渠道页模板归属需确认 | 0.5 天 |
| D | TikTok ref 链接 / 二维码 + 一键授权（端点核实后） | TikTok 控制台核实 | 1 天 |
| E | 文案重写（去内部术语、拆段）+ 图标/品牌色条 + 管线示意图 + 移动端 | 无 | 1 天 |
| F | 付款页拆出 + 「代办申请」CTA + 埋点 | 老板拍板代办是否作为收费项 | 0.5 天 |

## 2. 五视角问题清单

### 2.1 开发工程师

1. **双壳并存**：`base.html` 与 `workspace_base.html` 令牌不通（`--t2` vs `--tk-text-muted`），任何主题调整都要改两处；页面应归主产品壳。
2. **索引耦合**：`loop.index == 6`（抖音）/ `== 4`（TikTok）决定面板位置，改一行教程文案就可能把表单挂错步。
3. **`<style>` 硬编码语义色**：`#16a34a / #dc2626 / #d97706 / #1e8cf2` 绕开 `--tk-ok-ink / --tk-danger-ink / --tk-warn-ink / --tk-brand`，暗色下不随主题。
4. **i18n 默认值双写**：模板里 `(i18n or {}).get('obg.x', '中文默认')` 与 `onboarding_guide_ui.py` 各存一份，已出现两处措辞不一致的苗头；`data-i18n` 或统一由后端注入。
5. **对外地址信任 Host 头**：`_public_base()` 用 `X-Forwarded-Host/Host` 生成回调与 webhook 地址，反代配置不当会生成错误地址（极端情况下被 Host 注入）；应优先读配置（复用 `official_media.public_base_url`，或新增 `web_admin.public_base_url`），Host 只做回落并在页面标注「自动推断，可改」。
6. **重启才生效**：webhook 挂载与 worker 注册在启动期；`register_douyin_routes` / `register_douyin_official_worker` 本身幂等，具备热挂载条件。
7. **错误直出原因码**：`?error=exchange_failed:10008` 直接渲染。
8. **公开回调无速率限制**、`complete_oauth` 未处理同一 code 并发重放（抖音会返回 10008，可接受，但应记审计而非只 debug）。
9. **表单 CSRF 靠 Referer/Origin**：中间件判定通过，但更稳的是把 `csrf_token` cookie（`httponly=false`）注入 hidden 字段，一致于其它表单。
10. **禁用态实现**：授权按钮 `<a class="dis">` 用 `pointer-events:none`，无 `aria-disabled`、键盘仍可聚焦触发。
11. **TikTok 令牌无刷新、面板手填**：OAuth 端点未核实前是刻意的，但需要在状态灯里显示「令牌来源：手填」并提示到期风险。
12. **测试缺口**：EN 模式无中文泄漏门禁（`test_sealed_pages_en_no_cjk_leak`）尚未纳入本页；无真浏览器截图；`onboarding_guides` 7 元组无 schema 校验。

### 2.2 市场经理

1. **没有入口就没有转化**：这页是「扩渠道」的转化页（现有客户加抖音/TikTok、销售演示、潜客评估），却只能靠小智或口头发 URL。
2. **无法对外分享**：整页在登录墙后，销售不能把「抖音接入需要什么」发给潜客；需要一个**公开只读版**（无面板、无实例地址）供市场使用。
3. **缺 CTA 与服务化**：4–8 周的资质路径是阻力，「让智聊团队代办申请」（收费或含在年框）是最自然的转化钩子，页面没有。
4. **缺「为什么不用 AI 即用」**：抖音自家免费智能客服是最直接的替代，页面应有一张对比卡（多平台一颗大脑、拟人化、私域承接、跨境）。
5. **地区不可用 → 交叉销售缺位**：TikTok 在美国/欧洲不可用时，应就地推荐 WhatsApp / Instagram 官方通道与 Messaging Ads 路径（respond.io 的做法）。
6. **信任背书不显**：核实日期有了，但「走官方 OAuth、不碰账号密码、不做协议破解、数据不出实例」这几句合规承诺没有做成可见模块；竞品把合作伙伴徽章挂在接入页。
7. **内部术语泄漏**：实施96、TK-1、`config.local.yaml`、`douyin.enabled` 出现在客户可见文案里，影响专业感。
8. **付款页放错位置**：与渠道 tab 并列，既稀释渠道主题又让付款信息难被找到；人民币通道进度是营销信息，应有独立页与官网一致。
9. **无埋点**：看不到每步流失、从打开到首条私信的时长（time-to-first-message）、代办 CTA 点击。
10. **预期管理不足**：「4–8 周」只在导语；每步的耗时、谁来做、平台审核节奏应结构化展示，减少「怎么还没好」的客诉。

### 2.3 用户（中小商家老板 / 运营 / 兼职技术）

1. 打开第一眼是三段字，不知道**能不能接、要多久、要花多少钱、需要谁**。
2. 术语墙：client_key、Webhook、HTTPS 域名、open_id、im.message_card——运营不敢点，老板不想读。
3. 7 步没有进度，关掉再打开不知道做到哪；审核等 5 个工作日后没人提醒。
4. 「公网 HTTPS 域名」对非技术用户是死路，页面没有说「云实例用户已有域名，自动填好」或「找我们代配」。
5. 保存凭证后要求「重启智聊」——用户不知道怎么重启、也不该知道。
6. 授权成功后横幅只说「已登记」，没有「现在去抖音发一条『你好』试试」的下一步。
7. 错误提示像日志（`exchange_failed:10008`），不知道该干什么。
8. 密钥在哪里找没有截图/示意；「授权回调域」在控制台哪个菜单没有指路。
9. 我的号能不能用？（企业号 / 员工号 / 个人号）缺一个 20 秒自测。
10. TikTok「注册地」是什么、在哪看（App → 设置与隐私 → 账号 → 账号信息）没有说明；填错就误判。
11. 多人协作没有分工提示（老板扫码、技术配 webhook、运营关工作台）。
12. 手机上打开：三列表单挤、长地址溢出、tab 折行。

### 2.4 美术设计

1. **无识别度**：页面与任何一张后台页长得一样，没有抖音红、TikTok 青/红的存在感，也没有图标。
2. **序号圆一律品牌蓝**，7 个同色圆点没有节奏，无法传达「完成 / 进行 / 未开始 / 阻塞」。
3. **层级扁平**：导语卡、步骤卡、面板、规则列表用同一套 14px 圆角卡，缺一个视觉锚（hero / 状态灯）。
4. **表单气质生硬**：三列等宽输入框 + 圆角 99px 按钮，与工作台 8px 圆角、38px 高的表单语言不一致。
5. **徽标系统杂**：pill 用了四种边框色，缺统一的底色+墨色配对（`--tk-ok-ink` + 12% 底）。
6. **复制块**没有 monospace 字体层级，长 URL 省略后看不出结尾差异（`/webhook/douyin` vs `/webhook/douyin/oauth/callback`）。
7. **错误码表**是纯边框表格，窄屏挤成一列；代码列没有等宽字体强调。
8. **空态/成功态无图**：授权成功、账号列表为空都只有一行字。
9. **暗色主题**下 `color-mix` 透明底 + 硬编码墨色的 pill 对比不足（琥珀 `#d97706` 在 `#17181d` 上约 4.3:1，正文级不达 4.5）。
10. **动效缺席**：状态变化、折叠展开无过渡；复制成功只把按钮文字换成 ✓。

### 2.5 UI/UX 设计专家

1. **心智模型错位**：用户来「完成接入」，页面给的是「阅读手册」。应是**有状态的向导**（wizard with persistence），手册退为参考区。
2. **信息架构**：付款与渠道并列；参考区（规则/错误码/链接）默认全展开，把操作区推到第二屏之后。
3. **渐进披露不足**：每步正文全量展示，200 字段落；应标题 + 一行摘要 + 展开。
4. **表单 UX**：密钥字段用占位符显示脱敏值，用户会误以为已填；「留空＝保留」规则没有可见说明；缺内联校验（client_key 以 `aw` 开头等），错误只能提交后跳回顶部横幅。
5. **主次动作不清**：「保存凭证」（次）与「扫码授权」（主）视觉权重一样；禁用原因不可见（悬停应说「先填 client_secret」）。
6. **状态反馈**：PRG 横幅刷新后仍显示；成功态没有引导下一步；「需重启」是文字不是状态。
7. **可达性**：`.dis` 无 `aria-disabled`；复制按钮无 `aria-live` 反馈；tab 是链接而非 `role="tablist"`；`--t3` 在暗色上的 muted 文本对比需复核；表格无 `<caption>`/`scope`。
8. **i18n**：EN 模式下 `client_key / business_id` 等 label 保留英文合理，但中文页里也全是英文技术 label，应加中文说明副标（「应用 Key（client_key）」）。
9. **移动端**：三列 grid 只在 640px 以下折为单列，768–1024 区间挤；tab 折行。
10. **多入口一致性**：从收件箱/渠道页/小智进来时应保留返回路径（`← 返回渠道页`），现在只有壳侧栏。
11. **复制交互**：应同时提供「复制」与「在新窗口打开控制台对应页」的组合，减少来回切换。
12. **确认与撤销**：更换 client_key 会让已授权账号失效（open_id 绑的是旧应用）——需要确认弹层并说明后果，现在直接覆盖。

## 3. 美化方案（落到具体改法）

以下全部以 `workspace_base.html` 的 `--tk-*` 令牌为准，日/夜自动适配；不新增图片资源，图标用现有 `platform_icons.js` + 内联 SVG。

### 3.1 版式与栅格
- 容器 `max-width: 920px; padding: 18px; margin: 0 auto`（与 `setup_wizard.html` 一致）；两栏在 ≥1100px：左 620 主流程，右 280 参考区（sticky）；<1100px 单栏，参考区折叠到底部。
- 顶部返回链：`← 返回渠道页`，12px `--tk-brand`（复用 `.db-back`）。
- 页头：h2 19px/700 `--tk-text`；副标 13px `--tk-text-muted`，一句话说清「能接 / 多久 / 谁做」。

### 3.2 平台识别（不大面积用平台色）
- Tab 改为 `role="tablist"` 的 segmented control：高 34px，圆角 `--tk-radius`（10px），选中项底 `--tk-surface`、边 `--tk-border`、阴影 `--tk-shadow`；每个 tab 左侧 16px 平台图标（抖音音符红 `#FE2C55`、TikTok 黑底青红双影小标），图标取自 `platform_icons.js`，颜色来自 `platform_registry.json`（同源，不再手写）。
- 状态灯卡左缘 4px 色条：抖音 `#FE2C55`、TikTok `#25F4EE`；其余全部中性。付款页无色条。

### 3.3 状态灯卡（hero）
- 复用 `golive_checklist.html` 的 `.gl-light` 语言：54px 圆点 + 标题 + 摘要 + 右侧「x / 7 已完成」。圆点色：`--tk-text-muted`（未开始）/ `--tk-brand`（进行中）/ `--tk-amber`（等审核或需重启）/ `--tk-danger`（阻塞）/ `--tk-emerald`（已连通）。
- 下方进度条 8px，`--tk-surface-2` 底、`--tk-grad` 填充（这是页面唯一使用渐变的地方）。
- 主动作按钮 38px 高、8px 圆角、`--tk-brand` 实心白字（`.sw-btn.primary` 同款）；次动作 ghost（`--tk-surface-2` 底、`--tk-text`）。
- 右上角小字：`核实日期 2026-09-08 · 预计 4–8 周`，11px `--tk-text-muted`，`font-variant-numeric: tabular-nums`。

### 3.4 步骤卡
- 每步一张 `--tk-surface` 卡，边 `--tk-border`，圆角 `--tk-radius-lg`（14px），内距 14px 18px，间距 10px；进行中的一步加 `outline: 2px solid var(--tk-brand); outline-offset: 2px`（复用 `.sw-hl`）。
- 左侧 28px 状态圆替代纯序号：未开始＝`--tk-surface-2` 底 + 序号 `--tk-text-muted`；进行中＝`--tk-brand` 实心白字序号；完成＝`--tk-emerald` 实心 ✓；阻塞＝`--tk-danger` 实心 !；等审核＝`--tk-amber` 实心 ⏳。
- 标题 15px/700；元信息 chip 行 11px（`谁做 · 耗时 · 状态`），chip 高 20px、`--tk-surface-2` 底、`--tk-text-muted` 字。
- 正文 13px / 行高 1.65 `--tk-text-muted`，默认 2 行 `-webkit-line-clamp`，「展开」链接 12px `--tk-brand`；进行中步骤默认展开。
- 右侧动作：`[去做 ↗]`（外链，`.gl-act` 样式）或 `[已完成]` 勾选（手动步骤）；自动探测到的步骤勾选禁用并标「自动检测」。
- 展开/收起 160ms `ease`；状态圆颜色变化 200ms。

### 3.5 面板（抖音第 6 步 / TikTok 第 4 步）
- 表单改单列 + 双列自适应：`grid-template-columns: repeat(auto-fit, minmax(260px, 1fr))`；label 13px/600 `--tk-text` 在上，中文名 + 括号英文键（「应用 Key（client_key）」）；hint 11px 在下；输入 38px 高、8px 圆角、focus 环 `--tk-ring`（`.sw-field` 同款）。
- 密钥字段：已配置时**不用占位符**，改为只读态「已配置 ••••1234 [更换]」，点更换才出现输入框；「留空保留」文案随之消失。
- 主次动作：「用企业号抖音扫码授权」是主按钮（`--tk-brand` 实心、左侧抖音图标）；「保存凭证」次按钮；禁用用 `aria-disabled="true"` + 50% 不透明 + `title="先填写 client_secret"`。
- 复制块：`--tk-surface-2` 底、1px `--tk-border`、8px 圆角、12.5px monospace（`Consolas, JetBrains Mono`）、左侧 14px 链接图标、右侧内联「复制」按钮；长 URL 用 `direction: rtl; text-align: left` 省略头部保留尾部（回调地址与 webhook 地址一眼可辨）。
- 复制成功：按钮变 ✓ 1.2s 并触发工作台统一 toast（`aria-live="polite"`）。
- 已授权账号列表：行高 44px，头像位用平台图标 28px，账号 monospace，右侧 pill。

### 3.6 徽标（pill）系统
- 统一 22px 高、11px/700、圆角 99px、左右 8px；配色只用三对：`ok`（`--tk-ok-ink` 字 + `rgba(16,185,129,.14)` 底，与 `.b-ready` 同）、`warn`（`--tk-warn-ink` + `rgba(245,158,11,.16)`）、`danger`（`--tk-danger-ink` + `rgba(225,29,72,.12)`）；中性 pill 用 `--tk-surface-2` 底 + `--tk-text-muted`。
- 暗色对比：三对墨色在 `--tk-surface` 暗值上均 ≥ 4.5:1（`#34d399 / #fbbf24 / #fb7185` 系）；不再使用 `#d97706` 一类亮底墨色。

### 3.7 参考区（规则 / 错误码 / 链接）
- 右栏三张折叠卡（`<details>`），默认只展开「平台规则」；标题 13px/700 + 计数 chip（「6 条」）。
- 错误码改「卡片列表」：每条＝code（monospace pill）+ 含义（13px）+ 处置（12px muted）；≥768px 用两列 grid。
- 官方链接：图标 + 名称 + 外链箭头，`rel="noopener noreferrer"` 保留。

### 3.8 空态 / 成功态
- 未配置：面板顶部一条「三步走」小示意（填凭证 → 扫码 → 发一条私信），用三个 24px 圆 + 连线的纯 CSS 管线图，无图片。
- 授权成功：状态灯变绿 + 卡内出现「现在去抖音发一条『你好』，30 秒内应出现在收件箱 [打开收件箱]」；首条私信到达后自动打勾第 7 步。
- 地区不可用（TikTok）：红灯 + 「这个账号注册地不支持私信 API」+ 三个替代卡（Messaging Ads / 店铺客服 / WhatsApp 官方通道）。

### 3.9 文案规范
- 客户可见文本**禁止**出现：实施编号、指令编号、配置键名（`douyin.enabled`）、文件名（`config.local.yaml`）、内部模块名；技术键只以「中文名（英文键）」形式出现在 label。
- 每步正文 ≤ 60 字摘要 + 展开细节；细节用有序小步（「① 打开控制台 ② … ③ …」），每小步一行。
- 数字统一半角、单位前空格（「5 个工作日」「≤ 1000 字」）。

### 3.10 移动端
- <768px：tab 横向滚动不折行；状态灯卡竖排；表单单列；复制块换行显示全地址（不省略）+ 独立复制按钮；参考区折叠到底部。
