## 2. 每单怎么核（通用五步）

1. `git log --oneline --all --grep "#<N>"`（含带圈数字形态 `#<N>②` 用 `--grep "#<N>"` 即可命中）→ 列出全部相关 commit。
2. 每个 commit `git show --stat <hash>` 看改了哪些文件；**核这些改动仍在 HEAD**（`git log -1 --format=%h -- <文件>` + rg 关键函数名/常量名）。
3. 版本归属：`rg "<hash前7位>|#<N>" docs/发版对账_v1.0.6*.md docs/发版对账_v1.0.7*.md engines/chengjie/desktop/CHANGELOG* website/**/changelog*`（rg 找 changelog 真实路径），定「进了哪个版本号」。
4. 台账时间线：`bug_events` 里该单的 verify_no / 按钮回调时刻 + 原话（body 里 `[验证未过 …]` / `[按钮验证 …]` 行）；对照当时用户机版本（`docs/报障对账_钧_花无缺_2026090*.md` 或 body 里「版本: 1.0xx」行；1.0.62 发于 08-30 早、1.0.63 08-30 晚、1.0.64 08-31）。
5. 写结论四选一：**A 修复有效，反馈发生在修复入包前**（回访即可）/ **B 反馈是误归属**（回访说明 + 指向真单）/ **C 修复有效但需用户操作**（回访必须带步骤）/ **D 修复失效或残缺**（转修复，写清缺哪层）。
