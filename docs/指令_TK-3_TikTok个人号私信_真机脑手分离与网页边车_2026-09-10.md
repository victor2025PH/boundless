# 指令 TK-3：TikTok 个人号私信——① huoke 真机脑手分离（能收能发）· ② 网页托管边车（先只读辅助、后人工可发）

> 拍板：2026-09-10 21:43 老板「做 1 和 2」；21:53 确认两个假设：**智聊只接管对方开口之后的对话**（主动首触归 huoke 智拓）；**客户账号全球分布，真机为主路、边车为无手机客户兜底**。官方 Business Messaging（③）保持 TK-1 现状等权限，不在本条内。
> 事实：TikTok **没有任何官方接口给个人号收发私信**（Business Messaging API 文档：Personal accounts are not eligible）。两条路都是**非官方** → 准入区 + `notice_unofficial`（同 Zalo / IG 个人号口径），任何对客文案不得写「官方」。

> 与 TK-2 的关系：TK-2 A 段（网页边车）**并入本条 ②**；TK-2 保留评论回复 API / Ads 归因 / Shop 连接器 / 溢出。本次 TK-1 E 段的评论桥保留，同一模块加 `dm` 通道。

## 0. 架构

```
TikTok 个人号（platform=tiktok，会话键统一 tiktok:user:<username>）
 ├─ ① 真机 mode=personal_rpa（编排器不接管）
 │     进线  huoke check_inbox --reply_engine=chengjie--> POST /api/tiktok/huoke/dm（桥记关系态 → emit → 起草）
 │     出站  坐席/自动链 → send_via_adapters 回落桥适配器 → 回传队列 → huoke 认领 → tiktok_send_dm → 回执 → 镜像 sent/failed
 └─ ② 网页边车 mode=web（编排器接管，同 IG/Zalo 个人号）
       阶段 1 assistOnly：读 DOM → ingest → 起草 → 坐席一键粘贴
       阶段 2 人工可发（72h 自有账号去风险验证后）；永不自动发
```

## 1. 决策

| 编号 | 决策 | 默认 |
|---|---|---|
| D-P1 | 合规分层 | 两路皆非官方：准入区 + `notice_unofficial`；`platform_registry` 官方私信 `implemented=False` 不变 |
| D-P2 | 脑手分离 | huoke `reply_engine: local \| chengjie`，默认 `local` 零 diff；`chengjie` 时不跑 `ChatBrain`、不查协调器 CRM、不本地回复；`auto_reply=True` 与之互斥 |
| D-P3 | 消息请求规则 | 非互关且对方从未回复 → 智聊一条都不发（首触归 huoke）；对方回过 → 正常；对方 72h 未回 → 自动链停、人工可再发 1 条 |
| D-P4 | 节奏 | 每号日上限（新号 10–20 起）、随机间隔、`work_hours_gate` 夜间静默、按**账号时区**切日；huoke 侧限速与 chengjie 闸门双保险 |
| D-P5 | 自动化档位 | 个人号会话默认 L3 必审；边车永不自动发 |
| D-P6 | 边车两阶段 | 阶段 1 assistOnly；阶段 2 人工可发需 72h 去风险验证 |
| D-P7 | 策略键 | `channel_policy` 追加 `tiktok:personal_rpa` / `tiktok:web` mode 键（无 48h 窗、无配额、首条禁链、≤1000 字）；平台级 `tiktok` 留给官方 |
