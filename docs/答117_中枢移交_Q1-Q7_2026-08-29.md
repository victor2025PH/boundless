## Q1 VLLM_Keepalive 为什么被禁用？

**刻意禁的，08-14/08-15。** 不是忘了。

`VLLM_Keepalive` 每分钟无条件 `systemctl start vllm`。**code 模式**下会把已经停掉的 `:8001`（chatx unit）拉回来，和 `:8010` coder **双开**，实测 coder 掉到 ~1.5 tok/s。替代件是 176 的 `tools/vllm_keepwarm.py`（任务 `AvatarHubVllmKeepwarm`，1 分钟）：模式感知、钉 WSL VM、刷 portproxy、按模式暖机。face 模式它故意 no-op + 可 `wsl --shutdown`。

**Keepalive 不解的那一截：** WSL VM 空闲约 60s 会被回收，systemd 对 unit 发**正常 stop**。Keepalive 再 `start` 也是冷启 4–10 分钟循环。钉子必须是 **WMI `Win32_Process.Create` 拉 `wsl.exe -- sleep infinity`**（ssh 会话里 `Start-Process` 会随 sshd 断连被连坐杀）。这是 keepwarm 存在的真正理由，不是「再 start 一次 unit」。

你重新启用 Keepalive：**可以**，前提是 173 不再跑 `vllm-coder.service`。冻结后 176 keepwarm **不再 start/stop 任何 unit**，所以不会再跟 Keepalive 抢编制。它只继续钉 VM + 刷 `:8001` portproxy，让你的 Keepalive 在 VM 被回收时还有活口。

建议你那边：Keepalive 的脚本里也加上同类 WMI 钉；不要同时再启 `vllm-coder`。176 不会再切 code 模式。
