## 二、交付物（P0 + P0.5，本批全绿落地）

### 因素注册表（防再散的机制核心）

- `src/inbox/autoreply_factors.py`：九因素注册表（chat / vision / asr / voice_out /
  short_msg / translate / budget / quota / session），纯函数、输入全注入、零 IO。
  判定复用各域**权威单点**：standby_mode（发送链）、media_capability（识图/转写
  就绪）、peer_bot_guard.budget_flags（额度语义）、delivery_block.seat_banner
  （近窗拦截）——绝不另算第二套语义。
- **防再散门禁**：`DOMAIN_FACTOR` 必须覆盖 `delivery_block._KNOWN_DOMAINS` 全部
  拦截域（`tests/test_autoreply_factors.py`）。以后新增拦截域，门禁先红，逼着
  同步接进总控台。
- `GET /api/reply-settings/health`（只读）：路由层取数注入（额度台账 to_thread /
  quota_probe 60s 缓存 / 会话健康表 / 拦截快照），任一数据源缺席按保守判定降级，
  绝不 500。`summary.verdict`＝full / degraded / attn / paused 四档总裁决。

### 总控卡（/reply-settings「🤖 AI 接管」卡内，不建新页面）

- 并行线同日上午已交付三档主控（全自动/拟稿人审/关闭，POST /api/companion/standby
  捆绑写）；本批在其下新增「**会影响全自动的因素**」清单：色点+人话一句后果+右侧
  一个动作按钮。全绿时显示正向空态「✓ 全部就绪」。
- **修复动作零新增写端点**，全部复用既有写入口：
  识图/转写 → `POST /api/companion/media-capabilities/preset`（understand_all，
  供给先于开关）；短消息 → 本页白名单 `POST /api/reply-settings`；翻译 →
  `POST /api/setup/features/toggle`；额度 → 锚点滚到守卫卡（豁免仍走收件箱同一
  relief 端点）；算力/掉线 → 深链 /membership、渠道页。
- **「全自动」一键捆绑**：选全自动后前端顺手补齐 识图/转写（bad 才补）+ 短消息
  门槛归零（warn 才写），toast 汇报「已顺手补齐：…」。发送链归 standby 单写入口、
  理解链归媒体预设单写入口——捆绑在客户端编排，不造服务端复合写端点。
  翻译**刻意不自动开**（增强项非阻断项，留给清单黄灯显式决定）。
- 工作台拦截红条加「修复设置 →」深链（仅 master/operator 角色渲染——坐席点
