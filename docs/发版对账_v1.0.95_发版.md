# 发版对账 v1.0.95（2026-09-21）

一句话：**把「智聊 无法关闭」弹窗的第三个、也是最后一个出处剪掉**——随包 messenger-web 里一份用不上的 Playwright headless shell，其中一条路径装到 `%LocalAppData%` 下长达 264 字符，超过 Windows `MAX_PATH`（260），安装器既删不掉也覆盖不了。本版打包时剪掉这棵树、加路径长度门禁，并给 oldrm 补一趟 `\\?\` 扩展路径删除，让从 1.0.93 / 1.0.94 升上来的机器这一跳也不弹。

---

## 1. 1.0.94 之后为什么还弹（第三个出处）

1.0.94 的 C11 工作了：本机 `%TEMP%\chatx_install_reap.log` 显示旧版 9426 个文件被新安装包清掉、卸载入口已删、「模板将跳过 uninstallOldVersion」。但 oldrm 结束时留了 **1 个** 残留，且标注 `left free`（没有任何进程占用）：

```
...\resources\services\messenger-web\node_modules\playwright-core\.local-browsers\chromium_headless_shell-1228\chrome-headless-shell-win64\resources\accessibility\reading_mode_gdocs_helper_manifest.json
```

完整路径 264 字符，整棵安装树只有它一个超长。NSIS 不带长路径清单，`Delete` / `CopyFiles` 遇到它一律失败。随后 `extractAppPackage.nsh` 把 7z 解到临时目录再 `CopyFiles` 覆盖进 `$INSTDIR`，这一个文件覆盖失败 → 整次 `CopyFiles` 报错 → 静默重试 5 次 → `MessageBox appCannotBeClosed`。这就是它出现在「正在安装智聊组件」进度条中间、而不是一开始就弹的原因。

三轮弹窗的区分方法（进度条位置）：

| 版本 | 出处 | 位置 |
|---|---|---|
| 1.0.92 → 1.0.93 修 | `_CHECK_APP_RUNNING` 6.3 秒关不掉 | 进度条前 |
| 1.0.93 → 1.0.94 修 | 旧卸载器 `UninstallLoop` 原子改名回滚 | 进度条一开始 |
| 1.0.94 → **1.0.95 修** | `extractAppPackage` `CopyFiles` 撞 264 字符路径 | 进度条中段「正在安装智聊组件」 |

## 2. 为什么之前 excludes 排不掉

`messenger-web/node_modules/playwright-core/.local-browsers` 在源码树里是一个 **junction**，指向共享的 Playwright 浏览器缓存；electron-builder 的 `files` 排除规则作用在解析前的路径上，对 junction 内部条目不生效。`after-pack.js` 本来就有一步把 junction/symlink 物化为包内真实目录，C12 就在物化之后剪：

- 剪 `chromium_headless_shell-*`（messenger-web 不用 headless shell，`server.js` 的 Playwright 回退 channel 显式写死为 `"chromium"`，不再让 Playwright 自己挑）；
- 剪 `ffmpeg-*`（Playwright 录屏用，产品不用）；
- 保留完整 `chromium-*`（网页版消息平台登录依赖它，用户登录态不受影响）；
- 新增路径长度门禁：包内任一相对路径 + 最长安装前缀预算超限即打包失败（`package-layout.test.js` 锁住 glob 与预算）。

## 3. oldrm 长路径补删（`installer.nsh`）

`cxSweepLongPaths $INSTDIR`：在 `Delete`/`RMDir /r` 常规清扫之后，调 PowerShell 用 .NET `[IO.File]::Delete('\\?\' + path)` / `[IO.Directory]::Delete('\\?\' + path, $true)` 把常规清扫删不掉的长路径条目补删，日志一行 `[oldrm] longpath pass under <INSTDIR>: ... removed=N failed=M`。

- 随 1.0.95 包发出的版本对树里剩余条目全量尝试，所以 `failed=` 会把被锁文件的祖先链也算进去（冒烟里 `failed=10` = 被锁文件 + 9 层祖先目录，全部是预期残留）；
- 合回主线的后续提交 `687f0151`（本对账所在分支 `3c4129cc`）改成只处理 `FullName.Length -gt 259` 的条目、再顺手收掉腾空的祖先目录，日志变为 `long=/removed=/failed=`，`failed` 只计真长路径失败。**该提交不在 1.0.95 包里**，下一版随包生效。

## 6. 沉淀

1. **同一句弹窗至少有三个出处，看进度条位置分辨。** 前两轮的修复都有效，只是没修到第三处。
2. **`left free` 的残留就是线索。** 没被占用却删不掉，只剩权限或路径长度两种可能；量一下长度比猜杀软快。
3. **排除规则对 junction 内部不生效**，要在物化之后剪，并用测试锁住 glob。
4. **探针里的 Windows 路径别放进 PowerShell 字符串拼接的转义歧义处**：`'...\resources\accessibility'` 在某些写入链路里会被当 `\r` `\a`。种植失败要看成探针 bug，而不是让 PASS 依赖它「碰巧」跑过。
