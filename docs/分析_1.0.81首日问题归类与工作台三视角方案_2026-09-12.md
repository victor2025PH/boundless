## 三、聊天工作台——三视角

### 3.1 开发工程师视角（问题 → 出在哪里）

1. **`unified_inbox.html` 是 2.8 万行单体**（模板 + 内联 JS + CSS），跨线协作靠 `xl- / ay- / aif- / ad- / rk-` 前缀和 `stage_hunks` 切 hunk；一次 checkout 的 CRLF/LF 漂移就让三条线互踩（R79 §5、Q-15 / Q-17 落点表都点名）。任何 UI 修复的门禁是 `test_workspace_template_js_syntax` 这类文本正则（`test_no_dynamic_dot_access_concat` 对 `'inbox.adult.cat_'+x` 字符串键误报），没有组件级测试。
2. **自动出站有两条链**：`autosend_worker`（过 `autosend_policy` + 人工优先闸 + 节奏）和 Q-15 软回应的「人工通过链」（`_inbox_deliver_cb`，刻意绕闸）。绕闸的理由是「不受 Q-3 闸拦」，代价就是 A′ 事故。**所有自动出站必须走同一个门**。
3. **守卫是纯文本函数**：`adult_grader.grade(text)` / `risk_grader.grade(text, direction)` / `keyword_risk_hits(text)` 都不带 `conversation` 上下文（群 / 私聊、档位、语言、发送方是否同事）。加一个 `GuardContext{is_group, mode, lang, sender_kind}` 参数就能把 R1 一次收掉。
4. **画像与记忆两条抽取链**在 1.0.82 后门禁不一致：`profile_fill` 有 `slot_validate + anchor + lang_mismatch`，`episodic` 没有；目标引擎的「AI 问 → 客户答」回填走另一条路（Y39D8U「AI work」）。三处应共用一个 `FactGate`。
5. **状态不可见的根源是没有「会话状态机」**：让位 / 风险保持 / 需人工 / 作息外 / AI 未生成 / 边车失败 是六个各自的 KV 或标签，前端六个 chip 各画各的；`reply_diagnosis` 是事后诊断不是实时状态。需要一个 `conv_state` 视图（服务端聚合，一个端点，一个 chip 条）。
6. **语言决策三套**：`resolve_outbound_lang`（出站翻译，六级 + `decided_by`）、起草 `reply_lang`（Y82GWM 的 `lang=zh` 来源不明）、TTS 语种（`xlate=ja` 再判克隆能力）。应在起草前算一次 `conv_lang_plan{reply_lang, xlate_target, tts_lang, decided_by}` 落日志，三处只读它。
7. **翻译弹层**（`7c4aae3b` 后）用 portal + 裁切盒计算 + ResizeObserver 维持几何——复杂度已超过一个弹层该有的；深色主题对比度靠零散内联色（`inline_color_ratchet` 门禁长期红 3 项）。
8. **边车契约缺类型**：Messenger 边车只认文本 / 图片消息，reaction / 来电 / e2ee 状态都不在事件表里；发送失败把 Puppeteer 异常原文吞成 500。
9. **回归债**：干净树 102 条红（HEAD 依赖别线未提交文件），`gate_sweep` 18 红中 14 项 >48h 旧债——门禁红成常态，新红没人看得见。

### 3.2 市场经理视角（承诺 vs 客户体验）

1. **核心卖点「全自动陪聊」两天里被自己的机制掐停三次**（成人误触 / 让位丢稿 / 边车连败），客户端表现全是「已读不回」——这是留存杠杆最重的一项，比任何新功能都值钱。
2. **人设是产品的「品牌」**：AI 否认客户给的名字、克隆声换成微软男声还标着人设名、粤语人设说书面语、说「没这个功能」——每一件都在客户面前把「一个真实的人」拆成「一个客服机器人」。人设一致性（名字 / 声音 / 语言 / 记忆）应作为一条对外承诺来验收，不是四条 bug。
3. **报障群事故是最贵的一条**：软回应发进了客户（内测方）的群——如果这是客户的客户群，就是公关事故。对外必须能说出「群聊永不自动发言」这句话，并有门禁背书。
4. **单一版本 + 拦截可见 + 风控分级可配 是这周真正可宣传的三件事**，但入口散、文案死链、需重启才生效，演示时会翻车。发版说明已按「讲用法」写，产品页 / 帮助中心要同步一版「我为什么没回：五种原因与去哪看」。
5. **多语言是海外销售的门面**：粤语缺席、日韩语音无克隆、中文草稿发给英语客户——目标市场（港 / 日 / 东南亚）每一个都踩到。建议以「语言能力矩阵」作为对外文档与内部门禁的同一份表。
6. **内测反馈质量极高（用户自己写量化脚本、逐条给修法）**，但报告工具两次上传失败、对照单噪音多，值守回执文案模板化——给这位用户一个「已确认 / 排期 / 已发」三态看板比群消息更省双方时间。

### 3.3 用户（坐席 / 运营）视角

1. **「绿灯到底会不会发？」**——一个会话同时可能处于 全自动 + 让位 + 风险保持 + 作息外，用户只看到档位徽标。要的是一句话状态：「AI 会在 23 秒后接回」「AI 不发：需人工（要钱）· 点我知道了恢复」「AI 不发：边车离线，正在重连」。
2. **「为什么没回」要在会话里立刻看到**，不是去回复设置翻台账，也不是去 backend.log。今日拦截卡是运营视角，会话头才是坐席视角。
3. **一处设置一处生效**：发送语言、成人政策、见面政策、风控级别，用户不想记住哪个在人设页哪个在回复设置；更不想点一个链接发现是死链。
4. **失败要说人话**：「发送失败」→「Messenger 网页输入框丢失，已自动重试 4 次，下次 40 秒后；你可以手机发」。
5. **画像只显示能追溯的事实**：每条 AI 推断旁边要有「依据：客户原话『…』」，点确认必须有反应；宁可空着不要错。
6. **深色主题不是二等公民**：下拉、弹层、译文都要看得见；字体不能因为翻译变大。
7. **语音**：选人设声之前就要知道它会说哪些语言；不支持就别让我发出去一个陌生人的声音。
8. **升级后告诉我要不要重启**，以及重启后哪些东西变了。
