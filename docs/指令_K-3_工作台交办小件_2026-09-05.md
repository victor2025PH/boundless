## 5. B —— 草稿旁记忆 chips + 「来源原话 → 定位到那条消息」（#183 #177，J-10 交 J-4）

- 契约（照 `发版对账_v1.0.74_J10.md`「交 J-4」，不要改接口）：`GET /api/episodic-memory/used?conversation_id=<platform:acct:chat>&limit=1` → `{ok, count, batches:[{batch_id, ts, chain, inbound_msg_id, conversation_id, items:[{id, content, source: user_stated|ai_inferred, tier, review_reason, impact: high|normal, source_quote, source_ts, status, recall_count, …} | {id, deleted:true}]}]}`。`count==0` 不渲染。动作：`POST /api/episodic-memory/{id}/ignore`（不再使用，软删）/ `POST {id}/confirm` / `POST /api/episodic-memory/resolve-conflict {keep_id}`。
- 渲染位置：草稿卡底部、发送按钮上方一行 chips「本轮用了 N 条记忆 ▾」；展开每条 `content`，`impact=high` 红点、`source=ai_inferred` 琥珀点、`review_reason` 非空加小标「需要你看」；每条右侧「不再使用」（调 ignore 后该 chip 消失）。取数时机 = 草稿生成完成回调后；取 `batches[0]`，`inbound_msg_id` 与草稿所回复的入站 id 对账（不一致不渲染，避免串轮）。
- 「来源原话 → 定位」：chip 展开项里 `source_quote` 可点 → 在会话流里按 `source_ts` ±60s 窗口内找文本包含 `source_quote` 前 20 字的入站气泡，滚动 + 高亮 2s（rg `scrollIntoView|_jumpTo|locateMsg|highlightMsg` 找现成函数复用）；没加载到就 toast「这条原话在更早的历史里」（不做历史回拉）。
- i18n 键进 `inbox_workspace.py`（`inbox.mem.used_n` / `inbox.mem.ignore` / `inbox.mem.need_review` / `inbox.mem.locate_miss` …）；样式进 `unified-inbox.css`（沿用 `--green/--amber` 变量）。

- 自证：AI 记忆页 → 客户档案抽屉「最近被用」分区同一接口。
- 测：模板三门禁 + `test_template_window_t_keys_resolve.py`；新 `tests/test_memory_chips_template.py` 静态钉（函数挂 window、i18n 键存在、接口路径字面）。
- commit：`feat(chengjie/ui): #183 #177 草稿旁「本轮用了 N 条记忆」chips + 不再使用 + 来源原话定位（J-10 交办）`
