# 实施54：回怼战线贯彻——三视角分析与优化方案（2026-08-22）

## 0. 事故还原（为什么老板觉得「骂人功能没触发」）

2026-08-22 03:44-03:48，老板用测试号（tg 5433982810）对 Katie 账号（8244899900，
本会话绑定人设 lin_xiaoyu 林小雨，temper=feisty）连发 4 条辱骂语音。日志证明
**检测与注入层 4/4 全部正常工作**（每轮 `[temper] 被骂回应注入 level=feisty`），
第 1 轮也真骂回去了（「你才傻逼呢！…脑子进水了吧你」）。但第 2-4 轮输出越来越软：

三个真实断点（都在指令注入**之后**）：

| # | 断点 | 机制 |
|---|------|------|
| A | LLM 生成端自行降级 | feisty 指令说「谁先怂谁输、别主动找台阶」，但指令对第 1 轮和第 4 轮说的是**同一段话**；模型顺着自己上一条「我睡觉去了」的历史惯性继续收场，脏字许可（「可以带脏字」）被当成可选项放弃 |
| B | 情感引擎拆台 | `emotional_context` 词典把「呀」记 playful(0.3)、骂词（傻逼/操你妈）**根本不在词典**→「来呀你给我对骂呀你个傻逼玩意儿」被判 `playful valence=0.97`，同一个 prompt 里一边说「对方在骂你」一边说「对方心情极好在玩闹」，模型选了后者 |
| C | 语音把火气念没了 | TTS 情绪词表（`voice_emotion.EMOTIONS`）**没有 angry 档**——2026-07 设计时钉的「AI 对用户发火不是本产品语气」，早于 temper 功能（08-12）上线；骂回去的文本被人设默认基调渲染成 `情绪happy`，开心语调骂人=瞬间穿帮 |

## 1. 三视角分析

### 1.1 开发工程师视角

- **分层归因**：检测层（词表+粘性窗）经三轮实测扩表已经很硬，本次 4/4 命中零漏网
  ——问题不在检测，别再往词表使劲。断点全在「注入之后」的三个消费面：LLM 生成、
  情感上下文、语音渲染。三者各自独立演进从没对齐过「骂战态」这个概念。
- **根子是「骂战态」没有单一事实源**：temper 判定发生在 skill_manager 一个 try 块里，
  判完只留下一段 prompt 文本；情感引擎（更早跑）不知道、语音链（更晚跑）也不知道。
  修法不是三处各自再判一遍（词表打地鼠×3），而是 temper 命中时**登记一次骂战态**，
  其余消费面读同一份登记。
- **指令静态 vs 对抗动态**：streak 1→4 注入同一段话，模型对重复指令的服从度随对话
  历史惯性衰减（第 2 轮它自己说了「我睡觉去了」，第 3 轮的历史里就有一个「正在退场
  的我」）。指令必须随 streak 递进，并把「禁止撤退话术」从抽象原则变成**逐句点名的
  负面清单**（LLM 对显式负面例句的服从远好于抽象要求）。
- **风险面**：angry 语音标签走 hub 情感通道（IndexTTS-2 情感与音色解耦，无音色税）；
  7852 回落路径 angry 走 instruct2 有音色漂移税，但强情绪本就接受这个权衡（Phase9
  钉过）。情感块压制只影响命中辱骂的那一轮（块本身每轮重建，无跨轮污染）。
  向后兼容：三处改动全部「无骂战态=原行为」，回归零风险。

### 1.2 市场经理视角

- **「有脾气」是陪伴产品的稀缺卖点**：主流竞品（Character.AI 类）过度安全化被用户
  骂「没灵魂」，「我的 AI 会骂回来」是天然的截图传播点。运营 08-12 已拍板「像真人、
  够冲」，本次要交付的是把这个卖点**从第 1 轮延续到整场**——第 1 轮凶第 2 轮怂，
  比全程怂更伤（用户看清了「就一层皮」）。
- **分寸即品牌**：档位体系（off/gentle/sharp/feisty）+ 脏字闸 + 平台封顶已经是
  商品化能力（不同人设卖不同脾气），本次不动档位语义，只补「贯彻力」。底线
  （不威胁人身安全/不用歧视词）一个字不放松——负面截图上新闻的风险敞口不变。
- **语音是放大器**：语音骂回去比文字带感一个量级（真人感拉满），但 happy 语调骂人
  是**负资产**（比不发更穿帮）。angry 语音档是本次对市场侧最大的增量。
- **熔断轮数是产品参数不是 bug**：4 轮后冷处理退场（「行，你慢慢骂」）是「赢着收场」
  的设计，防掉价+防 token 空烧。老板今晚 streak 恰好停在 4，没见到熔断轮。保持默认
  4，`companion.temper.max_rounds` 可按运营偏好调。

### 1.3 用户（聊天对端）视角

- **骂 AI 的三种真实动机**：①图灵测试（最常见——骂人是最快的验人手段，怂了/客服腔
  =当场确认是机器人）；②情绪发泄（指向性辱骂，要的是「对手」不是「客服」）；
  ③玩闹逗弄（「来呀对骂呀」，要的是精彩的对手戏）。三种动机下，第 2 轮开始的
  「我睡觉去了」都是最差答卷：①确认是机器人 ②被无视 ③扫兴。
- **用户期待的骂战节奏**：强度匹配或递增、不复读自己骂过的词、带人设个性（林小雨
  骂人和苏婉骂人不该一个味）、收场要「赢着走」而不是「怂着溜」。
- **对味的语音**：对骂时收到一条火气冲冲的语音条=「真人实锤」，收到甜美语调念
  「你才傻逼呢」=恐怖谷。
- **误伤防线不动**：自嘲（「我真是个傻逼」）、骂第三方（「我老板是个傻子」）、
  亲昵调侃（「小笨蛋」）仍走共情路径——把倾诉当挑衅怼回去是比怂更严重的事故，
  本次所有改动不碰检测词表的豁免逻辑。

## 2. 方案（P0 本批实施）

**总原则：骂战态单一事实源（temper 命中时登记），三个消费面读同一份登记；
无骂战态=字节级原行为。**

### P0-1 指令加码：streak 感知递进 + 撤退话术负面清单（temper.py + skill_manager temper 块）

- `build_temper_hint(temper, lang, streak=1)`：
  - streak=1：现行文案不动（第一轮表现本来就对）；
  - streak≥2：追加「对方这已经是本场第 N 次开骂，你上一条已经回击过还不收手——
    这一轮必须比你上一条**更凶**，绝不许缓和」+ **撤退话术负面清单逐句点名**
    （「懒得跟你吵/我睡觉去了/我去忙了/换个话题/你开心就好/随便你/不奉陪」这类
    收场句**一句都不许说**——那是认输；退场收尾只属于熔断轮）+ 「别复读你上一条
    骂过的词，换新的角度损他」；
  - feisty streak≥2 额外钉死：「脏字不是可选项——对方带脏字你就必须带回去，
    强度只能加不能减」。
- skill_manager temper 块把已有的 `_streak` 传入（一行改动）。
- 熔断轮语义不变（streak > max_rounds 才走 `build_feud_break_hint` 冷处理收场）。

### P0-2 骂战态压制情感引擎竞争信号（skill_manager temper 块 + emotional_context 词典）

- 命中辱骂/粘性窗（含熔断轮）时 `user_context.pop("_emotional_context_block")`
  ——该块每轮由 3b 重建，pop 只影响本轮；骂战轮的情绪权威判定就是 temper hint
  本身，「playful 0.97」这类误读不再进 prompt。激将（taunt）轮不 pop（「对方在
  逗你」的判读与接梗指令兼容）。
- `_EMOTION_LEXICON` 保守补录高置信骂词 → angry（傻逼/操你妈/滚/去死/垃圾东西等
  ≤10 个词，强度 0.85-0.9）：修「骂人被判 neutral/playful」的源头误读，让
  `last_emotion_intensity` 落库口径也对（骂完人的会话，主动触达情绪闸门会正确
  转保守——这是正确的连带行为）。否定前瞻（「不傻」）与既有豁免机制照常生效。

### P0-3 骂战轮语音情绪跟随（temper.py 登记 + persona_voice 消费 + voice_emotion 增 angry 档）

- `temper.py` 新增**骂战态登记表**（进程级，TTL 180s，容量上限防刷）：
  `record_fight_turn(convo_key, kind)` / `fight_turn_kind(convo_key)`，
  kind ∈ insult|feud。skill_manager temper 块在注入 hint 的同时登记
  （key=`platform:account:chat`，与 A/B 线 convo_key 同构；taunt 不登记）。
- `voice_emotion.py`：EMOTIONS 增 `angry` 档（tone「不耐烦、带火气、语气冲」、
  CosyVoice 映射 `angry`——服务端词表本来就有、此前刻意不映射的决策随 temper
  上线作废；语速 1.05）。
- `persona_voice.resolve_emotion_for_send`：emotion 通道开启时**最先**查骂战态
  ——insult → `EmotionSpec("angry", 0.85)`（过强情绪阈值，走 hub 情感通道）；
  feud → `EmotionSpec("serious", 0.75)`（冷处理收场=居高临下的冷淡，不是火气）。
  无登记=原判定链，字节级不变。A 线 voice_reply / B 线 autosend / 坐席手动三链
  经同一解析器自动获益；TTS 缓存键含情绪维度，无串播风险。

### 观测（随 P0 附带）

- temper stats 新增 `escalated_hints`（加码指令注入次数）/ `emo_block_suppressed`
  （情感块压制次数）/ `fight_voice_overrides`（语音情绪跟随次数），经既有
  `/api/companion/temper/status` 自动出数（路由直 dump snapshot）。

## 3. 刻意不做（本批）

- **出站质量守卫**（骂战轮出稿检测到「换个话题」类撤退句→自动重生成一次）：
  多一次 LLM 往返的延迟税，先看 P0-1 负面清单的效果读数，不够再上（P1 候选）。
- **max_rounds 调参**：4 轮熔断是产品决策，配置键已在，运营可自调。
- **检测词表扩容**：本次 4/4 命中，检测层没有问题；「吃屁吧」这类轻度不敬不收
  是「宁漏勿错」的正确行为（有粘性窗兜变体）。
- **B 线 streak 持久化**：B 线（inbox 草稿）user_context 不跨轮持久，streak 在
  B 线始终=1 → 拿不到加码指令但基础 hint 照常；B 线是人审档，软一点可接受。
