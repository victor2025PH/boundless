## 0. 一句话

实施81/82 把「回得出、有按钮」做到了；本方案解决「回得**快**、回得**好看**、
用户**有回执**、值守**少手工**」——四个 P0 全是当晚实锤 bug 的机制化收口，

## 1. 先摆事实

### 1.1 现链五段（读码结论）

1. **观察登记**：`bug_intake.trigger_verdict`（危机 hold → 限频 → 截图收集窗 →
   dup 折叠 → bug_new），AI 群内全静默；per-user/群 双限频，**限频同时挡了
   「回复」和「登记」**。
2. **值守答复**：`tools/duty_reply.py`（bot 优先经 `/api/admin/bug-intake/{id}/reply`
   → `build_reply_text` @报障人+🎫footer；回落 pyro send+拨回 auto_ai）+
   `support_reply_guard` 红线；台账 `duty_replies.jsonl`（**text 截 500 字**）。
3. **修复回访**：标 fixed → `build_fix_notify_text`（🔧 @人「title 截 60」(#id)
   已修复上线（本次改动：fix_note）📦获取方式：update_hint）+
   `build_verify_keyboard`（✅修好了/❌还是不行，callback_data=`btv:…`）。
4. **按钮回调**：官网 webhook `btv:` 分支（本人/管理员校验、即点即
   answerCallback+editMessageText 划按钮）→ JSONL → 117 `DutyCallbackPoll`
   5 分钟拉取 → y=verified / n=confirmed+告警 @ai_zkw。
5. **安全网**：DutyGroupWatchdog（30min 未答告警/240min 重提）、DutySlaWeekly、
   duty_known_issues 周公示、duty_notify_pending 积压冲刷。

### 1.3 2026 新技术底牌（已核原文）

- **Bot API 10.x**（changelog 原文核实）：`setMessageReaction`（**bot 可对消息
  贴 reaction**——零消息噪音的已读回执）；`InlineKeyboardButton.style`（按钮
  颜色）+ `icon_custom_emoji_id`；**`DisabledButton`/disabled**（10.3，点击后
  置灰保留痕迹）；**`CopyTextButton`**（点按钮复制文本）；**Checklist**（消息
  内任务清单，可逐项勾选/按任务回复）；`InputRichMessage` 富文本块；Mini App
  全屏/主屏快捷方式（注意 2026-07-20 起 Mini App 方法限同域安全加固）。
- **行业 agent-assist 共识**：四级自主度阶梯（答案只读→**拟稿人审**→审批后
  执行→强制人工）；拟稿必须 **grounded**（引知识库/工单上下文并留引用，
  幻觉率是采用率的生死线）；升级判定**召回优先于精确**；核心度量=坐席对
  AI 稿的**编辑率**。我们产品自身的 L1-L4 档位/小智四层答案/审核台正是同构
  ——值守链缺的只是把自家能力接到自己身上（dogfooding 缺口）。

## 2. 五视角问题清单

### 2.1 开发工程师

- D1 自咬守卫在冷启动 getMe 负缓存窗内失效（E1）；无启动预热、无 msg_id 锚兜底。
- D2 「回复预算」与「登记预算」耦合：`_rate_ok` 超额直接 return False，真报障
  只落 event 不落工单（E2）——限频本意是防刷屏（省回复），不该省登记。
- D3 `duty_watchdog.find_unanswered` 全局水位语义：任意官方出站清零 pending
  （E3）；bot 的 fixed 回访也算「应答」。
- D4 文案构造缺陷：`build_fix_notify_text` 双句号（E4）；工单 title 直截原文
  60 字含「[图片内容] 类型=B…」VLM 段（E4）；`_html_esc` 后的 title 里竖线/
  换行未净化。
- D5 台账不完整：`build_ledger_row` text[:500]（E5）；处置台按钮发送**不落**
  duty_replies.jsonl（只有 CLI 落）——同一条链两本账。
- D6 出站无节奏闸：连续 fixed/回复无条间间隔（E6）；notify-pending 批量冲刷
  有 1.5s 间隔，单发路径没有。
- D7 回调闭环依赖 5min 轮询+VPS JSONL 单点——可接受，但 poll 失败无告警面
  （state 停走没人知道）。
- D8 duty_reply 的 `--reply-to` 仅回落路径支持；产品端点 `/reply` 不支持引用
  原消息（回复与被回复消息无视觉关联，群里多话题并行时对不上号）。

### 2.2 市场经理

- M1 响应时效没有对外承诺面：内测期「报了没人理」是最伤信任的时刻（E7 当天
  真实发生 9 小时）；SLA 只有内部周报，群里没有「工作时段 30 分钟内首响、
  深夜次日上午」的明示预期管理。
- M2 修复效率没有营销化：一天发三版修十几单，群里只有零散回访——没有周度
  「成绩单」可视资产（修复数/平均时长/亮点），错过把「快」变成卖点的机会；
  官网无 changelog 页承接。
- M3 bot 品牌面弱：按钮无品牌色（style 字段已可用）、回访文案无固定视觉
  开头、bot 简介/头像未按品牌规范核过。
- M4 测试人验证行为零激励：点 ✅ 是在给我们干活，无任何感谢/积分反馈；官网
  bot 已有龙珠码/积分体系，未打通。
- M5 官方群闲置：bot 未进官方群（400），打法在内测群验证成熟后无平移预案；
  周公示的官方群口径（只报成绩不报未修）仍未拍板（实施82 决策点 3 遗留）。

### 2.3 用户（测试人 skuio/钧 视角）

- U1 「我报的单现在怎么样了」只能群里问：无自助查询面（/status 或卡片），
  重复追问既费他也费值守。
- U2 报障发出后无即时回执：不知道「系统收到没有、登了几号单」；值守在线时
  也平均滞后数分钟。
- U3 「要信息」类交互全靠打字：要机器码/截图/版本号没有结构化引导，用户
  不知道去哪抄机器码（CopyTextButton/深链可解）。
- U4 长文答复难读：一条 1000+ 字多主题（当晚 20:11 实例），手机上一屏翻不完，
  重点淹没。
- U5 「获取方式」是纯文字：让用户自己去找下载页/更新按钮，没有一键跳转。
- U6 点 ❌ 后没有可见下文：编辑后的消息只写「已转回跟进」，用户不知道多久
  会有人接、要不要再补充信息。

### 2.4 美术设计

- A1 回访/回复消息无统一版式：emoji 语义混用（🔧 既当「修复」又当模板图标）、
  工单号有时在头有时在尾、标题引用长而破碎（E4 的 VLM 噪音是重灾区）。
- A2 按钮视觉裸奔：默认灰按钮+文字，✅/❌ 全靠 emoji 撑语义；10.x 的按钮
  颜色/自定义 emoji 图标/置灰态全没用上。
- A3 处置台快捷模板是 4 枚裸 emoji 按钮（📥🎫❓🔧），不 hover 不知道是什么；
  详情页截图是链接列表不是缩略图墙。
- A4 周公示是纯文本长消息：无卡片化视觉资产（brand-assets 已有海报生成管线
  `build_release_poster.py`，完全没被支持链复用）。
- A5 消息里的状态语义没有色彩/符号系统：new/confirmed/in_progress/fixed/
  verified 在群消息里只有文字，扫一眼分不出轻重。

### 2.5 UI/UX 设计专家

- X1 处置台没有「待应答」视图：值守的第一任务（谁在等答复）反而要去 CLI/
  翻群才知道——今天 9 小时欠账的工具面根因。
- X2 回复全手写：无 AI 拟稿（产品自己就是 AI 拟稿人审的专家系统，值守链
  却在裸写）；快捷模板只有 4 枚且不带工单上下文。
- X3 标 fixed 即自动发回访，**发出前看不到成品**：双句号/长标题事故的流程
  根因——缺「回访预览」确认步。
- X4 SLA 在列表不可见：无「等待时长」列、无超时红标——watchdog 的判定
  没有 UI 常驻面。
- X5 逐单 fixed 流程重（进详情→写说明→更新状态），批量分诊又刻意不含
  fixed——缺一个「半批量」中间态（串行逐单填说明+受控节奏发送）。
- X6 按钮点击后 editMessageText 追加文字，键盘整个消失——用 DisabledButton
  置灰更符合「操作已完成」的心智；无文字消息（纯图回访）分支只是清空键盘，
  两分支行为不一致。
- X7 回访/回复不引用原报障消息（D8 同源）：多话题并行时用户对不上「这条
  是在回我哪件事」。

### 配套（不改码的机制项）

- 值守 SOP 补「响应时效对外口径」：群置顶消息写明「工作时段 30 分钟内首响、
  23:00-08:00 次日上午统一答复」——预期管理比苦熬更省信任（M1）。
- 值守监控循环（当晚临时脚本 tmp_duty_poll.py）在 P1-1 落地后退役，判定
  逻辑归一到 watchdog/处置台，避免三套「已应答」口径。

## 4. 决策点（要老板拍板）

1. **reaction 已读回执**是否豁免「AI 群内静默」纪律（实施82 决策点 1 遗留；
   P0-6 依赖。论据：reaction 不是发言、零刷屏、可随时关）。
2. **AI 拟稿**确认档位＝「拟稿人审后发」（recommend-only），值守绝不直发
   AI 稿——与产品 L2 档位同哲学（P1-2 依赖）。
3. 测试人自助查单走 **/mybugs 私聊**（便宜、快）还是 **Mini App**（体验好、
   成本高、受同域新政约束）——建议先私聊后 Mini App（P2-1）。
4. 验证激励是否接**龙珠积分**体系（P2-4）。

## 5. 刻意不做（防跑偏）

- **bot 群内自动答疑**（AI 直接回答报障问题）：2026-08-20 支持号串戏事故 +
  行业共识「低置信直答是信任杀手」；答疑永远人审后发，AI 只到拟稿为止。
- **117 消费 bot 更新流**：铁律不动（官网 webhook 是唯一消费方），一切
  「收」类新能力（reaction 更新/回调）都落官网侧。
- **全自动批量 fixed 回访**：实施81 P2-2 的刷屏论据依旧成立；只做 P1-3 的
  「预览确认+受控节奏」半批量。
- **换 webhook 拉取为长连接**：5 分钟轮询对回调闭环足够（用户侧体感在
  webhook 即时完成），复杂度不值得。
