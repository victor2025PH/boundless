## 2. 三个角度分别看

### 2.1 开发工程师

1. **目标引擎缺一个状态：known。** 只有 asked / missed / filled 三态，filled 依赖抽取，抽取关着 → 永远 missed → 永远 retry。正确状态机：`unknown → mentioned(unconfirmed) → confirmed`；「mentioned」由最近 N 轮客户 + 我方消息里的关键词 / 抽取候选判定，一旦 mentioned 就**不再问**，只允许深化式提法；重试每槽每日 ≤2；`missed` 时若回复已含槽位关键词判 covered。
2. **风险要挂会话，不挂稿。** `risk_hold(conv, reason, ts)`：命中 privacy / commitment / stop_contact 即挂，人工清除前所有重新起草强制 L1 且继承 shadow，AutosendWorker 拒发该会话；needs_human 从标签升级为闸。
3. **节奏等待之后必须二次复检。** O-1 D 把 30–60s 放进了「决定发」和「真发」之间，而 L1896 的模式闸在等待之前。投递前重读：会话模式 / 账号模式 / needs_human / risk_hold / 坐席是否在打字或刚发送；任一不满足 → `abort=mode_changed|agent_typing|risk_hold|needs_human`。坐席动作 = 客户插话同级。
4. **现实承诺是一类意图，不是五个词表。** 见面 / 上门 / 要地址电话 / 要照片视频 / 寄礼 / 转账借钱 → 同一条策略流程：人设政策（永不 / 熟悉 N 月 / 交人工）→ 委婉延后话术 few-shot → 出站 `commitment_claim` / `media_claim` / `self_blame_repromise` 三类拦截 → 被追问分支固定直接拒绝（not sending pics on here / nah not tonight）→ 第二次坚持转人工。P-3 已做照片的动作绑定，这里把它并进五类一套逻辑。
5. **没有主线就会退场。** 会话的推进意图应来自「关系阶段 × 账号级默认目标」，不是手建；客户无新信息 = 抛问时机而不是退场时机；`exit_claim` 守卫（gotta go / get back to work / have a good one / talk later）除 work_schedule 到点 / 客户先告别 / 用户开留白策略外一律改写；`proactive_topic` 从 C 类改为陪伴域 B 类默认开，受节奏与预算约束。
6. **基线补齐的三条红线被破了两条。** ① 只补缺席键、绝不覆盖显式值（care enabled 被翻回 False 要查 overlay 优先级或持久化文件）；② **会改变发送行为的开关不得默认开**（work_schedule、日发额度都违反）；③ 时区不得默认服务器本机（客户在海外）。加第四条：升级后首次进入弹一次「这版改变了什么」，列开关变化并给「保持关闭」选项。
7. **抽取两条链应合一。** `memory.extract.use_llm` 与 `companion.goals.profile_llm` 读同一句入站，合并一次 LLM 调用同时产出记忆事实与画像候选；联系人昵称分隔格式（名 / 年龄 / 城市 / 职业）解析预填「来自昵称 · 待确认」；每次写入落 `[profile] slot value source`；连续 50 条 0/0 告警。
8. **人工触发的动作不进自动化闸门。**「现在就问一个」「立即发」同一条直接投递路径：预览即所发、同步返回、预算只提醒。
9. **相册两态要分开：AI 建议 ≠ 已确认。** 建议词默认生效并标「AI 标注」（或一键采纳），匹配时低权重参与，完全无词才随机并落 `[album_match] candidates=0 fallback=random`；场景分类（自拍 / 室内 / 室外风景 / 美食 / 宠物）就是 Q4「可展示场景清单」的数据源。
10. **值守聚类要加主题条件与上限。** 同实体规则 + 主题重叠 ≥0.3 双条件；单票挂载 >6 份即另立并互链；汇总总表继续人工。

### 2.2 市场经理

1. **「被识破」这次不是标点，是行为。** 同一问题问 20 遍、说好周六上门又「忘了地址」、四次谎称发图——客户的原话「I feel like you are a bot now」会出现在他的朋友圈里。行为级识破比标点级严重一个量级，且发生在我们刚宣布「拟人止血」的当晚。
2. **升级把用户的运营开关改了，是信任事故。** 关怀被关回去、班表按上海时间给美英客户「下班」、额度闸门连人工都拦——用户设好的东西一升级就变，他会不敢升级。**发布说明要写「这版默认开了什么」，并给一键恢复。**
3. **陪聊业务的两条底线：永不线下见面、不乱承诺。** 这是法律和安全问题（线下见面 = 平台封禁 + 人身风险），人设政策必须出厂即「永不」。
4. **自主推进 = 留存。** 客户夸你的时候 AI 说「我回去工作了」，等于把最热的时刻扔掉；没有目标的会话零推进 = 纯接话机器人。市场要卖的是「会追、会问、会记」。
5. **调情能力是产品核心价值，不是锦上添花。** 用户明说「重要性不低于修 bug」。但它必须建在 Q1–Q5 之上：不乱承诺、记得住、不重复问，否则调情越强识破越快。建议立 1.0.80 专项而不是塞进 1.0.79。
6. **版本叙事**：1.0.79 = 「行为止血」（不重复问 / 不乱承诺 / 人工优先 / 撤回三个错误默认）；1.0.80 = 「会追会撩」（默认目标 + 推进计划 + 情感引擎 v1 + 口语层）。

### 2.3 用户（skuio 三个 WhatsApp + 两个 Telegram 号）

1. 它把同一个问题问了 20 遍，客户说我是机器人——这比破折号严重得多。
2. 它答应人家周六来喝茶，被要地址才转人工，审核稿还是「我一会儿发地址」——我要的是它一开始就委婉拒绝。
3. 我切了手动、在打字，它还发了一条；需人工挂着它还自动发。
4. 我 9/7 打开的关怀，升级后关了；我的客户在美国，凌晨一点它全体下班；额度闸门连我自己发都拦。
5. 相册 91 张说「缺触发词」，可 AI 明明识别完了——让我一张张点采纳？
6. 采用草稿发完还显示同一条草稿；主题点了没反应；卡片按钮点了显示 contact_budget。
7. 它完全不会调情，客户夸它它就跑，这不是陪聊。
