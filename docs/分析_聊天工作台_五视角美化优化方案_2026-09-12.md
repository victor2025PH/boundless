## 四、五视角——各自的问题清单（重要项标位置）

### 4.1 开发工程师

1. **认领体系的开关默认错了**：`resolve_seat_mode` 缺省 `multi`、异常也 `multi`（「不误藏」思路），子账号 ≥2 即多坐席——桌面单人端一旦建了第二个登录用户就进多坐席模式；`selectChat` L8399 无条件 `renewClaim`，「查看」被当成「占线」。修法在 §五 P0-1。
2. **档位有三个真相源**：`mode-select`（会话级）、`mode-eff-chip`（effective_automation）、`cdraft-reason`（服务端 L1 reason=global_default）——彼此不校验，#308 就是它们不一致时的样子。Q-26 A 的 `conv_state` 已聚合六源但**没把「本会话档位 / 全局默认 / 有效档位」三者纳入**。
3. **头部 14 控件 + composer 13 层横幅**全靠各自 `style.display` 切换，没有一个「同时最多显示几层」的仲裁；每加一条线就多一层。
4. **内联样式 531 处、硬编码色 728 处**（模板）+ CSS 1,055 个 hex：`--th-*` 只覆盖了 78 处；暗色主题靠 `[data-cp-theme=dark]` 覆盖 200+ 条选择器补洞（CSS L6–26 全是 `color-mix(...) !important`）。
5. **字号纪律未落地**：CSS 305 处 <12px（11px 是 chip / 副行的默认），`--cp-fs-tiny` 抬到 12 只管副驾。
6. **emoji 当图标**：`mode-select` 四个选项、`ai-diag-btn` 🩺、`ai-toggle-btn` 📝、`inbox.claim.mine` 🔒、i18n 包 110 条带 emoji 的 UI 串——与 `workspace_emoji_ratchet` / `uiIcon` 纪律相悖，跨平台字形不一致、深色下发光。
7. **404 个内联 `onclick`**、25 个 `<script>`、2.8 万行单文件：任何 UI 改动都是全文件 hunk，`stage_hunks` 切前缀是唯一协作手段；无组件级测试，门禁是文本正则（已出过 `'inbox.adult.cat_'+x` 误报）。
8. **内部原因码直出界面**：`media_caught_repeat`、`agent_sent`、`lang_unknown`、`clone_unavailable:*`——有的有人话映射有的没有，没有统一的「原因码 → 文案」表。

### 4.2 市场经理

1. **卖点是「全自动陪聊」，客户装上 1.0.84 第一眼看到的却是「处理中 / 释放认领 / 我 / AI」**——这些是客服中心话术，直接把产品定位从「你的 AI 分身」拉回「工单系统」。用户原话：「属客服思维」「用户版去掉认领体系」。
2. **头部像驾驶舱仪表盘**：接管、原生页打开、能力对照、AI 状态、待审、助手、工作目标——演示时讲不完，客户记不住；第一屏应该只回答「它在替我聊吗、聊得怎样」。
3. **同屏矛盾 = 信任流失**：顶栏绿灯全自动 + 草稿条「需要确认」，客户第一反应是「这软件不靠谱」，不是「我配置错了」。
4. **多语言 / 深色是海外与夜班的门面**：粤语、日韩、深色对比这些在 1.0.84 都修了，但如果头部依然堆 emoji、字号 11px，专业感立不住。
5. **可宣传的三件事**（一条状态带「AI 会不会回」/ 五类硬拦其余不停自动 / 单一版本）要有统一的视觉身份：状态带四色、风控卡、拦截台账应该长得像一家人。
6. 内测方反馈质量极高、频率极高（两天 90+ 份报告），说明**测试者就是最好的产品共创者**——回访文案模板化、验收三步已成型，缺一张只读看板给他们。

### 4.3 用户（坐席 / 运营，单人桌面端）

1. 「我点开一个会话，AI 就不聊了」——这是 #310 的体验本质；用户不需要知道认领。
2. 「绿灯为什么不发」——需要一句话：会 / 不会 / 几秒后 / 为什么 / 点哪里恢复。状态带做到了，但头部还有三个东西在跟它抢话。
3. 「这堆按钮哪个是我该点的」——每天真正用的只有：切档位、看状态、发消息、翻译、助手。其余应收进「更多」。
4. 「红条上的英文单词是什么」——`media_caught_repeat` 这类必须是人话。
5. 「字太小、深色看不清」——11px 副行、灰字压深底。
6. 「列表里一会儿我一会儿 AI」——列表行只该告诉我：谁没回、谁在等、有没有风险。
7. 「输入框上面一层层横幅把消息顶没了」——1024 宽 + 右栏展开时消息区只剩三行。

### 4.4 美术设计（视觉）

1. **色彩**：品牌蓝之外，页面里同时出现靛蓝（`--xl-accent #4338ca` 翻译族）、紫（`--xl-violet`）、青（`--xl-teal`）、绿（翻译按钮 `--xl-trbtn`）、琥珀、红——翻译一个功能就占了 4 个色相，与「品牌蓝唯一强调」相悖；徽章 `--bdg-*` 五档是对的，但头部 chip 各自 `color-mix` 自配色。
2. **字号阶梯**：实际出现 10 / 11 / 12 / 13 / 14 / 15 / 16px 混用；副行与 chip 大量 11px，与 `--cp-fs-tiny 12` 纪律不一致；行高无统一（1.4 / 1.55 / 默认）。
3. **间距**：`--tk-gap 12`、`--cp-gap 4/6/10/14` 之外大量 2px / 3px / 5px / 7px 手写值；头部 chip padding `2px 8px` 与按钮 `hdr-btn` 高度不齐，基线不在一条线上。
4. **圆角**：chip 10px、按钮 6px、卡 10px、弹层 14px 混用，同一头部里三种圆角。
5. **图标**：SVG stroke 2 的线性图标（对）与 emoji（错）混排；`uiIcon` 已有 check / lock 等，但只用了一半。
6. **深色**：结构面「中性深灰」做得好，但翻译族 / 徽章 / 头部 chip 用 `color-mix(品牌蓝 14%)` 叠底，饱和度不一致，出现「一块蓝一块紫」；`--th-*` 暗档只覆盖 78 处内联。
7. **层级**：58 处 `z-index` 手写（1000 / 9999 混），弹层阴影 `--tk-shadow-md` 与 `--cp-shadow` 两套。
8. **动效**：`--cp-dur .2s` 只在副驾用；工作台 chip 出现 / 消失无过渡，状态带 45s 轮询刷新是硬跳。

### 4.5 UI/UX 设计专家（信息架构与交互）

1. **一个页面三套「谁在管」模型**：认领（多坐席）、档位（manual/review/multi/auto）、让位（agent_sent 60s）——用户只需要一套：「AI 会不会替我发」。
2. **状态优先级没有仲裁**：状态带（Q-26 B）定义了 manual > held > sidecar_down > off_hours > deferred > lang_unknown > ai_fail > auto，但头部 `mode-eff-chip` / `aif-chip` / `claim-hdr-btn` / 草稿条 `cdraft-reason` 都在带外自己显示，等于优先级没生效。
3. **头部 = 身份 + 一个决定**：头部只该有「对方是谁」和「AI 档位」这一个决定，其余是次级动作（收进 ⋯）；状态带紧贴其下作唯一状态。
4. **列表行 = 三个问题**：谁没回（未读）、谁在等（SLA）、有没有风险（红点）——「我 / AI / 审 / 手」角标是运营视图，应只在多坐席 + 「我的」筛选时出现。
5. **Composer 栈要有「最多两层」规则**：一层「上下文」（引用 / 编辑 / 媒体 / 语音 之一），一层「AI 草稿」（cdraft 收成一行：就绪 + 原因 + 采用 / 忽略）；身份条、账号退出、语言错配这类**状态**全部并入状态带，不再各自占一行。
6. **原因码人话表**：所有 `reason_code` 走一张 i18n 映射（`inbox.reason.<code>` = 一句话 + 一个建议动作），缺键时显示「AI 暂停：<code>（点详情）」而不是裸码。
7. **弹层策略**：翻译选语等二级选择改**右栏抽屉**（与助手同层），弹层里不再套下拉。
8. **首次 / 空状态**：新装机第一屏应引导「选一个人设 → 选档位 → 看状态带」，现在空状态是灰字一行。
9. **可达性**：状态带已有 `role=status aria-live`；头部按钮多为 `title` 提示无 `aria-label`（图标按钮）；键盘焦点环 `--tk-ring` 只在部分控件生效。
