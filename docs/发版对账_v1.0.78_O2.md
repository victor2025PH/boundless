## 〇. 为什么第三次「出厂默认没进基线」（给 N-5 / 未来发版的核对步骤）

**三次同根**：① 07-31 工作目标卡（演示机 overlay 开、包里关）→ 立 `feature_registry` A 类 + `_ensure_baseline`；② 09-06 L-5 D1/D7 三键（只写在 `cloud_light.yaml` 与内测种子，clean 升级机两条路都不经过）→ 补进 A 类；③ 本次 `memory.extract.intents`。机制早就有，**漏的是「哪些键该进表」这一步没有系统化核对**：L-5 只按老板决策 D1/D7 点名的三键补（`companion.goals.sprint.enabled` / `companion.wellbeing.crisis_audit` / `companion.wellbeing.crisis_escalation`），没有回头把「服务器 `config.yaml` 有、内测种子有、min 种子没有、且代码里**缺省即关**」的键全量扫一遍。`memory.extract.intents` 正是这种键：`should_extract_intent`（Phase D）为存量零回归刻意「空即不抽」，服务器 `config.yaml` L1770 有四值、内测种子 `config.desktop.internal.yaml` 用 `match_all: true`（只进 smart 包），而 `config.desktop.min.yaml` **没有任何 `memory` 块**，`config.example.yaml` 的 `memory` 块也**没有 `extract` 子块**——clean 包 / 照抄 example 的自建实例，记忆抽取从安装第一天起就是死的，卡片和日志还写「已启用」。

**「基线键清单核对」步骤（每次发版打包前，N-5 E 段或发版人跑一遍，5 分钟）**：

1. 在 `engines/chengjie/` 下跑一行：把 `config.desktop.internal.yaml`（内测种子）与本机 `config/config.yaml`（服务器真值，untracked）的叶子键逐个对 `config.desktop.min.yaml` 合并 `feature_registry.baseline_patch` 后的客户视图做 `dig(...) is None` 差集（本次实测差集 494 键，绝大多数是 LAN 地址 / 人设 / 音色等**本就不该随包**的内测专属）。

### 1.1 改前核实的机制链（与 L-5 §1.1 同一条）

- `ConfigManager.load()`（`src/utils/config_manager.py` L400–431）：读 `config.yaml` → `_merge_overlay`（`config.local.yaml`）→ **`_ensure_baseline`**（桌面态 `AITR_DESKTOP_MODE`；`feature_registry.baseline_patch` 算「合并视图缺键」→ `save_overlay_patch` 落 overlay + 即时合进内存）→ `_ensure_deploy_profile`（`cloud_light` 只在全新播种时）→ 迁移们。
