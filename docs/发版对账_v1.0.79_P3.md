## §〇 先答一问：守卫为什么「看见了却没拦」——识别 → 无动作权 三段

1. **[PHOTO] 请求失败后，正文仍按「图已发」写。** `build_photo_protocol_prompt` 明令「正文把照片当作已经拍好正在发来写（可以说"刚拍的"）」——这在图真发出时是对的；`run_autosend_image` 按请求选图失败（相册避重耗尽 / 冷却 / 无匹配场景 / 能力关）返回 False 之后，`_autosend_deliver` 只是「继续走文本」，配文「Just took this one for you—」离开了图就是谎，而承诺词表没有 `took this … for you` 这条，`detect_media_promise` / `detect_media_claim` 都判 ''。识别层零命中 → 无动作。
2. **第二句配文体在图发出后「语境闭合」。** `_mctx`（客户在索图）的判定是 `_media_ts < _req_ts`：14:49:20 图真发出后请求已兑现、门关上，14:49:51 的第二句 claim 即便词表认得也不会进 `detect_media_claim(media_context=True)`；`near_duplicate 跨轮相近放行`（worker）只看相似度不看「这句是不是照片文案」，放行。
3. **已发假声明对照 30 分钟账本被判「真话」。** 14:51「I thought it went through—let me try sending it again」`detect_sent_claim` 命中，但 `_media_sent_recently(window=30min)` 看到 14:49:20 那张 → 「近窗真发过＝真话放行」。账本口径没有「客户刚说没收到」这一维；而 `lie_caught` 在 `skill_manager._maybe_flag_media_complaint` 只写 `_media_coherence_hint` 让模型「别编」——实录证明 hint 式纠偏挡不住传输借口。14:51 客户「Where honey? No picture」连 `lie_caught` 都没认出（词表无 `no picture`）。

**修法 = 把四处接成固定动作（全部在 B 线投递层 `autosend_helpers._autosend_deliver`，那里才知道本轮有没有已回执的 send_media）**：A `[PHOTO]` 请求失败 → 正文强制进承诺链，回喂「无图可发」重生一句（`[media-bind]`）；B 承诺/断言无已回执媒体 → `strip → rewrite → review`（`[media_promise]`）；C 最新入站 `lie_caught` → 重发上一张（回执账本 / 相册投放账本）/ 强制实话模板 / 连续第二次转人工（`[media_complaint] action=`）；D 人设 `photos=false` → 剥空换诚实拒绝模板；E 5 分钟内刚真发过 + 本轮又是配文体 → 强制媒体语境判、必须附图否则改写。「真发成功」= `send_media` 回执 `delivered=True`（M-2 D 口径）+ `message_id` 进账本。
