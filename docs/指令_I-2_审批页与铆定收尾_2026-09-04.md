  2026-08-29 有一条线跑了个不带路径的 stash，一次卷走 169 个别人的未提交文件。

  `offset`/`limit` 取 ±80 行窗口。** 同规则适用 `store.py`、`desktop/main.js`。

## 2. A2（P1）#158 草稿审批工作台进得去出不来 —— **先做这个**

### 现象与证据

证据包 `D:\boundless\tmp_diag\U7WQES`。用户从 L4 草稿点「去审批」进入审批页后，
**点顶栏「聊天」回不去**，只能关掉整个窗口。

链路事实（已核准，行号可能漂移，先 Grep 确认）：
- 页面 `/workspace/drafts` 由 `src/web/routes/drafts_routes.py` L3558 提供
- 模板 `src/web/templates/draft_review.html`，`extends workspace_base.html`
- 顶栏「聊天」= `workspace_base.html` L845 的 `#nav-inbox href="/workspace"`

### 两个嫌疑，**先定层再修**（别直接猜着改）

1. **打包态弹窗吞导航**：该页在 `desktop/main.js` L1684 `openBackendPopup` 开的弹窗里，
   点 `/workspace` 被 L1723 `makeBackendPopupHandler` **deny 掉或被 `focusMainInbox` 吞掉**
   —— 表现就是"点了没反应"。
2. **页级脚本错误 / 全局 click 拦截**：#129 在同一页报过脚本出错，脚本崩了会让委托的
   click 处理器整体失效。

定层方法（按顺序，都很便宜）：
- `Select-String -Path desktop/main.js -Pattern "makeBackendPopupHandler|openBackendPopup|focusMainInbox"`
  看 deny 分支的判据到底是什么
- 打包态从 L4 草稿「去审批」进入，看 `renderer.log` 有没有 `Uncaught`
- 如果两条都不成立，才去查 `workspace_base.html` 的导航拦截器

### 修

- 审批页顶部加**固定的「← 返回聊天」**入口：
  - 弹窗态 → 关弹窗并 `focusMainInbox()`
  - 主窗态 → `location = '/workspace'`
- 弹窗内点 shell 导航 → **关弹窗并聚焦主窗对应标签，不能静默 deny**。
  「点了什么都没发生」是最糟的形态，比报错还糟。
- **导航不依赖页级脚本**：脚本崩了也要能出去（用原生 `<a href>` 或 `onclick` 直接
  `location`，别挂在需要初始化的委托器上）。

⚠ 这个仓库有「返回工作台去重」的既有语义（`_win_unique.html::__wsGoHome`：别处有活跃
坐席就交接、没有才本窗导航）。**先 Grep `__wsGoHome`，复用它，不要另写一套**——
另写一套会导致同一 profile 出现两个坐席工作台（这是 2026-08-11 修过的实录事故）。

### 验收

1. 两条进入路径（主窗直接开 `/workspace/drafts`、打包态从 L4 草稿「去审批」）
   → 点「聊天」和点「← 返回」**都能回 `/workspace`**
2. `renderer.log` 无 `Uncaught`
3. `desktop/test` 加一条导航用例（`cd desktop && npm test` 全绿）
4. 脚本被人为打断（临时注入一个抛错）时「← 返回聊天」**仍然可用**
