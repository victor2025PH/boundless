# 实施82：报障群互动与消息美化——五视角分析与统一方案

> 日期：2026-08-29 ｜ 状态：**方案 + P0「bot 代发」已实施（见 §4）**
> 缘起：老板问「群里的回复为什么没有按钮、没有和用户互动的地方」。
> 产出方式：三个并行分析 agent（技术底账 / 市场+用户 / 美术+UI/UX）+ 主线合成。
> 关联：实施81（值守闭环工具链，本方案的执行地基）、实施74（报障闭环 P0）。

## 0. 先回答老板的问题：为什么没有按钮

**因为群里所有官方消息都是「支持号 6834964252（@htqp456）」这个 Telegram
用户账号发的，而 inline 按钮是 Bot 专属能力**——用户账号（含 userbot）发不出
可点击回调的按钮，这是 Telegram 平台规则，不是我们没做。本仓代码甚至把
「消息带按钮」当成判定对方是 bot 的证据（`peer_bot_guard.tg_inline_keyboard`）。

用户账号**能**用的互动面：HTML 富文本、@深链、**引用回复**、**emoji
reactions**（可发可读）、**发起投票**——这些今天一个都没接。要真按钮只有一条
路：让 bot（现成的 @tgzkw_bot 或新专用 bot）进群发流程类消息 + 挂 callback
消费循环。结论：**短期用「reactions + 引用回复」把互动做出来（用户号就能做），
中期 bot 进群拿真按钮——人管对话、bot 管流程。**

## 1. 五视角问题清单（精选，完整版见分析记录）

### 开发工程师（技术底账）

- E1 工单表**不存消息 id**（source/notify message_id 皆无）→ 引用原报障、对着
  消息点 reaction、编辑已发消息全部被卡（这是几乎所有互动的共同地基缺口）。
- E2 `_send_group_text` 不带 `reply_to`、不存返回 id；回访是「广播」不是「回帖」。
- E3 Telegram reactions/poll 零接线（坐席 `/react` 只支持 WA/Messenger）。
- E4 @tgzkw_bot 只有单向 sendMessage，无 getUpdates/callback 消费；仓内先例
  `scripts/cs_redeem_bot.py`（独立 sidecar 长轮询）可照抄骨架。
- E5 周公示走 `/api/unified-inbox/send` 无 parse_mode＝纯文本链路；回访/回复走
  pyrogram HTML 链路——两套排版能力不同，美化稿必须分 HTML 版与纯文本版。
- E6 群消息互动零观测（发出去多少人理会，一个数字都没有）。
- E7（顺手抓到的真 bug，已修）处置台错误态 colspan=7 对不上加勾选列后的 8 列。

### 市场经理

- M1 最有营销价值的「已修复」消息写成运维回执：「关单/工单/并入」全是内部术语，
  全程不出现产品名，截图传播零品牌。
- M2 内部严重度 P0/P1/P2 直接漏给用户（等级焦虑 + 看不懂）。
- M3 手握好数据不讲故事：p50 首响 2.4 分钟、修复时长（created→fixed）都在库里，
  对外一克没用。
- M4 周公示是台账转储不是周报：以负面清单收尾、无汇总行、两个群同一份
  （对官方群播全量未确认 bug＝放大负面）。
- M5 互动率为零且不可度量——将来对外讲「内测社区活跃」拿不出一个数。
- M6 官方身份裸奔：@htqp456 无品牌名/头像/管理员头衔，仿冒成本≈0（而词表里
  备着「骗子/诈骗」说明信任敏感真实存在）。
- M7 「已在列的问题不用重复报」在杀自己的优先级信号（≥3 人报告 P2→P1 的机制
  被公示文案劝退）。
- M8 官方消息无固定节奏（回访冲刷无间隔配额、公示靠值守自觉）＝随机噪音。

### 用户（内测群成员）

- U1 报完 bug 在值守首响前**零确认**（AI 静默纪律下 footer 只随人工回复出现；
  p95 首响 96 分钟里用户不知道有没有人看见）。
- U2 处理过程黑箱：登记后到回访前没有任何中间态。
- U3 验证要打字且只认词表（「好了/还是不行」；「嗯」「ok」都不算）——点个 👍
  不被识别。
- U4 回访不引用原消息：被 @ 时只看到 60 字截断标题，想不起自己报了什么。
- U5 跟进自己的单没有通道（30 分钟收集窗过期后，补充信息=重新描述）。
- U6 用户做了动作没回音（回「好了」静默关单，没有致谢/确认）。
- U7 没有置顶指南：怎么报、带什么信息、官方是谁、会发生什么，全靠猜。
- U8 并单不透明：「已并入工单 #12（第 3 人反馈）」——用户看不到 #12 原本是什么
  问题，并错了也没有渠道说「这不是一回事」。

### 美术设计

- A1 修复回访 100+ 字挤一段、括号套括号、工单号无 `<code>` 等宽——视觉密度失控。
- A2 emoji 语义不成体系（🔧🎫📦💡✅🔁 混用无规则）。
- A3 周公示单行 140+ 字手机折 5-7 行塌版；「请报障的朋友验证」逐条重复十遍。
- A4 处置台徽章硬编码色值放着 `--rs/--as/--gs` token 不用；fixed 与 verified
  仅差 8% 透明度肉眼不可分；P2 与 closed 同款灰。
- A5 无签名/头部品牌区：官方消息与群友闲聊在视觉上零区分。

### UI/UX 设计专家

- X1 回访文案没教用户怎么回（词表就认「好了/还是不行」，文案却不说——自动
  关单命中率在文案层白丢，这是全部 17 项里最值钱的一条）。
- X2 处置台详情面板不吸顶（长列表选中后动作区滚出视野）、移动端点行无反馈、
  无骨架屏、无轮询刷新。
- X3 `bt-d-hint` 输入会被列表重载抹掉（编辑中丢字）。
- X4 「互动」的信息架构缺失：验证/附议/跟进三个用户动作没有各自的固定入口与
  一致话术。
