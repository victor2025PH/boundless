# 实施98：人民币收款主体——落地清单与技术接入点

> 日期：2026-09-08 ｜ 性质：**老板拍板「人民币收款主体开始做」后的执行清单**（商务/财务动作 + 工程接入点），不改定价数字
> 依据：`products/zhiliao/product.yaml`（充值唯一化：USD/USDT，1U=1,500 Token，首充加赠；企业两形态 lead-based）、
> `docs/实施96` §3.2（抖音企业版客群付人民币是市场缺口）、`docs/实施10_合规隔离`（支付主体 / 域名 / 可索引页面分离）。

## 0. 一页结论

抖音企业版的客户是国内商家，付人民币用微信/支付宝，而智聊今天只收 USD/USDT。**收款主体不是一个支付按钮，是「主体 + 商户号 + 发票 + 合规分层 + 定价换算」五件事**；商户号审核 1–3 周，主体设立（若新设）更长，所以与抖音资质一样必须今天启动。工程侧只做**接入点预留**，不动现行定价与结算。

## 2. 工程接入点（本批只预留，不改现行结算）

- **展示单一真相**：`website/lib/chatx-pricing.ts` 由 `products/zhiliao/product.yaml` 派生（改价先改 yaml）。人民币上线时在 yaml 的每个充值 SKU 加 `price_cny`（固定档价），前端按 `currency` 切换展示；**不加浮动汇率逻辑**。
- **下单流**：官网下单页新增 `pay_channel ∈ {usd_card, usdt, wechat_native, alipay_pc, alipay_h5}`；微信 Native 走二维码轮询，支付宝走跳转回调；回调统一进现有履约（`chatx_fulfillment.py` 的充值凭证 `ref` 幂等 → Token 到账）。
- **履约不变**：凭证仍按 `ref` 幂等发 Token（当前发 `chars`、无过期列——实施96 §… 已点名的欠账一并修：改发 `tokens` + 12/24 个月有效期）。
- **发票**：下单页采集抬头/税号 → 订单表新列 → 财务导出；电子票对接留 P2。
- **合规分层**：人民币下单页只在合规主站域名与主体下渲染；准入区产品不出现人民币入口。
- **对客口径**（已落）：小智问答与教程页 `/help/onboarding/payment-cny`：「当前支持 USD/USDT 充值；人民币通道（微信支付/支付宝）办理中，上线后官网出现入口；企业客户可走对公合同」。商户号下来当天把该页第 3 步改为可用状态。

## 3. 时间线（建议）

- 第 0 周：定主体；准备执照/对公账户/场景截图；对公通道立即可用。
- 第 1–2 周：微信支付、支付宝商户申请与打款验证；定价换算拍板；yaml 加 `price_cny`。
- 第 2–3 周：官网下单页人民币入口 + 回调 → 履约联调（沙箱）；发票信息采集上线。
- 第 3–4 周：小额真付验证 → 对外开放；教程页/小智口径切换。

## 4. 刻意不做

- 不做日汇率浮动定价（对账噩梦、客户看不懂）；
- 不在人民币通道页面出现 USDT/加密字样；
- 不把准入区产品接进人民币主体；
- 本批不改任何现行 SKU 数字与结算代码。
