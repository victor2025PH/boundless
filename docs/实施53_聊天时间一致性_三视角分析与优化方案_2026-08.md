## 一、深度排查：两个症状、三个根因（全部已在代码/生产配置里核实）

### 症状 A：「凌晨 3 点在二手书店看书」——场景轮换的深夜盲区（真 bug）

**复现链**（以生产在档的台北人设「大学生/生活博主」为例，UTC+8 与服务器同钟）：

1. 该人设 `selfie_scenes` 池含 `secondhand bookstore aisle, browsing paperbacks`、
   `university library window seat on a rainy day`（zhiliao 实例
   `profiles_runtime.yaml` 实查），`tastes.likes` 还有「二手书店淘旧书」强化词。
2. 凌晨 3:31 属深夜桶（22-6）。场景轮换 `pick_scene_hint` 的时段过滤
   `scene_conflicts_with_hour` 是**负面剔除**设计：只剔带显式时间词的场景
   （afternoon light / dusk / morning rush…），**无时间词的场景任何时段放行**
   （设计注释原话「宁可放过，不误杀」——对生图够用，对聊天注入不够）：

```611:641:engines/chengjie/src/ai/companion_selfie.py
_SCENE_DAY_WORDS = ("morning", "sunrise", "dawn", "noon", "midday", "afternoon",
                    "daytime", "daylight", "sunny day")
// ... more code ...
def scene_conflicts_with_hour(scene: str, hour: int) -> bool:
    // ... 深夜(22-6)只剔全部白天+黄昏词；无时间词恒 False ...
    return any(w in s for w in _SCENE_DAY_WORDS + _SCENE_EVENING_WORDS)
```

3. 于是深夜桶照样能轮到「二手书店」→ `scene_chat_note` 注入
   「【你此刻的状态（内部设定）】你现在的场景：secondhand bookstore aisle…
   不要与它矛盾」；行程线（Phase20）还会把它标成「深夜(现在):bookstore」。
4. 同一个 prompt 里 `build_time_context_line` 的【作息合理性】深夜行却说
   「合理状态是宅在室内/准备睡」——**两个系统注入互相打架**，场景块更具体、
   还带「不要与它矛盾」指令，LLM 常选它 →「我在二手书店看书」。
5. 出站最后防线 `world_clock_guard` 只抓**问候/餐/星期/错城**断言
   （`_DAYPART_CLAIMS`：早安/刚吃午饭/good evening…），抓不住
   「深夜在白天场所活动」类断言 → 放行出站。

**结论 A**：不是 LLM 抽风，是场景状态机在深夜时段把「白天场所」当合法状态
喂给了 LLM，且下游没有兜底防线。

### 症状 B：「一会白天，一会晚上」——跨时区人设的双时钟矛盾（真 bug）+ 设计未被感知

**根因 B3（多人设并测的感知问题，不是 bug）**：温哥华护士（林佳欣，Seawall

## 二、三视角分析

### 视角 1：开发工程师

- **「现在几点」有四个事实源**：服务器钟（`time_context.build_now_anchor_hint`）、
  人设当地钟（`persona_location` → `build_time_context_line`/`local_time_line`）、
  场景桶时钟（`pick_scene_hint`，已用人设钟）、客户钟（`user_clock`）。单一事实源
  原则在 B 线锚点处破功——**这是本次事故里唯一的「架构级」缺陷**，其余都是词表/
  覆盖面问题。修法不是再造一个源，而是让 B 线锚点消费既有的人设钟。
- **过滤器语义错位**：`scene_conflicts_with_hour` 的负面剔除对**生图**是对的
  （图不带钟，模糊光线词白天黑夜都成立）；对**聊天状态注入**不够——深夜的语义
  是「正常人只会在室内/家里」，需要正面白名单，而不是「没写 afternoon 就算你对」。
  同一个函数服务两个消费面，其中一个消费面需要更强不变量时，应该在共用层收紧
  （生图深夜出书店照同样穿帮，收紧对两面都是纯收益）。
- **防线不对称**：出站守卫抓问候/餐/星期/错城，独漏「场所×时段」断言——而这恰是
  客户验证成本最低的穿帮之一（看一眼手机时间）。守卫已有句级剥离基建
  （`apply_world_clock_guard`，A/B 线双接线），扩词表即可，零新管路。
- **观测缺口**：没有「出站时段/场所断言 vs 发送时刻（人设当地）」的错位率读数。
  本次靠老板凌晨肉测发现——等价于拿最贵的告警器抓最便宜的缺陷。
- **测试缺口**：时间一致性有零散门禁（world_clock_guard/scene 各自的单测），但
  没有「同一 prompt 只允许一个『现在』口径」的**组装级**不变量测试——双时钟这种
  两个模块各自正确、拼起来矛盾的缺陷，单测网天然抓不到。

### 视角 2：市场经理

- **时间穿帮是信任的秒杀项**：陪伴产品卖的是「对面是个活人」，客户验证真人感的
  成本最低手段就是时间常识（几点了你在干嘛）。一次「凌晨在书店」的穿帮，前面
  几十轮养出的信任清零，且客户会截图传播——负面外部性远超单会话。
- **时差本应是资产不是负债**：海外人设（温哥华护士、旧金山工程师）是刻意的产品
  设定（异地感、生活丰富度、「你那边该是深夜了吧，早点睡」的关心是高价值情绪
  瞬间）。现在的问题是时差**没被经营**：AI 不主动点破时差，客户就只能按自己的钟
  理解——把设定做成了穿帮源。方向是显式经营（点破时差话术），不是抹平（全改
  UTC+8 会让海外人设的整个背景故事塌掉）。
- **内部信任成本**：老板/坐席看不到人设时钟 → 把设计当 bug → 报障/排查/解释
  三重成本。运营侧需要一张「人设×时区×账号」的底账和工作台可视化，让「这个号
  为什么说中午」一眼可判。
- **质量门槛**：「时间一致性」应成为和翻译质量/危机响应同级的常驻评测轨——
  这是对外可信的硬指标（客户/渠道问「你们怎么保证不穿帮」时拿得出手）。

### 视角 3：用户（客户 / 坐席）

- **客户视角**：① 同一个人上一条晚上、下一条白天＝精神分裂感，直接怀疑机器人；
  ② 凌晨说在书店＝常识违背，直接怀疑骗子；③ 反过来，如果 AI 说「我这边刚过中午，
  你那边很晚了吧？早点睡」——时差被自然点破，真实感反而**加分**。用户要的不是
  「AI 和我同时区」，是「AI 的世界自洽且能感知我的世界」。
- **坐席视角**：AI 拟稿写「我在书店」，坐席若不知道人设在温哥华，要么不敢通过
  （效率损失），要么改错（把对的改错）。坐席需要：回复区一眼可见「人设当地时间」；
  草稿卡对「时段可疑」的稿子给黄标预判（与既有稿龄 chip 同族——预判必须与守卫
  行为一致，否则比没有更糟）。

## 三、优化方案（P0 修穿帮 / P1 建防线与观测 / P2 产品化经营）

### P0-1 B 线时间锚点统一到人设当地钟（修「一会白天一会晚上」）

- **改法**：`build_now_anchor_hint` 增加可选参数（人设当地 naive datetime +
  `place_label`），有 place 时输出「（XX当地）」标注，与 ai_client 时间行**同钟
  同措辞口径**；`persona_reply` 两个注入点（回复锚点 `:455`、opener `:1079`）
  按 persona_id → `resolve_place_with_fallback` → `persona_now` 解析当地钟；
  解析不出（无 location 人设）保持服务器钟＝现状零回归。
- **不变量（新组装级门禁）**：含 location 人设的 B 线 prompt 中，「当前时间」类
  注入行**全部同一时段词、同一日期**（温哥华人设在服务器 03:31 → prompt 只允许
  出现「中午/12:xx」，不允许出现「深夜/03:xx」）。
- 涉及文件：`src/inbox/time_context.py`、`src/inbox/persona_reply.py`；
  门禁扩 `tests/`（time_context 既有用例 + 新组装断言）。

### P0-2 深夜场景正面白名单（修「凌晨在二手书店」）

- **改法**（`companion_selfie.py`，选择器层收紧，**不动人设档案**）：
  1. 新增 `_DAYTIME_VENUE_WORDS` 保守词表（bookstore/library/campus/classroom/
     school/office/meeting room/mall/stationery/metro/commute/cafe/dessert/
     bubble tea/gym…）；深夜桶（22-6）内，场景含场所词**且不含显式夜间词**
     （night/midnight/late night）→ 判冲突剔除（夜市/夜景酒廊自带 night 词，照常
     放行）。
  2. 深夜桶**全池冲突时不再回退原池**（现行为 `fitting 为空 → 用回原池` 正是
     bug 的再入口），改回退内置中性场景
     `at home, winding down for the night, cozy dim light`——聊天与生图两个消费面
     都安全；其他时段保持「回退原池」旧语义不动。
  3. 行程线 `build_day_itinerary` 深夜桶经同一函数自动获益（不再出现
     「深夜(现在):bookstore」）。
- **连带收益**：场景块与【作息合理性】深夜行从此不再打架（场景保证深夜恒室内）。
- **不变量门禁**：凌晨 3 点 × 含书店/图书馆的池 → 永不返回场所场景；全场所池 →
  返回中性夜场景；白天时段行为逐位不变；`night street food market` 在 22:30 仍可选。
- 涉及文件：`src/ai/companion_selfie.py`；门禁扩 `tests/test_scene_state.py` 族。

### P0-3 出站兜底：「深夜×白天场所」断言剥离（world_clock_guard 扩展）

- **改法**：`world_clock_guard` 新增 `_VENUE_CLAIMS`（保守中文正则：
  `(正|刚|现在)?在.{0,4}(二手)?书店|图书馆|商场|学校|办公室|健身房|地铁` ×
  各自合理营业时段窗），当地深夜（约 0-6）命中**现在进行语义**才句级剥离；
  显式排除过去/计划语（昨天/上次/白天/明天/打算/想去 前置即放行）、24h 场所
  （便利店）不进词表。挂进既有 `apply_world_clock_guard` 单一入口——A 线 5c2 与
  B 线 9c 零新接线自动双覆盖。
- **哲学**：与该守卫既有口径一致「宁可漏报不误伤」；这是**最后防线**，主修在
  P0-1/P0-2 的源头，词表只兜 LLM 自由发挥（如爱好词驱动的「我在二手书店」）。
- **不变量门禁**：正例（凌晨「我正在书店看书」剥离）+ 反例（「白天去了书店」

### 6.2 实施中的再优化（相对第三节原方案的偏差，全部有意为之）

1. **P0-1 比原方案更简**：排查发现 persona_reply 在锚点之前**已经**把 persona_id 解析成
