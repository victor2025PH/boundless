## 3. C1 —— 节奏档接进主规划链（**先做这个，是 #65 的根因**）

把 `pace.resolve_pace` / `is_sprint` / `slot_key` 接进目标**规划与推进判定**
（`planner.py`、`service.py`、`sprint_ticker.py`），使：

- `session` 档目标按**入站回合**拿出手机会
- `today` 档目标按**小时槽**拿出手机会
- `natural` 档**行为完全不变**（这是回归钉，见验收第 3 条）

**四条硬约束，别顺手放开：**

1. `SPRINT_OK` 白名单**之外**的模板（关系 / 唤回 / 摸底类）仍走自然天。
   放开它们会让 AI 变成催命的推销机器，那是另一个方向的事故。
2. 坐席表单**不暴露 `pace` 字段**：写进 `goal.params['pace']`，模板 params schema
   不渲染它。理由——多一个坐席看不懂的旋钮，不如让系统自己判。
3. 档位自动落值：短期限目标（< 1 天）创建时自动落 `session`，1–2 天落 `today`，
   其余 `natural`。
4. 「拿到出手机会」≠「必须出手」。既有的情绪闸门 / 冷却 / 主动预算全部照旧生效
   —— 你只是让它**有机会被评估**，不是绕过护栏。

### 验收

1. 60 分钟的 `custom` 目标：在 **3 个入站回合内至少注入 1 次**，且不被判 `expired`
2. 3 小时目标的进度**按回合爬升**（不是卡在个位数百分比）
3. `natural` 档金标**一字不变**（跑既有 goals 测试文件，输出逐字对比）
4. `_note_meta` 的原因码在新链路下仍然正确——`beat_rejected` 不该因为接了 pace 就消失

## 4. C2 —— 摸底类目标从软提醒改硬约束（#38 / #40）

用户诉求原文是「**AI 不主动搜集客户信息**」。

现状两层都不给力：画像只在客户说出**标准句式**时才入档；目标层只做**软提示**，
LLM 经常忽略。

**改：** 设了信息采集类目标（`profile_slots` 相关模板）后，注入块**每轮必须自然带出
一个还没采集到的字段**。`src/companion/goals/profile_slots.py` 已有槽位表，取**第一个
未填槽**即可。

注入文案必须明确写「**像朋友闲聊，不要像查户口，一轮只问一个**」——
一轮连问三个字段比不问更糟，用户会直接觉得是机器人在做问卷。

### 验收

1. 连续 5 轮对话 → 5 个**不同**未采集槽位各被自然问过一次
2. **无重复追问同一槽**
3. 已采集的槽**不再问**

## 5. C3 —— 画像归纳兜底（不再等客户说标准句式）

聊过的内容定期自动沉淀进客户画像（`profile_llm.py` 已有 LLM 抽取能力），
**低把握的标「待确认」而不是丢弃**。

⚠ **必须过 `src/ai/memory_grounding.py` 的接地护栏，不许绕过。**
规则是「抽出的事实必须与客户原话有内容级词汇重叠（CJK bigram / 拉丁词 / 数字），
宁可漏记不可错记」。

这条护栏是 2026-07-13 幻觉事故的防线，事故长这样：AI 自己问「明天不用上班？」→
记忆抽取把 **AI 自己的猜测**存成「用户事实」→ 下轮注入 prompt → AI 更确信 →
最后 AI 对着用户复读「你说想去大阪玩」，而用户从没说过。

绕过接地护栏做画像归纳，就是把那起事故重新造一遍，而且这次是写进**长期画像**
（比 episodic 记忆更难清理）。

`memory_grounding.py` **只读复用，不要改它**。

### 验收

1. 给一段自然对话（客户提到城市 / 职业但**非标准句式**）→ 画像出对应槽位且标「待确认」
2. AI 自己臆测的内容**一条都不入档** —— 直接复用 `tests/test_memory_grounding.py`
   里的事故语料当金标
