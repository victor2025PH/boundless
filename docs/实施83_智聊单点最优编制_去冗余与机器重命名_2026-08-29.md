## 指令 1+2 的技术路径（关键：原架构做不到，需要新落点）

### 为什么现在做不到

智聊现在走 `hub_fish` → `176:9000/api/tts_only`。查 Hub 的 OpenAPI：

```
POST /api/tts_only
required: profile, text
properties: profile, text, language, emotion, fish_params, best_of,
            format, channel, scene, tts_engine, instruct
```

**没有任何传参考音的入口**——走 Hub 就必须报 176 角色库的档名。而 IndexTTS 服务本体 `176:7865` 对外 **401**（需 AvatarHub 令牌），智聊无法绕过 Hub 直连。

**所以指令 1（全 IndexTTS-2）和指令 2（不用角色库）在现架构下互斥。**

### 出路：给智聊部署专属 IndexTTS-2，代码零改动

查 `173:C:\models\index-tts\index_tts_server.py` 的服务端契约：

```
POST /v1/tts/clone
{ text, reference_audio_b64, reference_text, emotion, emo_audio_b64, references }
```

`_pick_spk()` 优先读 `reference_audio_b64` —— **原生支持直传参考音，不需要 profile**。还支持 `emo_audio_b64` 让情绪参考音与音色参考音分离，这正是 IndexTTS-2「情感不吃音色税」的实现机制。

而智聊侧**已有对应后端**（`tts_pipeline.py::_try_minicpm_clone`）：

```python
"""MiniCPM-o 情感克隆（与 fish_speech 共用 /v1/tts/clone 契约，复用 VoiceCloneClient）。
用人设 voice_profile.reference_audio_path 作参考音克隆音色"""
```

契约逐字对齐，参考音读本地 `config/voice_refs/`，还带 `cloud_fallback` 开关（置 false = 不回落，符合指令 4）。**代码一行不用改，只改配置。**

### 落点选择

IndexTTS-2 权重 **9.72 GB**（173 实测）。各机可用空间：

| 机器 | 空闲 | 可行性 |
|---|---|---|
| 104 | 11.8 GB | ✅ **唯一可行**（ComfyUI 已按老板决策停掉） |
| 198 | 5.1 GB | ✗ 装不下 |
| 140 | 1.6 GB | ✗ |
| 173 | 0.3 GB | ✗（vLLM 0.93 占满） |
| 176 | 11.0 GB | ✗ 那里已有一份，且要腾给出图 |

**⇒ 104 改作智聊专属声音节点。**它刚清空、有 11.8 GB、零其他负载，装 9.72 GB 权重后余 2 GB 供推理——比 176 上和十个服务抢卡更稳。

**代价（如实）**：4070 比 5090 慢，IndexTTS-2 单轮从 8–10s 可能变成 12–18s。老板已定「只做最高质量」，接受。

### 单点化的风险（必须说清）

老板要求「不做兜底和备用」，我执行，但如实标注后果：

| 能力 | 单点后，那台机器挂了会怎样 |
|---|---|
| TTS（104） | **所有人设语音停发**（strict 模式拒发，客户只收到文字） |
| ASR+SER（176） | **客户发的语音消息无法转文字**，AI 完全不知道说了什么 |
| 识图（198） | 客户发的图片无法理解 |
| 嵌入（140） | 记忆召回降级为关键词（不致命） |
| 出图（176） | 无法出图（老板已接受） |

176 在 08-28 17:40 **整机崩过一次**（GPU 驱动级错误、ping 100% 丢包），单点化后同样的事故会让「语音理解」这条链完全消失。这是老板的决策，我照做并记录在案。
