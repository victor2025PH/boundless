# 实施31 · 影子模式部署指南（S3.5 灰度前置）

**日期**：2026-07-20
**范围**：智控王 `D:\aixyc2026\tgkz2026`（写入端） + chengjie 引擎（决策提供端）
**用途**：一份可直接照做的操作步骤，把"AI_BACKEND=chengjie 灰度开灯"这个需要业务方拍板的决策，转化为"先用真实流量采集对比数据，业务方看数据再决定"。**本指南不改变任何真实回复行为**——完整原理与代码见融合方案文档 §9.12。

---

## 零、开始前必须确认的三件事

1. **有一台 chengjie 实例在跑，且已接好 `/api/replybus/decide`**——影子模式是"问一次 chengjie 会怎么回"，chengjie 没启动，影子模式只会记录"未采集到"（`chengjie_available:false`），不会报错，但也没有数据可看。
2. **AI_BACKEND 保持 `local`（默认值，不要动）**——影子模式与 `AI_BACKEND` 完全正交，开影子模式**不会**让任何真实回复改用 chengjie。如果你已经把 `AI_BACKEND` 设成了 `chengjie`，说明你已经在正式灰度了，这时开影子模式没有意义（多打一次重复请求，不算错但没必要）。
3. **确认要采集的是哪一台智控王实例**——多机部署的话，先在一台低风险/非核心账号所在的实例上开，观察几天再决定是否扩大范围。

---

## 一、开启影子模式（两个环境变量）

在智控王后端进程启动前设置（**必须在进程启动前**——`config.py` 在模块 import 时读一次环境变量并缓存，运行中途改环境变量不会生效，这是与 `AI_BACKEND`/`ENABLE_AI` 相同的既有惯例）：

```powershell
# Windows PowerShell 示例
$env:TG_REPLYBUS_SHADOW = "true"
$env:BOUNDLESS_BUS_URL = "http://<chengjie实例地址>:<端口>"   # 例如 http://127.0.0.1:18787
# 可选：如果 chengjie 那台配置了鉴权（web_admin.auth_token 非空）
$env:BOUNDLESS_BUS_TOKEN = "<对应的令牌>"

# 然后正常启动智控王后端（按你现有的启动方式，例如）
python main.py
```

```bash
# Linux/macOS 示例
export TG_REPLYBUS_SHADOW=true
export BOUNDLESS_BUS_URL="http://<chengjie实例地址>:<端口>"
export BOUNDLESS_BUS_TOKEN="<可选，鉴权令牌>"
python main.py
```

**确认生效**：进程启动日志里应该能看到（`config.py` 启动时打印的诊断信息）：

```
[Config] Replybus 影子模式 (REPLYBUS_SHADOW): 啟用
```

如果看到"關閉"，说明环境变量没有在进程启动前设好，检查一下设置顺序。

## 二、影子模式跑起来之后，会发生什么（预期行为）

1. 用户发一条私信 → 智控王照常走**本地 `ai_auto_chat`**生成真实回复并发送（**完全不变**）。
2. 真实回复发送完毕后，**背景**（不阻塞、不拖慢真实回复）额外问一次 chengjie 的 `/api/replybus/decide`『如果是你，会怎么回』。
3. 把"本地怎么回"与"chengjie 会怎么回"这一对数据，写进本地文件 `backend/data/replybus_shadow/shadow-YYYYMMDD.jsonl`（按天分文件，JSON Lines，一行一条）。
4. 任何环节出错（chengjie 没启动、网络不通、超时）都会被静默吞掉，只在日志里记一条"未采集到对比"，**绝不影响真实回复**，也绝不重试骚扰用户。

**这一步不需要人做任何事**——开好开关、让服务正常跑几天，数据会自然积累。

## 四、怎么解读这份报告、决定要不要继续灰度（业务方视角）

| 看这个指标 | 说明什么 | 该怎么办 |
|---|---|---|
| **采集率**（`chengjie_available` 比例） | 数据是否够多够看 | 低于 70%~80% 说明 chengjie 实例不够稳定，先解决稳定性问题，别急着看质量 |
| **决策分布**（draft/silent 占比） | chengjie 是"太爱回"还是"太惜字如金" | 明显偏一边（比如 95% 都是 silent）可能说明人设/知识库配置不足，需要先补配置再评估 |
| **分歧 A 抽样**（本地回了、chengjie 说不回） | chengjie 可能过于保守，会漏接真实商机 | 抽 5-10 条人工看，如果这些消息本该有回复（如明确的价格询问），说明 chengjie 判断偏严，需要调整触发条件 |
| **分歧 B 抽样**（本地没回、chengjie 说该回） | chengjie 可能比本地更主动 | 抽样看 chengjie 的草稿质量，如果写得好，这恰恰是"chengjie 比本地强"的证据 |
| **回复长度对比** | 风格差异 | 长度差异过大（比如 chengjie 明显啰嗦或过短）值得关注，但不是决定性指标 |

**建议的决策标准（供参考，不是强制）**：采集率 > 80%，且人工抽样 10-20 条分歧记录后，chengjie 的草稿在大多数case下"至少不比本地差"，可以考虑进入下一步——挑 1-2 个非核心账号，正式设 `TG_AI_BACKEND=chengjie`（这一步开始才是真正切真实回复，请单独评估风险，不在本指南范围）。

## 五、常见问题

**Q: 影子模式会不会让 chengjie 那边多消耗算力/API 调用量？**
A: 会——影子模式确实会让 chengjie 对每一条真实私信都跑一次决策生成（哪怕不用于真实回复）。如果 chengjie 走的是按量计费的外部 LLM API，这是真实成本，请评估用量再决定开多长时间/多少台实例。

**Q: 能不能只对部分用户/部分时段开影子模式？**
A: 当前实现是进程级开关（整个智控王实例的所有私信都会被采集），没有做到按用户/时段抽样。如果需要更精细的控制，属于后续增强，不在本次范围。

**Q: 关闭影子模式会不会丢已经采集的数据？**
A: 不会。关闭只是停止写新数据，已经写好的 `shadow-*.jsonl` 文件不受影响，`shadow_report.py` 随时可以再跑。

**Q: 怎么确认影子模式真的没有影响真实回复？**
A: 融合方案文档 §9.12 记录了完整的验证过程（子进程级测试，覆盖默认关闭/总线不可达/mock 联网三种场景），已确认真实回复在所有场景下都未被影子任务读取或篡改。如果你想自己二次确认，可以对照检查 `backend/private_message_handler.py` 里 `_maybe_shadow_log_replybus` 的调用点——它在 `ai_response` 已经算出**之后**才被调用，且是"fire and forget"（`asyncio.create_task`，不 `await` 结果）。
