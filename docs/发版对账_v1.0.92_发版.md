## 1. 本版唯一改动：安装器进程收割

现场故障（09-19/20，远端坐席与老板本机各一次）：升级装到一半弹「智聊 无法关闭。请手动关闭它，然后单击重试以继续。」→ 点重试无效 →「Failed to uninstall old application files ... : 2」；重启电脑再点「继续」才装完。

根因（117 上用自建 makensis harness 实测）：`build/installer.nsh` 的 `cxReapFamily` 原来用
`Get-Process | Where-Object { $_.Path -like '*\<pkg>\*' }` 找进程。`Process.Path` 走
`Process.MainModule`，需要目标进程的 `PROCESS_VM_READ`——**按用户安装的安装器上下文拿不到**：
实测可见 342 个进程，只有 18 个 `.Path` 读得出，谓词命中 **0**，占坑进程原样存活。也就是说这张安全网
**从写下那天起在真机上就是空转**；此前没暴露，是因为 `$INSTDIR` 里只有 `智聊.exe`（模板自带的按名检查覆盖得到）。
1.0.90 起随包的 `resources\backend\backend.exe` + 它的电脑微信副驾子进程住进了 `$INSTDIR`，
按名检查管不着 → `un.atomicRMDir` 改不动它的镜像文件 → 旧卸载器 exit 2 → 上述两个弹窗。

修法（`engines/chengjie/desktop/build/installer.nsh`）：

| 改动 | 为什么 |
|---|---|
| `Get-CimInstance Win32_Process` + `ExecutablePath` 筛进程 | WMI 走内核，不需要对目标进程持句柄，能看见本用户全部进程 |
| 杀完轮询复查，20s 预算内不干净才认输（退出码 0/1） | 固定 `Sleep` 不是「已死」的证据，下一步模板就要改名 `$INSTDIR` 全部文件 |
| PowerShell 用绝对路径 `$SYSDIR\WindowsPowerShell\v1.0\powershell.exe` | 它不在 System32 根下；PATH 被裁就会静默失效 |
| 新增 `customUnInstallCheck`：旧版卸不掉 → 再收割一轮 → 重试卸载 → 仍失败则就地覆盖安装并如实弹报（`MessageBox` 带 `/SD`） | 模板原尾巴是「无 `/SD` 的 MessageBox + exit 2 + Quit」：交互式＝告诉用户升级失败让他自己重来；静默 `/S`＝**无限挂在看不见的模态框上**（实测挂满 18 分钟） |
| 反模式钉进门禁 `test/uninstall-nsh-invariants.test.js`（禁 `Get-Process \|` 按 `.Path` 筛） | 同一个坑不许再挖第二次 |
