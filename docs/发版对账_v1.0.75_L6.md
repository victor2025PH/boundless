**两个实测结论，写进代码注释与本表**：
1. **Ollama 0.31/0.32 的 OpenAI 兼容层 `/v1/chat/completions` 忽略请求体 `options.num_ctx`**（带 `options.num_ctx=8192` 发，`ollama ps` CONTEXT 仍 4096；`vision_client.py` 2026-08-15 也记过同一结论）。所以网关侧 `options.num_ctx` **不是修法**，生效点只能是中继 Modelfile；网关仍随请求声明它（线上契约 + 告警对照值）。
2. 指令建议的「新 tag + 网关指向新 tag」在 140 上会出事：LAN 直连客户端（117 生产实例 / 坐席机）按原名 `qwen3-vl:8b-instruct` 钉着 4k 版常驻，新 tag 一来两份 6 GB 模型互相挤显存换入换出（实测 8k 版服务完一个请求就被 4k 版挤回）。故改为**原 tag 就地加参**，LAN 直连与网关拿到的是同一份 8k 模型。

**等价复现**：1 张 800px 图 + 长 prompt（`usage.prompt_tokens=4753` > 4096）打两台中继 `/v1/chat/completions` → 均 **200** 并正确抄出票据文字（修前 4170 即 400）。网关流水 `ai-gateway.jsonl` 里钧机原事故对得上：`2026-09-05T17:30:19Z ev=chat mid=B990… status=400 vision=1`。
