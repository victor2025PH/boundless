## A（止血，先做先提）stop_contact / self_harm 硬停 + risk=high 不直发 —— D-O1

- 现象：21:00:26 起草 `shadow=stop_contact hits='please stop' risk=high` → 21:00:39 发出；21:02:18 `hits='stop writing to me' risk=high` → 21:02:30 发出「I hear you, and I'll stop here… Take care.」；21:03:38 客户已说「Never write me again, please」→ `shadow=-`（漏判）→ 21:03:48 又发。
- 根因：09-04 #160 v2「L3/L4 全放行只记录」在 `autosend_policy.decide` 无豁免项；停联词表缺 never write me again / don't contact me / leave me alone / stop texting。
- 修法：① `autosend_policy.decide`：`shadow ∈ {stop_contact, self_harm}` → 不看 policy_mode：本轮**只允许一条告别**（人设口吻、≤1 句、不解释是 AI、不承诺「助理联系」——模板走 i18n，按会话语言）→ 会话置 `frozen_reason=stop_contact`（`protocol_autoreply.tag_needs_human` 同一入口）→ 后续入站不起草、关怀 / 目标 / 问候对该会话全部跳过（`care_dispatcher` / `sprint_ticker` / `GreetingSkill` 查同一标志）→ 列表标签「客户要求停联」+ 通知中心一条；② `risk=high`（非停联）稿在全自动下 → 转人工审（review），不直发；③ 词表补上述四组 + 中文「别再发了 / 不要再联系我 / 拉黑」；④ 日志 `[stop-contact] conv=… action=farewell|frozen|skipped`。
- 验收：回放 XAM4KV 三条入站 → 第一条发一条告别并冻结，第二、三条零出站；`risk=high` 非停联稿进 review 队列；tests：停联三例 + 冻结后关怀 / 目标不出手 + 人工解冻后恢复。

## B 出站确定性「去 AI 标点 / 句式」 —— D-O2

- 现象：一天 5 条 em dash 跨 3 个 WhatsApp 账号（同一人设 Mizuki）；「复述 → 破折号引申 → 人生感悟式总结 / isn't it 反问尾」固定套路；出站文本不落日志无法统计全量。
- 修法：新 `src/inbox/outbound_humanize.py` 纯函数 `humanize(text, lang, *, mode) -> (text, stats)`：U+2014/U+2013 → 逗号或拆句；弯引号 → 直引号；分号 → 句号；`…` → `...`；`°C/°F/%` 等 → 口语；冒号列表 / 项目符号 / 编号 → 散文；连续 ≥2 `!` 或 emoji 串截断；删结尾总结 / 感悟句与 isn't it / aren't they / right? 尾巴（句式表可配）；默认 ≤2 句（超长精简不切分，与 L-1 A「不拆条」一致）。挂在 `outbound_translate` `pass_gate_only` 之后、所有 AI 生成路径（自动回复 / 关怀润色 / 目标冲刺 / 问候），**verbatim 与人工手发绕过**。生成侧同步：MaxTokens 默认 60–80 + few-shot 禁破折号 / 分号。每条出站落 `[outbound] conv=… len=… punct_fix=n style_fix=n`（这就是 78W8DN 要的出站文本日志）。
- 验收：200 条样例（含英 / 中 / 日 / 泰）0 em dash、0 分号、0 总结尾句；tests 覆盖每类替换 + verbatim 绕过 + 中日文标点不误伤（「——」中文破折号按语言表处理）。

## C 陪伴域系统提示词重写 + 客服腔守卫 —— D-O3

- 现象：`13:14:46 System prompt loaded from domain pack (1868 chars)`，域包 conversion = 销售 / 客服底稿；「I hear you… Take care」「我的助理会联系您」「Absolutely, I'm looking forward to it. Have a great morning over there!」皆源于此；人设口语描述叠在上面盖不住。
- 修法：① 新 `domains/conversion/prompts/system_companion.*`（或 `domains/companion_prompts/`）「私人聊天」底稿：第一人称、口语短句、有情绪、允许不完美、不总结不说教；明确禁止客服 / 助理 / 品牌代言语气，禁止 I hear you / I understand / Take care / I'll be around / Feel free to / Let me know if / 如有需要 / 很高兴为您 / 我的助理；`ai_client` 加载时按 `business_domain`（N-3 A）选文件，`sales` 仍旧稿；② 该底稿覆盖自动回复 / 关怀 AI 润色 / 目标冲刺 / 问候 / 翻译改写（identity 与 verbatim 除外）；③ `persona_guard` 客服腔黑名单扩到上述词组 + 「致谢-确认-告别三段式」「条件句收尾」句式：命中 → 按人设口吻改写一次 → 仍命中 → 降级人工审核，落日志 `[persona-guard] service_tone=… action=rewrite|review`；④ 人设说话指纹默认 5–10 条真实口吻 few-shot（有 `spoken_style` 包的用包，没有的用底稿自带示例）。
- 验收：50 条拒绝 / 冷淡 / 告别 / 抱怨场景样例盲评「像真人」≥45；tests：黑名单每词 + 三段式识别 + sales 域仍旧稿。

## D 拟人节奏默认档 —— D-O4

- 现象：240 分钟全局零 typing / pacing / composing / presence 日志；起草→发出固定 12–13 秒与长度无关；全天秒回；客户点名 typing speed。
- 修法：① 节奏引擎（`reply_pacing_settings` + worker 调用点）：读延迟 3–6s + 每 10 词 +1s 上限 20s ±30%；思考 3–8s；打字 英文 35–45 wpm / 中日韩 60–90 字/分 ±30% 上限 90s；发出前 1s 停 composing；客户连发合并等 8–15s 一次回（与 L-1 A 镜像口径合并）；首次接触 / 沉寂 >6h 首回延 1–5 min；夜间按账号时区 01–08 不回、08 后随机 0–40 min 补（默认开可关）；② composing 真发：Telegram `sendChatAction`、WhatsApp 边车 `presence composing`——查 `typing_callback` 为什么零日志（是没接还是被 `typing_indicator` 覆写关了），LINE / Messenger 无能力位则日志写 `typing=unsupported`；③ 界面：`reply_settings.html` 顶部「拟人程度」三档 自然（默认）/ 偏快 / 偏慢 一键改全部节奏参数；平台专家覆写表预填 WA / TG / LINE / Messenger 默认；回复策略 / 覆写表 / 缓冲收进「专家设置」折叠区；③ 每条出站落 `[pacing] read=… think=… type=… composing=… total=…`。
- 验收：回放 20 条入站，发出间隔与字数正相关（相关系数 >0.6）、无两条间隔相同到秒；夜间样例不发；日志每条都有 `[pacing]`；tests 覆盖三档与夜间。
