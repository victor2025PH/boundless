## 1. 微信客服 API 事实（2026-09 核实，实现依据）

- Base `https://qyapi.weixin.qq.com/cgi-bin/`；`gettoken?corpid&corpsecret`（7200s）。必须用**自建应用** secret，且应用配在
  「微信客服 → 可调用接口的应用」（2023-12-01 起系统 secret 不可用）；应用需配可信 IP。
- 收：回调 `kf_msg_or_event`（XML 加密，含 10 分钟有效 `Token` + `OpenKfId`）→ `kf/sync_msg{cursor, token, limit≤1000,
  voice_format, open_kfid}` → `msg_list[]`：`msgid / open_kfid / external_userid / send_time / origin(3 客户,4 系统,5 接待人员)
  / servicer_userid / msgtype`。**无 token 拉取受严格频控**（数值未公开→轮询间隔可配、退避）。消息保留 3 天；读不到 API 发出的消息。
- 事件：`enter_session{scene, scene_param, welcome_code}`、`msg_send_fail{fail_type 4=超48h, 6=超5条, 8=主体未验证, 10=拒收, 11=无成员登录, 13=安全限制}`、
  `servicer_status_change`、`session_status_change{change_type 1接入/2转接/3结束/4重新接入, msg_code}`、`user_recall_msg`、
  `servicer_recall_msg`、`reject_customer_msg_switch_change`。
- 发：`kf/send_msg{touser, open_kfid, msgtype, ...}`——**用户最后一条消息后 48h 内最多 5 条**；仅会话状态 0/1 可发；成功≠送达。
  `kf/send_msg_on_event{code}` 欢迎语（20s 有效）。
- 会话状态：`kf/service_state/get|trans`，0 未处理 / 1 智能助手接待 / 2 排队 / 3 人工接待 / 4 已结束；转 3 需正在接待的 servicer_userid。
- 媒体：`media/get?media_id`（3 天）；`media/upload?type=image|voice|video|file`。无 typing、无已读回执（协议层硬限制）。
- 回调加解密：企微 WXBizMsgCrypt（AES-256-CBC，SHA1 `msg_signature`；GET 校验回 `echostr` 明文）。

### 2026-09-08 · 线 B 真机联调（PC 微信 4.1.12.55 + 独立联调实例 18898）

**场景**：主人登录 PC 微信；两个显示名完全相同的客户号「无界科技BOUNDELESS」各发一条（「说得好」「急急急」），另一位「十三香小龙虾」
收到主人发的「22」。要求：进后台、同名不同号不并成一个会话、能从工作台回。

**结果**（`http://127.0.0.1:18898/workspace`，账号 `wxpc-dev-1`）：

| 会话 chat_key | 显示名 | 线程 |
|---|---|---|
| `wx:id:zhu0396000` | 无界科技BOUNDELESS | [in] 说得好 02:27 → [out] 第二条联调测试… 04:11 |
| `wx:id:zhu0396002` | 无界科技BOUNDELESS | [in] 急急急 02:27 → [out] 收到，这条是从智聊工作台发出的… 04:08 |
| `wx:id:ai26_sbs` | 十三香小龙虾 | [out] 22 02:26（主人手发，镜像为己方） |

两条出站均由坐席在工作台 `POST /api/unified-inbox/send` 发起 → 桌面桥回落入受控队列（`kind=manual`）→ 半自动档服务认领 →
五步守卫（开会话**含资料卡微信号核对**→标题→填入→发送→回显）→ 回执 `sent` → 微信侧实发（会话预览与时间已变）→ 下一轮回显镜像为 out。

**真机实锤（全部已固化进 `uia_backend.ANCHORS` 与纯函数单测）**：
