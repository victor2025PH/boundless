## §〇 先答一问：为什么登录 / 切全自动会群发？

**答：三段链每一段都缺一道闸，历史消息一路被当成「刚到的新消息」。**

1. **边车把历史当新入站推**：`services/whatsapp-baileys/server.js` 登录后 `syncFullHistory: true`，`messaging-history.set` 携带每个会话的末尾 `WA_BACKFILL=20` 条消息 → `pushWaMessage(entry, msg, true)` 逐条 `POST /api/internal/protocol/ingest`，payload 与实时消息**零差别**（H3BAJD 15:00:12 pairing completed → 15:00:15–16 六个老会话进箱）。占位会话拉历史（`fetchMessageHistory` → `syncType=ON_DEMAND`）同一条路（ZH3ZQ5 14:37:43 「WA history fetch requested」同秒起草）。Telegram `backfill_telegram` 首连 `get_dialogs` 末条走 `emit_incoming` 实时 sink，同病。
2. **后端没有「回填」概念**：`ingest_incoming` → `normalize_chat(unread=1)` → `ingest_collected_chats` 对每条新插入的入站行发 `_new_inbound_cbs`（auto-draft / 关怀捕获 / 影子扫描）+ SSE + 意图情绪 + 记忆抽取；`normalizer.py` 只用 `is_self` 定方向，`peer == self`（Message yourself）也照常当客户。
3. **起草层没有年龄闸**：`drafts.auto_generate_draft` 只看冻结 / 幂等 / 风险；`l1_reason._first_contact` 只数「入站 ≤1」把老会话当首次接触 → 全自动下就是 L2 直发（`chain=opener` 还会编造「you mentioned that hiking trail」）。停联冻结（O-1 A）记在会话标签 + 档位上，clean 重装即丢 → Sinue 又被起草。

**修法 = 三道闸 + 一张清单 + 一份名单**：① 边车 / 桥打 `backfill` 标，落库不触发（A）；② `auto_generate_draft` 入口 72h 年龄闸，超龄进「沉寂会话待你决定」清单（B / D）；③ 切档 / 登录确认框两栏，默认只碰「最近 3 天有来信」（C）；停联名单账号级持久 + 登录同步后扫描复冻（E）；自聊会话 `self_chat=1` 排除全部自动化（F）。
